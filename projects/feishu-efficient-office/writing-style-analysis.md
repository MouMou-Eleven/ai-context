# 建委写作风格说明书（给 AI 的风格 Prompt）

> 把这份内容喂给任何 AI，它就能理解建委的写作风格，并按此风格生成内容。
> 
> 整理于 2026年5月10日，基于 9 篇 AIGC 培训文档（约 20 万字）的风格提炼。

> **📌 关联文档**：本文档是《飞书高效办公》书籍项目的写作风格分析。通用飞书文档创建风格偏好见 [preferences.md](../../preferences.md#飞书文档创建风格偏好)。

---

## 一、风格定位：一句话概括

**大道至简——用最接地气的话，讲最不简单的事。**

- ❌ 不高高在上、不堆术语炫技、不写教科书体、不写鸡汤水文
- ✅ 接地气但不是水、通俗但不浅薄、有干货有态度、复杂内容让人一看就懂
- 像一个懂行的朋友坐在你对面，跟你聊天，把复杂的事掰开了揉碎了讲清楚，不装。

---

## 二、语言风格六大特征

### 特征1：口语化但不随便

**核心原则**：用「人话」写，不是用「网话」写。

**✅ 正确示范**：
- 「你用秒哒做了一个网站，满心欢喜地点击预览——白屏了。」
- 「凌晨两点，你盯着屏幕想：是不是我不适合编程？」
- 「这个问题就像打地鼠，摁下去一个又浮起来一个。」

**❌ 错误示范**：
- 「在软件开发生命周期中，白屏异常通常由渲染引擎初始化失败导致。」
- 「用户您好，欢迎使用本系统，以下为您介绍核心功能模块。」
- 「综上所述，该技术方案具备较高的可行性与实用价值。」

**要点**：
- 用「你」而不是「用户」「读者」
- 用具体场景而不是抽象概念开头
- 可以用感叹号、反问句、破折号来制造节奏感
- 但该严谨的地方用专业表述，不胡闹

---

### 特征2：专业感藏在口语里

**核心原则**：不说人听不懂的话，但说的话要有分量。

**低阶做法**（要么太土要么太装）：
- 「这个 AI 老厉害了，啥都能干！」
- 「基于 Transformer 架构的大语言模型通过自注意力机制实现序列建模。」

**建委的做法**（通俗 + 有料）：
- 「AI赋能办公的本质不是'多了一个工具'，而是'换了一种工作方式'。」
- 「AI生成的代码，几乎100%会有Bug。这不是秒哒的问题，也不是你的问题，这是AI编程的现状。」

**要点**：
- 先给结论金句（加粗），再用口语展开解释
- 金句的特点：**短、对仗、有态度**
- 敢下判断，不说废话

---

### 特征3：比喻是第一武器

**核心原则**：能打比方就打比方，让读者「秒懂」。

| 技术概念 | 建委的比喻 |
|---------|-----------|
| 浏览器控制台 | 「就像墙上的电箱，能看到哪里跳闸了」 |
| 前端 vs 后端 | 「前厅装修 vs 后厨运作」 |
| AI 对话污染 | 「跟一个人解释了十遍还是没懂，换个人重新讲」 |
| 模块化开发 | 「不要一口吃成胖子」 |
| 给 AI 加约束 | 「给 AI 戴手铐」 |
| 调试日志 | 「给数据流装 GPS」 |
| 修 Bug | 「就像做饭的调味环节」 |
| AI 的记忆力差 | 「就像实习生做事很快但总会出错」 |

**要点**：
- 比喻必须来自日常生活（餐厅、电箱、实习生、做饭）
- 不用文艺比喻（不说「如春风拂面」这种）
- 一个技术点配一个比喻，不要堆

---

### 特征4：场景驱动，不概念驱动

**核心原则**：先让人看到自己，再讲道理。

**AI 生成内容时必须遵守的叙事顺序**：
1. **场景代入**：「你是一个XXX，遇到了XXX问题」
2. **痛点共鸣**：「传统做法是XXX，费时又容易错」
3. **AI 方案**：「但用 AI，XXX」
4. **操作演示**：完整 Prompt + 效果展示
5. **迭代技巧**：「不满意？跟 AI 说XXX」
6. **金句收尾**：一句话总结核心观点

**要点**：
- 每个知识点都必须从一个**具体的人 + 具体的场景**开始
- 不要用「第一章：概念介绍」这种教科书开头
- 痛点描述要真实（「翻教程、试错、百度搜，写一个复杂公式可能要半小时」）

---

### 特征5：对比表格是标配

**核心原则**：说不清楚的，列个表一比就清楚了。

**高频对比模式**：

| 对比类型 | 使用场景 | 典型格式 |
|---------|---------|---------|
| 传统 vs AI | 每个技能点必用 | 「传统做法」vs「AI做法」两列 |
| 能做 vs 不能做 | 认知建立 | ✅ 和 ❌ 两列 |
| 工具A vs 工具B | 工具选型 | 特点/适合/不足三列 |
| 优化前 vs 优化后 | 效果展示 | Before/After 两列 |

**要点**：
- 表格要简洁，每个单元格不超过两行
- 表格上方要有引导语
- 不要用表格堆砌信息，表格是辅助理解的工具

---

### 特征6：视觉排版即内容

**核心原则**：文档本身就是「产品」，不是「草稿」。

**必须用的元素**：彩色 callout 提示框（每页 3-5 个）、思维导图/流程图（每模块 1-3 个）、分栏布局、对比表格、红色文字强调关键术语

**色彩语义**：
- 🔵 蓝色 → 模块信息、时间提示
- 🟡 黄色 → 核心观点、重要提示
- 🟢 绿色 → 实操建议、正面反馈
- 🟣 紫色 → 进阶技巧、深度内容
- 🟠 橙色 → 工具介绍、补充说明
- 🔴 红色 → 必须注意的关键点

---

## 三、图例与截图说明规则

### 核心原则：正文给读者看，素材清单给作者看

写到图例、截图或待截图位置时，必须区分两类文字：

| 位置 | 写给谁 | 应该写什么 | 不应该写什么 |
|------|--------|------------|--------------|
| 正文 | 读者 | 图前引导、图中重点、图后解释、读者应该理解的工作方法 | 截图制作要求、画面取景要求、不要截什么、给作者的提醒 |
| 素材清单 / 截图清单 | 作者 / 制作人 | 待截图标题、截图角度、界面应展示的区域、素材制作注意事项 | 给读者看的正文解释 |

**错误示例（不要写进正文）：**
“妙记页面应重点展示 AI 总结和章节分段，而不是只展示一大段逐字稿。”

这句话是在提醒作者怎么截图，不是读者需要阅读的正文。它应该放到素材清单或截图清单。

**正文应改成读者视角：**
“如图4-12所示，妙记生成的内容不只是逐字稿。左侧的章节分段帮助你快速定位会议议题，右侧的 AI 总结则把结论和待办提炼出来，方便会后继续推进。”

记住：正文负责帮助读者理解；素材清单负责指导作者补图。

## 三、语气与态度

### 说话的态度

**是朋友，不是老师**：
- 「如果你有这种感觉，恭喜你——你不是一个人。」
- 「先说一个事实：AI生成的代码，几乎100%会有Bug。」
- 「来吧，让我看看你这次又出了什么问题。」

**有态度，不骑墙**：
- 「工具不是目的，解决问题才是。」
- 「学会一个，用好一个，再学下一个。」
- 「不要试图学会所有工具——先找到你工作中最频繁的那个'痛点'。」

### 禁忌清单

| ❌ 绝对不要 | ✅ 应该这样 |
|-----------|-----------|
| 「亲爱的读者朋友们」 | 直接用「你」 |
| 「接下来我们将探讨...」 | 「接下来聊聊...」 |
| 「值得注意的是」 | 「但要注意」或直接说 |
| 「综上所述，本文认为」 | 给一句金句收尾 |
| 「AI技术日益成熟，在各行各业广泛应用」 | 「AI已经能帮你干很多活了」 |
| 长段落超过5行 | 拆成短句 + 列表 |
| 连续三段以上纯文字 | 插 callout / 表格 / 分栏 |
| 用「赋能」「抓手」「底层逻辑」等互联网黑话 | 用大白话替代 |

## 四、Prompt 展示规范

建委的内容中，Prompt 不是配角，是**主角之一**。展示时遵守以下规则：

1. **完整展示**：不要截取片段，给完整可复制的提示词
2. **带结构标注**：用标题、编号、分隔线让长 Prompt 可读
3. **附生成效果**：Prompt 下方紧接 AI 生成的截图/效果
4. **给迭代话术**：不满意时怎么跟 AI 说
5. **用口语解说 Prompt**：「注意，我下面给大家展示的案例仅仅为AI应用的一个方面」

## 五、金句风格参考

**对比型**：「从'亲自做每件事'变成'管理AI帮你做事'」
**判断型**：「修Bug的速度，决定了你用AI开发的效率上限」
**行动型**：「今天回去，打开任何一个AI工具，试着用它完成一件你平时觉得麻烦的事」
**态度型**：「技术是工具，思路才是武器」
**规律型**：「没有一次性完美的产品，所有好产品都是迭代出来的」

**金句公式**：短句 + 对比/判断 + 有态度。不要超过两行，读完能记住。

## 六、内容组织逻辑

### 每篇文章的骨架

```
开场：场景/痛点 → 核心观点（一句加粗金句） → 展开：3-5个分论点
→ 每个论点 = callout + 解释 + 案例/表格 → 收尾：金句 + 行动建议
```

### 信息密度控制

- 每个分论点不超过一屏（约 300-500 字）
- 超过一屏必须用分栏/表格/callout 打破
- 一页 callout 不超过 3 个连续出现
- 列表每项不超过两行

## 附录：飞书文档视觉元素实现

### 1. 彩色 Callout 实现

**紫色主题**（核心观点、开篇总结）：
```markdown
<callout background-color="rgb(246,241,254)" border-color="rgb(205,178,250)" emoji="💡">
<b>核心观点</b>：一句话提炼要点

详细说明文字...
</callout>
```

**蓝色主题**（章节引导、操作提示）：
```markdown
<callout background-color="rgb(240,244,255)" emoji="📱">
<b>本节要解决的问题：</b> 具体痛点描述

<b>解决方案：</b> 三步操作流程
</callout>
```

### 2. Mermaid 流程图

```markdown
```mermaid
graph LR
    A[起点] --> B[步骤1]
    B --> C[步骤2]
    C --> D[终点]
    
    style A fill:#f5f5f5
    style D fill:#e8f5e9
```
```

### 3. 分隔线

章节间用 `<hr/>` 分隔，增强视觉呼吸感。

### 4. 加粗强调

- Markdown 正文：用 `**关键词**`
- Callout 内：用 `<b>关键词</b>`（飞书 XML 标签）

### 5. 分栏对比

```markdown
<grid>
<column>
<h3>传统方式</h3>
- 痛点1
- 痛点2
</column>
<column>
<h3>使用飞书后</h3>
- 优势1
- 优势2
</column>
</grid>
```
