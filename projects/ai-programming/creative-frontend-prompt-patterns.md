# 创意前端提示词结构与选型方法

> 状态：当前有效的方法论参考
> 素材整理日期：2026-07-15
> 适用范围：用 Claude、Codex、v0、Lovable、秒哒等 AI 编程工具生成具有视频、3D、视差和滚动叙事的展示型网站

本文不绑定单一平台，负责解释高质量创意前端提示词如何组织、不同交互机制如何选型，以及如何避免把复杂案例机械拼接。五份完整原始样例保存在 [`reference-materials/creative-frontend-prompts/`](./reference-materials/creative-frontend-prompts/)。

## 一、五类样例的价值与边界

| 类型 | 核心机制 | 最值得复用 | 主要风险 | 适合 JIANWEI FIELD 的位置 |
|---|---|---|---|---|
| 神经 AI 视频站 | 多段全屏视频、鼠标视频拖动、字符扰动、滚动 3D 文本 | 视频状态、时间映射、移动端替代、明确动画参数 | 全站等宽字体和连续视频容易单调；外链视频与版本会失效 | Seedance 开场视频与滚动逐帧控制 |
| 时尚档案画廊 | 固定视频、黑色面板上推、散点图片网格、进出视口缩放 | 图片不是标准卡片；精确描述布局算法和 RAF 位置计算 | 固定层过多，滚动高度难维护；动态后台内容要重新映射槽位 | 作品展馆的多图空间轨道 |
| 3D 创作者作品集 | 磁吸肖像、双向跑马廊、逐字显影、黏性堆叠项目 | 个人站章节节奏、磁吸与黏性卡片 | 普通 3D 设计师模板感强；大量 GIF 和圆角卡片容易廉价 | 个别微交互，不作为整站视觉模板 |

## 二、组合原则

高质量创意站不是“把五份提示词的效果全加上”。每一章只设一个主机制，其余动效服务于它。

推荐密度：

- 首屏：一个主叙事媒体 + 一个可交互三维核心物 + 一套前后景文字。
- 作品区：一个空间图片轨道，不再叠加第二套视频叙事。
- 个人与背书：恢复稳定阅读，只保留轻量视差或进入动画。
- 联系页：以转化为目标，停止炫技。

判断某个效果是否应该加入时，依次问：

1. 它是否帮助用户理解内容或建立空间关系？
2. 它能否由后台动态内容驱动？
3. 移动端和低性能设备如何降级？
4. 删除它后页面是否反而更清楚？

答不清楚的动效不进入主版本。

## 三、创意前端提示词的十二个组成部分

### 1. 产品与受众

先写清网站是谁、给谁看、希望用户完成什么动作。不要只写“做一个高级网站”。

### 2. 视觉母题

限定一个可持续使用的视觉语言，例如数字展馆、工业雕塑、档案索引或电影片场。避免同时要求赛博朋克、极简、复古、奢侈品和游戏 UI。

### 3. 技术栈与可变边界

明确 React/TypeScript、动画库、3D 引擎、视频格式和图标库，同时说明哪些库只是可选。不要为了显得专业堆叠 GSAP、Framer Motion、Lenis、Three.js、Spline 和多个滚动框架。

### 4. 资产清单

每个图片、视频、模型写明用途、尺寸、比例、加载方式和替代方案。外部 URL 只能作为样例，不作为长期资产策略。

### 5. 页面章节

按用户叙事顺序写，不按组件名称堆列表。每章说明：内容目标、视口高度、主视觉、文字位置、进入与退出方式。

### 6. 图层与深度

明确背景、远景文字、中景媒体、三维主体、前景遮挡和固定 UI 的 Z 层级。只写“增加空间感”不会得到可靠结果。

### 7. 滚动时间轴

使用 0%-100% 或明确的视口区间描述每个阶段。写清哪个元素在何时出现、移动、遮挡、退出，以及是否允许反向滚动还原。

### 8. 交互状态

分别定义默认、hover、pointer move、click、loading、error、empty、reduced motion 和触屏状态。鼠标机制不能直接假定在移动端存在。

### 9. 动态数据边界

品牌视频和固定 3D 素材可以写死；作品、客户、奖项、活动和文章必须来自数据结构或后台。禁止把可变内容烘焙进固定视频。

### 10. 响应式与性能

至少写明桌面、移动端、低性能和 `prefers-reduced-motion` 四种策略。包括视频格式、模型面数、贴图尺寸、懒加载、像素比上限和动画关闭条件。

### 11. 视觉红线

明确禁止普通卡片网格、无意义渐变球、默认圆形遮罩、全站同一种动画、文字压在主体脸部、3D 模型只原地自转等降级结果。

### 12. 验收标准

把“好看”改成可检查项目：桌面和移动端尺寸、全页滚动截图、Canvas 非空像素、控制台错误、交互可逆、文字不溢出、模型和视频加载失败的 fallback。

## 四、关键机制写法

### 视频逐帧控制

滚动叙事优先使用绝对进度映射：

```ts
video.currentTime = scrollProgress * video.duration
```

鼠标横向拖动适合短暂探索，不适合作为全站唯一导航。必须设置 dead zone、`video.seeking` 防抖、触屏自动播放或滚动替代，并在视频元数据加载完成后再计算时间。

### 空间作品轨道

作品数据和空间槽位分离：后台返回作品，前端按 `featured`、`sortOrder` 和分类映射到预定义 X/Y/Z 槽位。每屏同时保留 3-5 张不同深度的图片，避免退化成“一次一张”的轮播。

### 3D 与 HTML 共存

Canvas 可铺满视口，但文本与按钮保持 HTML。背景 Canvas 需要鼠标时，非交互文字层可使用 `pointer-events: none`，真正按钮重新设为 `pointer-events: auto`。同时提供模型加载失败和移动端静态替代。

### 前后遮挡

先建立 Z 层级表，再写动画。常用结构：

```text
z-0  背景视频或场景
z-1  远景描边文字
z-2  中景图片和主体
z-3  三维前景或透明遮挡素材
z-4  章节文字
z-10 固定导航和必要按钮
```

不要依赖一个 `z-index: 9999` 解决所有问题。

## 五、可复用总提示词骨架

```text
你是一名 Creative Developer 和交互设计师。请构建【项目名称】的【站点类型】。

一、目标与受众
- 网站服务于：【受众】
- 核心任务：【用户看完后应理解或完成的动作】
- 视觉母题：【单一视觉语言】

二、技术与边界
- 技术栈：【React/TypeScript/Vite/GSAP/Three.js 等】
- 固定品牌资产：【视频、场景图、GLB】
- 动态后台内容：【作品、客户、奖项、活动等】
- 禁止把动态内容烘焙进固定视频或模型贴图。

三、页面章节
按顺序逐章写：内容、视口高度、背景、中景、前景、文字、进入、主运动、退出。

四、滚动时间轴
- 0%-25%：【状态】
- 25%-60%：【状态】
- 60%-85%：【状态】
- 85%-100%：【状态】

五、交互状态
分别说明 pointer move、hover、click、touch、loading、error、empty、reduced motion。

六、数据结构
给出 TypeScript interface 和后台字段，说明数据如何映射到前端槽位。

七、响应式与性能
分别写桌面高性能、桌面低性能、移动端、reduced motion。

八、视觉红线
列出必须保留的空间关系和禁止出现的普通化结果。

九、验收
在 1440x900、390x844 检查整页；验证 Canvas 非空、滚动可逆、文字无溢出、控制台无错误、资源失败有 fallback。
```

## 六、JIANWEI FIELD 的推荐组合

- 首页：采用“视频逐帧 + FIELD CORE 三维主体 + 前后景文字”，借鉴神经 AI 视频站和 Spline 首屏的技术契约。
- 作品展馆：采用时尚档案画廊的多图空间槽位，但数据来自后台，不照搬固定商品图。
- 个人介绍、客户、奖项、培训与微课：采用深色编辑作品集的信息架构，降低动效密度。
- 个别交互：可借用磁吸和黏性堆叠，但不采用 3D 创作者样例的整体视觉风格。
- 删除双层显影、无意义加载页、普通 Bento 卡片、过量跑马灯和全站圆角胶囊。

## 七、使用原始样例时的注意事项

- 样例中的依赖版本、视频 URL、图片 URL 和 Spline scene 都是历史参考，执行前重新核验。
- 不复制样例品牌、文案、人物、客户数据或统计数字。
- 不同时引入多个滚动驱动系统；一个页面优先选择 GSAP ScrollTrigger 或 Framer Motion 的一套主控制器。
- 原始提示词写得很细，不等于技术路线一定正确。先保留视觉意图，再根据当前项目和浏览器性能调整实现。
