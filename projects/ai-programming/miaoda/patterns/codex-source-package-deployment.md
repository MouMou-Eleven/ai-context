# Codex 本地源码打包导入百度秒哒工作流

> 状态：当前有效
> 来源：2026-08-09 至 2026-08-10「混世魔牛」游戏实战交付
> 最近核验：2026-08-10
> 产品边界：本文只指百度秒哒 MIAODA（miaoda.cn），不指飞书妙搭 Spark

## 适用范围

本文用于这类任务：项目先由 Codex 在本地完整开发、测试和优化，再把源码与生产素材分包上传到百度秒哒，由秒哒接管云端对象存储、可选数据库、构建和部署。

如果项目已经完全存在于秒哒云端，本地没有权威源码，只需要 Codex 分析问题并生成分批提示词，应改读 [codex-assisted-workflow.md](./codex-assisted-workflow.md)。

两条工作流不能混用：

| 场景 | Codex 的职责 | 秒哒的职责 |
|---|---|---|
| 本地源码交接 | 直接开发源码、测试、浏览器验收、性能审计、生成分包与清单 | 接收校验、上传对象存储、适配云端环境、构建部署 |
| 既有云端项目迭代 | 读取证据、诊断、写最小修改提示词和验收清单 | 在云端项目内修改并回报 |

## 总流程

```text
需求与边界确认
  → Codex 本地开发
  → 自动测试 + 生产构建 + 浏览器/真机验收
  → 性能、网络、内存和素材闭包审计
  → 源码包 + 素材包 + PRD 基线 + SHA-256 清单
  → 秒哒先接收校验，禁止提前创作
  → 素材解压进云端对象存储
  → 按业务需要建立真实数据库
  → 秒哒依据源码生成 PRD 并开始创作
  → React/Vite 构建部署
  → 桌面、Android、微信、iOS Safari 与弱网回归
  → 增量补丁包或回滚
```

## 一、本地开发门禁

Codex 不能只说“代码改好了”。交付前至少完成：

1. 读取项目 README、现有测试、素材清单和协作约定。
2. 保留用户未授权删除的源码、素材和历史，不用重构掩盖问题。
3. 运行项目现有单元测试、集成测试和生产构建。
4. 用真实浏览器检查桌面和移动端：控制台、网络请求、布局、点击、触控和音频。
5. 对游戏、3D、视频或序列帧项目额外检查 FPS、纹理内存、DPR、预加载、对象池和页面隐藏状态。
6. 区分“运行时真正引用的素材”与“制作母版、旧版本、导出中间件、重复副本”。只交付运行时闭包，不以删除有效效果来减小体积。

生产交付必须以 `npm run build` 成功为门槛。秒哒收到的是可构建源码，不是只在 Codex 本机开发服务器里可运行的临时状态。

## 二、先统一技术栈

百度秒哒 Web 应用当前使用 React + Vite。源码导入提示词必须明确：

- 交付形态是 Web 应用。
- 构建命令是标准 Vite 构建，产物为 `dist/`。
- 禁止 Next.js、SSR、Next API Routes、`next` 依赖和必须常驻 Node 服务才能打开的方案。
- 不把 ChatGPT Sites、Vercel、Cloudflare 等平台专用 worker 或托管配置当成秒哒必需文件。

“Next.js 导入后黑屏”是 2026-08-09 当前秒哒 Web 交付环境的实战结果和交付红线，不应扩写成永久官方承诺。以后执行时仍要复核秒哒当前能力；未复核前继续使用已验证的 React + Vite 路线。

## 三、打包前先做运行时闭包

### 必须保留

- `src/`、入口文件、Vite 配置、`package.json`、锁文件。
- 与当前源码匹配的生产图片、视频、音频、字体、模型、图集和运行时 JSON。
- 能在交付环境执行的测试。
- PRD 基线、资源映射说明、上传提示词、验收标准。
- 每个包的文件路径、字节数和 SHA-256。

### 默认排除

- `.git/`、`node_modules/`、`dist/`、测试截图、日志、缓存和临时目录。
- 原始制作母版、未引用旧素材、重复导出、超大工作文件和本机密钥。
- 与秒哒无关的平台专用部署目录，除非项目仍需同时维护对应渠道。
- `.env`、Token、Cookie、API Key 和任何真实凭证。

### 为什么不能把整个工作目录直接压缩

本地工作目录常同时包含源码、数 GB 原始素材、依赖、构建产物和重复视频。直接压缩会产生四类问题：上传超限、对象存储浪费、秒哒误选旧素材、终端用户首访下载过大。

正确做法是从生产构建和源码引用反推资源闭包，再单独保留原始素材的本地归档位置。

## 四、分包规则

2026-08-09 当前界面实测约束：单次消息最多 5 个附件，单文件最大 20MB。该限制属于时效性事实，每次新交付前必须重新核验；不能写成永久平台能力。

建议：

1. 每个压缩包目标不超过 18至19MB，为界面计量差异留余量。
2. 文件名使用连续编号，例如 `01-source-and-prd.zip`、`02-runtime-assets.zip`。
3. 第一个包放源码、PRD 基线、全局清单和提示词；后续包按运行职责拆素材。
4. 每个包内保留可直接覆盖回项目的相对路径，不能打乱目录层级。
5. 每包放唯一命名的 `MIAODA-PACKAGE-MANIFEST-*.json`，避免多个包解压后互相覆盖清单。
6. 外部上传说明列出包顺序、压缩后字节数和压缩包 SHA-256。
7. 本地重新解压全部压缩包，逐文件校验清单，再在重建目录执行安装、测试和生产构建。

素材已经是 MP4、WebP、PNG、MP3、GLB 等压缩格式时，ZIP 往往不会显著变小。分组时应按未压缩总量预留空间，而不是期待 ZIP 自动把大素材压到很小。

## 五、上传分成“接收”和“创作”两阶段

### 阶段 A：只接收、校验和入库

第一条提示词要把红线放最前：

- 当前不生成页面、不改写源码。
- 按编号解压，核对每包文件数、字节数和 SHA-256。
- 缺文件、哈希不一致、对象存储额度不足时停止并报告。
- 禁止秒哒用占位图、重绘或自由发挥补缺失素材。

先让秒哒回贴接收报告，再进入创作。否则它可能在素材尚未齐全时开始生成，并把缺失资源替换成自己的版本。

### 阶段 B：确认齐全后开始创作

创作提示词必须再次声明技术栈、禁改范围、对象存储映射、测试和构建要求。不要依赖上一轮对话隐含记忆。

最终执行句固定为：

```text
严格依照上传的源码，给我生成网页应用，给我生成产品需求文档，并立即开始创作。
```

“生成产品需求文档”不能省略。实战中只要求“生成网页应用”时，秒哒可能直接开始应用创作而不创建 PRD。

## 六、静态素材进入对象存储

压缩包附件不是线上运行时 URL。图片、音频、视频、模型、图集和运行时 JSON 必须解压后进入秒哒云端文件/对象存储。

要求秒哒建立：

```text
原相对路径 → 对象键 → 稳定 HTTPS URL → SHA-256
```

并检查：

- HTTPS、CORS、MIME 和文件大小写。
- MP4 与音频 Range 请求，确保可拖动、分段加载和恢复播放。
- 版本化素材使用长期缓存；资源映射清单使用短缓存或重新验证。
- 禁止 Base64 大资源、临时 Blob URL、过期签名 URL 和逐文件 Edge Function 代理。
- 上传前后核对对象存储当前额度、实际占用和剩余额度。

官方后端存储参考：[百度智能云《后端存储使用技巧》](https://cloud.baidu.com/doc/MIAODA/s/Dmh2w3m8t)。该页面说明后端持久化能力，但不能把“业务数据库”和“静态对象存储”混为一谈。

## 七、数据库按业务需要接入

数据库只存需要查询、权限、关联和跨设备持久化的业务数据，例如用户、存档、报名、订单、排行榜或后台内容；不要把图片和视频二进制塞进业务表。

如果项目需要数据库，提示词必须要求：

1. 给出数据表、字段、主外键、索引和权限规则。
2. 所有新增、查询、修改、删除使用真实后端 CRUD。
3. 敏感写操作经过身份和权限校验。
4. 说明本地旧数据迁移与回滚方式。
5. 用无痕窗口、另一台设备或另一个账号验证跨设备持久化。
6. 明确列出仍使用 `localStorage` 的位置及用途；它只能保存非关键偏好或缓存，不能冒充业务数据库。

如果当前产品没有登录、排行榜或云存档需求，不要为了“看起来完整”强加数据库。

## 八、不降质的性能优化

性能优化的优先顺序：

1. 删除未引用副本和制作母版，不删实际运行帧。
2. 主代码按路由或运行阶段拆分，重型游戏/3D运行时延迟加载。
3. 首屏只加载首屏资源；关键战斗资源在开场期间预加载；非关键资源空闲加载。
4. 图集代替逐帧小文件请求；特效、音频和临时对象使用对象池。
5. 移动端限制 DPR 和粒子数量，但不替换素材或删除技能效果。
6. 页面隐藏时暂停渲染和音频。
7. 显示真实加载进度；弱网时不能在资源未完成前切到黑屏。
8. 记录编码体积和解码后的纹理/内存体积。WebP 很小不代表 GPU 解码占用小。

禁止用“删帧、降低画质、删除音效、减少敌人、把素材塞进 Base64”解决性能问题。

## 九、部署验收

秒哒完成后必须回报并验证：

- `npm install`、自动测试和 `npm run build` 均成功。
- 标准产物位于 `dist/`，没有 `next.config.*`、`next` 依赖或 SSR 入口。
- 控制台无 error，必要素材请求全部 2xx。
- 对象存储 URL、MIME、CORS、Range 和缓存正确。
- 桌面、Android Chrome、微信内置浏览器、iPhone Safari 的真实交互通过。
- 游戏或交互项目的移动、点击、长按、技能、音频和横竖屏都是真实可操作，不只截图正确。
- 5Mbps 和更慢网络下有加载进度、失败提示和有限重试。
- CPU、内存、纹理和网络占用不通过删减产品质量来掩盖。

iPhone Safari 通常不允许普通网页强制调用 `screen.orientation.lock()`。Web 应用必须保留手动横置提示，或实现经过真机验证的页面级虚拟横屏；不能把 Android 成功当作 iOS 也成功。

## 十、已部署项目的补丁包

线上版本出现问题时，不要重新上传整个项目并让秒哒自由重写：

1. Codex 先在权威源码修复并完成回归。
2. 生成只含改动源码、必要新素材、补丁说明和哈希清单的增量 ZIP。
3. 提示词明确允许修改的文件、严禁修改的模块和现有对象存储路径。
4. 要求秒哒修改前建立可回滚版本，修改后回贴文件清单和构建报告。
5. 线上真机复测通过后，把云端最终改动同步回权威源码仓库，避免本地与秒哒分叉。

## 十一、每次交付复盘清单

- [ ] 已确认是百度秒哒，不是飞书妙搭。
- [ ] 已确认应用形态和当前技术栈。
- [ ] 已运行测试、生产构建和真实浏览器验收。
- [ ] 已排除依赖、日志、原始母版、重复素材和秘密。
- [ ] 每包、每文件都低于当前限制并有 SHA-256。
- [ ] 已从压缩包重建项目并再次构建。
- [ ] 秒哒先校验再创作，没有边收包边重写。
- [ ] 静态资源已解压到对象存储并生成 URL 映射。
- [ ] 数据库只承载真实业务数据，跨设备验证通过。
- [ ] 桌面、Android、微信和 iPhone Safari 均做真实交互回归。
- [ ] 最终提示词包含“生成网页应用、生成产品需求文档、立即开始创作”。
- [ ] 秒哒云端最终版本已同步回源码仓库。
