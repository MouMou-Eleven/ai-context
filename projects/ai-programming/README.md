# AI Programming — AI 编程工作与知识库

> 本目录是建委的长期 AI 编程工作领域，沉淀无代码 AI 平台、AI Coding Agent、应用开发、网站制作和自动化工具中的实战经验、踩坑、提示词与案例。
> 子目录按"工具/平台"切分，每个子目录都是一个独立知识包，互相独立、互不依赖。
> 注意：百度秒哒 MIAODA 与飞书妙搭 Spark 读音相近但完全不是同一产品。当前 [miaoda/](./miaoda/) 只放百度秒哒；未来飞书妙搭请单独建 `feishu-spark/`。

## 阅读顺序

1. 先看本 README，了解 AI 编程类知识的整体布局
2. 选择对应的工具子目录，进入后必读其 README.md（每个子目录的入口）
3. 按子目录 README 的索引指引深入具体文件

## 如何扩展本目录

### 场景 A：新增一个工具的知识包

例如未来加入 Cursor / Lovable / v0 / 飞书妙搭等新工具的实战经验：

1. 在本目录下创建 kebab-case 子目录（如 `cursor/`、`feishu-spark/`）
2. 子目录内必须有 `README.md` 作为入口（含概述 + 文件索引 + 维护约定）
3. 回到本文件，在「当前包含的工具」表格追加一行
4. 工具的实战内容按"平台基础 / 提示词模板 / 踩坑 / 案例"四个维度组织，文件命名参考 [miaoda/](./miaoda/)

### 场景 B：新增方法论或跨工具的横向内容

例如"AI 编程通用提示词原则"、"无代码平台选型对比"等不绑定单一工具的内容：

1. 在本目录下直接创建 .md 文件（避免再嵌一层目录），文件名 kebab-case
2. 在本文件「当前包含的工具」表格下方新增「方法论」表格，把该文件加入索引

### 场景 C：建委补充临时经验、灵感、片段

如果还没想清楚归属，先放进对应工具子目录的 `inbox.md`（不存在就新建一个），后续再整理到正式文件中。

## 维护约定

- **不重复**：同一信息只在一个文件里写，其他地方用相对链接引用
- **可追溯**：涉及"官方文档说……"的地方必须附官方 URL
- **不靠猜**：写不准的事实宁可空着，也不要编造
