# AI 编程课程结构设计

> 版本日期：2026-06-22
> 状态：阶段方案，后续会随第一期招生、直播反馈和学员问题继续修订。
> 适用范围：理解建委正在研发的 AI 编程付费社群课程定位、课程结构、教学顺序和每节课的交付重点。

## 核心定位

这门课不应被压缩成“3 个月做一个小网站”，也不应被包装成传统编程课。

当前更准确的定位是：

**3 个月，带普通人系统进入 AI 编程新范式：看懂主流工具，搭好基础环境，用 AI 做出网页、小工具、自动化和可展示作品，并建立自己的数字化经验库。**

它卖的不是代码本身，而是：

- 对 AI 编程全景的认知升级。
- 从“想法”到“可打开、可分享、可交付结果”的路径感。
- 主流 AI 编程工具链的基础使用能力。
- 遇到报错、卡点、不会表达时的解决方法。
- 用 GitHub / GitLab / 飞书等方式沉淀个人经验的新范式。
- 在大学生求职、职场提效、自媒体获客、个体创业、课程交付等场景里的实际应用。

## 目标人群

课程默认面向非程序员设计。主力人群包括：

| 人群 | 需求 | 课程应交付的结果 |
|---|---|---|
| 大学生 | 做作品集，提升求职竞争力 | 个人主页、作品展示页、小工具、AI 编程基础链路 |
| 职场打工人 | 提升效率，解决重复工作 | 表单、统计、资料整理、自动化、内部小工具 |
| 自媒体 / 知识博主 | 做资料页、工具页和获客承接 | 资料领取页、选题工具、口播脚本工具、案例展示页 |
| 个体创业者 / 小团队 | 低成本做展示和业务工具 | 业务展示页、客户登记工具、预约页、小型管理工具 |
| AI 学习者 / 自费学习者 | 系统进入 AI 编程 | 工具地图、学习路径、保姆级资料和社群答疑 |

明确不以专业程序员为主要对象。课程语言、案例、作业和答疑都应默认服务零基础或弱技术背景用户。

## 当前确认权益

主产品为 **399 元 / 3 个月** 的 AI 编程付费社群。

已确认权益：

- 社群答疑。
- 社群知识库。
- 团队自研工具的 3 个月会员权益。
- 每周直播课。
- 直播回放。
- 课程资料。

当前不主推：

- 高客单定制陪跑。
- 把“项目诊断 + 作业精修”作为主卖点。
- 每日技巧 KPI。
- 固定“急诊室”等重运营栏目。
- 每场直播都从零现场做完整作品。
- “包变现”“包赚钱”“三个月成为程序员”等过度承诺。

## 课程总目标

三个月结束时，学员不一定成为程序员，但应具备以下能力：

1. 知道 AI 编程工具分为哪些类型，各自适合什么场景。
2. 能搭好基础环境，知道 Python、Node.js、Git、GitHub、VS Code 等为什么存在。
3. 能使用对话式 AI 生成简单网页，并部署成一个可访问链接。
4. 能理解 HTML、CSS、JavaScript、服务器、数据库、域名、DNS、SSL、备案、图床等基础概念。
5. 能用秒哒这类工具，从 PRD 出发做一个带后端能力的小工具。
6. 能用 Codex / Claude Code / 龙虾等工具理解项目、修改代码、排查问题。
7. 能理解 Skills、MCP、CLI 这类“给 AI 装能力”的机制。
8. 能做基础自动化任务，理解 API 能解决什么问题。
9. 能走一遍标准网站开发链路：GitHub 管代码，Supabase 管数据，Vercel 做部署。
10. 能把自己的经验沉淀成知识库，让后续 AI 更快理解自己。

## 建议课程结构

课程周期 3 个月，每周一场直播，建议按 **12 节课** 编排。每节 1.5-2 小时。

### 第 1 节：AI 编程全景与新范式

目的：解决新手对 AI 编程的基础疑问，建立全景框架。

这一节不讲具体安装，不讲 API 配置，不让学员一开始陷入细节。

核心内容：

- AI 编程是什么：不是传统写代码课，而是用 AI 把想法拆成可执行任务。
- AI 编程和传统编程的区别：从“先学语法”转向“先定义问题、描述需求、验证结果”。
- 主流工具类型：
  - 网页端：秒哒、扣子等。
  - 对话式：DeepSeek、豆包等。
  - IDE 型：Cursor、Antigravity、Codex 等。
  - 终端 / Agent 型：Claude Code 等。
- 每类工具适合什么场景。
- AI 编程运行环境的基础概念：Python、Node.js、Git、终端、浏览器、编辑器为什么会出现。
- 渐进式披露：它不是名词，而是一种信息架构，适合用于知识库和 AI 协作上下文。
- 常见误区：不会代码不能学、AI 会写代码所以人什么都不用懂、工具越多越好、提示词万能。

课后最低动作：

- 用一句话说清楚自己想用 AI 编程解决什么问题。

### 第 2 节：AI 编程环境与工具安装实战

目的：带学员把基础环境搭起来，解决“去哪下载、怎么装、为什么装、怎么验证”的问题。

核心内容：

- Python：为什么自动化、脚本和数据处理经常用它。
- Node.js：为什么网页项目、前端工具和很多插件需要它。
- Git：先理解 clone、commit、push 三个动作。
- GitHub：注册登录、搜索项目、看 README、下载项目、判断项目是否值得参考。
- VS Code：打开项目、查看文件结构、基础插件。
- Codex：Windows / macOS 安装和启动。
- Claude Code：安装、基础启动和适合场景。
- cc-switch：解决模型/供应商切换，不要和插件市场解锁混为一谈。
- Codex++：作为 Codex 插件市场解锁和工具避坑案例。
- 龙虾：安装、自定义 API 接口、自定义模型供应商。

课后最低动作：

- 发一张环境验证截图。
- 在 GitHub 搜索一个 AI 编程相关项目，并把链接发到群里。

### 第 3 节：Skills、MCP、CLI：给 AI 装能力

目的：让学员理解 AI 工具可以被扩展，重复流程可以沉淀成能力。

核心内容：

- Skill 是什么：给 AI 的可复用工作说明书。
- Skill 怎么写：何时该写，基础 `SKILL.md` 应该包含什么。
- Skill 怎么优化：AI 每做错一次，就把规则补进 Skill。
- MCP 是什么：让 AI 连接外部工具和数据源的协议。
- 以 UI 组件库为例讲 MCP：AI 调用组件库，而不是凭空写 UI。
- CLI 是什么：命令行工具是服务的自动化入口。
- 飞书 CLI 示例：读写飞书文档、处理知识库、沉淀资料。
- 微博 CLI 示例：说明社交平台能力也可能通过工具化入口接入。

课后最低动作：

- 写一个最简单的个人 Skill，例如“帮我写短视频脚本时先问目标人群、痛点、案例、结尾引导”。

### 第 4 节：第一个可公开访问的网页：从 HTML 到一键部署

目的：让学员第一次获得“我用 AI 做出来了，而且别人能打开”的体验。

核心内容：

- 用 DeepSeek / 豆包等对话式 AI 生成一个简单 HTML 页面。
- 本地打开 HTML 文件查看效果。
- 解释 HTML、CSS、JavaScript 的分工。
- 解释为什么本地能看不代表别人能看。
- 讲正常网站上线链路：服务器、域名、域名解析、备案、SSL、时间和成本。
- 引出建委自研部署平台：上传 HTML 或项目文件，生成可访问链接。
- 演示单 HTML 文件和 HTML + CSS + JS 多文件项目。
- 顺带讲图床、服务器和数据库的边界。

课后最低动作：

- 做一个个人主页、小游戏、PPT 页面或资料页，并部署成链接。

### 第 5 节：秒哒基础：从 PRD 到带数据能力的小工具

目的：用秒哒承接静态页面之后的进阶需求，让学员理解“自带服务器和数据库”的工具价值。

核心内容：

- 秒哒作为静态页面和完整服务器数据库之间的过渡工具。
- 秒哒能解决数据保存、表单提交、简单后台、小型业务工具。
- PRD 是什么，为什么 AI 编程需要先写 PRD。
- 新手 PRD 基础结构：做什么、给谁用、怎么操作、页面有哪些、数据保存什么、什么结果算完成。
- 前端和后端概念。
- 用秒哒做报名登记、课程资料领取、个人项目展示等简单工具。

课后最低动作：

- 按模板写一份自己的小工具 PRD。

### 第 6 节：秒哒进阶：Bug 修复、控制台、多模态辅助

目的：解决非程序员做工具时最容易崩溃的问题：出错了不会描述，也不知道让 AI 怎么改。

核心内容：

- AI 生成工具出现 Bug 是正常开发过程的一部分。
- 控制台是什么，怎么打开，常见红色报错怎么看。
- 向 AI 描述错误的模板：目标、当前步骤、现象、报错、已尝试动作、期望结果。
- 多模态辅助：用录屏交给 Gemini 等模型分析问题，再把分析结果交给秒哒或 Codex 修改。
- 插件和功能边界：什么时候该用插件，什么时候别硬让秒哒做超边界复杂系统。

课后最低动作：

- 找一个问题，按“问题描述模板”提交到群里。

### 第 7 节：Codex、Claude Code、龙虾：主流 AI 编程工具协作

目的：让学员理解三类更强的 AI 编程入口，知道不同工具适合什么场景。

核心内容：

- Codex：适合项目级修改、阅读仓库、执行任务、写文档、调用工具。
- Claude Code：适合终端里进行代码理解、修改、排错和自动化。
- 龙虾：作为另一类 AI 编程 / Agent 工作入口，重点讲模型和工作流配置。
- 三者不是互相替代，而是不同任务的工具选择。
- 项目文件夹、README、规则文件、资料索引对 AI 输出质量的影响。

课后最低动作：

- 整理一个自己的项目文件夹，包含 README、需求说明、资料目录。

### 第 8 节：浏览器插件、微信 / 飞书入口与工作流工具化

目的：让学员看到 AI 编程不只是做网站，还能做贴近自己工作流的小工具。

核心内容：

- 用 Codex 开发一个简单浏览器插件，例如网页信息提取、页面高亮、资料收集。
- 浏览器插件的价值：把能力放到浏览器里，让日常网页工作更顺手。
- 插件安装到浏览器的基础流程。
- 龙虾接入微信 / 飞书：让日常聊天入口可以直接调用 AI 工具。
- 工作流工具化：把重复动作变成工具，并接到每天真正使用的入口。

课后最低动作：

- 选一个自己每天重复 3 次以上的动作，写成“我想把它工具化”的需求说明。

### 第 9 节：自动化任务与 API 调用

目的：让学员理解自动化和 API 的价值，并用具体案例建立直觉。

这一节开始再讲 API，不把 API 放在第一节。

核心内容：

- 自动化任务：定时执行、批量处理、自动抓取整理推送。
- Codex 如何做定时化任务：目标、频率、输入、输出、验证。
- API 是什么：系统之间互相调用的接口。
- API 能解决获取数据、提交数据、调用模型、调用平台能力等问题。
- 案例：提取公众号视频信息、抓取抖音视频文案或视频信息、自动整理素材。
- 风险边界：注意平台规则、版权、隐私和接口限制，不鼓励违规抓取。

课后最低动作：

- 写一个“我想自动化的任务”说明，包括触发时间、输入、处理过程、输出结果。

### 第 10 节：标准网站开发链路：Codex + Supabase + GitHub + Vercel

目的：带学员了解真正网站项目从代码、数据、版本、部署到访问链接的完整链路。

核心内容：

- 标准网站开发为什么比静态页面复杂。
- GitHub 管项目仓库和历史。
- Supabase 提供数据库和后端能力。
- Vercel 从 GitHub 项目到线上访问。
- 注册登录能力：邮箱验证码、短信验证码分别需要什么服务。
- 数据库购买和配置概念：CPU、内存、带宽、存储。
- 真实案例：个人网站、技术展示网站、公司官网、课程资料站。

课后最低动作：

- 用 GitHub 建一个项目仓库，写 README，准备后续部署。

### 第 11 节：上线后的 SEO、安全与运维

目的：让学员知道网站上线不是结束，还要考虑搜索、稳定、安全和持续维护。

核心内容：

- 域名购买和选择。
- DNS 解析，A 记录、CNAME 的基础理解。
- SSL 证书和 HTTPS。
- 国内服务器与备案基础常识。
- SEO：标题、描述、关键词、页面结构、速度、内容质量。
- 站长工具：检测收录、SEO、访问情况。
- 安全：登录、权限、数据泄露、接口滥用、依赖漏洞。
- 运维：看日志、看报错、看访问数据、持续迭代。

课后最低动作：

- 检查自己页面的标题、描述、访问速度和基础安全风险。

### 第 12 节：AI 时代个人知识库与成果复盘

目的：把课程收束到建委自己的长期方法论：把经验数字化，和 AI 形成长期协作。

核心内容：

- 为什么要把经验沉淀到 GitHub / GitLab / 飞书知识库。
- 建委 ai-context 仓库范式：README 入口、项目文件夹、revisions、资料索引。
- 渐进式披露在知识库里的落地：项目 README、专题文件、具体教程和修订记录。
- 为什么资料越来越多不是问题：模型上下文、RAG、工具调用、检索能力都在进化。
- 学员成果展示：每个人展示一个链接、工具或知识库结构。
- 后续路径：网页、业务工具、自动化、内容获客分别如何深入。

课后最低动作：

- 建一个自己的经验库入口文件，写清楚：我是谁、我在做什么、我的项目有哪些、AI 以后应该先读什么。
