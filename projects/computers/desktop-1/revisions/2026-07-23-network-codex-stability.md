# 2026-07-23 网络与 Codex 稳定性修订

> 记录时间：2026-07-23
> 触发原因：台式电脑1连续出现 Codex 502/503/504、413、流式断联、频繁自动压缩、网站无法访问和插件重启后消失。
> 当前状态：上下文硬编码已移除并验证不再写回；活动任务链路未重启；部分 Clash 新规则等待安全窗口加载。

## 一、已确认根因

1. Codex 的 `64K` 自动压缩并非官方默认值。自定义 `plugin-persistence-guard.ps1` 每 3 秒强制写入 `128000` 上下文窗口和 `64000` 自动压缩阈值。
2. 网络错误不是单一原因：曾同时出现上游供应商超时/5xx、切换代理导致流中断、上游 413 请求体限制，以及 Clash 持久规则未进入当前运行内核。
3. 火绒拦截的是启动目录 VBS 重写，不是普通项目目录写入。
4. 插件持久化守护功能本身有价值，但不应管理模型上下文参数。

## 二、本次变更

- 从活动守护脚本删除 `model_context_window` 和 `model_auto_compact_token_limit` 两项。
- 停止旧守护进程并启动修正后的守护脚本；未重启 Codex、CC Switch 或 Clash。
- 验证多个 3 秒循环后，活动 `config.toml` 没有再次出现 `64K/128K`。
- 核对官方 Codex 模型目录：上下文 `272000`，95% 有效窗口为 `258400` token。
- 记录当前 CC Switch、Clash、Codex++ 的职责边界与排障顺序。
- 将需定向代理的网站规则写入持久配置；因 Codex 正在执行任务，没有强制重载 Clash 内核。

## 三、纠正的旧判断

排查早期曾根据 Codex++ 支持相关配置字段，怀疑它是 `64K/128K` 的直接写入源。继续观察写回时间并比对守护日志后，确认直接写入源是本机自定义插件持久化脚本。后续不得再把“工具支持某字段”当成“该工具正在写入”的充分证据。

## 四、后续有效口径

- Codex 上下文上限和自动压缩阈值优先由官方模型目录决定；本机不再硬编码 `64K/128K`。
- CC Switch 是当前 Codex 请求网关；Codex++ 的供应商自动切换保持关闭，避免双重管理。
- 配置文件和运行内核必须分别核验。
- 活动任务期间只做不影响链路的诊断和可回滚修改；会断开长连接的操作等待安全窗口。
- 413 与 502/503/504 必须分开处理：413 看请求体和上游限制，5xx 看供应商、DNS、节点和长连接。

## 五、尚未完成

- 在无活动任务时重载 Clash，确认 `minimal.gallery`、`awwwards.com`、`chatgptshare.com` 等规则进入 `/rules` 运行态，并逐站验证。
- 用新建 Codex 任务观察自动压缩是否稳定回到官方模型目录对应的有效窗口；旧任务可能保留创建时快照。
