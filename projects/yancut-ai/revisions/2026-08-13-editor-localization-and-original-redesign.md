# 剪辑台中文化与原创重设计

> 日期：2026-08-13
> 状态：已落地本地原型并完成构建、浏览器验证

## 问题来源

此前“中英双语”只覆盖言剪外层 Studio 页面，`/editor/[project_id]` 仍直接渲染 OpenCut 英文组件，因此素材、导出、预览缩放、时间线和上下文菜单出现中英文混杂。同时编辑器仍沿用 OpenCut 的顶栏、三栏工作区和纯图标工具条，形成明显的换皮感。

## 本轮决策

不重写底层剪辑引擎，也不做静态假工作台。继续复用 OpenCut 的素材处理、预览渲染、时间线、属性和导出能力，但重建言剪自己的产品层：

- 中文优先：工具、素材空状态、导出、预览缩放、时间线动作和辅助标签统一中文；英文只通过语言切换进入。
- AI 指令优先：顶部加入常驻自然语言命令栏，指令会真实联动右侧计划面板，而不是装饰性输入框。
- 原创信息架构：顶部品牌命令栏、带中文名称的创作工具轨、上下文素材抽屉、中央预览舞台、右侧 AI 创作副驾、底部“主生产舞台”。
- 计划可控：维持“生成计划 → 检查 → 确认 → 执行 → 可撤销”的产品口径。
- 取消上游更新弹窗和反馈入口在言剪编辑器中的直接露出，避免产品身份混淆。
- 修复 Studio 在超过 1920px 屏幕上因居中最大宽度导致的左侧大面积空白。

## 设计过程

- 使用 Product Design 对当前 Studio 和 Editor 做了截图审计。
- 使用 Superdesign 建立仓库设计索引和设计系统，先生成当前基线，再分支两套方案。
- 选择“YanCut AI Command Studio / AI 指令工作室”作为实现基线。

## 验证结果

- Next.js 16.1.3 生产构建通过，26 个页面/接口路由完成生成。
- 浏览器验证素材、预览、AI 副驾和时间线工作区正常渲染。
- 顶部输入“删除停顿并生成字幕”后，右侧成功生成包含 `remove_silence` 和 `generate_captions` 的计划。
- 浏览器控制台无 error/warning。
- Studio 左侧栏在宽屏下的起始位置恢复为页面左边缘。
- 本地生产服务继续监听 `0.0.0.0:3417`。

## 后续边界

当前完成的是核心剪辑台中文化和第一轮原创产品结构。属性面板深层参数、字幕导入流程、贴纸/音效内容库仍有上游英文文案，需要在对应功能进入比赛演示范围时继续做完整 i18n，而不是宣称全仓库所有上游页面已经双语化。
