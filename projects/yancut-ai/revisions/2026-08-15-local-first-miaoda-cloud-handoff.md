# 本地优先开发与百度秒哒云端交接规划

> 日期：2026-08-15
> 状态：当前有效
> 适用产品：百度秒哒 MIAODA（miaoda.cn），不指飞书妙搭 Spark

## 决策背景

言剪 AI 后续采用“本地权威源码 + 百度秒哒云端接管”的两阶段路线。前端界面、核心业务逻辑、剪辑流程、AI 计划与执行、价格和权益策略、数据库结构、接口参数、错误状态及自动化测试，凡是能够在本地可靠完成和验证的内容，均先在本地完成。

本地版本通过构建、测试和真实浏览器验收后，再生成连续编号的交付压缩包，由用户逐包上传到百度秒哒。秒哒负责把经过验证的本地实现适配到云端，并接管登录、数据库、对象存储、Edge Function、服务器资源、构建与部署。

这项决策延续 [`projects/ai-programming/miaoda/patterns/codex-source-package-deployment.md`](../../ai-programming/miaoda/patterns/codex-source-package-deployment.md) 已验证的交付模式，不把对话附件当作生产存储，也不允许秒哒在文件未收齐时提前重写项目。

## 角色与权威边界

### 本地权威源码负责

- 中文优先、中英双语的完整页面与交互。
- 素材导入、预览、时间线、导出和 AI 指令剪辑闭环。
- 个人声音库、授权确认、克隆和配音接口边界。
- 参考视频分析、剪辑计划、计划确认、局部执行、撤销和失败回滚。
- 价格中心、套餐配置、功能权益、用量单位、配额和超额处理规则。
- Postgres 兼容的数据模型、迁移文件、字段名、索引、权限意图和 TypeScript 类型。
- Auth、数据库、对象存储、AI 模型、声音供应商和渲染服务的适配器接口。
- 本地 Mock、测试数据、错误态和降级路径；不得用静态假页面冒充真实功能。
- 单元测试、集成测试、生产构建和桌面/移动浏览器验收。

### 百度秒哒云端负责

- 使用平台内置 Auth/用户体系完成真实注册、登录、会话和账号恢复。
- 创建并连接真实 Postgres 数据库，执行迁移并设置行级权限。
- 把图片、音频、视频、模板和导出结果写入对象存储，生成稳定 URL。
- 将需要密钥、权限或长任务的逻辑落到 Edge Function 或平台可用的服务端能力。
- 配置环境变量、短信能力、域名、构建、发布、日志和云端配额。
- 完成跨账号、跨设备、无痕窗口、弱网、CORS、MIME 和音视频 Range 请求验证。

本地源码始终是业务逻辑和产品口径的权威来源。秒哒云端产生的必要改动必须回同步到本地源码和上下文记录，禁止形成只能在线上继续修改、无法回收的分叉版本。

## 本地先完成的数据和接口合同

第一版数据库合同至少覆盖以下业务域；具体字段由后续实现和迁移文件确认，不能只写在页面 Mock 中：

| 业务域 | 建议实体 | 核心约束 |
|---|---|---|
| 用户资料 | `profiles` | 关联平台 Auth 用户 ID；不保存明文密码和短信验证码 |
| 剪辑项目 | `projects`、`project_versions` | 所有者、项目 JSON、版本号、状态和更新时间；支持冲突检测与回滚 |
| 素材 | `media_assets` | 对象键、MIME、大小、哈希、时长、所有者和处理状态 |
| 声音 | `voice_profiles`、`voice_consents` | 供应商 voice ID、授权状态、用途、撤回与删除记录 |
| AI 与渲染任务 | `ai_jobs`、`render_jobs` | 输入摘要、状态、成本、失败原因、重试和产物引用 |
| 套餐与用量 | `plans`、`subscriptions`、`usage_ledger` | 权益配置、周期配额、扣减来源、幂等键和人工调整记录 |
| 订单与支付 | `orders`、`payment_events` | 仅在支付渠道确定后启用；回调必须幂等且服务端验签 |

价格不能散落硬编码在页面中。套餐名称、价格、周期、AI 次数、存储额度、导出规格、声音克隆额度和超额策略使用统一配置；页面展示、权限判断和服务端扣减共享同一合同。正式价格、支付渠道和模型成本未确认前，价格中心只能标记为方案草案，不能自动收费。

## 登录方案的当前口径

目标体验是中国大陆手机号注册和登录：注册阶段可使用平台提供的短信能力完成验证，之后支持手机号加密码登录。优先使用秒哒内置 Auth/登录插件，不自行编写一套验证码 Edge Function。

该能力目前属于用户确认的目标方案，不写成已完成事实。交接时必须在秒哒当前环境重新核验插件入口、百度短信集成方式、收费、模板审核、手机号加密码是否为原生支持，以及账号找回流程。

手机号必须在所有路径统一规范化。`+86` 与裸 11 位号码不能创建两个账户；注册、登录、RPC、异常兜底和旧用户兼容必须共用同一组规范化 helper。业务数据库不保存密码、短信验证码或可逆认证凭证。

## 技术栈冲突与处理门禁

截至 2026-08-15，言剪 AI 本地基线使用 Next.js 16.1.3；秒哒经验库在 2026-08-09 实测的稳定 Web 导入形态是 React + Vite，直接导入 Next.js 可能构建后黑屏。

因此当前源码不能在最后阶段直接整体压缩上传。后续开发必须遵守：

1. 剪辑命令、AI 计划、计费、数据模型和云服务合同优先写成框架无关 TypeScript 模块。
2. 浏览器端不得依赖 Next.js Server Component 才能执行核心剪辑逻辑。
3. `/api/yancut/*` 的能力必须有可迁移到秒哒 Edge Function 的输入/输出 Schema，密钥只存在服务端。
4. 正式交付前重新核验秒哒是否已支持 Next.js；若未支持，必须形成 React + Vite 的秒哒兼容应用，`npm run build` 输出 `dist/`。
5. 没有完成秒哒兼容构建和重建测试前，不得宣称“压缩包可直接部署”。

## 编号压缩包规划

最终数量由重新核验后的单文件和单消息限制、源码体积及素材闭包决定，编号保持连续，不机械限定只有四包。建议首版职责如下：

1. `01-source-prd-and-global-manifest.zip`：可构建源码、锁文件、PRD 基线、全局清单、验收标准和总提示词。
2. `02-database-auth-and-cloud-contracts.zip`：SQL 迁移、TypeScript 类型、Edge Function 合同、Auth/存储适配器、环境变量示例和云端接线说明。
3. `03-ui-runtime-assets.zip`：运行时真正引用的图片、图标、字体、音频和资源清单。
4. `04-video-templates-and-render-assets.zip`：Remotion 模板、字幕/包装资源、示例工程和渲染验收素材。
5. 超出当前限制时继续拆为 `05`、`06`；补丁使用独立版本号和补丁清单，不覆盖历史交付。

每包保留原相对路径，包含唯一清单和 SHA-256。默认排除 `.git`、`node_modules`、`dist`、缓存、日志、测试截图、原始制作母版和所有真实密钥。打包完成后必须在空目录依次解压、校验哈希、安装依赖、运行测试并重新生产构建。

## 秒哒上传与执行顺序

1. **接收阶段**：逐包上传；提示词要求秒哒只解压、统计、校验哈希并报告，禁止生成页面、改写源码或用占位素材补缺。
2. **素材入库阶段**：将运行时素材写入对象存储，生成“原相对路径 → 对象键 → 稳定 HTTPS URL → SHA-256”映射。
3. **云能力接线阶段**：创建 Auth、数据库、对象存储和 Edge Function，按本地合同替换 Mock 适配器。
4. **构建阶段**：在所有文件齐全后，严格依照源码生成网页应用和产品需求文档并开始创作。
5. **验收阶段**：验证登录、跨设备持久化、权限、上传、音视频 Range、AI 任务、用量扣减、失败回滚和生产构建。
6. **回收阶段**：把秒哒必要改动、数据迁移和对象映射同步回本地权威源码，再生成下一版补丁。

## 本地与云端验收边界

本地可以并且必须验证：页面跳转、按钮和表单、编辑器操作、AI 计划和命令映射、声音库流程、价格和权益判断、数据库 Schema、API 参数校验、Mock CRUD、错误状态、响应式布局、构建和浏览器回归。

只能在云端最终验证：真实短信、真实账号会话、跨设备数据库、对象存储 URL/CORS/Range、生产密钥、并发任务、服务端渲染、支付回调、云配额、域名和发布层行为。

本地 Mock 通过不等于云端能力已部署；云端页面能打开也不等于数据、权限和存储已接通。每项能力必须分别记录“本地逻辑完成”“云端接线完成”“生产验收通过”三种状态。

## 对后续开发的约束

- 新功能同时给出本地实现、云端适配点、数据合同和验收方式。
- 不把 `localStorage` 当作生产业务数据库，只用于非关键偏好和临时缓存。
- 不把视频、音频或图片二进制存入业务表。
- 不把 API Key、短信密钥、模型密钥或支付密钥写入前端和 Git。
- 不让秒哒自由重写已在本地验证的剪辑内核；云端修改以接线和兼容为主。
- 每次打包前重新核验秒哒技术栈、附件限制、登录插件和存储能力，不把历史实测当作永久承诺。

## 与旧口径的差异

此前 README 把生产级账号、云端项目同步、计费和存储统一列为“方案待定”。本次修订明确了目标分工：本地先完成产品逻辑、数据和接口合同，百度秒哒作为计划中的云端承载平台；具体短信插件、支付渠道、生产供应商和秒哒当期技术能力仍需在接线时实测确认。
