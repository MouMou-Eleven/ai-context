# 言剪 AI 路线图

> 当前阶段：比赛原型；更新时间 2026-08-15。

## 第一阶段：可讲清、可操作的比赛闭环

目标是让评委看到真实操作，而不是一组静态界面。

1. 用户上传一段常见口播或知识分享视频。
2. 用户用中文说“删除停顿、生成字幕、改成 9:16”。
3. AI 返回结构化计划和影响范围，缺信息时先追问。
4. 用户确认后，把可执行命令落到真实时间线。
5. 用户选择个人声音完成一段配音。
6. 用户应用一个 Remotion 视频包装并导出结果。

比赛前必须准备一个本地兜底素材和本地规划器路径，避免现场网络故障导致核心演示中断。

## 第二阶段：在本地把接口闭环变成产品闭环

- 声音克隆：补齐录音质量检查、授权确认、试听、重命名、删除和配音回写时间线。
- AI 剪辑：增加执行前后差异预览、撤销、失败回滚和部分成功提示。
- 包装渲染：部署独立 Remotion 服务，验证时长、分辨率、并发、成本和失败重试。
- 参考剪辑：提取参考视频的镜头边界、节拍、BPM、响度和高潮点，用用户自己的素材生成可确认方案。
- 价格与权益：完成套餐配置、功能权限、用量单位、配额、超额处理和价格中心；正式成本确认前不收费。
- 数据与接口：完成 Postgres 兼容 Schema、迁移、类型、索引、权限意图、API 参数和本地 Mock CRUD。
- 云适配：把 Auth、数据库、对象存储、模型、声音和渲染服务收口到适配器，不让核心业务依赖单一平台。
- 质量门禁：完成单元测试、集成测试、生产构建和桌面/移动浏览器验收。

## 第三阶段：生成百度秒哒兼容交付包

- 重新核验秒哒当期 Web 技术栈、附件数量和大小限制、Auth 插件、短信、存储与后端能力。
- 解决当前 Next.js 基线与秒哒 React + Vite 稳定导入形态的冲突；必要时提供独立 Vite 兼容应用。
- 按 `01`、`02`、`03`、`04` 连续编号拆分源码、PRD、云合同、运行时素材和视频模板。
- 为每个文件和压缩包生成 SHA-256，并在空目录重建、测试和生产构建。
- 生成“接收校验 → 对象存储入库 → 云能力接线 → 构建部署 → 验收 → 改动回收”的分批提示词。

## 第四阶段：由百度秒哒接管云端能力

- 使用平台内置 Auth 完成真实手机号注册、登录、会话和账号恢复；短信插件能力以当期实测为准。
- 创建真实 Postgres 数据库、对象存储和 Edge Function，按本地 Schema 与接口合同接线。
- 验证跨账号和跨设备持久化、权限隔离、音视频 Range、任务重试、配额扣减与云端日志。
- 把秒哒产生的必要兼容改动同步回本地权威源码，后续修复使用增量补丁包。

## 第五阶段：验证商业价值

先验证大众高频任务，不同时追求所有专业剪辑能力：

- 口播去停顿 + 字幕。
- 个人声音复用配音。
- 横竖屏改版。
- 知识分享、产品介绍和生活记录的统一包装。
- 一条长素材生成多个短版本。

建议先观察四项指标：第一次成片成功率、从上传到导出耗时、AI 计划确认率、每次有效导出的模型与渲染成本。

## 上线前条件

- 确认独立源码仓库与开源/商业分发策略。
- 补齐隐私政策、服务条款、声音授权和数据删除机制。
- Key 全部服务端保存，增加配额、限流、日志脱敏和滥用防护。
- 验证主流 Chrome/Edge 环境、常见视频格式和长视频内存占用。
- 价格中心在正式成本测算前只显示“方案草案”，不得自动收费。
- 云端上线前完成手机号规范化、账号唯一性、数据库权限、对象存储映射和数据删除回归。
- 秒哒交付前必须完成 React + Vite 兼容构建或重新确认平台已支持当前 Next.js 基线。
