> 状态：当前有效
> 口径确认：2026-08-01
> 作用：管理可跨项目复用的表达方法，不把它们误当成项目事实、课程设计规则或全局文风。

## 飞天闪客的定位

飞天闪客属于“外部技术科普写作参考”。当前可学习的不是标志性措辞，而是四类方法：从现象和问题进入、以“问题-旧办法-新问题-改进办法”推导概念、用日常比喻解释抽象知识、在结尾给出有证据支撑的判断。

它适合帮助普通人理解技术和 AI 概念，也能用于课程中某个技术知识点的解释；它不负责课程的教学节奏、课件版式、招生转化或建委所有日常写作。

## 调用规则

| 当前任务 | 默认读取 | 是否调用飞天闪客 | 原因 |
|---|---|---|---|
| 技术科普文章、AI 概念解释、面向普通人的技术口播 | `tutorial-writing/README.md` | 是，读 `style-profile.md` | 需要把抽象概念讲清楚并减少模板化表达 |
| 付费社群的短视频、直播口播、资料引流 | 课程项目 README + `script-patterns.md` | 按需 | 先保证人群、场景、承接和转化；只有需要解释技术原理时再借用其推导方式 |
| 课程学员正文 | `course-design/README.md` + `tutorial-writing/README.md` | 按需 | 教学目标、练习和验收优先；技术难点可借用其解释方法 |
| 讲师备课、课程大纲、课件结构 | `course-design/README.md` | 否，除非要写技术概念讲解 | 这是教学设计任务，不是技术科普写作任务 |
| 销售海报、私聊转化、运营通知 | 课程项目的 `operations-playbook.md` | 否 | 转化任务应使用已验证的产品口径和行动引导，不能被科普节奏拖慢 |
| 飞书书稿 | 飞书书籍项目 README + `writing-style-analysis.md` | 否，除非建委明确要求 | 书稿有独立读者、出版和截图规则 |
| 日常消息、报告、邮件、项目记录 | 任务自身要求 | 否 | 不需要为自然表达额外加载某个作者的风格 |

## 不可混用的底线

- 写作风格只影响“怎样讲”，不改变事实、产品承诺、课程结构或操作步骤。
- 不逐句模仿飞天闪客，不复制原稿的表达，也不把原稿中的模型参数、版本和结论当成今天的事实。
- 课程设计规则只在课程、课件、教学活动和讲师交付中生效；不能自动套进短视频、销售页、普通文章或飞书书稿。
- 自媒体口播先服从社群产品的受众、场景、证据和唯一 CTA；风格只能帮助解释，不能替代真实案例和转化路径。

## 新增参考的写入方式

新增喜欢的博主或作者时，在 `references/writing-style/<author>/` 保存来源说明、原始材料和风格提炼；同时更新本文件的分类和调用边界。没有来源、用途和禁忌的“喜欢一句话”不单独入库。
