# 秒哒平台基础认知

> 实战角度对秒哒（百度 MIAODA）平台架构的理解。这部分认知能让你在与秒哒 AI 协作时，准确判断"这件事归哪个层做"。

## 一、四套独立运行时

秒哒生态里有 4 个不同的"地方能跑代码"，**它们的环境变量、密钥、运行语言、生命周期都互相独立**。混淆它们是新人最大的踩坑源。

| 运行时 | 跑什么 | 语言 | 环境变量从哪里来 | 何时执行 |
|---|---|---|---|---|
| 应用前端 | 用户浏览器里的页面 | TypeScript/React | 不能放密钥 | 用户访问页面时 |
| 应用后端（Edge Function） | Supabase 风格的 Deno 函数 | TypeScript/Deno | Supabase Functions Secrets | API 被前端调用、或外部 webhook 触发 |
| 应用数据库 | Supabase Postgres | SQL | DB 连接信息 | Edge Function 访问时 |
| 自定义技能（Skill） | 上传的 .zip 包内的 scripts/ | Python / Shell | 技能控制台「环境变量」面板 | AI 在"生成代码 / 执行任务"时主动调用 |

### 关键含义

- **支付密钥这种敏感凭证**：放"自定义技能的环境变量"或"Edge Function Secrets"都可以，**永远不要**放前端。
- **如果你把密钥填到了"技能环境变量"，Edge Function 里读不到**，反之亦然——这两套是完全隔离的。
- **写在 SKILL.md / scripts 里的脚本，最终是在秒哒服务器上跑的**，不是在用户浏览器、也不是在你的电脑上。

## 二、"自定义技能"与"自定义插件"的演变

| 时间 | 名称 | 接入方式 |
|---|---|---|
| 2026-02 之前 | 自定义插件 | 在输入框粘贴 API 文档文本 → AI 解析自动配置 |
| 2026-05-10 起 | 自定义技能 | 上传 `.zip` 技能包，根目录含 `SKILL.md`，AI 解析后注册 |

**「集成外部API说明」章节明确写：「目前官方暂时下架了提供 API 文档链接或 API 说明创建自定义插件的方式」**——只有 `.zip` 上传这一条路。

这也意味着如果你看到"粘贴 API 文本"的旧教程，那是 2026-02 之前的写法，不能再用。

## 三、应用底座是 Supabase 风格

秒哒生成的应用底座有以下确凿迹象：
- 后端用 `Deno.env.get(...)` 读环境变量
- 数据库是 Postgres（通过 `@supabase/supabase-js` 访问）
- API 用 `supabase/functions/<name>/index.ts` 形态
- 异步通知接收端是 Edge Function

**实战意义**：写给秒哒应用后端的参考代码必须是 Deno + Supabase 形态，写 Flask/FastAPI/Express 都会被秒哒"翻译"，翻译过程中很容易引入 bug。

## 四、应用预览域名 ≠ 自定义域名

- 秒哒生成应用后默认给的域名形如 `app-bd0ygtaa9zwh.appmiaoda.com`
- 通过「应用发布 > 自定义域名发布」可以绑到自己的域名
- **YunGouOS / 微信支付的"支付授权目录"配置时，必须填实际访问支付页的那个域名**——绑域名前后是两个不同的值，不能写错

## 五、秒哒 AI 的协作模式

| 特性 | 含义 | 应对 |
|---|---|---|
| 指令式执行 | 发指令后秒哒直接修改代码，没有"先讨论再做"的对话能力 | 提示词必须一次写到位，事后修补成本高 |
| 自由发挥 | 即使你提供了技能/参考代码，它仍可能"自己另写一遍" | 必须在提示词里明确"禁止重写 X"，并指明使用哪个文件 |
| @ 技能调用 | 在输入框 `@技能名 + 自然语言` 是让秒哒明确使用某个技能的标准方式 | 涉及技能的提示词开头必须有 `@<技能名>` |
| 容易丢失上下文 | 改完一处可能忘了另一处保持不变 | 强约束写在提示词最前面（"红线"），不要藏在中段 |

## 六、文档与实现的差异（必记）

秒哒官方文档（2026-05-10 版）描述自定义技能 SKILL.md 时**没有提到 YAML frontmatter 是强制的**，但实际上传时校验会拒绝没有 frontmatter 的 SKILL.md，报错信息是：

> ❌ SKILL.md 格式校验失败：SKILL.md 的内容必须以 "---" 开头

类似的"文档未明说但实际强制"的细节可能还有更多。**永远以实际报错为准，不要相信文档完备**。这也是为什么这套实战经验库存在的价值——补齐文档没写的部分。
