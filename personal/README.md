# 个人信息

这里保存关于建委本人的事实，按下面四项阅读。新身份、经历、荣誉由建委补充或明确确认；AI负责整理、查重和同步。

| 顺序 | 入口 | 内容 |
|---|---|---|
| 1 | [我是谁](./profile.md) | 姓名、背景、教育与稳定身份 |
| 2 | [个人经历与阶段里程碑](./timeline.md) | 经历时间线、成长阶段；不混入仓库维护和项目开发日志 |
| 3 | [背书荣誉和成果](./credentials.md) | 获奖、聘任、成果、客户及数字的核验状态 |
| 4 | [业务与项目概要](./business-overview.md) | 简短工作方向、实践能力摘要与边界；具体事项进入工作目录 |

证书、聘书等原件照片放在 `evidence/`，背书表逐条引用，例如[百度秒哒 AI 金牌讲师证书](./evidence/miaoda-ai-gold-lecturer-2026-05.jpg)。

个人介绍按用途读取，不默认读全部项目。荣誉和数字使用前核对证据状态，资料收录不代表事实已独立核验。

## 对外介绍怎么写（默认）

写个人简介、讲师介绍、个人主页时，目标是让读者自己看出建委是设计、视频、AI 开发、AI 培训都在接单交付的复合型人才，而不是由文字自夸。

- 每块业务写“能做什么”加“真实项目与客户”。像这样写：“抖音 KV、红果短剧海报、华润置地”；不要写：“审美出众、能力全面”。
- 不记流水账：届别、专业全称、“走过一条意外之路”这类经历叙述不放进对外介绍，学术成果压成一行。
- 结构按“认识我 → 荣誉与背书 → 四块业务 → 社群 → 联系”排，每块配醒目的小标题和卡片，扫一眼就能抓住重点。
- 荣誉和数字只按[背书表](./credentials.md)的口径写。

来源：建委2026-10-10修改飞书个人介绍页时明确表述。

## 能力与更新

能力摘要由AI在沉淀实践时按[证据规则](../system/repository/capability-evidence.md)检查更新，不需要建委手动填能力清单。一次了解、收藏Skill或复制教程不能写成“已掌握”。已有明确个人记录与后续推导分开。

表达要求、纠错和认可样稿留在[共享表达](../system/expression/README.md)及对应领域／项目；这里不设表达偏好分类。个人认知进入[建委大脑](../brain/README.md)。

新增事实更新对应正文与来源；新增项目通常只更新[项目入口](../work/projects/README.md)，只有个人工作方向或能力证据变化才更新个人概要。执行[沉淀流程](../system/repository/ingestion-workflow.md)，不重复维护项目状态。
