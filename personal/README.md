# Personal — 建委个人信息总入口

> 本目录保存“杨建委这个人”的身份事实、经历、背书与明确认可的表达偏好。具体项目过程、工具教程和领域方法进入工作与项目。

## 目录结构

```text
personal/
├── README.md              当前总入口、读取规则和写入准则
├── profile.md             我是谁：稳定身份、背景和基本信息
├── business-overview.md   我做什么：业务版图和项目概要
├── credentials.md         我的背书：荣誉、成果、聘任、客户和数据
├── growth-path.md         我的成长路径：重要阶段与能力形成过程
├── capabilities.md        我会什么：能力结构、优势与明确边界
├── timeline.md            个人经历与阶段里程碑
└── expression-preferences.md  个人表达偏好与认可样稿依据
```

## 快速查看

| 想了解什么 | 首读文件 | 继续读取 |

| 建委目前有哪些业务和项目 | [`business-overview.md`](./business-overview.md) | 具体事项进入对应 `../work/` 项目 |

## 读取规则

- 个人简介只读 `profile.md`；需要增强可信度时再组合 `credentials.md`。
- 业务介绍只读 `business-overview.md`；不要把具体项目 README 全部加载进个人介绍。
- 判断能力时读取 `capabilities.md`，不得因为仓库存在某个工具资料就推断建委精通该工具。
- 当前项目、平台版本、价格、进度和执行细节以 `work/` 中对应入口为准。
- 建委的思维认知在[建委大脑](../brain/README.md)；中文成品默认调用[表达与成品标准](../system/expression/README.md)，不把通用表达误写成个人身份事实。

## 写入准则

- 新信息属于人物事实、业务概要、背书、成长、能力或明确认可的个人表达偏好；偏好注明来源与适用场景。
- 具体客户任务、项目进度、方法模板和工具操作写入 `work/`，这里只保留一句概要和链接。
- 荣誉、数字、聘任和客户名称必须有建委确认或可核验材料；不确定就标记“待确认”。
- 同一事实只保留一个权威位置，其他文件使用链接或简短引用，不重复维护全文。
- 当前状态变化直接更新 `business-overview.md`；被替代内容不继续堆在当前入口，Git 历史负责追溯。

## 注意事项

- 本目录不是简历成品库，而是生成简介、合作资料和能力判断时的事实源。
- 通用表达与体裁标准共同负责成品质量；培训等专业方法仍由对应领域维护。
- 多领域依赖按本次任务自动选择，无需建委额外提出；不得因为个人业务多而无差别加载。
