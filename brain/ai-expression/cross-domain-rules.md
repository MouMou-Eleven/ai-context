# 跨领域中文表达规则

> 本文件是 AI 表达库的通用质量规则。它适用于培训、自媒体、书稿、设计文案、项目说明和其他中文内容，不负责任何领域的专业事实。

## 一、先确定表达任务

写作前先回答：

1. 内容给谁看或听。
2. 读者 / 观众要理解什么、做什么。
3. 交付物是文章、课程、口播、书稿、界面文案还是项目说明。
4. 需要口语化、书面化，还是二者结合。
5. 哪些是已核验事实，哪些是判断、示例或待确认信息。

## 二、中文句子质量

- 默认使用中文；只有必要的专业术语、产品名和代码标识保留英文，并保证前后一致。
- 直接进入问题，不写“当然可以帮您”“很高兴为您服务”等无信息客套。
- 主语、动作和对象必须匹配，避免动词泛化。
- 指代对象必须明确，不能让读者猜“它”“这个”“那里”具体指什么。
- 抽象概念后面尽量补具体场景、动作或结果。
- 一个句子承担一个主要判断；多个因果关系分成连续句子。
- 标题要回答“这部分讲什么”，不能只追求情绪和悬念。
- 表格已经表达的内容，正文解释关系、原因和使用方法，不逐行重复。
- 结论落到动作、选择、判断或下一步，不只做泛泛总结。

## 三、问句与选项

- 问题只问一件事，选项必须逐项回答这个问题。
- 选项写成填写者可以直接确认的话，例如“我会自备电脑 / 我不自备电脑”。
- 少用“不适用、其他情况、按需选择”等只有制表人理解的后台式措辞；确需保留时说明具体含义。
- 写完后从普通填写者角度复读；如果还会问“这是什么意思”，就继续改。

## 四、常见搭配纠偏

| 不建议 | 根据语境改为 |
|---|---|
| 先把话说稳一点 | 先说结论 / 先把这件事讲清楚 / 先给大家说一个真实观点 |
| 把问题接住 | 判断下一步 / 把问题解决掉 / 把卡住的地方处理好 |
| 赋能业务、实现闭环 | 具体说明改善了什么、谁完成什么动作、结果如何验证 |
| 提升用户体验 | 说明用户在哪个步骤更容易理解、操作或完成任务 |
| 打造、助力、全面赋能 | 根据事实改成制作、帮助、减少、完成、验证等具体动作 |
| 一键解决所有问题 | 写清适用条件、实际能力和仍需人工判断的部分 |

这些示例不是机械禁词表。每次要看动词和对象是否真正匹配，不能为了替换而替换。

## 五、事实与表达分离

- 表达可以自然，但不能替事实做保证。
- 平台能力、价格、版本、效果数字、菜单名和流程必须重新核验。
- 原始数据集、逐字稿和其他 AI 输出只能作为材料，不能未经判断直接成为规则。
- 发现旧说法与新说法冲突时，当前入口保留新结论，旧结论只在历史文件中追溯。

## 六、交付前检查

- 朗读一遍，检查是否有生硬的网络表达、主谓宾错位和绕口句。
- 检查标题、正文、图片、旁白和行动指令是否在回答同一个问题。
- 删除无意义客套、重复总结、空泛排比和不必要的免责声明。
- 检查中文标点、中英文空格、数字单位、术语首次出现和前后一致性。
- 检查所有效果承诺是否有真实证据；没有证据就标记“待验证”。
