# 中文数据、规则来源与质量检查

> 本目录是 AI 表达基础层的上游资料与中文质量检查入口。它登记经过筛选的数据集、开源规则、表达材料及授权边界，并保存从这些来源提炼出的通用检查规则。数据不是越多越好，未经授权、未经清洗或价值不明确的材料不得入库。

## 当前状态

当前收录两份内部参考数据，并建立了一份默认调用的中文语法与病句检查表。外部开源项目只登记链接、核验版本、授权、用途和提炼结论；没有把大型仓库或数据集复制进本仓库，也没有把任何外部材料声明为“可训练数据”。

`grammar-and-error-checklist.md` 属于默认执行规则，原始逐字稿和大型数据集不默认读取。数据存放在这里有三种价值：为规则提供来源、为修改提供对照、为模型升级后的质量回归提供测试依据。

## 来源到规则的处理层级

```text
第一层：原始来源
  只负责保留证据、来源和完整上下文，不直接激活

第二层：候选方法
  从来源中提炼“解决什么问题、怎样做、适用哪里、有什么限制”

第三层：当前规则
  同义内容去重，冲突内容分场景，经真实任务验证或建委确认后进入默认层或专项层
```

- 外部开源仓库优先保留链接、提交哈希、许可证和用途，不默认克隆全部内容。
- 原始资料中的事实、观点和个人风格不能直接成为当前规则。
- 已经形成提炼方法后，日常任务优先读取方法，不回读原文。
- 只有需要追溯来源、重新提炼或执行经授权的数据处理时，才读取原始数据。

## 数据集分类

未来可按以下类型建立独立子目录或索引条目：

- 高质量中文口语：真实交流、授课、访谈和口播，重点看自然停顿、因果和动作表达。
- 高质量中文书面语：出版物、教程、说明文档和编辑后的正式文本，重点看准确、完整和结构。
- 中文技术解释：把抽象概念讲清楚的案例，重点看场景、比喻、边界和验证。
- 中文改写对照：原表达、问题分析、修改版本和修改原因，重点看可复用的纠偏规则。

## 每份数据集必须登记

| 字段 | 要求 |
|---|---|
| 名称与版本 | 明确数据集是什么、何时整理、是否有版本 |
| 来源 | 原作者、原页面或文件来源，不能只写“网上收集” |
| 授权与用途 | 确认是否允许保存、分析、训练或内部使用 |
| 清洗方法 | 去重、去隐私、去广告、去错误和格式统一方式 |
| 质量判断 | 为什么值得保留，适合学习什么表达能力 |
| 已知问题 | 口径过时、事实待核验、样本偏差或版权限制 |
| 使用边界 | 只能分析、可以内部参考，还是可以用于训练 |

## 严格规则

- 不把数据集中的作者身份、个人经历或观点自动变成建委事实。
- 不把自然口语误判为高质量；语病、网络套话和无效噪声必须清理。
- 不保存个人敏感信息、未授权全文、密码、Token 或平台内部数据。
- 数据集只辅助 AI 表达质量，不替代当前项目事实、官方文档和实际核验。
- 真正需要加入数据时，先更新本 README 的索引和用途，再新增文件。

## 多来源与多人经验冲突治理

当后续沉淀五位、六位或更多创作者的资料时，不按“人物风格库”并排调用，统一按下面方式处理：

1. **人物不是触发条件。**记录来源只为追溯，AI 日常调用的是提炼方法，不是作者身份。
2. **先按功能分类。**例如技术解释、课程开场、案例展开、口语承接、书面组织分别处理，不把整套个人表达打包。
3. **同义内容只保留一条。**新来源与现有规则一致时，只补充证据，不新增第二套说法。
4. **兼容内容合并。**一个来源擅长问题推导，另一个来源擅长演示验证时，可以在同一教学链路中分工。
5. **替代方案不混用。**两种开头或两种课程结构只是不同选择时，写明受众、场景和目标，每次任务只选一种主方法。
6. **真实验证优先。**建委实际授课反馈、当前项目事实和已验证效果，高于外部创作者的个人偏好。
7. **无法消解就不合并。**保留冲突说明并向建委确认，不能取平均或全部叠加。

最终目标不是“收集多少个人”，而是形成更少、更清楚、适用条件明确的当前方法。
