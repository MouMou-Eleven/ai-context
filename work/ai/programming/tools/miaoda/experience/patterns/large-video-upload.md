# 大视频上传：先核验原生能力

> 这是当前决策入口，不包含旧分片实现细节。整理2026-09-12；额度依据仍为2026-08-27官方计费页记录，使用前重新核验当前购买页和项目控制台。
> 能力与官方来源：[current-capabilities.md](../../basics/current-capabilities.md)。旧失败证据：[pitfalls #14](../pitfalls.md)。

## 决策与验收

1. 确认当前会员与项目上传上限。已登记历史权益为免费版50MB、专业版及以上500MB；不把旧记录当今日实时上限，也不混用首页/对话附件额度。
2. 同时核对对象存储剩余容量；若当前权益允许目标大小，同步修改前后端校验和限制，不只改页面文案。
3. 用无敏感内容且接近真实业务大小的视频，在当前应用、套餐与正式域名测试；查网络和后端日志的CORS、413、超时、取消及对象大小不一致。
4. 核对存储对象字节数，刷新后仍存在；测试播放、拖动、Range、MIME、权限、删除及移动弱网恢复。秒哒未实际控制的浏览器或真机测试明确由实际操作者执行并回传证据。
5. 原生上传稳定通过就用原生能力。弱网需要重试时优先平台/存储原生multipart或断点续传，最终保存一个正常对象；产品上限和传输可靠性分别判断。
6. 只有当前旧项目仍可重复复现已登记限制，才读取 [旧兼容合同](../reference-materials/video-chunked-upload/legacy-contract.md) 和 [参考实现README](../reference-materials/video-chunked-upload/README.md)。测试前不预装旧架构。

## 范围选择

| 场景 | 处理 |
|---|---|
| 尚未核验会员、容量或原生上传 | 先核验和测试 |
| 原生上传或存储multipart已成功 | 使用当前原生合同 |
| 旧项目复现CORS/413/函数资源限制 | 按证据评估历史兼容实现 |
| 自有OSS/S3且有原生multipart | 直接核验该存储服务的正式合同 |
| 需转码、抽帧或其他服务端处理 | 核验完整对象交付；旧分片播放代理不等于已具备加工流水线 |
| 私密、付费或按用户隔离视频 | 独立验证授权与媒体访问；不能把UUID当鉴权 |
