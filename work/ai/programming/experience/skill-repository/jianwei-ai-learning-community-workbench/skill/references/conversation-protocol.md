# 精准对话协议

## 最多两轮

### 第 1 轮：识别与给方案

先用一句话复述用户身份、场景和期望结果，再给出一个暂定工作台骨架。只问 2–3 个会改变结构的问题：

1. 你最想优先推进哪类结果？（学习达标 / 作品交付 / 带人教学 / 社群运营 / 团队协作 / 自定义）
2. 你通常在哪里使用？（电脑为主 / 手机为主 / 两端切换 / 需要嵌入其他系统）
3. 你希望社群如何参与？（公开分享 / 小组互助 / 导师反馈 / 仅自己使用）

### 第 2 轮：锁定体验

根据答案只追问仍会影响实现的 1–2 项，例如：时间节奏（日计划/周计划）、AI 权限（建议/代办/自动化）或数据保存（本地/团队空间）。然后直接输出方案或实现，不再进行开放式访谈。

## 提问质量门

- 每个问题都说明它会影响什么，不问“你喜欢什么颜色”这类低价值问题。
- 选项互斥、短、可扫读；允许“都可以，按默认方案”。
- 用户已经明确的内容不得重复确认。
- 用户不回答时，采用最保守的默认：电脑+手机响应式、个人空间、AI 仅建议、数据可导出。
- 涉及公开发布、成员权限、敏感资料、付费或删除时，必须获得明确确认。

## 推荐开场模板

> 我先按“{身份} 在 {场景} 中要完成 {结果}”来设计。暂定首页包含：{主任务}、{进度/反馈}、{社群入口}。为了避免做成泛化看板，只确认三件事：
> 1. 首要结果选哪项？
> 2. 主要设备选哪项？
> 3. 社群参与选哪项？
