# 交付前品控门

## 产品完整性

- [ ] 能明确说出目标身份、首要结果和今天的下一步。
- [ ] 主流程从输入到成果闭环，至少包含反馈或复盘。
- [ ] 每个模块有数据对象、状态、空状态和权限边界。
- [ ] AI 的建议、确认、执行、结果可追溯；无密钥时有可复制提示词或手动降级。
- [ ] 不确定事实、示例数据和暂定决策已明确标注。

## 界面质量

- [ ] 首屏是工作中枢，不是装饰性 Hero 或卡片墙。
- [ ] 层级由间距、字号、对比和布局建立；没有重复入口。
- [ ] 颜色、字体、圆角、阴影、动效形成一致 token；没有紫蓝渐变和无意义发光。
- [ ] 关键按钮、表单、抽屉、弹窗、列表、进度和通知都有完整状态。
- [ ] 键盘、触控、屏幕阅读器名称和 WCAG AA 对比度可用。

## 跨端与工程

- [ ] 在至少一个桌面和一个移动视口检查过无溢出、无重叠、无布局跳动。
- [ ] 复杂桌面组件在移动端有明确降级，不是简单缩小。
- [ ] 真实数据为空、很长、失败、重复时仍能工作。
- [ ] 若改代码，已运行项目现有 lint/test/build 或说明无法运行的原因。
- [ ] 草稿、同步、导出和恢复策略与用户预期一致，敏感信息未进入示例或代码。

## 交付判定

任一“产品完整性”或“跨端与工程”硬项未通过，不得声称完成；应列出缺口并继续修复，或明确请求用户决定。视觉偏好项未通过时，先说明取舍，不用泛泛的“后续可优化”带过。
