# Motion Blueprint 输出契约

默认交付可读的 Markdown，不要求用户阅读 JSON。字段顺序保持稳定，内容长度按任务复杂度调整。用户要求 JSON、需要跨模型复用或要交给自动化时，使用 `motion-blueprint.schema.json` 的字段并运行 `../scripts/validate_blueprint.py`。

当目标包含代码、预览或渲染时，这份输出也是“制作规划确认单”。默认只交付规划，不在同一轮开始制作。

公开规划分成两层：先用简洁导演稿说明目标最终帧、状态反差、记忆点、动作链和收尾，让用户先判断“想不想看”；再用逐元素表、时间轴和参数契约证明“能不能稳定实现”。简单 4–5 秒片头只列关键元素和关键节拍，不为追求字段数量重复同一句话。JSON 全量结构只在自动化或跨模型传递时使用。

## 零、当前状态与确认范围

- 渲染状态：规划待确认 / 低清预览待确认 / 最终全量渲染已批准。

- 当前状态：等待确认 / 已确认 / 用户明确免确认。
- 目标交付：代码 / Studio 预览 / 低分辨率预览 / 视频渲染。
- 输出模式：参数化工程（默认）/ 固定成片（用户明确选择）。
- 本次需要确认：画面理解、核心视觉、逐元素动作链、时间轴、镜头、风格、保真模式、保留项和输出规格。
- 批准证据：只有用户明确确认或免确认时填写；不能把“帮我做一个”当作批准证据。

## 一、需求快照

- 输入模式：文字 / 图片 / 图文混合。
- 目标与观众。
- 交付深度：方案 / 代码 / 预览 / 渲染。
- 画幅、时长、帧率和平台。
- 已确认事实。
- 采用的默认值或设计假设。
- 参数化工程说明：MP4 是当前参数快照，随附 Remotion 工程才是可编辑载体。

不要把设计假设写成用户确认的事实。

## 二、画面理解

有图片时必填；只有文字时改为“画面设定”。

- 画面一句话理解。
- 第一、第二、第三视觉层级。
- 核心视觉。
- 色彩、排版、形状、材质和透视特征。
- 必须保留 / 允许修改 / 需要新增。
- 目标最终帧与已批准差异清单。
- 可拆图层与深度关系。
- 清晰度、字体、抠像、比例或版权风险。

## 三、创意总纲

参考图保真模式：`layout-locked` / `raster-motion` / `approved-redesign`；原图尺寸、关键边界框、每个视觉所有者和禁止新增项必须在规划中写明。默认 `layout-locked` 只允许“元素重建后连续运动到目标构图”，整张参考图只能作分析/对比资料，不得在生产 Composition 中作为片尾覆盖层。

- 一句话概念。
- 开始状态 → 结束状态的可见反差。
- 最值得记住的一秒：时间区间、动作和视觉对象。
- 干净收尾或开场回扣。
- 目标最终帧。
- 风格词 3–6 个。
- 动效强度 1–3。
- 空间模型：2D / 2.5D / 3D / 混合，并说明原因。
- 趣味钩子或视觉反转。

这些字段必须先组成一条连续导演逻辑。若“记忆点”只能写成发光、粒子或镜头推进，说明动作逻辑仍不合格。

## 四、画面、动作、节奏、镜头、风格、细节

用六个短段落补全用户的简单输入：

- 画面：起始构图、结果构图、主体和环境。
- 动作：预备、主动作、次动作、微动作和收稳。
- 节奏：关键时间点、速度变化和停顿。
- 镜头：景别、角度、路径、焦点变化和连续性锚点。
- 风格：色彩、材质、光影、字体和动效手感。
- 细节：阴影、边缘、视差、模糊、音效、纹理和负面约束。

### 逐元素动作表

关键元素必须逐项列出，不能写成“元素依次出现”。

| 元素 | 触发 | 起始状态 | 动作与路径 | 时长 / 缓动 | 因果与下一触发 | 结束状态 / 微动 | 实现 |
|---|---|---|---|---|---|---|---|
| 主体或指针 | 前置事件 | 位置、尺寸、裁切、透明度 | 明确路径或形变 | 秒数、加减速、回弹 | 怎样触发下一动作 | 最终构图角色 | DOM / SVG / Canvas / Three + 帧驱动 |

参考图任务在此表前增加“视觉所有者表”：

| 元素 | 参考图归一化边界框 | 生产视觉所有者 | 来源/重建方式 | 是否可编辑 | 最终状态 |
|---|---|---|---|---|---|
| 标题、编号、Logo、图标或主体 | `[x, y, width, height]` | 唯一组件名 | DOM / SVG / 局部裁片 / 平面层 | 是/否 | 与参考图对齐、尺寸、层级一致 |

禁止同一元素同时由“重建层”和“整图参考层”负责，也禁止最后一秒新挂载一张参考图来修正布局。

若用户使用“随机、自然变化、错落”等词，规划中必须把它翻译为可复现的预设顺序、方向和幅度，不能留下真正随机行为。

逐元素表是导演逻辑的实施证明，不是创意起点。先用一段自然语言描述完整动作链，再拆表；不得为了字段完整而把一个连续动作机械切碎。

## 五、时间轴

时间轴必须覆盖完整视频，不留无法解释的空段。

| 时间 / 帧 | 画面与动作 | 镜头 | 焦点与图层 | 因果重叠 | 节奏 / 声音 | Remotion 实现 |
|---|---|---|---|---|---|---|
| 0.0–0.4s | 描述可见变化 | 景别、角度、路径 | 当前主焦点和参与图层 | 与哪一动作重叠、由什么阈值触发 | 加速、停顿或音效 | 组件、Sequence、CSS/SVG/Canvas/Three |

时间范围使用秒，并在实施时换算为帧。复杂视频可按场景分表。区间允许重叠：第一段必须从 0 秒开始，后续不能留下无人负责的空档，整体必须覆盖到总时长。重叠时写清路径进度、闭合、点击、碰撞、数值或减速点等触发条件。

## 六、素材与图层计划

列出每一层：名称、来源、角色、深度、进入方式、持续时间、退出方式、是否可编辑。平面图片不能假装有不存在的隐藏区域。

## 七、参数化契约

默认使用参数化工程。先明确：

| 参数 | 类型 | 默认值 | 绑定元素 | 校验与长度风险 |
|---|---|---|---|---|
| 主文字 | string | 当前批准文案 | 标题等真实元素 | 最大长度、换行或动态字号 |
| 编号（存在时） | number / string | 当前编号 | 期数、章节、排名等 | 范围、前导零和容器宽度 |
| 颜色 | color | 参考图或批准色值 | 背景、主色、强调色 | 对比度和关联元素同步 |

- Schema 使用 Zod `z.object()`；颜色使用 `zColor()`。
- `<Composition>` 同时提供 `schema` 和内联 `defaultProps`。
- 参数名、默认值、组件 Props 和绑定元素一致，不允许只出现在面板而不改变画面。
- “可编辑”必须通过 Studio 右侧 `Inspector → Default Props` 实际修改验证；仅能选择 `Interactive` 图层不算可编辑。
- 交付前记录一组面板改值结果：主文字、编号和颜色分别改变了哪些真实画面元素；若字段不可见、改值不生效或出现 JSON 错误，参数化验收失败。
- 参数化工程交付源码或工程包；渲染 MP4 只代表当前默认参数。
- 规划至少指定一组非默认参数测试值，交付前检查文字、编号和颜色变化。
- 若用户明确选择固定成片，写明“不可在 Studio 参数化编辑”，本节记录固定值即可。

## 八、Remotion 实施计划

- 低清预览规格、渲染器策略、性能预算和最终全量渲染确认状态。

- Composition ID、尺寸、fps、时长。
- 场景与组件树。
- 需要的 Remotion 包和当前文档条目。
- Props/Zod 中可编辑的文字、颜色、素材、节奏和开关。
- 参数 Schema、默认值、Studio 编辑方式和非默认参数测试帧。
- 2D/3D/混合的技术分工。
- 代表帧与预览检查点。

方案阶段只写实现计划，不输出伪代码冒充已实现代码。

## 九、负面约束

至少包含本任务真正需要避免的内容，例如：

- 不做 PPT 式整页翻换。
- 不让所有元素从不同方向乱飞。
- 不使用无目的粒子、炫光、故障和镜头抖动。
- 不拉伸、误裁、改错或模糊关键素材。
- 不让镜头运动压缩标题的阅读时间。

不要机械复制整套禁用词，只保留与本方案有关的风险。

## 十、验收标准

写成可观察结果，例如“0.6 秒时卡片完成主回弹，标题仍清晰”“最终画面保持 0.5 秒且相机已收稳”，不要只写“高级”“丝滑”“有质感”。

参考图任务必须包含“最终帧与批准参考或差异清单一致”。参数化模式必须包含“非默认文字、编号和颜色仍可读、无溢出并保持动作关系”。

## 十一、确认请求

规划末尾固定写明：

> 当前状态：等待确认，尚未开始制作。默认输出参数化 Remotion 工程；规划获批后先渲染覆盖完整时长的低分辨率预览，并在第二次确认后才输出最终全量渲染。可在 Studio 编辑批准的文字、编号和颜色。请确认整体规划、输出模式，或指出需要修改的画面理解、动作链、时间轴、镜头、风格、保真模式与保留项。你明确回复“确认，开始制作”后，我再创建工程和低清预览。

如果用户提出修改，先更新规划并再次输出此确认请求。只有用户明确免确认时才省略等待，但仍要在实施报告中记录免确认原话。

## 十二、实施报告

只有实际实施后才增加：

- 修改或创建的文件。
- 已运行的检查。
- 已查看的代表帧或 Studio 预览。
- 参数化模式列出 Schema 字段、非默认参数测试和值变化证据。
- 渲染文件、规格与警告；未渲染时明确写未渲染。
- 低清预览链接、最终帧对比指标、渲染器与耗时；若未收到最终确认，明确写“尚未执行最终全量渲染”。
- 与 Blueprint 不一致的地方及原因。

## 简短文本示例

用户输入：“帮我做一个卡片弹跳动画。”

合格的补全方向：卡片从画面下方带 6% 预压进入，0.25 秒内释放并越过落点，0.55 秒完成主回弹，随后用 0.2 秒消除余震；镜头同步轻推近卡片中心，阴影在落地时压缩并变深，最终正面构图停留。风格克制、干净、轻松，避免花哨发光和多次无意义弹跳。

这个示例说明信息密度，不要求每个任务复用相同动作或时间。
