# 输入与图片分析

图片转视频不是给整张图加一次缩放。先判断图片提供了什么真实视觉信息、哪些区域可以独立运动、哪些内容必须保持完整，再决定空间和镜头。除非用户明确批准改版，参考图默认是动画必须回到的目标最终帧。

## 文本输入

从简短文本中提取：

1. 名词：主体、信息、场景、道具和必须出现的内容。
2. 动词：弹跳、汇聚、排序、穿越、揭示、展开、跟随等主动作。
3. 形容词：风格、重量感、速度感、情绪和材质倾向。
4. 目的：让观众理解、记住、比较、期待还是采取行动。
5. 限制：时长、比例、品牌、平台、禁用效果和素材边界。

一句话缺少的信息可用设计默认值补全，事实内容不可补写。

## 图片检查顺序

### 1. 客观事实

- 文件类型、像素尺寸、长宽比、清晰度、透明通道和明显压缩问题。
- 可见文字、Logo、人物、产品、界面、图表、图标和背景。
- 主色、辅色、字体气质、形状语言、边框、阴影、纹理和留白。
- 主体位置、视觉动线、对称关系、网格、遮挡和透视线。
- 至少三个不含前景的背景安全区域及其平均 RGB、亮度；复杂渐变记录 5–8 个采样区、渐变方向和暗角。背景不能只用“深色”“科技蓝”描述。

把“观察到的内容”和“设计推断”分开。无法确认的文字不要转写成确定文本。

### 2. 画面理解

用一句话说明图片正在表达什么，再列出：

- 第一视觉焦点。
- 第二、第三信息层级。
- 观众视线应如何移动。
- 哪些元素构成识别度，不能随意更改。
- 哪些空白区域可容纳镜头运动或新增信息。

同时记录目标最终帧契约：精确文字、编号、品牌、主体占比、关键对齐、相对位置、留白和画幅。需要为了动效重建图层，不等于获得重新设计最终构图的授权。

### 3. 核心视觉

核心视觉不是“图片里最大的东西”，而是最能承担视频记忆点和结果定格的对象。若有多个候选，只选一个主核心，其余降为支撑层。

### 4. 图层候选

按实际可分离程度记录，而不是假装平面 JPG 自带图层：

| 图层类型 | 常见内容 | 可用动作 | 风险 |
|---|---|---|---|
| 背景层 | 纯色、渐变、网格、环境 | 缓慢漂移、轻推拉、光影变化 | 放大后像素不足 |
| 环境层 | 装饰线、粒子、纹理、次要图形 | 反向视差、轻微旋转、遮挡转场 | 不能抢主焦点 |
| 主体层 | 人物、产品、主卡片、Logo | 跟随、抬升、弹性、定格 | 边缘抠像和缺失区域 |
| 信息层 | 标题、数据、标签、图标 | 分组揭示、路径跟随、强调 | 文字重排可能破坏原设计 |
| 前景层 | 大型遮挡物、光斑、框架 | 掠过、擦除、景深 | 过强会遮住信息 |

对不可分离的区域可选择：保持整图平面；用裁切窗口重复取样；用 CSS/SVG 重建简单几何；或在用户授权后准备蒙版。不要自动“补出”原图被遮挡的内容。

### 5. 从完成画面反推动作

参考图通常展示的是最终构图，不代表视频从整张图淡入。对每个可识别元素反推：

- 它在最终画面承担什么角色。
- 它可以由哪个前置元素“建立”或“触发”。
- 最可信的起始状态是什么：未绘制、被裁切、折叠、缩小、位于画外、附着在指针或路径端点。
- 它出现时改变了什么信息状态，而不只是增加一个可见对象。
- 它完成后如何成为下一动作的锚点。

优先利用图片本身暗示的交互语义：指针可以点击、拖拽和绘制；选框可以沿边界建立；控制柄可以在路径经过角点时弹出；标签可以展开；标题可以通过框体或蒙版揭示。不要在图中已经存在明确交互线索时，退回通用缩放、整体淡入或无关相机推拉。

若重建图形与文字，参考图只作为视觉事实和校准依据；生产 Composition 不得导入整张参考图，也不要让低透明度整图长期垫在重建层下面或在片尾淡入，否则容易产生重影、双文字、遮挡和错误元素。必须由同一套重建元素沿参考图目标边界框连续抵达最终帧。

### 6. 参数候选

默认参数化工程需要从图片中识别可编辑候选，但不能臆造字段：

- 文字：主标题、副标题、作者、标签等用户以后可能替换的文案。
- 编号：期数、章节、排名、百分比、日期或其他真实数字；图中不存在编号时不强行新增。
- 颜色：背景、主色、强调色和状态色；参数化后仍要保持足够对比度。

规划中记录参数默认值、类型、画面绑定和长度风险。图片中的品牌色可以参数化，但默认值必须与参考图一致；改变颜色后需要额外检查文字对比和装饰可见性。

## 选择空间模型

### 2D

适合排版、卡片、图表、扁平图标和信息演示。通过层级、遮挡、路径、形变和节奏建立动态，不必伪装成 3D。

### 轻 2.5D

参考图只有一个平面，但背景、主体、文字或装饰可合理拆分时优先使用。通过不同深度的平移、缩放、模糊和遮挡形成视差。默认只使用一条温和相机路径，避免“每个元素各飞各的”。

### 真实 3D

仅在以下情况使用：

- 需要绕物体、穿越空间或明显透视变化。
- 真实几何、灯光、阴影或遮挡是表达核心。
- 图片元素能合理映射到平面、材质、粒子或 3D 物体。

一张普通海报不因为用户说“炫酷”就必须重建为完整 3D。

### 混合

用 ThreeCanvas 承担空间、相机或背景，DOM/SVG/Canvas 承担精确文字与界面。适合科技感、数据可视化和产品界面，但要避免两个渲染层的光影和透视互相矛盾。

## 图片输入必须输出的结论

1. 画面理解。
2. 核心视觉。
3. 必须保留、允许修改、需要新增的内容。
4. 图层与深度建议。
5. 2D / 2.5D / 3D / 混合选择及原因。
6. 推荐主动作、主相机路径和焦点变化。
7. 时间轴。
8. 画质、抠像、字体、比例或版权风险。
9. 逐元素动作生命周期，以及每个动作怎样触发下一动作。
10. 等待用户确认的规划状态；确认前不得开始实现。
11. 目标最终帧契约与任何已批准的改版差异。
12. 默认参数化字段：文字、存在的编号和关键颜色，以及它们的画面绑定。
13. 背景分类、采样区域、默认色、渐变/纹理重建方式、允许的短时动态和最终背景验收门槛。

## 多图输入

- 先判断多图是帧序列、故事顺序、对比组、素材库还是风格参考。
- 如果用户没有指定顺序，不用文件名顺序冒充叙事顺序；按视觉因果排序并标记为设计选择。
- 选择一个贯穿多图的连续性锚点，例如同一颜色、人物、卡片、相机方向或几何形状。
- 不要把每张图变成一页依次翻过去；优先使用共享构图、遮挡、匹配剪辑或空间穿越连接。
