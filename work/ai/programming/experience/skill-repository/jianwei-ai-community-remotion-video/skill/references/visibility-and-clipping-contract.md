# 文字与关键元素完整可见契约

文字、编号、Logo、图标和主体只要没有被参考图或用户明确要求裁切，就必须在所有需要阅读/识别的帧中完整可见。动画期的揭示蒙版可以暂时裁切“尚未出现”的部分，但它不能延续到最终稳定区，也不能切掉已经出现的字形或主体。

## 1. 区分三个边界

实现前为每个受保护元素分别记录：

1. **目标布局框**：元素在最终构图中的位置与占比。
2. **实际可见/墨迹框**：包含字形升部、降部、斜体外扩、描边和变换后的真实内容范围；不能拿 CSS 容器框冒充。
3. **裁剪祖先框**：所有 `overflow: hidden|clip`、`clip-path`、`mask` 和画布边界。

实际可见框必须被画布和每个裁剪祖先完整包含。阴影或纯装饰辉光可以按批准设计越界，文字墨迹、Logo 轮廓和主体几何不可以。

## 2. 文字布局规则

- 等待 `document.fonts.ready` 后再测量。文字优先使用 DOM `Range.getBoundingClientRect()`；同时用 Canvas `measureText()` 的 `actualBoundingBoxAscent/Descent/Left/Right` 检查字形墨迹。只读取 `div` 的宽高不算验收。
- CJK、大写拉丁、数字、斜体、粗体、`text-stroke` 和 `scaleY/rotateX/rotateY` 都可能超出行盒。容器必须预留独立的上下左右保护垫，不能用负 `marginTop` 把字形硬塞回与字号近似等高的裁剪框。
- 若字体为 `146px`、行高为 `148px`，又有 `marginTop: -17px`、`scaleY(1.05)` 和 `overflow: hidden`，属于明确高风险组合；应扩大布局/蒙版框、取消负偏移或在揭示结束后释放裁剪，而不是继续微调字形位置。
- 精确对齐参考图时，调整外层布局坐标；不要通过切掉字形顶部、底部或斜体外扩来制造“对齐”。
- 文字容器默认 `overflow: visible`。必须擦除揭示时，使用独立的临时蒙版层，并给蒙版加入足够的墨迹保护垫。

## 3. 动作期蒙版、定格期释放

使用两层结构：外层负责目标位置和最终几何，内层只负责入场揭示。揭示进度完成后必须满足：

- `clip-path: none`；不能只停在 `inset(0 0 0 0)` 并假设没有边缘损失。
- `mask-image: none`，或直接卸载临时蒙版/遮罩层。
- 文字与关键元素的最终内容层为 `overflow: visible`。
- 最终 transform 回到已批准状态；若保留 3D 姿态，重新测量变换后的实际框。
- 中间 3D 世界层和元素布局层不要使用无必要的 `overflow: hidden`；通常只允许最外层 Composition 按画布边界裁切。

不能为了防止扫光、拖影越界而裁切承载真实文字的同一个容器。把扫光放进自己的受限层，文字留在独立可见层。

## 4. 参数化压力测试

默认参数通过不代表可编辑工程通过。至少测试：

- 默认文字；
- Schema 允许的最长文字/编号；
- 同时包含中文、拉丁字母和数字的代表值；
- 斜体、描边、字号自适应或自动换行实际启用时的极端值。

为每个字段事先决定 `auto-fit`、允许换行、缩小字号、扩大容器或拒绝超长输入中的一种策略。不得静默裁字，也不得只靠 `max(n)` 回避布局处理。

## 5. 可执行验收

至少检查主动作峰值、最终稳定区开始和最终帧；参数化模式再检查最长值代表帧。用浏览器实际测量生成 `visibility-report.json`，然后运行：

```bash
python scripts/check_visibility_report.py visibility-report.json
```

报告中的 `bounds` 是元素真实可见/墨迹框，不是设计常量；`clipAncestors` 记录所有会裁剪它的祖先。最终稳定帧中，所有受保护元素必须位于画布及裁剪祖先内部，且 `activeClipPath=false`、`activeMask=false`。若参考图本身有明确的边缘裁切，只能将 `approvedCrop=true` 并写入已批准差异原因。

实施报告必须列出被测元素、帧号、默认/压力测试值和脚本结果。只写“截图看起来完整”不算通过。
