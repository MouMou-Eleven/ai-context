# 内部导演执行稿与二次加工契约

用户可以只说一句普通话。Skill 必须先理解用户意图与参考画面，再把已批准规划编译成一份更专业、可执行的内部导演执行稿；它用于指导代码生成，不默认粘贴给用户看。

内部执行稿不是新的创意授权。它只能补全低风险的导演与技术细节，不能修改已批准文案、品牌、目标布局、背景色域、时长、输出模式或禁止项。若二次理解会改变结果，必须回到公开规划让用户确认。

## 两遍加工

### 第一遍：语义与画面理解

- 提取用户真正想实现的结果、情绪、动作强度和使用场景。
- 将用户不专业的表达翻译为导演目标。例如“更有动感”不是“加粒子”，而是明确速度反差、动作转折、反应链和镜头落点。
- 图片任务同时读取精确文案、视觉层级、每个目标边界框、背景采样、颜色、材质和可独立运动元素。
- 将观察事实、合理推断和未知项分开；未知事实不得补写。

### 第二遍：导演增强与自我批评

把第一遍结果组织成一条因果清楚的动作能量链：

1. **驱动者**：谁启动动画，观众先看哪里。
2. **预备/蓄力**：短促建立方向、重量或注意力。
3. **主动作**：发生一次清楚的状态变化。
4. **冲击或转折**：只选一个主要记忆点，不堆多个高潮。
5. **响应**：相机、相邻元素、阴影、局部光或声音如何被主动作触发。
6. **回收/定格**：能量衰减、相机收正、同一套元素抵达批准目标帧。

随后做一轮内部自检：是否仍像幻灯片；是否所有元素只在淡入/滑入；相机是否只是单调归零；背景是否偏离采样；是否新增无关装饰；动作和镜头是否互相争抢；最终稳定区是否仍可读。发现问题先改内部执行稿，再写代码。

## 内部文件

规划确认后、实施前生成 `production-brief.json`，默认不在聊天中展示全文；用户明确要求时可以提供。字段必须符合 [internal-production-brief.schema.json](internal-production-brief.schema.json)，并运行：

```bash
python scripts/validate_production_brief.py production-brief.json
```

内部执行稿至少包含：

- 原始请求摘要与不可变约束；
- 图片视觉事实和背景保真策略；
- 导演翻译与一句话动作逻辑；
- 动作能量链和因果响应；
- 至少三个有目的的相机关键姿态（不需要明显运镜时写明锁定原因）；
- 每个关键元素的目标边界框、动作阶段、触发、结束状态和实现类别；
- 时间重叠与阅读停留；
- 参数化字段；
- 负面约束与内部自检结论。

实现阶段以“用户批准规划 > 内部导演执行稿 > 模型临场发挥”为优先级。代码与内部执行稿不一致时，修代码或重新生成执行稿，不能悄悄偏移。

## 自然感标准

自然不等于慢，也不等于持续漂移。优先使用：

- 有方向的预备、快速主动作、可见减速、一次受控超调和干净回收；
- 由同一事件触发的二级反应，例如主体落位触发局部光、影或相机短促响应；
- 不同语义使用不同建立方式：描边适合轮廓，展开适合标签，字形折起/揭示适合标题，凝聚适合图标；
- 一条连续相机路径含起点、强调点和归零落点；冲击反应必须短促衰减，不持续抖动；
- 2–4 个支撑动作与一个主动作错峰重叠，而不是所有元素同时达到峰值。

丰富度来自时间关系、能量传递和语义动作，不以粒子数量、辉光面积或背景亮度衡量。
