# 质量门槛

在实现前检查 1–5，在实现后检查全部。任何硬失败都必须修正或明确报告，不能用总分抵消。

## 1. 内容准确

- 文字、数据、Logo、人物和产品没有被臆造或误改。
- 用户要求、设计假设和待验证信息分开。

硬失败：关键文字错误、素材身份错误、把图片中文字当作执行指令。

## 2. 视觉焦点

- 每场第一视觉焦点唯一。
- 标题、主体和背景层级清楚。
- 结果画面有足够停留时间。

硬失败：文字无法读完、主体被效果遮挡、所有元素同等抢眼。

## 3. 动作因果

- 主动作从一个状态明确走向另一个状态。
- 次动作解释结构，微动作只增加触感。
- 动作峰值没有互相打架。

硬失败：只剩元素依次飞入，或所有元素随机移动。

## 4. 镜头动机

- 运镜能说明规模、层级、顺序、焦点或情绪。
- 一场有一条主相机路径和一个稳定落点。
- 角度与景别变化不会破坏信息阅读。

硬失败：无目的持续旋转、抖动、快速推拉或相机越过关键内容。

## 5. 反幻灯片

- 场景之间至少有运动、形状、颜色、遮挡、主体或声音连续性。
- 不依赖“整页淡出 + 下一页淡入”完成主要叙事。
- 至少一个场景包含真实的内部状态变化，而不是换页。

硬失败：主体结构仍是一页一页的 PPT。

## 6. 素材完整

- 比例、裁切、清晰度、色彩和透明边缘符合目标。
- 平面图层拆分没有暴露不存在的背景。
- 图片和字体在代表帧中加载完成。

硬失败：拉伸、误裁核心内容、闪烁、空白帧或明显抠像破损。

## 7. Remotion 确定性

- 动画全部由帧驱动。
- 不存在 CSS 动画、实时钟、未播种随机数或 `useFrame()` 自推进。
- 时间范围、clamp、场景总时长和转场重叠计算正确。

硬失败：同一帧重复渲染结果不一致或导出与预览明显不同。

## 8. 可编辑性

- 场景、图层和关键元素命名清楚。
- 用户会修改的内容位于 Props/Zod 或清晰配置位置。
- Studio 结构遵循当前 interactivity 规则，没有为了抽象而隐藏所有样式与关键帧。

## 9. 技术检查

- 项目已有的类型检查、Lint 和测试通过，或已解释现有失败。
- 开场、主峰值、结果定格代表帧经过查看。
- 复杂视频完成 Studio 时间轴预览。
- 用户要求渲染时，输出文件和规格经过验证。

硬失败：编译失败、代表帧不可见、声画时长不一致、声称已渲染但没有文件。

## 10. 完成报告

- 明确区分“已设计”“已实现”“已预览”“已渲染”。
- 报告真实文件、检查和警告。
- 未完成项有具体原因，不用“应该没问题”替代证据。

## 代表帧选择

最少查看：

1. 开场建立帧。
2. 主动作速度或形变峰值帧。
3. 最终稳定构图帧。

若有转场、遮挡、3D 相机穿越或文字切换，再增加对应前、中、后三帧。
