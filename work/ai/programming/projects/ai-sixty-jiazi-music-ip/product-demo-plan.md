# 产品 Demo 规划

> 版本：2026-08-24
>
> 目标：先做可演示、可验证的响应式网页产品，不把首版变成资料陈列页。

## 一、平台决策

### 当前选择：Web App 优先

Web 是当前最合适的首发形态：可直接通过链接演示，桌面和手机都能访问，不需要等待应用商店审核或小程序主体、类目和隐私流程；也便于快速修正历法、音律和内容数据。

首版按响应式 Web App 开发，并预留 PWA 能力。只有当核心流程经用户验证，且明确需要账号长期留存、离线音频、系统推送、应用内购买或更强设备能力时，再评估 iOS App。微信小程序同理，不在首版同时维护另一套前端和审核口径。

### 当前不做的事

- 不在 Demo 阶段同时开发 Web、iOS 和小程序三端。
- 不先做注册、支付、社交社区和复杂后台。
- 不把所有六十甲子内容一次性做成高成本 3D 角色。
- 不把“数字人、AI 综艺、商城、收藏品”同时塞进第一条体验路径。

## 二、产品目标

Demo 需要在 3 至 5 分钟内回答三个问题：

1. 这套产品有什么独特数据和文化逻辑？
2. 用户输入自己的信息后，能获得什么可听、可看、可继续创作的结果？
3. 三个旧工具如何变成一个连贯产品，而不是三个内嵌网页？

甲子神 IP 孵化另立工作线，不纳入网站 Demo 的信息架构和验收。

## 三、用户路径

### 主路径：出生时间到个人古音律谱

1. 用户输入公历日期、时间和时区。
2. 系统计算年、月、日、时四柱，分别显示天干、地支、纳音和映射音符。
3. 用户打开或关闭四个声部，试听组合并观察五行构成。
4. 用户进入对应年柱甲子档案，查看调式、速度、乐器、意象和太岁神资料。
5. 用户选择“生成创作方案”，得到结构化的音乐提示词和补全后的旋律设计。

### 辅路径：查甲子与合音

- 不输入个人信息也可直接搜索六十甲子，按五行、阴阳、调式、乐器和角色筛选。
- 在“合音”中任选干支，或调用天干五合、地支六合预设，比较真实音高与音程并即时试听。

## 四、信息架构

### 1. 听命

- 公历日期、时间、时区输入。
- 四柱结果、年柱甲子、纳音和生肖。
- 四个声部的音符、音量和开关。
- 五行比例与音律圆盘。
- “查看甲子档案”“进入合音”“生成创作方案”三个后续动作。

说明：`40% / 30% / 20% / 10%` 只能作为 Demo 默认混音权重，界面必须标注待学术确认，并允许用户手动调整。

### 2. 寻甲子

- 60 条可搜索、可筛选的谱系表。
- 重点字段：序号、干支、纳音、阴阳、五行、调式、音阶、主音、速度、主辅乐器、意象、色彩、情绪、太岁神名、人物原型、性格关键词。
- 详情页分为“可计算数据”“资料记载”“创作转译”三层，避免混淆证据等级。

### 3. 合音

- 两个音位选择器：天干或地支、对应音名与实际频率。
- 结果同时显示：绝对半音差、十二平均律循环最短距离、上行/下行方向和标准音程名。
- 支持 A、B、同时播放和简单波形反馈。
- 天干五合、地支六合只作为预设关系，不预写吉凶、桃花、疾病等确定性结论。

### 4. 造曲

输入：甲子、内容用途、情绪目标、时长和生成平台。

输出：

- 调式、音阶、主音与速度。
- 主辅乐器及进入顺序。
- 旋律动机、音域、句法、起承转合和收束方法。
- 节奏、织体、空间、动态和段落结构。
- 画面意象、色彩、自然声与角色叙事。
- 禁用项、文化表达边界和平台格式。

首版必须解决现有 60 份提示词中“旋律设计”为空的问题；旋律内容应由数据规则生成并允许编辑，而不是凭空补充不可追溯的神秘描述。

## 五、三套旧工具的整合方式

| 旧工具能力 | 新产品归属 | 需要重做的部分 |
|---|---|---|
| 出生年份推演 | 听命、寻甲子 | 从“只输年份”升级为准确日期时间；拆分事实与文化解释 |
| 干支两两组合与钢琴试听 | 合音 | 修正音程算法、增加循环最短距离和方向音程 |
| 六十甲子与五合六合浏览 | 寻甲子、合音 | 从卡片堆变为筛选谱系；移除未经证实的吉凶健康结论 |

旧页面只作为需求原型和数据线索，不作为新应用的运行时 iframe，也不直接继承其算法结论。

## 六、技术建议

- 前端：React + TypeScript + Vite，单页路由，移动端优先。
- 状态：首版本地状态与 `localStorage`；没有账号需求前不引入后端。
- 历法：使用经 Context7 文档核验的 `lunar-javascript`，建立固定测试样例与节气边界测试。
- 音频：首版优先使用 Web Audio API 合成与混音；原始 WAV 仅在版权和压缩方案确认后接入精选预览。
- 数据：将确认后的六十甲子表导出为带版本号的 JSON；保留 `source`、`status`、`reviewedAt` 等溯源字段。
- 样式：设计令牌集中管理，满足键盘操作、可见焦点、对比度和减少动态效果偏好。
- 后端触发条件：需要账号同步、分享链接、云端 AI 音乐生成、额度、支付或内容管理时，再建立 API 与数据库。

## 七、验收标准

- 四柱固定样例 `2005-12-23 08:37` 在约定规则下返回 `乙酉 戊子 辛巳 壬辰`。
- 60 条甲子记录可搜索、可按五行和阴阳筛选，字段来源可追溯。
- 任意两个音位的半音差和循环最短音程计算通过单元测试。
- 四声部可独立开关、调音量并停止，不出现叠音失控。
- 至少一个甲子能生成包含非空旋律设计的完整创作方案。
- 手机宽度下主流程可完成；键盘可到达所有交互控件。
- 所有健康、命运与传统文化内容都带边界说明，不做确定性承诺。

## 八、阶段路线

### 阶段 A：设计与规则确认

- 批准视觉方向。
- 确认四柱、音高、权重和甲子真源。
- 确认音频版权边界；IP 角色在独立工作线确认。

### 阶段 B：前端 Demo

- 建立数据层、历法适配层和音频引擎。
- 实现四个模块中的完整主路径和关键辅路径。
- 完成响应式、可访问性和浏览器测试。

### 阶段 C：真实内容生成与展示

- 接入可编辑的音乐提示词生成。
- 选择是否调用音乐生成服务，并单独核验平台能力、授权和成本。
- 网站内容生成与甲子神潮玩形象分别验收，后者不接入网站。

### 阶段 D：平台化决策

- 根据用户留存、分享和生成数据，决定继续 PWA、封装 iOS，或适配微信小程序。
- 确认独立源码仓库、部署域名、账号、隐私和商业化范围。
