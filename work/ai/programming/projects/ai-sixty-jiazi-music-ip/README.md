# AI 六十甲子古音律与 IP 孵化

> 状态：响应式 Web Demo 已完成，待独立源码仓库与部署
>
> 当前口径确认：2026-08-24

## 项目定位

本项目以六十甲子、五行、纳音、古音律和相关文化资料为内容底座，先做一个可操作、可试听、可查询、可生成创作提示词的网页 Demo，再逐步验证五行种子形象、六十甲子神谱、AI 音乐内容和 IP 孵化路径。

项目不是把三个现有单页工具简单拼接，也不把未经验证的命理、健康或疗愈话术包装成确定性结论。Demo 要把分散数据和计算逻辑组织成一条清晰主线：输入出生时间或选择甲子 → 看见可追溯的干支、纳音和音律映射 → 试听与比较 → 生成音乐创作方案 → 进入甲子神 IP 档案。

## 当前确认事实

- 第一阶段产品形态：响应式 Web App，兼顾手机浏览器，预留 PWA 和后续封装能力。
- App Store 上架目前只是方向设想，不是已确定交付；微信小程序也暂不作为首发形态。
- 当前已有三套相互分散的网页工具：本命五音推演、干支五音组合、六十甲子与干支关系查询。
- 当前核心数据包括六十甲子纵表、五行古音律校勘表、音乐创作素材、音乐生成提示词和五行音乐全流程资料。
- 音频素材现有 20 个 WAV 文件，约 690 MB、总时长约 62 分 48 秒；Demo 是否使用原始音频、压缩预览还是浏览器合成，需先确认版权和体积方案。
- 当前六十份音乐提示词中的“旋律设计（Melody）”均为空，是 Demo 的明确补全任务。
- Web Demo 已用可复用规则补全 Melody 段落，生成结果仍需作曲人与文化顾问复核。
- 五个首发形象暂按五种纳音五行各选一个阳年代表：甲子金辨、戊辰赵达、丙子郭嘉、丙寅耿章、庚午王济；这是产品阶段选样，仍需居老师确认。
- 当前沟通材料提到学术、软件、内容 IP、数字人、自媒体和商业化等方向；其中合作、资金和正式背书状态尚未取得可核验正式文件，不能对外写成既成事实。

## Web Demo 产品结构

| 模块 | 核心作用 | 首版闭环 |
|---|---|---|
| 听命 | 输入公历日期、时间，计算四柱并映射音律 | 四柱、纳音、音符、分轨开关、可试听组合 |
| 寻甲子 | 查询和筛选六十甲子 | 干支、纳音、调式、速度、乐器、意象、太岁神档案 |
| 合音 | 比较天干地支及五合六合的音程关系 | 原始音值、循环最短音程、方向音程和 A/B 试听 |
| 造曲 | 依据甲子和使用场景生成音乐创作提示词 | 补齐旋律、调式、速度、乐器、意象和禁用项 |
| 神谱 | 展示五行种子形象并扩展到六十甲子 IP | 五个种子角色档案、统一视觉规范和后续 60 角色入口 |

详细方案见 [`product-demo-plan.md`](./product-demo-plan.md)。

## 数据与表达边界

- 六十甲子主数据优先使用 `60甲子总表_纵向版_拆开合并(1).xlsx`，并结合 `古音律五行整合表_校勘完善版_重排版.xlsx` 的校勘记录；`codexBIAOGE (1).xlsx` 仅作对照，不作为唯一真源。
- 五常、洪范五事、五礼、五刑和十神等条目必须按校勘记录处理；不得重新引入已标记为错误或存疑的旧口径。
- 四柱计算应使用经过验证的历法库，并为节气换年、立春换年等规则留下明确配置与说明。
- 当前四柱声部的 `40% / 30% / 20% / 10%` 只是 Demo 交互假设，必须在界面标记“待学术团队确认”，不能伪装成定论。
- 不输出医疗诊断、疗效承诺、寿命判断或确定性命运结论。所有相关内容需标注为传统文化与音乐体验参考。

详细审计见 [`data-audit.md`](./data-audit.md)。

## AI 调用规则

处理本项目后续任务时：

1. 先读本 README，再按任务读取产品规划、数据审计、角色提示词或修订记录。
2. 不把旧单页工具中的文案和算法直接复制进新 Demo；先核验数据、音程和历法规则。
3. 计算事实、传统文化解释、创作建议和商业叙事必须分层展示，不能混写成同一种事实。
4. 涉及历法库、音乐生成模型、App Store、小程序、版权、价格或平台规则时，必须重新查询当期官方资料。
5. 原始表格、压缩包、DOCX 和 690 MB WAV 素材保留在授权的本地资料目录，不复制进 `ai-context`；本仓库只保存索引、结论和决策。
6. 完整 Demo 源码应进入独立源码仓库；独立仓库未确认前，不把完整构建产物提交到 `ai-context`。
7. 新增学术口径或角色设定时记录来源；发生重要变更时新增 `revisions/YYYY-MM-DD-{slug}.md`，不得无痕覆盖旧结论。
