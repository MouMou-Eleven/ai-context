# 短视频口播结构

> 这些是内容组织工具，不是平台算法定律，也不保证播放、完播或成交结果。

## 三个质量原则

### 故事性

观点要落到角色、冲突、关键动作和结果。没有真实案例时可以写“示范场景”，不能伪装成建委、客户或学员经历。

### 信息密度

信息密度不是语速快和术语多，而是持续给观众新的理解、案例、步骤或判断。删除重复句、空泛铺垫和没有作用的态度表达。

### 推力结构

前一段应自然引出后一段。可使用阶段上升、问题加深、结果放大、能力升级和误区递进，不依赖“看到最后”这类明示话术。

## PREP：观点论证

适合纠正常见认知、输出明确判断：

1. Point：先给出有对象、有结果的观点。
2. Reason：解释原因和机制。
3. Example：给真实案例、操作结果或可核验依据。
4. Point：回扣并说明观众下一步做什么。

常见错误：观点只有情绪；原因只是重复；案例无法核验；结尾原句复读。

## SCQA：场景与冲突

适合让目标观众快速代入问题：

1. Situation：点名人群、动作和具体处境。
2. Conflict：只放大一个主要冲突。
3. Question：说出观众自然会产生的问题。
4. Answer：尽快给核心答案，再展开步骤或案例。

常见错误：背景太长；靠焦虑制造冲突；问题不是观众的问题；答案拖到最后且没有步骤。

## 结构选择

| 目标 | 推荐结构 |
|---|---|
| 输出观点、纠正认知 | PREP |
| 让某类人代入痛点 | SCQA |
| 教解决流程 | SCQA + 步骤清单 |
| 复盘真实案例 | 场景冲突 + 故事 |
| 同时留人并建立信任 | SCQA 开头 + PREP 主体 |

当内容涉及成果展示、用户动机、知识为什么没人看或课程知识怎样转成前端内容时，继续读取 [`../experience/outcome-and-motivation.md`](../experience/outcome-and-motivation.md)。观点负责建立相关性，知识和案例负责建立信任，不能用情绪观点替代真实交付。

## 给 AI 的输入字段

```text
平台与时长：
目标人群：
具体场景：
核心冲突：
希望传达的观点：
可用事实或依据：
真实案例（没有就写无）：
可见结果：
唯一行动：
```

AI 必须先选择结构，再输出“结构标注版”和“纯口播版”；不得编造数据、客户、学员、平台规则和个人经历。

## 复盘字段

- 平台、发布时间和标题。
- 使用的结构与开头。
- 真实案例或证据。
- 播放、观看时长、完播、收藏、评论和转化数据。
- 哪个变量有效、哪个判断仍待验证。

结论只能写成“当前账号和样本下的结果”，不能升级为所有平台通用规律。
