## 当前方法的唯一来源

- `jianwei-training-style.md` 是“建委希望课程最终呈现成什么样”的唯一当前来源，培训课件创建、修改、审核与复盘时必须读取；只查询项目事实、课程状态或资料位置时不读取。
- `teaching-and-course-design.md` 只负责任务入口、交付物和跨课程边界。
- `demo-driven-course-design.md` 是“课程怎样组织才可讲”的唯一活动方法。
- `visual-and-oral-training-docs.md` 是“学员可见培训文档怎样选择媒体、实现口语化并保护飞书既有内容”的唯一活动方法。
- `technical-explanation/problem-driven-technical-explanation.md` 是“技术内容该不该讲、怎样解释”的唯一活动方法。
- `tutorial-writing.md` 只在学员需要跟着完成操作时使用。
- 具体课程的事实、标题、案例顺序和进度留在对应项目；历史修订只用于追溯。

同一条方法不要同时写进多个活动文件。入口文件只做指向，项目文件只记录项目特有规则；发现重复或冲突时，先确定唯一来源，再删除其他位置的第二套表述。

## 多位讲师与创作者经验怎样合并

1. 先把资料拆成具体能力，例如课程开场、概念解释、案例展开、现场演示、互动、收束和复盘。
2. 每项经验写清适用受众、课程类型、使用条件和限制，不以作者姓名作为激活词。
3. 与现有方法一致时只补来源，不重复新增规则。
4. 可以前后分工的方法才组合，例如“问题驱动解释 + 演示验证”；多个互相替代的开头不得同时使用。
5. 发生冲突时按以下顺序选择：当前任务要求 → 当前项目事实 → 建委真实授课复盘 → 已验证培训方法 → 外部来源候选方法 → 原始逐字稿。
6. 无法确定哪种方法适用时，保留冲突并向建委确认，不把不同人的讲法平均混合。

## 真实复盘怎样转化为通用经验

当建委在 AI 培训语境中说“复盘、总结经验、沉淀经验、写进 GitHub”时，默认不是只新增一份具体课程复盘，而是必须完成一次通用化审查。即使建委没有再次写出“通用”二字，也按下面的双层结果处理：

1. **资料/项目层保留证据。** 先按[归属规则](../attribution-and-updates.md)确认项目与场次，在对应项目的 `revisions/` 记录主题、版本、问题和建委修正；未知归属先存待归属区，不能默认写成社群第几课。这里保存事实和来源，不承担所有课程的默认规则。
2. **通用层更新当前方法。** 判断这条反馈是否会影响其他会员课、企业培训、公开课或飞书培训文档。如果可以复用，就更新 `experience/` 中负责该问题的唯一活动文件，而不是只在项目复盘里写一句“长期规则”。
3. **入口层保证以后会读。** 新增活动文件或提高规则优先级时，同步检查本 README、培训总入口、`AGENTS.md` 和 `llms.txt` 的调用路线，让规则在适用任务中可被找到；不因此让事实查询预读全部课件规则。
4. **项目事实不得错误泛化。** 具体产品价格、课程标题、工具按钮、单课案例和临时安排仍留在项目层。不能为了形成通用经验而把偶发情况写成所有课程的固定模板。

每条复盘反馈都要得到一个明确结论：`仅保留项目证据`、`新增通用规则`、`修订已有通用规则`、`强化重复失误` 或 `信息不足，暂不泛化`。不能只保存原话而不判断。

## 已有规则再次被违反时怎样加强

复盘中再次出现一个已经沉淀的错误，说明问题不是“仓库里没有写”，而是规则的调用位置、可执行性或验收强度不够。此时不新增同义文件和重复段落，按顺序处理：

1. 核对活动方法中是否已经有这条规则，以及任务开始时是否应该读取该文件。
2. 将重复错误登记到 [`jianwei-training-style.md`](./jianwei-training-style.md) 的“当前高频失误与强化”，并补充新的独立实战来源。
3. 把规则从普通建议提升为明确的“必须 / 不得”，同时放进适用方法的执行前检查和交付前检查。
4. 增加一个能够被搜索或验收的具体检查动作，例如朗读、搜索讲师视角词、逐个知识点核对媒体、按资源清单回读；不能只写“注意加强”。
5. 检查默认调用链是否遗漏了对应文件。遗漏时先修复入口，而不是继续给规则加字。

只有来自不同课程、不同版本或修改后仍复现的问题才算重复失误；同一次反馈里的重复表述不累计。规则经过加强后仍保留原项目复盘，作为它为什么升级为硬门槛的证据。

## 写入规则

- 课程开始前形成的通用方法进入负责该问题的唯一活动文件，并由入口文件统一路由。
- 真实授课后的反馈、失败和修正先进入归属已确认的项目修订；缺项目证据时进入待归属区，再按上面的转化流程更新通用活动方法。备课修改与真实授课反馈分开登记。
- 某个具体课程或社群的事实留在 `projects/`。
- 自媒体表达方法不写入本目录。
- 外部中文表达语料进入 `brain/ai-expression/chinese-datasets/` 登记；专业课程案例、工具资料和建委培训反馈进入其真实主题与项目，均保存来源和使用边界。不得因为要提炼培训经验就把所有外部资料塞进表达语料库。任何原始资料都不能未经适用性判断直接成为通用规则。
