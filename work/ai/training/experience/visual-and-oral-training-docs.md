# 培训类飞书文档的可视化与口语化

> 状态：当前有效
> 口径确认：2026-09-06
> 适用范围：面向学员阅读或跟着操作的 AI 培训文章、课件和飞书知识库内容

## 一、默认不是纯文字文档

培训类飞书文档不能只把一篇文章铺成连续段落。文字负责讲清背景、原因、步骤和判断；图片、视频、高亮块、表格或思维导图只在能补充新信息时使用。

可视化不是装饰，也不是把文字换一种颜色。每一个可视化元素都要回答一个具体问题：

| 学员要理解的问题 | 更合适的呈现方式 |
|---|---|
| 前后到底发生了什么变化 | 原图与成片、操作前后截图或视频 |
| 这几种方式怎样选择 | 只列关键差异的比较表 |
| 这一步要特别注意什么 | 少量高亮块，写清边界或风险 |
| 多个步骤怎样连接 | 流程图、编号流程或简短结构图 |
| 一组内容怎样分层 | 思维导图或层级结构；仅在层级本身需要理解时使用 |

不能回答具体问题的图、表、思维导图和装饰性高亮块不进入正文。一个案例已经通过图片和视频证明的内容，文字只补充“怎么看”和“为什么”，不再把画面逐字复述一遍。

## 二、媒体必须放在它解释的地方

案例图片放在案例说明附近，视频紧跟在提示词或操作结果之后。先说明学员看什么，再放媒体；媒体后补充验收要点。不能把所有图片和视频集中到文末，也不能只留下静态截图而删掉承载时间变化的视频。

当用户明确要求保留原始案例时，先列出“案例名称、输入媒体、输出媒体、提示词”四项，再逐项核对。更新文字时不得删除或重建这些媒体块。需要改写结构时使用局部 block 更新，不使用会清空图片、视频和评论的整篇覆盖。

## 三、培训文章使用口语化表达

面向学员的正文要像讲师在课堂上解释问题，读者能顺着读下去，也能照着做。开头从学员熟悉的场景进入：以前怎么做、哪里麻烦、现在多了什么办法。不要一上来写“本文将系统介绍”“综上所述”或连续堆抽象概念。

口语化不是堆“其实、然后、就是说”，而是让每句话都有明确动作和对象：谁准备什么、AI 做什么、画面发生什么、学员怎样判断。长句包含多个判断时拆开；书面化连接词能用自然停顿替代时就替代。

## 四、文章与课堂主文档的结构

推荐顺序是：真实场景 → 过去的卡点 → 结果对比 → 学员要准备的材料 → 一次完整操作 → 结果验收 → 修改反馈 → 可复用的方法。

每一节都要让学员新看见一种变化、学会一个动作，或者获得一个选择标准。只用于显得“内容丰满”的背景、术语和排比句删除；技术细节只有在会影响操作、费用、风险或验收时才展开。

## 五、提示词与可视化要互相对应

提示词写清任务目标、输入、必须保留的内容、允许变化的范围、执行顺序、输出和验收方式。提示词中要求“保留原图文字”，正文就要在结果检查处提醒学员检查文字；提示词中要求“镜头从特写拉远”，视频后就要让学员观察这段镜头变化。

同一案例中，图片说明设计长什么样，视频说明它怎样动，表格说明不同制作方式怎样选，高亮块说明哪些素材不能交给 AI 猜。四者各自增加信息，不互相复制。

## 六、交付前检查

- [ ] 正文不是连续纯文字，且每个可视化元素都有明确问题和位置。
- [ ] 原始图片、视频、提示词和案例顺序与用户确认的一致。
- [ ] 媒体前有观看目标，媒体后有验收判断。
- [ ] 表格只保留真正影响选择的差异。
- [ ] 高亮块只提醒关键边界，不把普通段落全部做成高亮块。
- [ ] 思维导图只在需要理解层级或分支关系时使用。
- [ ] 正文按自然讲解来写，少用报告式和论文式连接。
- [ ] 每一节都能回答学员看完后会做什么、选择什么或检查什么。
- [ ] 修改飞书文档时使用局部 block 更新，未使用整篇覆盖。
