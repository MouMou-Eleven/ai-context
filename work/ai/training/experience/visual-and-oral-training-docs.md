# AI 培训课堂文档的可视化与口语化

> 状态：当前有效的通用培训方法
> 口径确认：2026-09-07
> 适用范围：讲师现场使用、学员同时可见的 AI 培训课件和飞书课堂主文档
> 高频强化来源：会员社群第 4—6 课、秒哒进阶课的真实修改与直播复盘

## 一、先确认这不是一篇普通文章

课堂主文档一直跟随讲师向前推进。正文要能直接讲，画面要能帮助学员当场理解，不能按公众号文章、项目报告或技术手册的方式连续铺文字。

面向学员的栏目直接说明“重点需要关注什么、这一步怎么做、怎样判断结果”，不出现“课堂要看什么、讲师这里演示、这一部分讲多久”等备课视角。完整的交付物边界见 [`teaching-and-course-design.md`](./teaching-and-course-design.md)。

## 二、每次都要做整篇可视化审计

AI 培训课堂文档默认不是纯文字。开始写正文前，先按核心知识点建立媒体清单；完成后再逐节检查是否还有只能靠想象、关系不清或没有真实证据的内容。不能等建委逐张指出后才补图。

可视化不是装饰，也不是把文字换一种颜色。每个元素都要回答“它让学员多看懂了什么”：

| 要呈现的内容 | 优先形式 | 不能怎样替代 |
|---|---|---|
| 真实软件界面、按钮、配置路径、价格和操作结果 | 官方截图或实际操作截图 | 不用 AI 仿造界面，不用逻辑图猜按钮位置 |
| 动效、交互、操作过程和随时间发生的变化 | 视频、动图或可运行案例 | 不把核心过程全部压成一张静态截图 |
| 步骤关系、角色关系、机制、分支和两条流程对比 | 流程图、逻辑图或并行逻辑图 | 不用一张平台截图代替抽象关系 |
| 抽象概念、生活场景、使用前后结果和没有现成画面的反差 | AI 生成图片 | 不重复正文，不复制真实平台截图，不伪造精确 UI |
| 三个以上对象的关键差别、选择依据或字段映射 | 简洁比较表 | 不把已经讲过的正文再排成一张表 |
| 特别容易误操作的边界或风险 | 少量高亮块 | 不把普通信息都包装成重点提示 |
| 一组内容的层级和分支 | 思维导图或层级结构图 | 层级本身不重要时不强行使用 |

一张图已经证明的内容，正文补充“怎么看、为什么、怎样判断”，不逐字复述画面。同一个知识点使用多种媒体时，每一种都必须增加新信息。

## 三、生图是必备手段，但不能生成重复画面

当知识点需要呈现抽象关系、生活场景、角色协作、工作机制、前后反差或结果感受，而真实截图无法表达时，必须主动安排 AI 生图。完整课程不能因为已有一些平台截图，就跳过对这些知识点的画面设计。

生图前先写清它要补充的唯一理解点。生成后检查：

1. 是否只是把正文标题和要点排进图片；
2. 是否重复了真实截图已经呈现的界面；
3. 是否与本节其他生成图表达同一个意思；
4. 画面中的对象、关系、动作和文字是否准确；
5. 去掉这张图后，学员是否真的会少理解一个画面、关系或变化。

如果前四项出现问题，图片应重做；第五项为否时，不放入正文。生图是补充画面感和理解，不是完成图片数量。

## 四、媒体必须放在它解释的地方

案例图片放在对应案例附近，步骤截图放在实际动作之后，视频紧跟提示词或操作结果，流程图放在关系第一次需要解释的位置。先告诉学员看什么，再给出媒体；媒体后补充结果判断或验收要点。

不能把所有图片和视频集中到文末，不能让图片与文字错位，也不能把编辑器、会员中心、个人面板等不同页面的截图放到不对应的章节。对流程中连续出现的多个确认页面，应按真实操作顺序完整呈现，不只保留第一张或最后一张。

## 五、培训正文必须能够自然讲出来

面向学员的正文像建委在课堂上解释问题。开头从学员熟悉的场景或上一节已经完成的事情进入：过去怎么做、哪里麻烦、现在改变了哪一步、学完以后怎样使用或判断。

不要一上来写“本文将系统介绍”“综上所述”“在数字化浪潮下”，也不要用“换一种方式、放回一个平台、不要死记旧数字”等生硬概括代替真实的承接关系。标题、问题和回答要站在同一个角度，不能提出一个问题后回答另一件相关但不同的事。

口语化不是堆“其实、然后、就是说”。每句话都要有明确动作和对象：谁准备什么、AI 做什么、画面发生什么、学员怎样判断。长句包含多个判断时拆开；朗读时正常授课不会说的句子直接改写。

## 六、提示词、文字和媒体要互相对应

提示词写清任务目标、输入、必须保留的内容、允许变化的范围、执行顺序、输出和验收方式。提示词中要求“保留原图文字”，正文就在结果检查处提醒学员核对文字；提示词中要求某段镜头变化，视频后就让学员观察这段变化。

同一案例中，截图说明从哪里操作，生成图片说明抽象结果长什么样，视频说明它怎样动，逻辑图说明各步骤怎样连接，表格说明不同方式怎样选。不能只把最容易迁移的一种媒体保留下来。

## 七、修改既有飞书文档时必须保护现场资产

修改前先盘点现有标题、段落、截图、视频、文件、链接、评论、红色重点标注和其他有效格式。用户明确要求保留的案例，再按“案例名称、输入、输出、提示词、媒体形式”建立清单。

更新时遵守以下规则：

- 优先局部 block 修改，不使用整篇覆盖。
- 不删除、重建或随意移动已经确认的图片、视频、附件和评论。
- 保留建委已经完成的红色重点标注和有效格式；建委负责新增标红，AI 不自行重新着色。
- 补充图片时插入对应知识点附近，不能因为方便就统一堆到章节末尾。
- 删除内容后重新核对标题编号、列表连续性、图片顺序、链接和残留媒体，不能只删标题或正文。
- 修改完成后按照修改前的资源清单逐项回读，确认数量、位置和用途仍然一致。

## 八、重复错误按硬门槛加强

书面化、纯文字、讲师视角混入学员稿、媒体错位和修改时丢失资源，已经在多轮真实课程中复现。它们不再是“有条件参考”的建议，而是每次飞书课堂文档都必须执行的检查。

以后复盘再次出现其中任何一项时，不在本文件追加同义段落。按 [`README.md`](./README.md) 的强化机制补充新的实战来源，检查默认调用是否遗漏，并把可执行检查前移。当前高频失误统一在 [`jianwei-training-style.md`](./jianwei-training-style.md) 查看。

## 九、交付前检查

- [ ] 已逐个核心知识点完成可视化审计，不是连续纯文字。
- [ ] 每张截图、视频、逻辑图、表格和生成图片都有明确作用和对应位置。
- [ ] 真实界面使用真实截图，流程关系使用逻辑图，抽象场景使用生图，动态结果保留视频或可运行证据。
- [ ] 生成图片没有重复正文、真实截图或其他生成图片，并且补充了新的画面感。
- [ ] 正文能够自然朗读，没有文章式、汇报式和讲师内部表达。
- [ ] 每一节都能回答学员看完后会做什么、理解什么、选择什么或检查什么。
- [ ] 原始图片、视频、附件、提示词、评论、红色标注和案例顺序完整保留。
- [ ] 媒体前有观看目标，媒体后有结果或验收判断。
- [ ] 表格只保留真正影响理解和选择的差异，高亮块只提醒关键边界。
- [ ] 局部修改后已复核标题编号、列表、链接、媒体位置和残留内容。
