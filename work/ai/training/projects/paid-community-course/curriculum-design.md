## 当前课程边界

产品名、价格、权益、目标人群和总定位统一以 [`README.md`](./README.md) 为准；已发布课程的最终名称、链接和状态统一以 [`course-materials-index.md`](./course-materials-index.md) 为准；招生表达统一进入 [`operations-playbook.md`](./operations-playbook.md)。本文件只维护第一季度课程结构和每节课的教学内容。

课程默认面向非程序员。第一课完整回答 AI 编程与不同职业的关系，再进入工具地图；后续系列课不重复职业案例和课程总价值，只讲本节独有的痛点、重要性以及与上一节、下一节的关系。单场独立分享没有前课铺垫时，再补足必要背景。

## 第一季度课程主线：AI 编程系统实战

第一季度课程不是“用 AI 写一个 HTML 页面就结束”。HTML 只是很浅的一步，真正能解决现实问题的是完整链路：需求描述、工具选择、环境搭建、代码生成、问题修复、部署上线、链接访问、数据能力、自动化运行和经验沉淀。

这一标题用于课程内部结构和详细目录。面向招生用户时，先从项目 README 读取当前季度对外主题，再展开不同职业能完成的具体结果；本文件不维护第二份销售标题。

第一季度课程要从浅到深跑通一条解决问题链路：

**问题定义 → 工具选择 → 环境准备 → AI 生成 → 人来判断 → 修复问题 → 部署上线 → 收集反馈 → 沉淀经验。**

## 学员基础资料表达规则

当前仍按 12 节课程保存整体方向，哪些课程已经确认、哪些仍可调整以项目 README 为准。课堂主文档不能直接照搬内部技术大纲；面向非程序员时，先讲职业场景、用户动作和能得到的结果，再解释对应工具和高频词。内部大纲里的 IDE、CLI、DNS、SSL、API 等名称，必须在学员已经知道它处于哪一步之后再出现，并立即说明它会影响什么。

第一节先回答“AI 已经会写代码，为什么人还要学”，讲清 AI 可以生成初稿，人仍要定义需求、提供真实业务信息、判断结果和完成验收。后续系列课程只建立本节新增的学习理由。开发前、开发中、上线前、上线后的四阶段结构只用于《AI时代技术词典》这篇综合资料；其他课程根据自己的目标和概念依赖组织，不复制固定章节。

课程资料只收录高频且影响判断、沟通或验收的技术词。每个词说明它在哪一步、解决什么问题、忽略后会发生什么、怎样让 AI 处理以及怎样验证；不再设置“当前不必学习”的负面清单，也不以传统编程知识覆盖面衡量资料是否完整。

## 12 节课程安排

### 第 1 节：先知道 AI 编程能帮你做什么，再看懂工具地图

主题：AI 编程和不同职业有什么关系，普通人应该从哪开始。

这一节不做安装，不讲 API 细节，重点解决新手的认知混乱。开场不要先讲工具分类，而要先讲“AI 编程和我有什么关系”。

开场必须先讲清楚：AI 编程不是让普通人转行当程序员，而是让每个职业的人都多一种把问题做成工具的能力。

| 人群 | 可以先讲的案例 |
|---|---|
| 老师 | 互动课件、问答游戏、点名小程序、排座位工具、作文批改辅助页 |
| 设计师 | 灵感收集工具、素材标签管理器、个人作品集网站、图片尺寸批处理工具 |
| 文员 / 行政 | 文档批量改名、表格字段整理、文件归档、数据脱敏、批量格式转换 |
| 财务 | 发票批量重命名与分类、报销材料检查清单、发票台账辅助录入、费用分类看板 |
| 自媒体 / 写作者 | 资料领取页、选题库、标题测试器、评论关键词整理、课程报名页 |
| 剪辑师 | 素材整理器、口播稿分镜表、字幕文案清洗工具、客户反馈收集页 |
| 导游 / 个体创业者 | 行程生成器、景点讲解页、客户登记页、报价计算器、游客反馈页 |

必须讲清楚 5 类 AI 编程工具：

| 类型 | 怎么理解 | 代表工具 | 适合谁 |
|---|---|---|---|
| 对话式 AI | 打开网页直接聊天，让 AI 生成代码或解释问题 | DeepSeek、豆包、ChatGPT、Kimi、Claude、Gemini | 完全零基础，先体验“用说话生成代码”的人 |
| AI 代码编辑器 | 自带 AI 能力的完整代码编辑软件，能理解项目文件 | Cursor、Windsurf、Trae、Qoder、Kiro、Zed | 想认真做项目、愿意安装软件的人 |
| IDE 插件/扩展 | 给传统编辑器装 AI 插件，相当于给原有开发环境加外挂 | GitHub Copilot、Cline、Continue.dev、Augment、Tabnine、Amazon Q Developer | 已经使用 VS Code、JetBrains 等开发工具的人 |
| 网页版 AI 编程 | 打开浏览器描述需求，直接生成项目、预览甚至部署 | 秒哒、豆包 AI 编程、Coze 编程、Bolt.new、v0.dev、Lovable、Replit | 想最快看到成果、不想先装环境的人 |
| 命令行工具 | 在终端里让 AI 读文件、改代码、跑测试、修 Bug | Claude Code、Codex CLI、Gemini CLI、Aider、Droid | 有一定基础，想追求效率和自动化的人 |

关键认知：

- AI 编程不是背语法，而是“把需求说清楚，让 AI 执行，再验证结果”。
- 工具不是越多越好，而是不同阶段用不同工具。
- 代码不是目的，作品和问题解决才是目的。
- 环境、GitHub、Node.js、Python、终端不是为了吓人，而是让作品真正跑起来的基础设施。
- 渐进式披露不是一个生硬名词，而是一种降低理解压力的架构：先给地图，再按层级展开。后续做个人知识库、课程资料库、项目文件夹，也可以借鉴这种结构。

课堂落点：让学员知道自己不是“要从代码语法开始”，而是先知道 AI 编程能如何服务自己的职业，再理解工具类型、学习顺序和未来能做什么。

### 第 2 节：把电脑变成 AI 工作台，新手最容易卡住的环境一次讲清

主题：把电脑变成能和 AI 一起工作的工作台。

讲解顺序：

1. 浏览器与本地文件：为什么 HTML 能直接打开，复杂项目却不能双击运行。
2. VS Code：怎么看文件夹、怎么看 HTML/CSS/JS、怎么看项目结构。
3. Node.js：为什么现代网页项目需要它。
4. Python：为什么自动化、脚本、数据处理经常会用到它。
5. Git：为什么 AI 改代码前一定要会保存版本。
6. GitHub：怎么注册、搜索项目、看 README、下载项目。
7. Codex / Claude Code / 龙虾 / cc-switch / Codex++：先知道它们解决什么，再安装。

课堂落点：让学员知道工具不是乱装，环境是未来所有项目能跑起来的工作台。

### 第 3 节：AI 时代的协作心法：从 Prompt 到 Skill、MCP、CLI、API 与 Harness

主题：先讲清楚为什么同样使用 AI，有人仍停留在一句话问答，有人已经能让 AI 读取真实资料、连接工具、执行操作并检查结果；再通过同一任务的传统做法、AI 做法和结果对比，让学员看懂这些概念怎样共同组成一条完整的 AI 协作链路。

开场必须建立三层认识：

- 当前痛点：只给 AI 一句模糊要求时，AI 只能根据有限信息猜，也无法自动获得项目资料、外部工具和电脑执行能力。
- 学习变化：Prompt 与 Context 负责信息，Skill 负责方法，MCP 与 API 负责连接，CLI 负责执行，Harness 负责组织；组合以后，AI 的使用才从零散问答走向系统协作。
- 后续用途：网页开发、UI 组件、数据库、部署和自动化都会反复使用这些概念，本节先建立后续课程共同使用的地图。

重点：

- CLI：用创建文件夹做三次对比，依次展示鼠标点击、手工输入 `mkdir` / `cd`、AI 根据自然语言自动执行并检查结果。
- Prompt 与 Context：用模糊文字、截图标注和操作视频比较输入效果；解释上下文窗口和压缩时，强调压缩会总结旧信息但不会取消窗口上限，也没有固定的能力折损比例。
- Skill：先说明它是给 AI 的工作说明书，再展示基本结构、官方与社区仓库、通过仓库链接或 ZIP 安装，以及 ChatGPT 的 `@` 和 Codex 的 `$` / `/skills` 调用方式。
- MCP：按“是什么 → 去哪里找 → 怎样接入 → 怎样验证”展开；用 shadcn/ui MCP 做页面前后对比，用报名信息表格和 Supabase MCP 解释数据库，只呈现学员能够直接看见的表格、字段和操作结果。
- API：在 MCP 之后首次引入；并排打开 GitHub 普通网页和 API 地址，让学员直接看到给人看的页面与给程序读取的数据有什么不同，再说明 CLI、API、MCP 的关系。
- Harness：用普通聊天工具和 Codex 执行同一任务的差别推出概念，再比较 Codex、OpenClaw 和 DeepSeek Harness 的产品位置、优势和使用门槛。
- 最后用一个带报名功能的课程页面串联七个概念，不再设置学习顺序长列表和标准答案式自检。

课堂落点：学员能够判断一个 AI 任务究竟缺少信息、上下文、做事方法、外部连接、执行入口还是整体组织，并能根据屏幕上的操作和结果说明每个概念改变了哪一步、后续什么时候会用到它。

### 第 4 节：第一次做出能发给别人的网页

主题：用 AI 写一个网页，并让别人真的能打开。

流程：

1. 用 DeepSeek / 豆包生成一个单文件 HTML 页面。
2. 本地打开，看效果。
3. 讲清楚 HTML、CSS、JavaScript 分别负责什么。
4. 解释为什么本地能打开，不代表别人能打开。
5. 使用团队自研 HTML 静态网页托管平台上传页面。
6. 生成公开链接。
7. 发到群里展示。

可选案例：

- 个人主页。
- 简历作品页。
- 课程资料页。
- 小游戏。
- PPT 风格展示页。

课堂落点：让学员获得第一次“我真的做出了一个链接”的感受。

### 第 5 节：网页背后的常识：图床、服务器、域名、备案到底在干什么

主题：承接上一节的静态网页，在下一节使用秒哒做带数据工具前，看懂网页背后分别负责文件、数据和持续运行的角色。

重点：

- 这是 12 节连续课程，第1课已经讲过“不是培养程序员”和职业应用场景；本节开场不重复总定位，也不提前抛出地域、实例规格和带宽等名词。用“电子菜单只能看，外卖工具会记住操作”承接第4课并引出第6课。
- 用本机路径和公网地址的 HTML 对比解释图床与对象存储；再用机制图说明对象存储保存图片源文件，数据库保存文件信息和链接。
- 以腾讯云 COS 购买页讲清地域、标准存储、低频存储、外网下行流量、CDN 回源流量和资源包规格。
- 先分别讲清数据库和服务器，再用一次点外卖串联页面、服务器、数据库和对象存储；不让总图早于前置概念。
- 数据库购买页先筛选普通人当前需要理解的选项，再分别说明数据库类型、容量、连接数和备份会影响哪一种使用或判断；不为了参数完整度把整张购买页逐项讲一遍。
- 服务器参数根据学员真正关心的问题选择讲法：CPU / 内存说明配置不足时网站和处理任务会出现什么现象，公网带宽说明用户访问和下载怎样受影响，月流量说明额度及用完后的处理方式；内网带宽和 PPS 只有会影响当前项目判断时才进入主讲。
- 静态网页与带数据工具不再用大段文字表格，改用“只能浏览的电子菜单”和“可以下单的外卖工具”做视觉对比；完整技术结构图后置为复习材料。
- 保留对象存储、服务器、数据库、域名、SSL 和备案的官方购买 / 操作入口；事实与截图严格核验，不用合同式免责声明占据课堂主线。
- 结尾说明秒哒已经把服务器、数据库和对象存储托管起来，但这些角色没有消失；学员会因此更容易理解数据和文件存放位置，也更容易让 AI 检查报错。

课堂落点：学员能从一次熟悉操作判断哪些内容只负责展示、哪些操作需要被处理和记住、哪些文件需要长期保存；打开购买页时能够分辨哪些参数与自己的项目有关、它们会改变什么，再让 AI 辅助比较并由自己决定。

### 第 6 节：从展示页到小工具：用秒哒做一个带数据能力的产品

主题：从展示页进入小工具：用秒哒做一个带数据能力的产品。

重点：

- 秒哒是真正的网站全栈开发平台，把前端、后端、数据库、文件存储、部署和运维等能力封装成普通人更容易理解和使用的一条龙服务。
- 学员不需要自行搭建每一层基础设施，也能够更快做出带表单、数据和后台能力的小工具；这些全栈角色仍然存在，只是平台把操作入口变简单了。
- PRD 的普通人模板：用户是谁、痛点是什么、页面有哪些、每页能做什么、要保存什么数据、什么结果算完成。
- 前端和后端是什么。
- 做一个资料领取页 / 报名登记页 / 客户预约页。

课堂落点：让学员从“做一个页面”进入“做一个有数据能力的小产品”。

### 第 7 节：报错不可怕，学会把问题描述到 AI 能修

主题：不怕报错：学会把问题描述到 AI 能修。

重点：

- 控制台是什么，怎么打开。
- 红色报错怎么看。
- 怎么截图、录屏、复制报错。
- 怎么把问题描述给 AI。
- 用 Gemini 等多模态模型分析录屏，弥补非程序员表达不精准的问题。
- 什么时候继续让秒哒改，什么时候换 Codex / Claude Code 介入。

可选跟做动作：用下面模板整理一个自己遇到过的 Bug 或修改需求。

```text
我想实现：
现在现象：
我点了哪里：
控制台报错：
我已经试过：
我希望改成：
```

课堂落点：让学员知道遇到报错不是失败，而是进入 AI 编程真实工作流。

### 第 8 节：别再乱选工具：Codex、Claude Code、龙虾各做各的事

主题：Codex、Claude Code、龙虾怎么选，怎么配合。

重点：

- Codex 适合：读项目、改文件、写文档、跑命令、沉淀仓库上下文。
- Claude Code 适合：终端内快速修改、排错、自动化和代码协作。
- 龙虾适合：配置模型、接入微信 / 飞书等日常入口，形成更贴近工作流的使用方式。
- VS Code 里的 Claude Code 怎么使用。
- README、AGENTS.md、需求文档、资料目录怎么影响 AI 输出质量。

课堂落点：让学员从“追新工具”转向“按场景选工具”。

### 第 9 节：把重复工作变成工具：浏览器插件和工作流入口

主题：把 AI 编程能力放进日常工作场景。

重点：

- 浏览器插件是什么。
- 用 Codex 做一个简单插件：网页信息提取、复制格式化、页面标记、资料收集。
- 微信 / 飞书入口为什么重要。
- 什么样的重复动作值得工具化。

课堂落点：让学员把“AI 编程”跟自己的真实工作动作连接起来。

### 第 10 节：让工具自己干活：定时任务、API 和素材自动化

主题：让工具自己跑起来：定时任务、接口调用、素材提取。

API 不放到第一节讲，而是在学员已经理解网页、工具、工作流后再讲。

重点：

- API 是系统之间互相调用能力。
- 自动化任务是定时、批量、触发、输出。
- 用 Codex 设计一个自动任务。
- 案例：公众号视频信息提取、抖音视频信息整理、素材文案抓取。
- 规则边界：版权、平台规则、隐私、接口限制。

课堂落点：让学员知道 AI 编程不只是“一次生成”，还可以变成持续运行的流程。

### 第 11 节：做一个正式网站：代码、数据库、部署、域名完整走一遍

主题：从小工具到正式网站：GitHub + Supabase + Vercel。

重点：

- GitHub 管代码。
- Supabase 管数据。
- Vercel 做部署。
- 邮箱登录、手机号登录、验证码服务分别意味着什么。
- 数据库里的表、字段、权限是什么。
- 传统数据库购买时 CPU、内存、带宽代表什么。
- 域名、SSL、DNS 解析怎么接上。
- 用一个真实案例带大家跑：个人网站 / 公司官网 / 课程资料站。

课堂落点：让学员第一次看懂“正式网站”背后的完整链路。

### 第 12 节：作品上线后才开始值钱：SEO、反馈、迭代和个人知识库

主题：作品上线后，怎么让它被看见、被使用、被继续迭代。

重点：

- SEO 是什么。
- 标题、描述、页面结构、加载速度为什么影响搜索。
- 分享卡片和 Open Graph 为什么影响点击。
- 数据统计为什么重要。
- 用户反馈怎么收集。
- 为什么要把经验沉淀到 GitHub / GitLab / 飞书知识库。
- 建立个人 AI 协作上下文：README 做入口，项目资料分类，重要变化写修订记录。
- AI 时代的新范式：你的经验越沉淀，AI 越能读懂你；模型能力和上下文能力也会不断升级，长期看这是个人能力的复利。

课堂落点：让学员知道 AI 编程最终不是一两个工具，而是一套长期增强个人能力的工作方式。

## 交付节奏

每周直播不要强依赖作业点评。作业提交是概率事件，不能作为直播结构成立的前提。单节时长按建委当前任务确定，不在仓库设置固定的 90 分钟或 120 分钟模板。课程可以根据内容从下面几个阶段中灵活组织：

| 阶段 | 内容 |
|---|---|
| 场景切入 | 用真实场景说明本节独有的问题和重要性；系列课同时承接前一节 |
| 建立认知 | 宏观认知可以整体架构先行；具体实操先说明今天要完成的结果和必要前置 |
| 主体讲解和演示 | 边讲边展示动作、变化和结果，技术概念按前置关系出现 |
| 案例复盘 | 展示结果、拆过程、讲真实坑点和判断方法 |
| 互动答疑 | 承接新手问题和直播间提问 |
| 课程收束 | 总结本节新增能力、提示资料位置并承接下一节 |

可以提供“可选跟做动作”，但不要把课程交付建立在强制作业上。
