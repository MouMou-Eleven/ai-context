# 2026-08-23：第 4 课可视化与案例交付修订

## 反馈来源

第 4 课“用 AI 做出并发布一个静态网页”初稿虽然包含 HTML、CSS、JavaScript、部署和 GitHub Pages，但仍有明显的 AI 式标题、书面化表达、概念表格和缺少真实案例的问题。建委要求课程回到口语化授课表达，并明确指出：不是只补固定三张图片，而是整节课中所有适合用画面解释的知识点都要补充可视化。

## 旧版本的问题

- 使用“这节课最后要留下的判断”“你真正要关心什么”“出现问题时，从现象反推原因”等模板化标题。
- 重复强调“这不是一节前端语法课”“不需要成为程序员”，没有按建委的口语表达讲清 AI 时代人的角色变化。
- HTML 盒子、浏览器渲染和网页文件组成使用表格、思维导图或定义解释，学员看不到真实机制。
- CSS 与 JavaScript 只有文字说明，没有同一页面逐步加入结构、样式和交互后的前后变化。
- 提到个人简介、GitHub Pages 和坦克大战，但没有交付可以运行、修改和上传的项目文件。
- GitHub Pages 缺少二次修改后保持原链接更新的操作，也没有写清入口文件、发布目录、大小写、相对路径和网页上传限制。
- 混入 Elements、Sources 等对普通学员过早的专业调试面板，以及平台容量、审核状态等项目介绍式内容。

## 新口径

- AI 培训内容默认使用自然、可朗读的口语表达，不把文章式总结和模板化判断当作授课标题。
- 抽象概念按知识点逐项判断是否需要可视化，不限定“补几张”。图片必须呈现机制、关系或前后变化，不能只重复概念名称。
- 网页文件、浏览器渲染、HTML 盒子、CSS 前后对比、JavaScript 状态、静态网页边界、PRD、单文件/多文件、部署、GitHub 更新和常见问题均使用对应画面解释。
- 结构、路径和交互优先使用代码原生可视化：先制作真实 HTML/CSS/JavaScript 页面，再从实际运行状态截图。
- 课程案例必须交付可运行文件。本次交付三阶段 HTML/CSS/JavaScript 演示、GitHub Pages 个人简介案例和多文件坦克大战，并在飞书正文附可下载案例包。
- GitHub Pages 同时讲第一次发布与二次更新：网页替换同名文件或本地 `git add / commit / push` 后，发布分支重新构建，原链接保持不变。
- 常见问题章节使用“你可能会出现以下问题”，并把页面表现、GitHub 要求、具体原因和处理方式放在一起。
