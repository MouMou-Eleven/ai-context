# 培训资料的归属与更新

> 当前规则：2026-09-12。AI 在收录、移动、更新或查询课程归属时读取；普通备课不必加载全部修订历史。

## 先识别三个对象

| 对象 | 记录什么 | 不能推断什么 |
|---|---|---|
| 培训项目/产品 | 社群、已确认的企业培训项目、图书馆项目、夜校系列等；项目标识、受众、目标、权益和负责人 | 使用 AI、在飞书写课件、标题含“第几课”不能推定为会员社群 |
| 授课场次 | 所属项目、客户/主办方、日期、受众、实际使用的资料版本、反馈来源 | 资料发布不代表已授课；同一课程在不同场次使用，不等于同一个课程系列 |
| 课程资料 | 稳定主题标识、标题、正文链接、用途、版本、归属证据、核验时间 | 课号只在已确认的课程系列内有效，不是全培训的唯一编号 |

同一资料用于多个项目时只保留一个主维护位置；各场次引用它，并写明采用版本与项目差异。培训经验按具体能力提炼，一条方法可以引用多个项目证据，不能把来源都改成社群。

## 归属证据

1. 建委当前明确确认优先。
2. 其次核对明确写出产品/主办方的原需求、已发布课程介绍或具体授课记录，保存出处与日期。
3. 仓库历史总结只能证明“曾这样记录”；如果已发现同批混课、同号异课或证据不足，不能用同一批总结互相证明。
4. 无法确认时进入 [待归属区](./materials/pending-attribution/README.md)。保留标题、链接、内容和复盘，撤销无依据的社群/客户断言；不阻止继续整理或提炼适用方法。
5. 已确认是外出培训，但客户、类别、系列或场次未知时，保存在 [external-training](./projects/external-training/README.md) 对应主题下，未知字段明确写“待确认”。不得猜成企业、图书馆或夜校中的任何一种。

仅当缺少归属会影响具体交付、权益、客户信息或课程承接时，向建委提出所需的最小问题；不为了整理资料重复要求批准。

## 状态分开维护

- **规划状态**：设想 / 规划中 / 已确认安排 / 取消。附确认来源；大纲中的章节不自动成为已发布资料。
- **资料状态**：草稿 / 修改中 / 已写入并回读 / 待复核。正文链接、revision 和最近核验日期独立记录；旧记录可注明“原记录已发布”，不能把今天的整理日期写成今天重新打开正文的日期。
- **授课状态**：待确认 / 已排期 / 已授课 / 取消。写具体场次和授课证据；只有备课或发布记录时不得填“已授课”。

计划、资料、授课分别回答不同问题。待归属资料不能进入社群或任何具体项目的当前进度。

## AI 自动完成的写入流程

1. 读取本页与目标项目/资料的最近一层 README，搜索现有主题、链接和重复规则。
2. 判定主归属和证据。正文在飞书时，GitHub 只保存长期索引、版本、来源和方法；新的归属不明项先落待归属区。
3. 更新唯一正文或索引条目；同资料多用途用引用，不再建另一份全文。保存业务类型、受众、场景、使用条件、资料版本和核验来源。
4. 更新最近一层 README；新增项目入口时更新 projects，新增可复用方法时更新 experience。只有入口改变时才更新更上层路由。
5. 分别同步受影响的课程规划、资料状态和授课状态。修复旧链接、错误来源标签与从属关系；重要口径变化在所属项目修订中记录原因和新旧差异。
6. 复盘必须给出“仅保留证据 / 新增方法 / 修订已有方法 / 强化重复失误 / 信息不足暂不泛化”的处理结论；能复用的经验写清触发、输入、动作、验收、限制和来源，方法入口同步更新。
7. 按仓库维护规则运行链接、索引、目录与路由检查；用一句自然任务验证能从入口找到该资料或方法。提交和远端核验按根级规则执行。

这些同步由 AI 负责，不要求建委记住文件名或提醒“更新 README”。建委只需说明要沉淀的内容和大致领域；AI 应利用已有证据完成能确定的归类。
