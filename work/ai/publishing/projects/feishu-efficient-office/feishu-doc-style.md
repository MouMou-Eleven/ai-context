# 本书飞书审稿文档样式参考

> 仅在本书审稿文档需要飞书组件和视觉安排时按需读取。历史通用偏好不能把所有飞书任务路由到本书，也不能覆盖当前出版规则与具体章节编辑稿。

**记录时间**：2026年4月5日凌晨首次确认，2026年6月5日再次强调并细化

## 核心原则

用户在创建或改写飞书文档时，明确偏好 **图文并茂、结构清晰、视觉节奏强** 的呈现方式，拒绝纯文字堆砌。文档应该像一个"产品"，而不是草稿。

## 具体要求

### 1. 必须可视化
- 优先使用 **Mermaid 思维导图、流程图、对比表格、分栏布局**
- 关系、流程和对比在图表确实有助理解时使用可视化，避免与正文重复
- 拒绝纯文字堆砌

### 2. 彩色 callout 高亮块
- 用 callout 突出核心结论、注意事项、操作提示、风险提醒、关键信息
- 颜色要有区分：
  - 🟨 警告用黄/橙
  - 🟩 成功用绿
  - 🟦 信息用蓝
  - 🟥 错误用红

### 3. 代码块/提示词块
- 涉及 Prompt、命令、步骤脚本、API 调用时，必须用代码块或清晰块状结构承载
- 不能混在正文段落中

### 4. 标杆参考
飞书 AIGC 知识库 → 编程辅助类 → OpenClaw → 应用案例 →《OpenClaw 实战使用场景全记录》

这是视觉风格和信息架构的黄金标准。

### 5. 结尾写时间
- 内部审稿和素材清单需要时间记录时，使用真实生成/更新时间；出版正文不自动追加时间落款
- 格式示例：
  - "2026年4月5日凌晨3:33"
  - "2026年6月5日下午2:15"
- 实际写作时取实时值，并按中文时段表达（凌晨/早晨/上午/中午/下午/傍晚/晚上/深夜）

### 6. 整体感
- 文档应像一个"产品"，不是草稿
- 默认追求图文并茂、结构清晰、视觉节奏强
- 每个 section 应该有视觉呼吸感，避免大段文字堆砌

## 默认策略

**触发条件**：本书内部审稿或素材清单需要视觉编排；普通飞书文档按其业务主题读取对应规则。

**执行要求**：
- 按任务选用此处组件；当前出版短规则、章节编辑稿和Word交稿要求优先
- 若是正式出版书稿正文，则在保持出版规范的前提下，仍要尽量保留可视化结构和阅读节奏

## 为什么这样做

用户对飞书文档的审美和交付标准很高，认为视觉结构是内容的一部分。纯文字堆砌会让文档显得敷衍，尤其是在飞书这种本身支持丰富 block 的平台里。

## 如何应用

做飞书文档前先规划视觉结构：
1. **开头** callout — 点明文档目的/核心信息
2. **章节间分隔** — 用分割线、空白、标题层级制造视觉节奏
3. **关键流程** — 用 Mermaid/画板/流程图可视化
4. **信息归纳** — 用表格或分栏布局
5. **Prompt/代码** — 用代码块
6. **结尾** — 加精确时间

- 涉及实际飞书文档操作链路（参考：飞书文档操作链路记忆）
