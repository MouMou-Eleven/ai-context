## 五、修改方案

### 5.1 结构重组

**现有结构** → **建议结构**：

```
现有：
  开篇（大段焦虑场景 + "适合谁"）
  4.1.1 消息管理三步法
  4.1.2 飞飞AI伙伴
  4.2.1 模板+AI+评论链路
  4.2.2 初稿到终稿四步
  4.3.1 四件套串联
  4.3.2 三个自动化
  本章小结 + 写在最后

建议：
  开篇（精简为1个综合案例 + 本章方法论金句）
  4.1 消息管理：标签分层 + 消息转任务 + 任务中心
  4.2 AI伙伴：飞飞的日常用法（每日推送+即时问答+读文档）
  4.3 文档协作：模板→AI起草→评论→历史记录→审批/归档
  4.4 会议闭环：妙记自动记录→AI总结→待办提取→创建任务
  4.5 轻量自动化：3个场景（认知层面，不讲操作细节）
```

### 5.2 核心改动原则

1. **开篇精简**：把现有多段焦虑场景合并为一个200字以内的综合案例，紧接本章方法论（从"写在最后"提炼上来）
2. **删除所有对比表**：读者学完自然有体会
3. **小贴士融入正文**：所有callout/blockquote中的核心观点提升为正文段落
4. **一个知识点只讲一次**：飞飞介绍合并为一处、AI速览合并为一处、评论协作合并为一处
5. **自动化只讲认知不讲操作**：告诉读者"这些事可以自动化"，具体怎么配置指向第5章
6. **补截图位置标记**：在关键操作处标注 `[截图：xxx]` 占位
7. **增加AI指令迭代段落**：在4.3中补充"当AI生成不满意时如何迭代"的实操内容

### 5.3 预估改动量

| 改动类型 | 预估 |
|---------|------|
| 删除内容 | ~4000字（对比表、重复场景、小结） |
| 位置调整 | ~2000字（小贴士→正文、方法论前置） |
| 新增内容 | ~800字（AI迭代段落、截图占位标注） |
