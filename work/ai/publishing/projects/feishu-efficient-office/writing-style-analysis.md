# 《飞书高效办公》当前出版写作规则

> 规则整理：2026-09-12；产品与书稿事实仍按各自核验日期判断。本文件是生成书稿前的短规则卡，不包含历史培训风格配额。
> 项目与章节入口：[README.md](./README.md)。中文先读 [AI 表达短卡](../../../../../brain/ai-expression/README.md)，详细语言规则按任务需要读取。

## 对象与行文

1. 面向非技术职场读者，以具体工作问题组织章节；用通俗、准确的出版书面语解释方法。保留亲切感，不套培训口播、销售金句或“传统 vs AI”的固定结构。
2. 操作写到小白能照做：说清作用对象、入口、动作、结果和必要条件；未经验证不补移动端、管理员能力或精确耗时。复杂流程按实际执行顺序展开，简单连续动作可以用完整段落。
3. AI 提示词完整、可复制，说明输入前提和输出判断标准；先检查生成结果的结构与事实，再写针对偏差的追加指令，不能止步于“生成初稿”。
4. 标题只说明主题；导语承诺的能力要在后文闭环；大节说明问题如何承接。案例保留唯一对象主线，并增加职责分工、数据归属、异常分支或成效判断，删除前文的同义复述。
5. 表格用于比较和清单，图片用于界面和流程位置，正文解释意义与下一步。按理解需要选用，不设表格、callout、流程图或金句数量配额。

## 事实与版本

- 飞书功能、菜单、按钮、权限和操作路径必须核验官方资料或实际界面，记录来源、日期、版本和适用条件；无法确认的功能不写成事实。
- 当前项目术语为“豆包工作伙伴”（依据既有0713编辑核验记录）。新写或主动改写时重新核验；实际界面名逐处判断，不机械全局替换。旧截图像素的名称问题见项目 README 与第2章记录。
- 用户本轮明确要求和具体章节最新已接受编辑稿优先；“只接受修订”时保留该稿全部文字、空格、编号和格式，不擅自统一术语或润色。不能用全书规则覆盖第8章的编号例外。
- 当前章节身份按 [全书目录](./README.md#当前全书目录2026-06-26-确认) 判定。旧第4章素材没有当前第4章正文身份，不能沿用旧章号和图号。

## 正文、素材与图文

- 正文只写读者所需的方法、图前完整引导和图后解释；截图角度、待补图、作者提醒、资料搜集过程放素材清单、修订记录或参考文献。
- 实际看图再写引用；图前不复读图题，图中每个标注必须有对应解释。黑白印刷用位置、序号和界面文字定位，不依赖颜色。
- 图、表、流程图按当前章节编号；全书避免重复用图。替换或新增图后同时核对引用、图号、图题、caption、alt、文件名和后续顺序。
- 飞书审稿样式与 Word 交稿分开：Word 不含 emoji 或装饰图标，截图在正文栏宽下清楚可读，图与图题同页、续表重复表头、表格行不拆分。
