# 对外成品与内部工作稿的语言边界

> 来源：2026-08-21，建委在“琅琅分级悦读”MG 动画产品介绍片旁白交付后的明确校准。
>
> 当前结论：商业交付物一旦用于对外发送或正式审阅，就必须呈现为可直接使用的确定性成品，不能暴露内部协作对象、推敲过程和未确认状态。

## 一、先判断输出模式

### 内部工作稿

给建委本人看的分析、修改说明、风险提示、选项比较和沟通准备可以使用：

- 客户、委托方、甲方等角色说明。
- 建议、可选、待确认、需要补充等工作词。
- 为什么这样改、还有哪些选择、哪些事实需要核验。

### 对外正式稿

课程大纲、脚本、策划方案、项目方案、产品介绍、宣传片旁白、PPT 文案等内容一旦要直接对外，就进入正式稿模式：

- 只保留接收者需要看到的成品内容。
- 默认不写接收者是“客户”，也不在文件标题中标注“客户版”。
- 已确认事项写成确定陈述，不使用内部商议口吻。
- 不确定事项先退回内部确认，不能一边标“待确认”一边当作正式成品交付。

商业计划书、项目申报、比赛材料、路演 PPT 和融资材料还必须读取 [`competition-and-investor-materials.md`](./competition-and-investor-materials.md)，清除内部研发讨论、自证式声明、本地路径及外部无法访问的证据。

## 二、默认清除的内部表达

| 内部工作表达 | 对外成品处理 |
|---|---|
| 客户版 / 客户审阅版 | 从标题、文件名、页眉和正文中删除，直接使用交付物名称 |
| 给客户看的旁白稿 | 改为“产品介绍片旁白稿”或具体片名 |
| 建议采用正式 MG 动画风格 | 改为“整体采用正式、克制的 MG 动画风格” |
| 建议突出微信小程序 | 改为“内容重点突出微信小程序” |
| 可以重点表现测评报告 | 改为“重点表现测评报告中的阅读等级、能力分布和分析结果” |
| 可根据客户需求调整 | 已确认的调整机制写清范围；没有确认时从成品删除，转入内部说明 |
| 请客户确认 / 待客户确认 | 只有用户明确要求制作确认清单时才保留；否则先向建委确认后再生成正式稿 |
| 供客户参考 / 仅供参考 | 直接删除；如内容确实不是最终结论，应先明确文件类型，不能伪装成正式成品 |
| 这里暂定 / 后续可优化 | 不进入对外正文，转为内部待办或修订说明 |

这些词不是永久禁词。判断标准是：它们是否暴露了内部协作关系、犹豫过程或不必要的接收者身份。只有用户明确要求呈现建议、角色或确认动作时才使用。

## 三、主体角色的改写方式

对外稿默认让交付物中的真实业务对象充当主语：

| 交付物 | 默认主体 |
|---|---|
| 课程大纲、培训方案 | 本课程、课程内容、课程结构、授课过程、学习成果 |
| 视频脚本、旁白稿 | 本片、画面、旁白、产品、平台、使用者 |
| 策划方案、项目方案 | 本项目、实施方案、执行阶段、项目成果 |
| 产品介绍、网站方案 | 产品、平台、系统、页面、功能、用户 |
| 合作方案 | 合作内容、服务范围、实施团队、双方；只有合同或正式合作文本需要时才使用甲乙方 |

不要为了避开“客户”而机械替换成“甲方”“对方”“需求方”。先判断真正的业务主体，再重写整句话。

## 四、确定性不等于擅自保证

对外成品需要确定性，但不能虚构事实或效果。

| 信息状态 | 处理方式 |
|---|---|
| 已确认事实 | 直接、完整地陈述 |
| 已确定的创作或实施选择 | 使用“采用、设置为、分为、重点呈现、包含”等确定动词 |
| 尚未确认的事实 | 不进入对外稿；单独向建委提出待确认项 |
| 必须由接收方选择的事项 | 用户明确要求后，以“方案一 / 方案二”或确认清单呈现 |
| 效果、数据和承诺 | 只有存在证据和明确责任边界时才能确定表达 |

确定性解决的是**成品口吻**，不是把未知内容强行写成已知结论。

## 五、默认交付方式

当用户同时需要判断过程和正式成品时，输出分成两层：

1. **给建委看的内部说明**：说明改动、风险、待确认项和选择依据。
2. **可直接对外使用的纯净正文**：从标题开始，只保留成品内容，不出现“客户”“建议”“给你参考”等元话语。

如果用户明确说“单独给我”“直接发给对方”“只要正文”，只输出第二层。

## 六、交付前检查

- 文件名、标题、页眉、页脚是否出现“客户版”“客户审阅版”。
- 正文是否出现“给客户”“供客户”“请客户”等接收者身份提示。
- 是否把已确定内容写成“建议、可以、考虑、尽量”等犹豫口吻。
- 是否把“待确认、暂定、可调整、后续优化”等内部状态混入正式成品。
- 每句话的主语是否是项目、课程、产品、平台、画面或实施动作。
- 是否因为追求确定性而擅自写入未经确认的事实、数据或效果承诺。
- 用户要求“单独正文”时，是否仍夹带解释、致谢、修改说明或使用提示。
- 面向评委、投资人或孵化机构时，是否仍出现内部研发过程、自证式声明、本地路径或私有链接。

## 七、本次经验形成的直接规则

以后处理商业内容时，只要建委说“给客户看的”，默认执行以下动作：

```text
先识别内部工作信息
  → 将待确认事项留给建委
  → 删除接收者身份和协作元话语
  → 把已确认内容改写为确定陈述
  → 以项目、课程、产品或画面作为主体
  → 单独输出可直接交付的成品
```

除非建委在当前提示中专门要求，否则对外成品不主动出现“客户”和“建议”等内部协作词。
