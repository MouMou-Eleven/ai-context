# 赛事、路演与融资材料的对外边界

> 来源：2026-08-27，建委在“言剪AI”商业计划书审阅中的明确校准。
>
> 当前结论：面向评委、投资人、合作方和其他外部决策者的商业材料，只呈现有助于理解项目价值、验证可行性和作出决策的信息。内部研发讨论、写作过程、自证式声明和外部无法访问的本地证据不得进入成品。

## 一、触发范围

出现以下任一任务时，默认调用本规则：

- 商业计划书、项目申报书、比赛报名材料、答辩材料和路演 PPT。
- 面向评委、投资人、孵化机构、合作方、采购方或政府部门的项目介绍。
- 融资材料、招商材料、合作方案、产品白皮书和可行性说明。
- 任何会直接影响外部主体对项目价值、团队能力、技术可行性或商业前景判断的正式材料。

## 二、内部研发讨论不进入对外叙事

对外材料不主动呈现与评审决策无关的内部研发过程，包括：

- 底层来源、分支选择、二次开发过程、上游兼容策略和内部技术争议。
- “照搬、抄袭、模仿、不是抄袭”等会把注意力引向负面联想的词语。
- 为什么删除某段文字、为什么更换技术路线、如何规避某种表述等写作或协作过程。
- 给建委看的风险分析、开发备注、任务清单和版本差异记录。

需要说明技术时，改为呈现外部决策者真正关心的内容：产品解决什么问题、核心流程怎样工作、哪些能力已经验证、哪些能力处于建设阶段、系统如何保证稳定性与可扩展性。

内部研发记录仍应在项目仓库中保留，用于开发、合规和版本追溯；它们不等于对外商业叙事。

## 三、删除没有决策价值的自证式声明

商业材料不反复声明写作者“没有编造”“不是演示”“不是替代”“不会承诺”或“没有某类问题”。这类句子通常不能增加证据，反而会提醒读者怀疑原本没有关注的问题。

处理原则：

1. 有事实和证据时，直接陈述事实、数据、责任人和验证结果。
2. 事实尚未确认且不影响当前决策时，从对外成品删除，留在内部待办。
3. 事实尚未确认但必须披露时，只写客观状态、影响和下一步，不评价写作者是否诚实。
4. 法律、合规、财务审计或尽调明确要求的声明，按正式要求单独提供，不套用到普通商业叙事。

示例：

| 不进入成品 | 对外处理 |
|---|---|
| 本计划书不自行编造技术、运营或市场岗位。 | 已确认的成员职责直接列入团队章节；未确认的岗位不写入成品。 |
| 本项目不是只做演示页面。 | 展示可操作产品、真实任务结果、测试数据或公开演示地址。 |
| 本计划书不把市场规模等同于项目收入。 | 市场规模用于说明行业环境，收入预测另按用户、价格、频次和转化率测算。 |
| 本项目不是简单调用模型。 | 直接说明任务规划、执行控制、数据资产和交付流程。 |

## 四、外部证据必须可访问、可理解、可验证

评委和投资人看到的证据必须在其阅读环境中成立。正文、脚注、附录和资料来源中默认删除：

- 本地磁盘路径、局域网地址、`localhost` 地址和个人电脑文件夹。
- 私有仓库路径、内部测试目录、内部截图索引和只有团队成员能访问的文档。
- 无法打开的临时链接、登录后仍无权限的页面和未公开的开发记录。
- 只写“见内部记录”却没有在材料中展示结论或证据的引用。

可采用的对外证据形式：

- 可公开访问的官方网站、权威报告、正式公告和产品页面。
- 直接嵌入材料的产品截图、流程图、测试结果和关键数据，并写清时间与验证条件。
- 稳定的公开演示地址、公开视频、可下载样例或评审现场可运行的产品。
- 经授权后可提供的检测报告、合同、获奖证明、用户反馈和知识产权材料。

内部资料可以作为事实核验依据，但不把内部路径直接暴露给外部读者。若一项产品事实只能由本地记录证明，应把可公开的证据本身嵌入材料，或在提交前转为评委能够访问的交付物。

## 五、对外商业材料的默认信息顺序

商业计划书、路演材料和项目申报材料优先回答：

1. 市场为什么需要这个项目。
2. 目标用户正在承受什么具体成本或阻力。
3. 产品如何完成关键任务，当前已经验证到什么程度。
4. 相比现有方案，差异和商业价值在哪里。
5. 收入逻辑、成本结构和增长路径是否成立。
6. 团队为什么有能力推进，下一阶段需要什么资源。
7. 主要风险如何通过产品、运营和合规机制控制。

内部来源、研发过程和写作说明不能挤占以上信息的位置。

## 六、例外边界

以下场景可以披露必要的技术来源、第三方依赖或内部证据，但只提供对方明确需要的范围：

- 技术尽调、采购评审、安全审计和合规审查。
- 法律文件、授权清单、第三方软件清单和知识产权核查。
- 评委或投资人明确追问技术来源、授权关系或可复现证据。

例外材料应单独组织为尽调附件或问答，不把合规细节提前塞入普通商业计划书和路演主线。

## 七、交付前检查

- 是否出现只对内部开发者有意义的来源、版本、兼容、分支或修改过程。
- 是否出现“照搬、抄袭、不是抄袭”等会制造负面联想的词语。
- 是否出现“本计划书不编造、本项目不是……”等无证据的自证式声明。
- 是否把未确认岗位、收入、用户数或技术能力写成既成事实。
- 是否出现本地路径、局域网地址、私有仓库或外部无法访问的链接。
- 每项关键市场数据、竞品判断和产品结果是否有评委可理解的证据。
- 产品内部记录是否已转化为截图、数据、演示或公开附件，而不是只留一个路径。
- 删除上述内容后，材料是否把更多篇幅留给市场机会、用户价值、产品验证和商业模型。

## 八、默认执行流程

```text
确认外部受众与决策目标
  → 区分内部研发信息和对外价值信息
  → 删除写作过程与自证式声明
  → 把关键事实转化为可访问证据
  → 按市场、产品、验证、商业、团队和风险组织主线
  → 检查本地路径、私有链接和负面联想词
  → 输出可直接提交的纯净成品
```
