# 案例结果叙事与商业演示

> 本文件记录可跨行业复用的案例选择、定位、演示和结果叙事方法。它适用于产品演示、产品答辩、方案提案、直播销售、课程或会员社群招生、发布会和自媒体中的商业案例，不针对某一个行业或单一产品。

## 一、核心判断

案例不是把做过的东西展示一遍，也不是用一个漂亮效果替代产品价值。一个有效案例同时承担五个作用：

1. **证明**：在明确条件下证明能力、产品或方法确实解决过某类问题。
2. **映射**：让目标人群看见自己的岗位、场景和痛点，而不是只看见制作者的作品。
3. **预览**：让受众看到使用产品或学习方法后可能抵达的工作状态、效率变化或交付结果。
4. **论证**：用案例支撑一个明确的观点，说明为什么这样判断、这样做，而不是只罗列功能。
5. **承接**：把结果与产品、课程、社群或服务中的具体机制连起来，解释受众下一步能获得什么支持。

因此，案例的基本结构是：

```text
精准人群 + 真实场景 + 可验证痛点 + 明确观点
  + 干预机制 + 可见结果 + 适用条件 + 下一步行动
```

“卖结果”应理解为展示可实现的进步和结果路径，不是承诺每个人必然获得同样的收入、客户或播放量。结果必须带有条件、证据和边界。

## 二、适用范围与组合方式

### 适用任务

- 产品或网站演示、产品答辩、方案提案和项目汇报。
- 直播中演示案例、销售课程或会员社群。
- 自媒体用案例解释产品价值、岗位价值或方法观点。
- 课程招生、训练营说明、服务方案和发布会演示。

### 默认组合

```text
AI 表达基础层
  + 本文件（案例结果叙事）
  + 一个最具体的专业领域、产品或项目 README
```

需要从真实需求出发设计选题、承接动作或购买顾虑时，再叠加 [`content-demand-and-conversion.md`](./content-demand-and-conversion.md)。如果任务是 AI 自媒体的标题、口播或直播销售，再叠加 AI 自媒体对应分支；不能因为出现“直播”就自动读取 AI 培训。

## 三、案例定位卡

准备案例前先填写以下字段。缺少关键事实时标记“待验证”，不凭空补齐。

| 字段 | 要回答的问题 |
|---|---|
| 目标人群 | 具体是哪个岗位、阶段、业务规模或决策角色？ |
| 触发场景 | 对方在什么时刻遇到这个问题？ |
| 原有痛点 | 原来的做法耗时、出错、难交付或难转化在哪里？ |
| 关键观点 | 这个案例要证明哪一个判断？ |
| 干预方式 | 产品、课程、服务或方法具体改变了哪一步？ |
| 结果 | 产生了什么可观察变化？数据、交付物或前后对比在哪里？ |
| 结果机制 | 结果为什么发生，哪些环节起了作用？ |
| 产品连接 | 受众要购买的产品、课程或服务中，哪项机制能复现这条路径？ |
| 适用条件 | 需要什么基础、输入、时间、权限或人工判断？ |
| 不作承诺 | 哪些收入、客户数、播放量或效率不能从单个案例推导？ |
| 下一步 | 观看后让受众采取什么低门槛动作或进入什么承接环节？ |

## 四、跨行业叙事顺序

演示时按照“先让人对号入座，再解释方法，最后连接产品”的顺序组织：

1. **先定人和场景**：说明这是为谁、在什么工作任务中解决问题。
2. **呈现旧状态与代价**：指出真实阻力，避免泛泛说“效率低”“不会用”。
3. **先给观点**：明确告诉受众，案例要证明的不是“我会做”，而是“某类岗位可以用某种方式得到某种改善”。
4. **展示关键干预**：只演示与痛点和结果有关的步骤，解释产品或方法改变了什么。
5. **呈现前后结果**：让变化可见、可核验；必要时同时展示过程证据和最终交付物。
6. **解释因果链**：说明结果来自哪些输入、判断、工具和人工校验，避免把偶然结果包装成万能能力。
7. **连接购买对象**：告诉受众产品、课程、社群或服务提供的是哪一段机制、训练和支持。
8. **说明边界并给行动**：写清适用条件、尚待验证部分和下一步，不用夸大承诺收尾。

## 五、案例选择检查

一个案例至少通过以下检查才适合公开演示：

- 目标人群能被一句话准确描述，不是“所有人”。
- 痛点在该人群的真实任务中出现，并且有时间、成本、风险或机会损失。
- 结果能被看见或核验，至少有交付物、前后对比、过程记录或明确的验证方法。
- 案例能解释“为什么有效”，不是只展示炫技、模板或偶然运气。
- 产品与结果之间有真实因果连接，不能借案例光环替产品背书。
- 案例的输入条件、人工参与、工具版本和样本限制已说明。
- 未经授权的客户资料、个人信息、内部数据和敏感画面已脱敏或替换。
- 不把单个样本写成普遍保证，不把潜在副业或收入机会写成确定收益。

## 六、不同任务的落点

| 任务 | 案例的主落点 | 不应停留在 |
|---|---|---|
| AI 产品或网站演示 | 某岗位如何用产品完成真实任务，节省哪一步或扩大哪种能力 | 功能列表、技术名词和界面炫技 |
| 产品答辩或方案提案 | 案例如何证明方案判断、实施路径和交付价值 | 只展示成品，不解释选择理由 |
| 会员社群或课程招生 | 学员可能获得的工作进步、解决问题能力和支持路径 | 只说“学完就能赚钱”或堆课程目录 |
| 自媒体直播销售 | 用一个案例强化观点、识别目标人群并导向下一步 | 只播放案例，让观众自行猜用途 |
| 设计或内容交付 | 结果如何服务业务目标、受众和转化，而不只是视觉好看 | 把审美偏好当成商业结果 |

例如，“我用 AI 做了一个网站”只是能力描述；更完整的定位应是“某类岗位在某个具体任务中，借助这个网站减少原来反复处理的步骤，并得到可直接使用的交付物”。只有在真实证据存在时，才补充具体耗时、质量或转化变化。

## 七、直播和现场演示动作

演示前先说清三个信息：目标人群、要解决的任务、今天要证明的观点。演示中只保留能影响结果的关键步骤，并持续解释“这一步为什么与受众有关”。演示后立即完成三次翻译：

```text
看到的功能 → 解决的任务 → 可能形成的结果
```

随后补充结果成立的条件和产品承接方式。不要让观众只记住“效果很酷”，却不知道自己是否适用、如何开始和购买后得到什么。

## 八、证据、合规与表达边界

- 数据、客户评价、收入、节省时间和转化结果只能使用已核验材料；没有证据就写“待验证”。
- 区分“演示样例”“本人项目结果”“第三方客户结果”和“可复现方法”，四者不能混称。
- 说明案例是预制演示还是现场完成，说明是否经过人工筛选、修改或后期处理。
- 案例可以呈现希望，但希望必须落在路径和条件上，不能用情绪替代事实。
- 收入、副业、客户增长和播放量属于可能结果，除非有充分样本和边界，不写成保证。
- 对外成品还要遵守 [`external-deliverable-language.md`](./external-deliverable-language.md)；涉及答辩、路演或融资时，再读取 [`competition-and-investor-materials.md`](./competition-and-investor-materials.md)。

## 九、AI 调用规则

### 触发词

出现“案例演示、产品演示、案例答辩、产品答辩、直播案例、案例叙事、结果展示、未来图景、卖结果、课程案例、社群案例、产品价值演示”等表达时，读取本文件。

### 默认行为

1. 先调用 `brain/ai-expression/`，保证中文语境、逻辑和输出质量。
2. 再读取本文件，确定案例人群、痛点、观点、证据、结果和边界。
3. 再读取一个最具体的产品、项目或领域 README，确认事实、功能、价格、权益和适用人群。
4. 任务同时承担内容获客或购买承接时，叠加 `content-demand-and-conversion.md`。
5. 只激活与提示词明确相关的专项；除非建委明确要求组合，不自动加载 AI 培训、AI 自媒体或其他领域。

### 输出前审查

- 是否点明了“为谁、在什么场景、解决什么问题”？
- 是否提出了一个可复述的观点，而不是只有功能和步骤？
- 是否展示了结果证据，并解释了结果机制？
- 是否把结果与购买对象的真实能力连上？
- 是否写明条件、样本限制和不作保证的部分？
- 是否把案例当作希望和路径，而不是虚假承诺？
