# Work — 工作领域与项目总入口

> 这里保存建委正在做的工作。先判断属于“设计、AI、其他项目”，再进入具体门类；不能把所有项目平铺在同一层。

## 一级结构

```text
work/
├── design/   设计工作：按最终设计交付物分类
├── ai/       AI 工作：编程、培训、视频、出版和自媒体
└── other/    不属于设计或 AI 的其他长期项目
```

## 设计门类

设计以交付物为分类依据，包括 PPT、海报折页、书籍、微课与 MG 动画、AE 宣传视频、AI 设计。入口见 [`design/README.md`](./design/README.md)。

AI 设计属于设计，不属于 AI 门类。是否使用 AI 不能单独决定归属。

## AI 门类

AI 以主要工作方式和交付目标分类，包括：

- [`ai/programming/`](./ai/programming/README.md)：AI 编程工具、经验和开发项目。
- [`ai/training/`](./ai/training/README.md)：AI 培训经验、大纲、资料和培训项目。
- [`ai/video/`](./ai/video/README.md)：AI 视频通用经验、片型、工具和项目。
- [`ai/publishing/`](./ai/publishing/README.md)：AI 相关书籍出版与书稿项目。
- [`ai/self-media/`](./ai/self-media/README.md)：标题、文章、口播、直播销售和自媒体经验。

## 其他项目

不属于设计或 AI 的长期项目进入 [`other/`](./other/README.md)，当前包括 Inshan POPUPIANO 海外电商项目。

## 项目与领域的关系

- 领域目录保存可跨项目复用的经验、规则和模板。
- 项目目录保存某个具体产品、客户、书稿或经营目标的当前事实。
- 项目经验只有在多个案例中重复验证后才能提炼到领域层。
- 同一正文只有一个权威位置，其他位置用链接，不复制两份。

## 严格激活规则

- 生成、改写或润色中文内容时，先读取 [`../brain/ai-expression/`](../brain/ai-expression/README.md)，再读取一个最具体的领域 README 和最多两个直接相关文件。
- AI 表达负责中文质量，不算额外业务领域；只查事实、执行代码或整理文件时不强制读取。
- 不因建委同时具备多项业务就自动组合领域。
- “AI 自媒体”使用 AI 表达 + 自媒体，不自动进入 AI 培训。
- “AI 培训”使用 AI 表达 + 培训，不自动进入自媒体。
- “微课”进入设计下的微课与 MG 动画，不进入 AI 培训。
- 只有建委明确要求“结合多个领域”时，才组合对应入口，并说明各自负责什么。

## 写入规则

- 新资料先判断领域，再判断是通用经验还是具体项目。
- 新项目必须有 README，说明定位、事实、文件索引、调用规则和待确认事项。
- 旧内容被新口径取代后退出当前入口；必要的简要变化写入项目 `history.md`，详细旧版本由 Git 历史恢复。
- 不保留无人索引、重复、过期且无当前价值的文件。
