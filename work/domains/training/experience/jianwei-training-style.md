# 建委的培训课件风格

写、改、审培训课件前先读本页。这里讲建委想要的课件是什么样；课程怎么组织，见[课程组织](./demo-driven-course-design.md)。

> 来源：会员社群、济南市图书馆、分享活动等多轮课件修改与讲后反馈，归属见[来源表](./sources.md)。口径确认 2026-09-07，2026-09-28 补充口语样稿并标注级别。

## 默认交付物

建委只说"课件""分享资料""讲课文档""拿着讲两小时"时，默认做**课堂主文档**：通常在飞书，建委拿着现场讲，学员同时看。正文、截图、视频、逻辑图、生成图片一起把知识讲清楚。

它不是公众号文章，不是项目汇报，也不是讲师备课稿。"讲两小时"只说明内容量，不代表要写时间表。

## 规则

### 红线（不能违反）

**1. 学员视角，不写讲师安排。** 正文、标题、表头、提示框里都不出现：

- 时长（"本节 20 分钟"）
- 讲师动作（"讲师这里打开""接下来演示"）
- 备课栏目（"课堂要看什么""转场""备注"）
- AI 的执行过程和资料整理过程

要写的是学员要理解什么、为什么、怎么操作、怎么判断结果。建委明确要内部备课稿时才写讲师安排，而且另写一份。

**2. 修改已有飞书课件时保护建委的成果。** 局部改，不整篇覆盖。建委插入的截图、视频、案例顺序、评论、红色标注都保留；不自己加标红。删了章节后检查编号、列表、图片位置有没有乱。改之前先列清现有资源，改完按清单回看。

**3. 事实不能错。** 软件界面、按钮、路径、价格用真实截图或官方资料，不用 AI 生图仿造界面；功能和价格写之前核对当前版本。

### 默认（没有特别理由就照做）

**4. 能说出口。** 课件要像建委在课堂上跟学员说话。动笔前读[口语样稿](../../../../system/expression/voice-samples.md)，写完读一遍，正常讲课不会说的句子就改掉。

| 像建委说的 | 不像 |
|---|---|
| "你开了一个月会员，可能这个月总共就用了五次，剩下的用不了就是浪费。" | "订阅模式存在资源利用率偏低的问题。" |
| "有的人安装不了，有的人汉化不了，还有的人压根就打不开。" | "学员可能遇到各类技术问题。" |
| 从学员上一节做完的事接着说："上节课我们把网页发出去了，那现在问题来了……" | "本节将系统介绍……" |

口语化不是加"其实、然后、就是说"。靠的是具体的人、事、数字，一句讲一层意思，连接词用说话时的"因为、而且、但是、所以"。

**5. 每一部分都要有东西可讲。** 每段至少让学员看到一个动作或结果、一组前后对比、一个原因，或者一个能用的判断。讲师现场大概率会跳过的背景、表格、提示框就删掉。

**6. 不是纯文字。** 写正文前先按知识点列一张媒体清单，写完逐个知识点检查有没有对应的画面：

| 要讲的 | 用什么 |
|---|---|
| 软件界面、按钮、操作结果 | 真实截图 |
| 动效、交互、操作过程 | 视频、动图或能运行的案例 |
| 流程、关系、机制、对比 | 逻辑图、流程图 |
| 抽象概念、生活场景、前后反差 | AI 生成图片 |
| 三个以上对象的横向比较 | 表格 |

具体怎么选、怎么放、怎么避免重复，见[可视化与口语化](./visual-and-oral-training-docs.md)。

**7. 贴地气，能实操。** 哪怕讲理论，也要连到学员的实际工作，能演示就演示。建委不喜欢纯理论、假大空的课。

### 可灵活（按场景判断）

**8. 用生图还是用演示，看知识点。** 概念抽象、没有现成画面的，适合生图；能在屏幕上直接看到变化的，适合现场演示或录屏。不要机械地"每节配 N 张图"。

**9. 用飞书还是 PPT，看讲法。** 要现场实操演示时用飞书文档；纯演讲用 PPT。PPT 的做法见[设计：PPT](../../design/graphic/ppt/README.md)。

**10. 篇幅和深度看受众。** 零基础学员多讲场景、少讲术语；有基础的学员可以直接用准确术语，不重复讲基础故事。

## 反复出现过的错误

下面的错误在不同课程里出现过不止一次，交付前逐条检查：

| 错误 | 在哪些课出现过 | 怎么检查 |
|---|---|---|
| 写成书面文章或 AI 报告 | 网页基础设施课、秒哒进阶课、秒哒开发流程课 | 逐段读出来，对照口语样稿 |
| 讲师备课内容混进学员正文 | 网页美化/静态网页发布课、秒哒开发流程课、GPT-6 Astra 分享资料 | 搜"分钟""讲师""演示""课堂要看"，看标题和表头 |
| 文字很多，缺画面和真实案例 | 静态网页发布课、秒哒进阶课、秒哒开发流程课 | 按知识点对照媒体清单 |
| 生图或表格只是把文字重复一遍 | 网页美化/静态网页发布课、秒哒开发流程课 | 每张图、每张表问一句"它让学员多看懂了什么" |
| 修改时弄丢图片、视频、评论、标注 | 秒哒进阶课、秒哒开发流程课 | 改前列清单，改后逐项回看 |

同样的错再出现时，在"在哪些课出现过"补上这次的课名，并想办法把"怎么检查"写得更具体。不要另加一条规则。

## 交付前

能运行 Python 时，先用脚本扫一遍讲师视角词：

```text
python system/repository/maintenance/check-deliverable.py <草稿路径> --profile learner
```

脚本只查已知的几类问题。然后自己按上面"反复出现过的错误"表逐条检查实际成品，写入飞书后再回读一遍。各类成品的通用自查方法见[成品自查](../../../../system/repository/execution-checks.md)。
