# 产品信息、渠道与对标执行卡

适用：产品价值表达、渠道选择、商业对标与最小测试方案。判断依据见[商业认知](../../../../../brain/business-cognition.md)，内容生产主流程和统一输入表见[需求与承接方法](./content-demand-and-conversion.md)。不用于给纯教学案例强加销售目标。

来源：从建委2026-07-15及2026-08-21至22材料中已校正的商业认知迁出执行部分（2026-09-12）。这是既有方法的去重整理，非新增效果验证。

## 产品信息化八要素

先填写[跨行业适配卡](./content-demand-and-conversion.md#四跨行业适配卡)，再确定需要制作哪些信息资产。

| 要素 | 要回答的问题 | 可形成的资产 |
|---|---|---|
| 目标人群 | 谁最可能需要，谁暂时不适合 | 人群画像、场景清单、排除条件 |
| 真实问题 | 用户现在卡在哪里，付出了什么成本 | 痛点内容、自测清单、问题案例 |
| 目标结果 | 用户买的到底是什么变化 | 前后对比、成果展示、结果描述 |
| 核心机制 | 为什么这套产品或方法能解决问题 | 方法框架、流程图、演示内容 |
| 可信证据 | 凭什么相信 | 真实案例、过程记录、评价、可核验数据、样品或演示 |
| 常见顾虑 | 用户为什么不行动 | FAQ、边界说明、风险提示、适用条件 |
| 渠道表达 | 在不同渠道用什么形式说 | 图片、图文、短视频、直播、详情页、资料页、私聊说明 |
| 下一步行动 | 用户看完之后做什么 | 评论关键词、领取资料、预约、试用、购买、进群或咨询 |

## 渠道选择七问

1. 目标用户是否真实存在于这个渠道。
2. 产品价值能否用这个渠道擅长的形式展示。
3. 这个渠道更适合触达、信任、成交还是交付。
4. 是否有清楚的下一步承接路径。
5. 内容生产和维护成本是否可持续。
6. 数据、用户关系和内容资产能否沉淀，而不是完全依赖平台流量。
7. 平台规则、账号风险和合规要求是否能够接受。

## 五步对标法

1. **收集事实**：保存页面、内容、报价、流程和公开反馈，区分事实与推测。
2. **拆解链路**：分析他如何被看见、被理解、被认可、被需要和承接。
3. **找到机制**：判断真正起作用的是选题、证据、渠道、报价、交付还是品牌积累。
4. **适配自身**：结合自己的能力、产品、受众、预算和语气重新设计。
5. **小步验证**：先测试一个变量，记录结果，再扩大。

```markdown
对标对象：
可确认的公开结果：
目标人群：
产品 / 服务：
报价与权益：

如何被看见：
如何让用户觉得“和我有关”：
如何建立认可：
如何证明被需要：
如何承接和成交：
如何交付、复购或转介绍：

可迁移的机制：
依赖对方资源、不能直接迁移的部分：
可能涉及版权、商标、隐私或平台规则的部分：
我方要测试的单一变量：
验证指标：
复盘结论：
```

不复制受保护的文字、画面、课程、品牌和他人数据。公开结果可比、资源条件相近才有参考价值，不能仅凭自称收入判断对标质量。

## 方案输出与验收

按任务需要组织，不要求每次照抄全部栏目：

1. 当前卡点：分别诊断产品力、信息化、渠道、信任、承接、交付与复购。
2. 已确认事实和待验证假设：平台、价格、规则、案例和效果附来源与当前核验边界。
3. 目标人群、具体场景、核心机制、可见结果与证据。
4. 需要制作的信息资产及其信任阶段；不要求每条内容都成交。
5. 渠道与承接路径：一个主行动，明确由谁或哪个页面/系统承接。
6. 可参考的对标机制、不可迁移资源与不可照抄部分。
7. 最小测试：一次改变一个变量，说明工具改善哪一步。
8. 指标、风险、复盘时间：区分首购、复购、转介绍、退款和反馈。

交付前检查产品是否真能解决问题、结果是否有证据、渠道是否有人群、主行动是否可完成、交付能否兑现承诺。缺失项写待验证，不许诺必然成交或效果倍增。自媒体应用再按[渠道入口](../../../self-media/README.md)选择标题、图文或口播方法。
