# 代码生成动画（三维场景与运镜）

用代码把整个画面造出来：程序化搭建三维场景，设计镜头路线，逐帧渲染成片。它和 [Seedance](../seedance/README.md)（AI 生成镜头）、[AE](../ae-production.md)（模板级包装与合成）并列，是第三种出画面的方式。

本目录管“画面怎么从无到有生成出来”。画面上的字号、间距、出场节奏和验收，照常读[代码式视频设计经验](../../../common/code-driven-video/README.md)，两边都要读。

## 什么时候用，什么时候不用（默认）

**适合：**

- 科技、工业、城市、设备这类可以用几何体搭出来的场景，比如智慧工厂、数据中心、产线、园区。
- 需要空间感和运镜的镜头：俯冲进厂房、沿产线穿行、拉升环绕出全景。
- 原理和流程动画：设备怎么工作、信号怎么传、多个站点怎么协同（例：激光定位的“单站扫描 → 双站定位 → 四站建场”）。
- 数字孪生、全息、线框这类“看起来就是数据”的风格。

**不适合：**

- 真人、写实人物表情、情绪叙事，走 Seedance 或实拍。
- 要照片级真实材质的产品特写（布料、皮肤、液体），代码几何体做不出质感，走 Seedance 或三维软件。
- 只是给已有视频加字、加标注，这不是生成画面，只读[代码式视频设计经验](../../../common/code-driven-video/README.md)。

**例：** 创赛片里“智慧工厂整体解决方案”这一句没有现成素材，Seedance 生成的工厂结构不可控、难以对上“产线 + 仓储 + 数据中枢”的表达，就用代码搭了一个数字孪生工厂，镜头路线按“全厂生长 → 进车间看产线 → 出顶看全局”讲完这句话。见[精尺匠造智慧工厂案例](./case-jingchi-smart-factory.md)。

## 三种出画面方式怎么选（默认）

| | 代码生成动画 | Seedance（AI 生成） | AE 模板 |
|---|---|---|---|
| 可控性 | 最高：每个物体、每段运镜、每一帧都能指定 | 低：靠提示词引导，结果要抽卡 | 中：模板结构固定，可换字换素材 |
| 改一处的成本 | 改代码后重新渲染，同一镜头前后完全一致 | 重新生成，整段都可能变 | 改图层后重新渲染 |
| 擅长 | 空间结构、精确运镜、原理演示、数据感 | 写实质感、人物、自然场景、氛围 | 文字包装、证书墙、粒子插件光效 |
| 短板 | 写实质感、有机形体 | 结构准确、精确文字、指定运镜 | 没有现成模板的内容 |

一条片子可以混用：写实镜头用 Seedance 或实拍，结构和原理镜头用代码生成，文字包装按[人机分工](../../promo/competition/ai-production-workflow.md#两种分工模式默认)走。为什么这样分：建委看重的是可控，代码生成的每个地方都能说出来、改得动，适合“这一句必须讲清楚”的镜头；AI 生成适合“这一镜要好看、要真”的镜头。

## 交付前检查表

在[代码式视频检查表](../../../common/code-driven-video/README.md#交付前检查表)之外，再查：

- [ ] 从成片按每 0.25 秒抽帧拼一张总览：没有黑块、黑帧、定格，也没有整屏发白。
- [ ] 镜头路线上没有穿过实体（梁、墙、设备）造成的大片黑影或白团。
- [ ] 高速段的主角（例：机械臂）在运动模糊下仍认得出；转向段没有旋转拖影。
- [ ] 每个元素都说得出它在讲什么；同一时刻只有一个主角在发光。
- [ ] 最亮的主体没有冲白，最暗的画面平均亮度没有压到一片黑。
- [ ] 分辨率、帧率和全片一致；交付的是干净无字版，除非这单明确要字。
