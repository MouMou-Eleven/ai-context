# 成片上叠加包装

已经有一段视频（实拍、AI 生成、录屏），在上面逐帧画标注、坐标、信息面板、扫描线、名称条，让画面讲清楚“这是什么、在哪、有什么关系”。通用流程见[通用流程与渲染](../workflow.md)，字号、间距、对齐、图层顺序这些排版规则见[代码式视频设计经验](../../../../common/code-driven-video/README.md)，本页写这类活儿从拿到素材到交付的做法。

## 什么时候用，什么时候不用（默认）

**适合：**

- 视频画面已经定了，要在上面加信息：设备位置、部件名、空间关系、检测过程、数据。
- AI 视频模型生成的画面里文字糊、数字错，要把字重新做清楚。
- 要和画面里的物体精确对位：标注跟着移动的车、跟着推镜缩放。

**不适合：**

- 画面本身缺内容，加包装也救不了，先补镜头（[三维场景](../3d-scene/README.md)、Seedance 或实拍）。
- 只是普通的对白字幕，剪辑软件更快。

## 不同片型怎么用

| 片型 | 常见用法 | 注意 | 状态 |
|---|---|---|---|
| 宣传片（创赛、企业、产品） | 装备名条、设备定位点、空间坐标、信息面板、科技感扫描线 | 文字包装要达到模板级完成度，好坏标尺见[画面文字包装：什么样算好](../../../promo/competition/ai-production-workflow.md#画面文字包装什么样算好默认) | 已验证（创赛） |
| 微课、操作讲解 | 圈出部位、引线说明、步骤编号、放大镜头 | 节奏放慢，一次只标一处，标完停够读的时间 | 暂无实战 |
| 比赛演示录屏 | 操作区域高亮、点击提示 | 比赛有自己的规定，按该比赛目录做（例：[天津大赛](../../../../../development/industry-cases/education/tianjin-agent-contest/README.md)） | 各比赛目录 |

## 怎么做

### 1. 先拆素材（默认）

量清楚：分辨率、帧率、时长、有没有黑边、机位动不动、画面里哪些东西在动、主体在哪、哪里有留白能放字（天空、地面、墙、虚化区）。

- 例：一段 5 秒的厂房实拍，固定机位，只有一辆小车在动。由此决定：场景里的标注按固定坐标放，只有小车要逐帧跟踪；面板放在两侧留白区。
- 有黑边的素材（例：放大到 4K 后带上下黑边），留边距时先扣掉黑边，否则字会离画面太近。

为什么：素材的这些性质直接决定标注怎么放、要不要跟踪、字放哪；不拆就动手，后面全要返工。

### 2. 定“标什么”（默认）

按“空间 → 对象 → 关系”三层想，每个标注回答旁白里的一个点，说不出意思的不标。

- 例：旁白讲“统一空间基准、多目标定位”，就依次出坐标系和地面网格（空间）→ 设备定位点和编号（对象）→ 设备与构件之间的连线和说明面板（关系）。
- 反例：画面里看得到的东西都标一遍，满屏标签，观众不知道该看哪。

### 3. 量坐标、做跟踪（默认）

- 先抽一帧原画面，在图上量出每个目标的坐标再写，不凭感觉写。
- 画面里在动的物体逐帧跟踪（模板匹配，每帧更新模板），标注跟着走。
- 推镜时，贴在场景上的元素（坐标轴、定位点、连线）跟着同一个变换缩放；屏幕上的界面元素（面板、名称条）不动。规则正文见[跟着画面走](../../../../common/code-driven-video/motion-and-verification.md#跟着画面走默认)。

### 4. 分层合成（默认）

从下到上：原视频 → 面板底色 → 画中画 → 线条和文字 → 发光。发光只从线条和文字算，画中画不参与，否则发光峰值时画中画整块泛白。详见[代码实现的常见坑](../../../../common/code-driven-video/motion-and-verification.md#代码实现的常见坑默认)。

### 5. 版面按成片算（默认）

- 字号按成片里的实际像素算，正文约 3%—3.6% 画面高起步，主要在手机上看的再大一档；见[字号按画面高度定](../../../../common/code-driven-video/layout-and-sizing.md#字号按画面高度定默认)。
- 面板、名称条的尺寸由内容算出来，不先写死一个框；见[容器跟着内容走](../../../../common/code-driven-video/layout-and-sizing.md#容器跟着内容走红线)。
- 靠近画面边缘的标签换到目标另一侧，不出画。

### 6. 文案只用给定的（默认）

分镜和文稿没给的文字（结论句、口号、英文副标）不要自己加；确实需要时，交付时标明“这句是自拟的，请确认”。

- 反例：分镜没写结论，第一版自拟了一行底部结论字幕，被客户要求删掉。

## 常见包装形式（可灵活）

按要讲的意思挑，不是每条片子都上一遍。外观（颜色、形状、光效）按主题重新设计。

| 形式 | 讲什么 | 做法要点 |
|---|---|---|
| 坐标系、地面网格 | 空间基准 | 贴在地面透视上，跟着推镜变换；线细、半透明，不挡主体 |
| 定位点 + 引线标签 | 某个对象在哪 | 依次弹出（间隔约 0.1 秒），标签离目标的方向和距离同组一致 |
| 连线、距离标注 | 对象之间的关系 | 在对象都出现之后再出，线可以流动表示数据传输 |
| 信息面板 + 画中画 | 局部细节、说明 | 画中画从原画面实时裁，不用静态截图；面板标题 + 画中画 + 说明条按内容累加高度 |
| 扫描线、检测框 | 正在识别、检测 | 扫一次就停，不常驻闪烁 |
| 名称条、标题条 | 这是什么 | 分层错开入场，换下一条前上一条先退场；好坏标尺见[画面文字包装](../../../promo/competition/ai-production-workflow.md#画面文字包装什么样算好默认) |

## 客户常见返修意见怎么改（默认）

| 客户说 | 实际问题 | 改法 |
|---|---|---|
| “这里空了一块，不好看” | 容器尺寸写死，内容只占一部分 | 容器按内容累加尺寸 |
| “字太小，按这个框的大小” | 正文按电脑屏幕的感觉定，成片里偏小 | 按客户框出的大小换算成画面高度比例，同层级统一放大 |
| 放大正文后看着别扭 | 标题比正文还小，层级倒挂 | 标题再大一档，或用字重、颜色拉开 |
| “这句不要” | 自拟了分镜没给的文案 | 删掉；以后自拟的文案交付时标明 |

## 检查项

- 每个标注都对准目标，移动物体的标注全程跟住。
- 没有标签出画、互相压住或挡住主体关键部位。
- 发光峰值时画中画和文字没有泛白；面板底色没有压暗画中画。
- 每段文字完整出现后停够读的时间，切镜头前已经读完。
