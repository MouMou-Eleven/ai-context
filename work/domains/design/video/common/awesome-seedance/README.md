来源：[LearnPrompt/awesome-seedance](https://github.com/LearnPrompt/awesome-seedance)，维护者为卡尔与 GoodCase 团队。**第三方资料，非建委自研或本人实测。** 本仓于2026-09-24按固定版本 `db659f2d9295e564728b0507ad7e28b3cd0adc62` 收录，主归属为[视频共用制作方法与工具](../README.md)，Skill总库只保留索引。

## 能力与证据

当前快照包含 **497条案例、25类模板、12个Skill入口（1个总库及11个专项）**，保留原帖、作者、提示词和复测字段。上游数据报告254条案例有264次跨模型复测：193次复现、68次降级、3次失败。复测模型与原始Seedance案例模型分开记录，不能称497条均由维护者亲测成功。热度不是稳定性；复现结论、分数和原始产物仍是上游报告，本次入库没有重新生成视频独立验证。

可借鉴的是按意图选结构、把动作与运镜写具体、引用案例核对，以及保留失败条件的做法。模型版本、接口、时长、清晰度、参考输入和口型支持须执行前核对当前平台；提示词中的4K、30秒或完美同步只是目标，不能作为能力或成片证据。原始风格库的提炼样本日期与最新案例总数不同，不能改称所有模板都在497条上验证。

上游技能推荐表还包含其他仓库的外部推荐；本次保存的是此仓库内实际存在的12个Skill，不表示那些外部项目也已收录或安装。

## 什么时候主动调用

- 建委明确说“用这个库／awesome-seedance／Seedance提示词Skill”时，读取本页后按[模板选择](./template-guide.md)执行。
- 制作宣传片、微课、故事影片或自媒体视频，且其中需要AI生成镜头、参考图动态化、视频提示词时，AI自主进入本库；不要求建委指定文件或模板名。
- 只说“制作视频”而尚未选择生成方式时，先按主片型判断哪些镜头需要生成；需要时再读本库。不因“视频”二字自动套入。
- 纯AE合成、Remotion图形动画、视频上传开发、口播文案、模型介绍文章、只查资料，均不自动执行提示词Skill。明确要求不使用或保留原提示词时遵守保护范围。

## 实际执行：读到模板正文再写

1. 沿当前片型入口保留受众、目的、脚本和交付规格；本库仅承担生成镜头这一步，不更改项目或课程归属。先确认主体、动作、时长、比例、工具及已有参考素材；已有信息直接复用，只问影响结果的缺项。
2. 读取[总Skill](./source/agents/skills/seedance-prompt-library/SKILL.md)，再按[模板选择与冲突处理](./template-guide.md)实际打开最接近的中文模板。中文分类页来自上游同一生成源，可替代一次加载12万字节的总参考；必要时再查[完整参考](./source/agents/skills/seedance-prompt-library/references/style-library.md)。有专项Skill时读对应Skill及其案例参考，不必把12个都加载。
3. 从相近案例中选一个锚点，读取提示词、输入依赖、原作者与复测状态；用[只读提取器](./lookup.py)按模板或slug提取本地数据，或在[画廊](./source/docs/gallery.zh.md)按案例定位。无贴近案例就说明差异，不把高热度案例强套进当前任务。
4. 用真实素材替换主体、场景、动作和时间；参考图锁身份，分镜锁顺序，文字补变化。通常选一种主体结构，角色约束等作为补充，不能把所有模板混成一个长Prompt。跨模型只迁移镜头结构，平台语法、音频与参考数量重新核对。
5. 交付可复制提示词、参考素材对应关系、采用模板及案例来源，以及本次需检查的连续性／动作／镜头／声音。需要整片脚本时，提示词作为对应镜头字段，不用Prompt取代整片设计。尚未生成时明确是提示词草案；生成后实际看片，不能仅凭提示词自检称验收通过。

## 与已有经验怎样配合

- 先读[建委Seedance实战](../tools/seedance/practical-workflow.md)：已有主体和场景参考时不堆重复描述；进入后期剪辑的素材默认只要环境和动作音效，BGM在后期处理。音乐MV或用户明确要求原生配乐时再按目的调整。
- 新库的“分镜网格转视频”是有条件的方案，不覆盖旧经验对复杂整图故事板的警告。只在当前模型支持、网格简洁、角色图与分镜图分工清晰时用一个低成本短片验证；漏镜、姿势串用或标注入画时退回逐镜参考图。逐秒脚本是计划，最终节奏以生成素材及剪辑为准。
- 教师微课由[教育作品方法](../../education/README.md)决定教学信息与音频覆盖；商业片由[宣传片方法](../../promo/README.md)决定信息和节奏；[AE](../ae-production.md)负责合成与文字包装。Logo、精确文字或数值不靠提示词保证，必要时后期制作。

## 后续沉淀与更新

用后把本次模型／平台／日期、素材、修改前后Prompt、结果或失败点写回真实项目；通用可复用结论补到[已有Seedance案例](../tools/seedance/prompt-cases.md)或相应片型方法，并回链案例。不要把案例表复制多份，也不在第三方source里写建委经验。只收藏资料不升级个人能力。

后续更新由AI按[统一流程](../../../../../../system/repository/ingestion-workflow.md)比较上游commit、许可、字段和Skill行为，再整体替换快照、刷新来源与模板入口、运行调用和边界回归、同步README与导航。当前是固定快照，不宣称实时同步；没有新增证据时不把候选方案升级成默认方法。仓库读取调用不需要全局安装；自动调用表示AI识别需求并读取方法，不表示已调用收费模型或自动出片。
