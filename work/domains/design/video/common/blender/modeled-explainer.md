# Blender 建模解说视频：从照片到一条有旁白的三维解说片

用 AI 驱动 Blender 把一个结构（桥、设备、产品构造）建出来，再做成“旁白讲到哪，镜头就带你看到哪”的解说视频。以前要调研、编剧、分镜、建模、动画、配音剪辑一个团队接力；现在人定主题、给照片、看结果，执行交给 AI。开工方式见[Blender 入口](./README.md)。

## 一条片子怎么走（默认）

```text
主题 + 参考照片 + 可靠资料
  → 低清试片跑通流程（十几秒、无声、低分辨率）
  → 对照照片重建模型，推近检查
  → 按构件分组做动画，低清预览确认顺序和镜头
  → 交接工程给做后期的 AI：写口播稿和分镜 → 配音 → 按真实时长对齐镜头和字幕 → 正式渲染
  → 人验收成片
```

用哪个 AI 做哪一步不是固定的：建委这次用 Codex 建模和做动画、Claude Code 做解说和合成，两个工具能力有重叠，换着用也行。

## 第一版粗糙不算失败（默认）

第一版只求把流程跑通：结构能按顺序出现、镜头能看清变化、工程能接着改。用十几秒的低清无声试片看方向，确认后再决定在哪儿下功夫；一上来就要高清成片，跑很久才发现方向不对，时间全浪费。

例：卢沟桥第一版是 12 秒、480×854、每秒 12 帧的无声试片，单跨石拱示意，顺序看得懂，但造型太概括、推近没东西看、认不出是哪座桥。所以先改模型，没急着加配音音乐。

## 让模型“更像”：给照片，用资料定尺寸（默认）

- **给一张参考照片，比说十遍“再精致一点”管用。** “高级一点”“真实一点”AI 不知道往哪改；有了照片，主拱是不是太圆、小拱位置对不对、桥面是不是一块平板，都能逐个对着比。
- **照片给不了尺寸，主要比例用可靠的公开资料定。** 照片里看不见的内部结构、完整纹饰，要么找资料，要么明确标成“推定”。交付时附一份说明：哪些已核实、哪些是照片可见、哪些是推定。
- **不用贴图假装开孔，不靠堆对象数量冒充精细。**

例（赵州桥）：主拱净跨、矢高、28 道拱券并排，依据赵县人民政府的介绍；模型把主拱分成 28 道 × 65 块，共 1820 块，这是为了后面能让石头一块块出现、单独高亮、拆开讲，不是真实古桥的石块数。

重建指令的写法：

```text
请在新文件夹中，根据我提供的＿＿照片重新建模，保留上一版。先提取照片中能看见的结构特征，再用可靠资料核对主要尺度。明确区分已核实信息、照片可见信息和推定细节。重点制作：＿＿（列出要看得见的结构）。请先交付正面、斜侧面和几处近景的渲染图和 .blend 工程。不要用贴图假装开孔，不要只增加对象数量来代替可见的质量提升。对照照片检查比例，发现问题后修改并重新渲染。
```

## 判断模型好不好：推近看（默认）

远看像，近看可能就是几个大方块。一个要被镜头绕着拍、还要一层层拆开的模型，从哪个角度看都得说得通：洞后面要有面，栏杆换个角度不能穿进桥面。多加一个近景镜头，就会暴露一批远景里藏着的问题。

看渲染图盯住三件事：像不像参考照片；部件有没有明显的错（悬空、穿插、洞没打通）；镜头能不能看清要讲的东西。提修改要具体到对象或镜头（“右边小拱里多出来一片石头”）；脚本跑成功不算完，回工程改、重新渲染、出同角度对比图。

```text
请检查这组实际渲染图。先指出与参考照片不一致、开孔不通透、石块穿插、构件悬空或相机裁切的问题。把问题定位到具体对象或镜头，优先修正影响结构辨识和近景观看的部分。修改后重新输出同角度对比图，并说明哪些问题已修复、哪些仍是模型精度限制。
```

## 动起来、交接给下一步（默认）

- **按构件分组安排时间线**：完整的全景开场 → 各部件依次展示 → 回到全景，同样先出低清预览确认顺序和镜头。构件依次浮现是“组装示意”，不能说成真实施工过程。
- **渲染还是要算时间。** AI 省下的是人盯着软件操作的时间，渲染和检查照样要花（赵州桥 20 秒、1280×720、480 帧的展示动画，那一次渲染日志累计约 22 分 46 秒，换台电脑不一样）。
- **交接交工程，不只交 MP4。** MP4 是算好的画面，换机位、拆结构都改不了。一起交：

| 交接材料 | 接手的 AI 拿它做什么 |
|---|---|
| `.blend` 工程与构件分组 | 改动作、改镜头、单独突出某个结构 |
| 参考照片、尺寸依据、推定说明 | 确认像不像、哪些是事实，避免把猜测写成史实 |
| 建模、渲染、合成脚本及运行说明 | 接着执行、排查问题、改完重新生成 |
| 静帧与短动画 | 快速了解当前质量，不凭文件名猜内容 |
| 讲解目标、分镜要求、交付标准 | 知道观众该看懂什么、做到什么程度算完成 |

## 做成解说片（默认）

展示片让镜头绕一圈就完了；解说片要回答观众心里的问题（为什么要搭支架？支架撤了重量往哪走？）。所以先想清楚观众要看懂什么，再定拍什么、每个镜头停多久。

- 先写口播稿和分镜表，每个镜头列：解说内容、可见对象、动作、机位、字幕、预期时长。旁白讲到哪个部件，镜头就展示哪个部件；需要改运镜或结构动作时改工程重渲，不把现有短视频循环拉长。
- 先生成配音、量真实时长，再对齐镜头和字幕（通用做法见[动效与节奏 · 跟着配音走](../video-craft/motion-and-verification.md#跟着配音走默认)）。缺配音条件时先完成无声预览，并说清缺什么。
- **竖屏要重新构图**，不能把横屏画面裁成竖屏：长条结构两头会丢。在全景、单个原理、局部细节之间切换，每段给要讲的东西留够位置。
- 可核实的形制和一般原理示意分开写；无法证明的古代工法不写成史实；受力箭头没有计算依据就标“定性示意”。
- 先做低清完整预览，查每个镜头的首、中、尾帧，再按图片序列正式渲染（能中断后续跑）。交付：MP4、可编辑 `.blend`、独立配音、SRT 字幕、口播稿、分镜表、事实依据、运行脚本；说清已完成和未解决的，不把占位文件说成成片。

按建委用过的完整开工指令改成的通用版（原文针对桥，“哪个对象”原为“哪座桥”；主题、路径换成自己的）：

```text
请作为这条视频的导演、Blender动画师和剪辑师，接手当前项目并实际完成制作。先读取模型说明、运行说明、参考照片、静帧和现有 .blend 工程。确认当前模型到底是哪个对象，不要混用其他项目的结构和资料。在新建的 explainer 文件夹中保存全部修改，保留原工程。目标：制作60～90秒、9:16、1080×1920、24fps的中文3D解说视频。围绕一个观众能理解的问题展开，旁白讲到哪个部件，镜头就展示哪个部件。先写口播稿和分镜表，每个镜头列出：解说内容、可见对象、动作、机位、字幕和预期时长。需要改运镜或结构动作时，修改 Blender 工程并重新渲染，不要把现有短视频循环拉长。先核查准备使用的历史和结构说法。把可核实形制与一般原理示意分开；无法证明的内容，不要写成史实。箭头若没有力学计算依据，标为定性示意。检查可用且已授权的配音工具。先生成配音、测量真实时长，再对齐镜头和字幕。缺少配音条件时继续完成无声预览，并明确报告缺口。竖屏重新构图，不能简单裁掉横屏模型两端。字幕不挡关键结构。先做低清完整预览，检查每个镜头首、中、尾帧，再按图片序列正式渲染，支持中断后继续。交付MP4、可编辑 .blend、独立配音、SRT字幕、口播稿、分镜表、事实依据和运行脚本。实际检查画面与声音是否同步、是否存在黑帧或穿模。说明已完成事项和未解决问题，不把占位文件说成成片。
```

## 验收（默认）

通用检查按[出片检查](../video-craft/verification.md)。解说片另外带着这几个问题回看：

- 关掉声音看一遍，画面顺序还讲得通吗？
- 旁白讲到某个构件时，它在不在镜头里？
- 字幕有没有挡住关键动作？
- 推定的内容有没有被说成确定的史实？

文件有声音不等于配音清楚，能打开不等于合格，这一关人要自己看。

## 想量产，每条留下什么（默认）

| 留下什么 | 内容 |
|---|---|
| 输入模板 | 主题、要回答的问题、目标观众、参考素材、关键尺寸和事实来源 |
| 能改的资产 | 工程、构件命名、材质、灯光、常用镜头；标出哪些能复用、哪些要跟着题材重做 |
| 三个检查点 | 模型静帧检查、完整低清预览检查、最终有声成片检查；前一关有问题先修好 |
| 交接说明 | 运行环境、文件用途、配音条件、真实时长、已知缺陷 |
| 实际投入 | 人检查修改的时间、工具运行时间、渲染时间、调用费用分开记，攒多了再算效率 |
