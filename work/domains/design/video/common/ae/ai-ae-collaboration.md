# AI 与 AE 协作：用 MCP 操控 After Effects

AI 要在 After Effects 里读工程、改模板、做动画和包装、渲染出片时，怎么连上 AE、本机两个 AE MCP 怎么挑、怎么操作不出错、渲染后怎么查。MG 动画、自媒体短视频、特效包装、企业片、创赛片都一样适用。

片子本身怎么设计分三层读：画面排版、字号、动效节奏、出片检查这些换哪种做法都成立的，在[视频通用设计与验收](../video-craft/README.md)（出片检查在[出片检查](../video-craft/verification.md)）；在 AE 里改模板时“模板怎么用、哪些动、哪些不动”的设计判断，在[改 AE 模板的设计判断](ae-template-design.md)；某个片型、比赛自己的要求，在片型目录（如创赛片的[改模板的排版与验收](../../promo/competition/ae-template-layout.md)）。本文件只管“AI 怎么用 AE”：连接、工具、操作和渲染的坑。

## 什么时候读

- 读：AI 要动 AE 工程，不管什么片型，也不管建委有没有提 MCP、脚本。
- 不读：只写“AE 风格”的视频提示词（走 [Seedance](../ai-generation/seedance/README.md)）；只用代码（Remotion、Python、HTML）做动画、不碰 AE（走[代码生成动画](../code-generation/README.md)）。

## 本机有两个 AE MCP，都能用

两个都是把 AI 和 AE 接起来的桥，都免费、开源（MIT），不按调用收费，花的只是 AI 自己的 token。都只负责“能操作 AE”，审美、镜头设计仍按设计目录的方法判断。Claude Code、Codex、Claude Desktop 三个 AI 软件都接了这两个；安装位置、端口、版本、接法见[设备环境](../../../../../../system/environment/computers/desktop-1/README.md)。

## 两个怎么挑：AI 自己判断（默认）

建委不指定用哪个，AI 按这一步要做什么自己挑，一个任务里可以两个混用（但不能同时调，见下一节）。挑的顺序：**能不能做到**（哪个有这个工具、现在连着没有）→ **出错少**（能退回、不会卡在弹窗上）→ **结果好**（有没有自带检查）→ **快** → **省 token**。

| 这一步要做 | 先用 | 为什么 |
|---|---|---|
| 开工第一步 | 两个都试一下：surehand 调 `ae_status`，Bridge 调 `ae_project_info` | 哪个不通，下面写“先用”它的那几行就改用另一个 |
| 读工程结构、找图层，改属性、关键帧、表达式、文字这类日常改动 | surehand；不通用 Bridge | 两个都能做；surehand 弹窗不会卡住、出错直接返回原因，core 工具说明短，每轮省 token |
| 改动多、怕改坏：重组合成、批量换字换图 | surehand：先 `ae_checkpoint`，用 `ae_batch` 一次做完，改完 `ae_prove_identical` 证明别处没动 | 改坏了能整体退回；只有 Bridge 时先另存一份工程再批量改 |
| 竖版改版、跟音乐卡点、一批多版本、检查下载来的模板 | surehand（`ae_tools` 搜到后 `ae_call` 调） | 它有专用工具；Bridge 只能拼菜单命令和脚本 |
| 动之前想知道“什么样算好”：动效、字体、构图、三维相机 | Bridge 的 `ae-*` 设计技能 | 只有它带设计知识 |
| 判断动效节奏、交付前查重叠、抖动、跳帧、看不清的字 | Bridge：`ae_review_motion`、`ae_proof` | 只有它有这套检查；用 surehand 改完的工程也能用它查（不同时调）。Bridge 不通时，按下面[渲染与出片](#渲染与出片默认)自己抽帧查，并在交付说明写“这次没跑 ae_proof” |
| 渲染 | AE 界面开着时：surehand `ae_render_background`，或 Bridge `ae_render_queue`（add 再 render，用界面的渲染队列，模板传中文名“最佳设置”“高品质”）。**不用 Bridge 的 `ae_render_video`**：它另起 aerender，等于再开一个十几 GB 的 AE，见下面[渲染与出片](#渲染与出片默认) | 驰热固芯 2026-11-23：两个 AE 合计约 33 GB，系统报低虚拟内存，aerender 渲到第 93 帧内存不足退出；同一段用渲染队列一次出完 |
| 其中一个连不上 | 先用另一个，同时按[连不上怎么办](#连不上怎么办默认)修 | 不退回自己写命令行脚本 |

这张表现在的依据，是两个项目的说明文档、源码和 2026-11-23 安装时的测量，**还没有在同一单上并排实测过**。所以每次用完，在[使用日志](../../../../../../system/repository/usage-log.md)那一行的说明里写一句：哪一步用了哪个 MCP、花了多久、出过什么错。同一类步骤积累到两三单，回来按实测改这张表。

**surehand 保持 core，不要改成 full（默认）。** full 只是把 114 个工具的说明一开始就全部加载，功能一样；core 里缺的工具用 `ae_tools` 搜、`ae_call` 调，按需取用，每轮少带约 3.8 万 token。

## 先用 MCP 自带的工具，不自己写脚本（默认）

建委 2026-11-23 的要求（大意）：AI 自己写脚本肯定不行，太低效了，本来就有现成的工具；两个 MCP 合起来一百多个工具，优先用这些内置工具。

按这个顺序找办法，前一步能做就不往下走：

1. **专用工具。** 读结构、改属性、加图层、加效果、改文字、关键帧、表达式、出帧、渲染，都有对应的 `ae_*` 工具。
2. **查目录。** 不知道有没有对应工具时，surehand 用 `ae_tools` 搜关键词（找到后 `ae_call` 调），Bridge 用 `ae_catalog`。
3. **确实没有对应工具，才在 MCP 里跑一小段脚本。** surehand 用 `ae_run_script`（先读 `ae_get_scripting_guide`），Bridge 用 `ae_run_jsx`。一段只做一件事，短，返回要用的结果。
4. **两个 MCP 都连不上、按下一节修不好，才用命令行脚本**（`AfterFX.exe -r`，做法见[后备：命令行脚本](#后备命令行脚本只在两个-mcp-都不可用时)）。交付时告诉建委这次为什么没走 MCP。

反例：2026-11-23 另一个对话改 AE 模板时没有调 MCP（Bridge 的 7788 端口当时没在监听，也没换用别的 MCP），自己写 `run.sh` 用 `AfterFX -r` 发脚本，再开弹窗守护点框。两个脚本撞在一起，AE 一次只跑一个脚本，后发的那个被丢掉，并弹出“当已在运行其他脚本时……第二个脚本未运行”，守护把框点掉，AI 不知道脚本没跑，干等了 20 多分钟；剩下的报错都是它自己写的脚本有错。这不是插件的漏洞，是没用插件。

为什么：MCP 工具是做好、测过的，一次调用就返回结果和错误原因；自己写脚本要从零写、调、处理弹窗和超时，慢，还会把自己的错当成 AE 的问题去排查。

## 一次只让 AE 做一件事（默认）

AE 同一时间只执行一个脚本，MCP 工具在 AE 里也是一段一段脚本在跑。所以：

- 工具一个一个调，等上一个返回再调下一个，不要并行发多个 AE 调用。
- 两个 MCP 不同时调；不让几个子代理同时操作同一个 AE。
- 渲染期间不发改动；改动没返回之前不开始渲染。
- 开工前确认没有别的对话正在用这个 AE：surehand 的调用记录（`activity` 子命令）看最近几分钟有没有调用，但它只记 surehand 自己的；Bridge 和命令行脚本看不到，要再查有没有 `aerender`、`AfterFX -r` 进程在跑、AE 界面里有没有正在跑的渲染。有就等它结束，不去抢。

## 开工前（默认）

1. **两个 MCP 是否都连着。** Claude Code 里运行 `claude mcp list`，after-effects 和 surehand-ae 都应显示 Connected；Codex、Claude Desktop 看各自的配置文件里有没有这两个（位置见设备环境）。AE 这边：Bridge 用 `netstat -ano` 看 7788 端口有没有在监听；surehand 调 `ae_status`。
2. **是否最新版（默认，建委要求保持最新）。** surehand 每天自动查一次 GitHub，有新版只提醒、不自动装：开工运行 `update --check`，有新版再按下面的时机更新：更新会重装 AE 扩展、要重启 AE，所以**建委正开着 AE 在用、或工程有没存的改动时，只提醒建委，不更新**；AE 没在用时先存盘、关 AE，再运行 `update`，重启 AE 后跑 `selftest` 确认连得上。Bridge 是从源码链接安装的：在它的目录 `git fetch`，看落后几个提交，落后就 `git pull --ff-only`（依赖有变再 `npm install`）。两个都更新完，重启 AE 和 AI 软件才会生效；时机同上。具体命令、目录和代理见[设备环境](../../../../../../system/environment/computers/desktop-1/README.md)。
3. **工程准备：先另存工作副本，原件不动（默认）。** 打开模板或旧工程后先另存一份（如“模板名_本单内容.aep”）再改；之后每轮改完也另存成递增版本，不覆盖正开着的那个（原因见下面[工程与图层](#工程与图层)的“另存新文件名”一条）。用 Bridge 改就在面板点“Use current”指到这份副本。片型目录只规定文件怎么命名。

**AE 用“AI协作”工作区（默认）。** 建委预设了“窗口 → 工作区 → AI协作”，里面已经放好 AE MCP Bridge 面板，打开 AE 默认切到这个工作区，不用另开面板。AI 自己启动 AE 或打开别的工程后，工作区可能被模板自带的布局覆盖，用 Bridge 的 `ae_menu_command` 执行菜单命令“AI协作”切回来（不自己写脚本）。**只在当前不是“AI协作”时切一次，不要每次操作前都切**：切工作区会重建面板，Bridge 的服务就在面板里，见下面[连不上怎么办](#连不上怎么办默认)；“所有面板”“动画”两个工作区里没有 Bridge 面板，切过去它就被关掉。

建委在 AE 里打开模板工程、打开 AE MCP Bridge 面板并把这个工程设为沙箱后，AI 可以直接读写正在打开的工程。本机面板的情况见[设备环境](../../../../../../system/environment/computers/desktop-1/README.md)。建委给的时间点如“6:24~13:22”是**秒:帧**（25 帧下即 6.96—13.88 秒），按这个去主合成里找对应的预合成。

## 连不上怎么办（默认）

- **surehand 报“bridge not reachable”。** 刚安装或刚更新完，要重启一次 AE 才加载扩展；再不行运行 `surehand-ae selftest`，按它给的修复提示做。
- **Bridge 面板显示在监听但连不上**，点面板里的 Restart。
- **AE MCP 桥接断开时不用重启 AE（默认）。** 打开较大的旧版模板后面板可能掉线，`ae_*` 全部连不上。先用 surehand 的 `ae_run_script` 执行下面两句；surehand 也连不上，才用 `AfterFX.exe -r 脚本.jsx` 向正在运行的 AE 发脚本：先 `app.project.save()`，再 `app.executeCommand(app.findMenuCommandId("AE MCP Bridge"))` 重新打开面板。建委在用电脑时不要把 AE 切到前台。
- 一个修不好，先用另一个把活干完，交付时说明哪个没连上。

**为什么会断（2026-11-23 驰热固芯一晚断了三次，查源码、日志和系统事件得出）：**

- **Bridge 的服务长在面板网页里。** 面板被关、被重建（切工作区、AE 重排布局，打开大工程时也遇到过）或网页崩掉，7788 就没了；它没有心跳，也不会自动重连。正在跑的调用报 `ECONNRESET` 不等于操作失败：先 `ae_project_info` 看当前开的是哪个工程，再决定重做还是继续。面板空白、`netstat` 里 7788 没在监听时，按上一条用菜单命令重新拉起，实测几秒恢复。
- **用 Bridge 的 `ae_open_project` 换工程后，立刻查 7788**，断了就拉起再干活；surehand 的桥接是隐藏扩展、不挂在面板上，理论上换工程更稳，等它实测过再改这里。
- **surehand“在监听”可能是假的。** aerender 每启动一个后台 AE，surehand 的隐藏桥接也跟着起一份、抢到 8765，渲完几十秒就消失；这时调它，命令会进到后台那个 AE 里。判断它连着界面 AE 要同时满足：surehand 安装目录里 `bridge-status.json` 的 `at`（目录见[设备环境](../../../../../../system/environment/computers/desktop-1/README.md)） 在两分钟以内；监听 8765 的进程一路往上是界面 AE 的进程；没有 aerender 在跑。装完或更新完不重启 AE，界面 AE 里根本没有它（2026-11-23 就是这样）。
- **内存是诱因。** 界面 AE 开大工程常占 15—25 GB，再起 aerender 就逼近上限（当晚系统记了一条低虚拟内存事件），面板网页更容易崩。所以界面开着时不用 aerender（见上面挑选表的“渲染”行），AE 私有内存过 20 GB、两个桥接又接连掉线时，存盘后重启一次 AE。

## 操作要点（默认）

两个 MCP 都适用；下面写到的工具名多是 Bridge 的，surehand 有对应工具（`ae_get_project_info`、`ae_get_comp_map`、`ae_render_frame`……）。

- **先读后改。** `ae_project_info` 看所有合成；`ae_comp_tree` 看主合成，找到要改的时间段对应的预合成（如“3分类”）；再往下读卡片、标题的子合成，弄清哪层是素材占位、哪层是文字、哪层是装饰。模板里常有多个同名合成（如 7 个“总合成”），按合成 id 定位，不按名字。
- **延长段落合成后，看原结尾之后的动画，嵌套合成一起延长（默认）。** 把段落合成延长后，要看原结尾之后的动画：模板原本藏在结尾外面的飞出、换图会被露出来。精尺匠造第 8 幕 C 延长后，摄像机飞出关键帧和最后一张卡的第二张图（本身是虚化的）都露出来了，改成删掉飞出、镜头慢推到最后一帧，并关掉那张虚图。图片的缓慢放大只把关键帧挪到新结尾，不要按比例继续放大，否则图片缩到比卡片还小，露出卡底。**嵌套合成也要一起延长**：只改外层合成时长不够，里面的预合成（常是 8 秒）和其中文字、形状层的出点到原长就结束，画面在中途突然只剩空框。驰热固芯 4.3 延长到 8.7 秒后，大面板的证书和文字在第 8 秒消失；改法是递归遍历段落里的预合成，时长短于目标的改长，出点等于原时长的图层一并延长，循环素材（如 8 秒的立方体视频）用 `stretch` 拉到新长度，再在新结尾出一帧确认。
- **先查共用，再决定改原件还是复制。** 模板的图片卡、标题常被多个段落共用：精尺匠造模板的“图片合成01—03”同时用在 2、3、5、6、7、8 分类里。用脚本读每个合成的 `usedIn`：只被本段用的直接改；共用的先 `duplicate()` 出本段专用的一份（如“第4幕卡片01—03”），在本段里换成新合成再改，其他段不受影响。
- **换素材先看素材本身。** 用 ffprobe 看分辨率、帧率、时长，用 cropdetect 查黑边：精尺匠造“机器人本体”1920×1080 上下各带 54 像素黑边，要按有效画面 1920×970 算铺满的缩放，否则卡片顶上露一条黑线。缩放按“铺满卡片”算（取宽高比例里大的那个，再放大 2%—3% 防露边）。
- **素材比卡片显示时间短，用时间重映射放慢铺满。** 卡片显示约 6.7 秒、素材只有 4 秒时，开时间重映射，按“素材时长 ÷ 显示时长”放慢，末帧保持；25 帧素材放慢后开帧混合。“素材不能播完定格”的要求见[动效与节奏 · 停留时间](../video-craft/motion-and-verification.md#停留时间默认)。
- **每改一处就出一帧看。** `ae_render_frame` 跟随合成的预览分辨率（常是 1/4），看字和细节时临时把该合成 `resolutionFactor` 设成 `[1,1]`，看完改回。
- **动了入点，检查出点。** 用脚本改图层入点时，出点可能被带着变短。精尺匠造的箭头把入场提前 0.15 秒后，出点也短了 0.15 秒，建委停在段尾那一帧时箭头已经消失，以为没做。改完时间后读一遍每层的入点和出点，并且在段尾那一帧也出图看。
- **渲染只渲本段。** 用 `ae_render_queue` 加本段的起点和时长；中文版 AE 的模板名要用中文：渲染设置“最佳设置”（传 Best Settings 会报“找不到模板”退出），输出模块“高品质”或“H.264 - 匹配渲染设置 - 40 Mbps”，可用 `ae_catalog` 查 `render_templates`、`output_templates`。渲染完用 ffmpeg 核对帧数、抽帧拼图、逐帧查亮度确认没有黑帧再交。
- **改完属性以出帧为准，不以工具返回的“after”为准（默认）。** 2026-11-24 驰热固芯 4.1：Bridge `ae_set_property` 改了照片卡和空对象的位置、缩放，返回值和读回都是新值，`ae_render_frame` 出的帧却还是旧版面，清缓存、存盘都没用；而改“启用”开关立刻生效。用 `ae_run_jsx` 对同一属性先 `setValue` 一个差 0.01 的值、再设目标值，渲染才更新。所以每改一处都出帧对照；出帧和设的值对不上，就这样重设一次再看。原因没查明，在 2.2 的三维层上同一工具是正常的。
- **建委在 AE 里手动改过之后，先读回数值再继续。** 建委直接在源文件上调的字号、位置就是这单的标尺：读出来换算成成片里的尺寸，写进下面的设计判断，后面同类改动照这个比例做。
- **换色按色相整体换。** 先遍历所有颜色属性（形状填充和描边、“填充”效果、文字填充、文字动画器颜色，含关键帧），只挑偏红的那些，色相改成目标色、饱和度和明暗保留；不要逐层手改，也不要只加一层调色，那样白色和光效也会被染。
- **换字后必查版式。** 模板的框按样例字数设计（人名条大多是两三个字），字数一多就出框、压到后面的职务，而且文字常是右对齐，越长越往左伸。按字数缩小字号、把后排文字右移，再出静帧确认。
- **素材放进 AE 里一起合成**，不要导出透明层到外面叠：模板光效多是叠加模式，单独导出会带黑底。

### 工程与图层

- **换工程后要在面板点“Use current”**，把沙箱指到当前工程，否则写操作全被拦（读和渲染不受影响）。
- 形状图层里**先建的组显示在上层**。先建圆底、后建箭头，箭头会被圆底盖住，要把箭头组 `moveTo(1)`。
- **32 位或 16 位色深的工程，`ae_render_frame` 出的预览会整体发暗或失真**，aerender 成片正常。预览时临时把 `bitsPerChannel` 切到 8，出片前切回原值再保存。
- 文字层被关闭但仍在画面上出现，多半是它被当作轨道遮罩，真正显示的是下面那层；要关掉的是用它做遮罩的那一层。
- **脚本每次另存一个新文件名，不覆盖正开着的工程（默认）。** 同一个 aep 打开后再存回原名，偶尔会因文件被占用存不进去：AE 弹出“无法将文件重命名”，脚本卡在弹窗上直到超时，目录里留下“名字.进程号.aep”临时文件。每次改完都存成 _v(N+1)，弹窗出现时先读弹窗文字再处理，不盲目重跑。
- **父合成统一染色的子合成里不放彩色底板（默认）。** 有的模板把一整组文字合成交给上层用填充、渐变统一着色（驰热固芯 4.3 的“文字修改01”），在里面加的浅色底条会被染成和字一样的蓝，字就被盖没了。要加底板，放到着色之外的合成里；放不了就只改字号、字距。
- **放大、挪动带轨道遮罩的层，遮罩层要一起动（默认）。** 模板里卡片、图片常用一段视频（蜂窝、粒子转场）做轨道遮罩，遮罩层是关着的、不显眼。只把卡片挂到空对象上放大，遮罩还在原大小，卡片边缘和标签就会被切掉（驰热固芯 2.2 第一次放大卡片时就是这样）。把卡片和它上面那层遮罩一起挂到同一个空对象；遮罩是视频而卡片要停留更久时，给遮罩开时间重映射、延长出点停在最后一帧，否则遮罩播完卡片就消失。同理，形状层按比例收放时先看锚点在哪：锚点不在要固定的那条边上，收窄后整个框会往锚点方向缩，要同时平移位置（4.3 合作意向蓝框）。
- **3D 内容层之间夹着 2D 层，就会“穿模”（默认）。** AE 里 2D 层会把 3D 层分成前后两组分别渲染：模板的飘带、光影是 2D 视频层，夹在几份 3D 内容层中间时，看起来一半在内容前面、一半在后面（驰热固芯 4.1 蓝色飘带盖住 logo 和胶囊、却在标题下面，建委说“穿模了”）。改法是让它整体在前或整体在后：要露出内容就把飘带连同它的遮罩层一起挪到所有内容层下面。

### 字体与文字

- **旧版本模板打开时会弹“需要从旧版本转换”和“解析字体”提示框**，挡住后续脚本，要先点确定。缺的字体（如包图粗黑体、ZhenyanGB）会被换成默认衬线体，模板的粗黑斜体质感就没了：用 fontTools 查本机字体的 PostScript 名，换成气质最接近的（精尺匠造用优设标题黑 YouSheBiaoTiHei 替代包图粗黑体）。**回退是静默的**：提示框点掉以后界面不再报错，成片里就是一行衬线体。精尺匠造第 15 幕论文、奖项模板用的 PangMenZhengDao-3（庞门正道标题体 3.0）本机没装，数字行一直是衬线体，到 v2 都没发现。所以开工前用脚本列出本段每个文字层的字体名，和本机字体的 PostScript 名逐个对（用 `fontTools` 读系统字体目录和用户字体目录），不在的立刻换。换完从日志读回字体名确认。
- **脚本新建的文字层先对齐锚点再摆位置（默认）。** 在部分模板工程里用 `addText` 新建的文字层，会带上工程默认的段落缩进，左对齐的字实际从“位置 + 约 120 像素”才开始画，整栏往右偏出画面（驰热固芯 4.2 第一版右侧标题和指标卡被裁掉）。建完立刻读 `sourceRectAtTime`，把锚点 x 设成文字框左边（居中对齐设成框中心），再按画面坐标摆；数字后面跟单位时，单位的 x 用数字层实测宽度算。
- **改文字层位置先看锚点和动画器（默认）。** 模板文字层的锚点常不在 0，算位置要用“位置 − 锚点 + 文字框左边”；复制出来的文字层会带着模板的文字动画器（字距、逐字偏移），改了字距不生效、字被拉开。新做的大字先删掉动画器、锚点归零再排；书法体单字的字面左右空白差别大（“专”右侧空很多），两个字拆成两层分别摆，看起来才等距。

### 素材

- **模板的离线素材先重新链接（默认）。** 模板作者常用自己电脑上的绝对路径，打开后是彩条。读每个素材的 `missingFootagePath`，在模板自带的“(素材)”文件夹里按文件名找到后 `item.replace()`。模板开头的“转场光效”“Light Flash”这类白闪层、模板音乐一并关掉。
- **工程引用的素材要放在项目文件夹里，不留在临时目录（默认）。** AI 在临时目录处理过的照片、签名、表格图，交付前复制到工程旁的“第N幕画面X素材”文件夹并重新链接，否则临时目录一清理工程就断链。复制时**保留子目录结构**：不同临时目录里常有同名文件（如两个 pt_1.png 分别是总裁和专家照片），按文件名平铺会互相覆盖链接。

## 渲染与出片（默认）

- **改完先存盘，再复制渲染副本（默认）。** aerender 读的是磁盘上的 .aep，AE 界面里没存的改动不会进成片（精尺匠造第 15 幕奖项 v4、v5 成片和 v3 一模一样，就是渲染副本在存盘前复制的）。做法：脚本末尾 `app.project.save()`，之后才复制副本或开始渲染。成片和工程同一帧对照、黑帧、接缝怎么查，见[出片检查 · 成片检查](../video-craft/verification.md#成片检查默认)。
- **AE 界面开着时不要跑 aerender（默认）。** 打开大模板的 AE 界面会占 15 GB 以上内存，aerender 同时渲染时报“无法分配内存”或出黑帧。渲染前先用脚本正常退出 AE（`app.quit()`），等不到再 `taskkill /F /IM AfterFX.exe`，渲完再开界面改下一处。
- aerender 某一块超过十分钟没有新帧、进程内存只有几 MB，就是卡在了弹窗或许可上：结束整棵进程树（`taskkill /F /T /PID 父 bash`，只杀 aerender 会被脚本的重试循环重新拉起），改用 AE 面板的后台渲染。
- aerender 一次渲染较长的合成会内存不足，**中途帧直接变黑而不报错**（实测 9 秒在 6 秒后全黑）。按 `-s/-e` 分段渲染再拼接（拼接要重新编码、查黑帧的命令和接缝检查见[出片检查](../video-craft/verification.md#成片检查默认)）。块多大看模板：普通 1080p 模板 1.5 秒左右一块；里面套了 4K 模板（如 3840×2160 的星空时间线）的段落，一个进程只能出 10—14 帧好帧，之后全黑，要按 **10 帧一块**渲，每块渲完立刻查，有黑帧就重渲这一块。渲之前 `app.purge(PurgeTarget.ALL_CACHES)`，渲染期间不要在 AE 里预览。

### 在 AE 里定位闪的层（默认）

频闪怎么查（逐帧亮度、RGB 均值、光点区域裁图）见[出片检查 · 频闪与转场](../video-craft/verification.md#频闪与转场默认)，画面里能不能闪、淡化多长见[动效与节奏 · 转场](../video-craft/motion-and-verification.md#转场默认)。查出在闪以后，在 AE 里这样找到是哪一层：

- 定位方法：在 AE 里用 `comp.saveFrameToPng(时间, 文件)` 出相邻两帧，用 Python 做差值图看哪块在变；再逐层关掉可疑层重出这两帧，二分到具体层。注意 `saveFrameToPng` 是异步的，要等文件写完再读。
- 精尺匠造第 14 幕查到的两个原因：一是模板里的 **Element 3D 层（效果名 VIDEOCOPILOT 3DArray，图层多叫 el）渲染时隔帧不一致**，整屏背景在两种样子间切换，好帧里它几乎不贡献画面，直接关掉；二是用作遮罩、光效的 **H.264 视频素材**（转场过渡遮罩.mp4、照片亮光.mp4）解码偶发出错，整张图片预合成某几帧消失，用 ffmpeg 转成 PNG 序列后 `replaceWithSequence` 替换，帧率按原视频设（25 或 30，别统一写 25），带透明的 mov 设预乘 Alpha。
- aerender 和 AE 界面结果可能不一样：界面导出平稳、命令行渲染在闪时，两边都要查，以命令行成片为准。
- **找真正的闪的层：逐层开关、比每帧 RGB 均值，不凭猜（默认）。** 精尺匠造第 14 幕 v3 建委说照片墙“会变色、一闪一闪”，我只关了粒子层，关错了。正确做法：对同一段用 `saveFrameToPng` 在多个时刻出图，一次只开或关一个层，比较整帧 R、G、B 平均值（只看亮度 YAVG 会漏掉色相、颜色脉动）；某层开着时 RGB 来回起伏（本例 R 97.8→105.8→101.1）、关掉就平，该层就是元凶。本例元凶是相加混合的“光影.mp4”（35%），不是粒子。修完后对成片逐帧取 V（或 RGB）通道，相邻差应接近 0（本例 0.22）。

## 后备：命令行脚本（只在两个 MCP 都不可用时）

前提见上面[先用 MCP 自带的工具](#先用-mcp-自带的工具不自己写脚本默认)第 4 条。

运行方式：`AfterFX.exe -r 脚本.jsx` 带界面执行脚本（`-noui` 实测不执行），脚本末尾 `app.quit()`；`aerender.exe -project 工程.aep -comp 合成名 -output 输出路径` 命令行渲染。运行期间不要手动操作 AE。

- **AE 跑脚本、渲染全程不要人点弹窗：先拉起常驻弹窗守护（默认，建委要求）。** 建委的原话是“一定要脱离人，我只负责最后的验收，中间的过程不需要我做任何的参与”。AE 会弹三类框，不点掉脚本就停住、表现为超时：被强行结束后再启动的“崩溃修复选项”（点“继续”，不点安全模式、重置首选项）、缺字体的“解析字体”（点“确定”）、文件改名失败等“After Effects 警告”（点“确定”）。做法：跑 AE 前先启动 [tools/ae_dialog_guard.py](./tools/ae_dialog_guard.py)（`pythonw` 后台常驻、单实例、日志写在脚本旁的 aeguard.log），跑脚本和渲染的封装脚本开头都检查它在不在、不在就拉起。守护只认 AE 进程的小窗口，按“继续、确定、关闭”的顺序点；**凡是弹窗文字里有“保存”一律按 ESC 取消，绝不按回车**（回车默认是“保存”，会把半成品覆盖进旧版本工程）。崩溃报告 WerFault 出现就结束它。另外关 AE 用脚本 `app.project.close(DO_NOT_SAVE_CHANGES)` 加 `app.quit()`，等 60 秒还没退再强杀，少触发崩溃修复框。反例：驰热固芯第 5 轮旧守护跑 550 秒就退出，AE 重启后没人点框，建委只能盯着手动点；新守护第一版对“是否保存”按了回车，把宝钛 v5 工程覆盖成半成品，靠脚本删掉新增项、重新打开关掉的图层才恢复。正例：同一轮改完后连续开关 AE 十几次、渲染十几段，没有一次要人点。**守护只在自动化运行期间生效，平时不碰任何弹窗（默认，建委要求）**：建委手动用 AE 时点的弹窗，常驻守护也会抢着关掉，影响正常操作。所以守护按一个标记文件判断：跑脚本、渲染的封装脚本开始时创建脚本旁的 `guard.active`，等待期间每几秒刷新一次，结束时（含出错退出）删掉；标记不存在或超过 60 秒没刷新，守护什么都不做。反例：驰热固芯第 7 轮建委发现“我现在手动地去点击关闭，也会被脚本识别到，然后直接把弹窗给我关掉”，日志里有一条在他手动关闭工程时按 ESC 取消了“是否保存”。
- **无人值守跑一连串脚本时，每个脚本自己开工程、另存新版本（默认）。** AE 跑完一个脚本常会崩溃重启，留下空工程；工程有未存改动时再 `app.open()` 会弹“是否保存”框，把后面的脚本全部挡住（表现为脚本超时）。做法：脚本开头先 `app.project.close(CloseOptions.DO_NOT_SAVE_CHANGES)` 再 `app.open()` 本轮的工程，末尾 `save(new File(..._vN+1.aep))` 另存递增版本；同名覆盖保存常因文件被占用改名失败并弹框。保存前读一下 `numItems`，防止把崩溃后的空工程存进去。驰热固芯第 2—6 幕一晚跑了几十个脚本，按此做后没有再丢改动。
- ExtendScript 里字符串直接拼日期、数组会报错，先 `.toString()`。
