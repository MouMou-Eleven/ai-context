# 微课交互式制作工作台

- ID：`interactive-video-production-workbench`
- 主归属：微课与教育交互
- 状态：当前采用，仅适用于微课。
- 范围校正：2026-09-18，建委明确本方法不属于视频共用，不适用于宣传片或一般视频；迁移原因见[修订记录](../revisions/2026-09-18-competition-and-microcourse-scope.md)。
- 确认依据：2026-09-15，建委根据《小树叶》制作页面的实际使用，确认交互式工作台比纯文档更直观、便于执行；随后明确工作台必须按本次已有素材设计，不能默认所有微课都有音频。
- 验证程度：《小树叶》音频驱动页面已实际完成分段音频播放和提示词复制检查；“只有逐字稿”“只有教学设计”“教学设计加逐字稿”等形态的页面结构已由建委明确，但尚待具体项目复用验证。

## 什么时候使用

当一个微课需要把教学设计、逐字稿、音频、分镜、参考图、提示词和修改记录组织成可执行流程时，可以制作交互式工作台。先盘点本次真实素材，再决定页面模块。它适合以下任务：

- 只有教学设计，需要先按教学环节转成画面任务；
- 只有逐字稿，需要拆出“哪一句对应什么画面”；
- 同时有教学设计和逐字稿，需要先建立教学环节、讲述内容和画面的对应关系；
- 已有歌曲、旁白或课程音频，需要按实际时间段制作对应画面；
- 每个制作单元同时存在场景图提示词、视频提示词、参考图职责和验收条件；
- 操作者需要频繁预览素材、复制提示词、切换单元并记录返工状态；
- 需要让客户、制作人员或后续 AI 快速理解整片结构，而不是在长文档中来回查找；
- 一个项目会经历多轮生图、生视频和后期修改，需要保留每段的当前版本和问题。

本方法不适用于创赛宣传片、企业宣传片、普通视频或故事影片；不能因这些任务也有逐字稿、音频或多镜头就自动调用。

以下微课情况可以不做完整工作台：只有一两个简单镜头、素材关系很少、一次交付即可完成时，用短分镜表和文件夹即可。工作台是制作控制界面，不是最终给观众播放的成片，也不能代替剪辑软件、素材存储或项目事实记录。多人实时协作、云端权限、审核流和数据库统计属于应用开发，应另行设计系统。

## 核心定位

纯文档适合说明方法，工作台适合执行项目。两者承担的任务不同：

| 载体 | 主要作用 | 保存内容 |
|---|---|---|
| 方法文档 | 告诉 AI 和制作人员“这类工作怎样做” | 原则、步骤、模板、边界和验收方法 |
| 项目案例 | 记录“这次项目实际发生了什么” | 输入、选择、失败修正、结果和证据 |
| 交互式工作台 | 支持“现在逐单元制作和检查” | 已有教学素材、分镜卡、参考图、提示词、状态、版本和操作按钮 |

工作台不是把 Markdown 换一种皮肤展示。每个交互都应减少一次查找、复制、定位或误用素材的成本。

## 一、先按现有素材选择制作主线

音频不是必备输入。收到材料后先判断属于哪一种形态，再决定工作台怎样拆分：

| 现有素材 | 制作主线 | 分镜拆分依据 | 工作台应重点展示 |
|---|---|---|---|
| 只有教学设计 | 教学环节 | 教学目标、导入、讲解、示范、练习、总结等实际环节 | 环节目的、教师与学生行为、知识点、画面方案、提示词和待补讲述内容 |
| 只有逐字稿 | 讲述内容 | 按完整语义、画面变化和可理解停顿拆成句段 | 原句、画面对应、镜头动作、生图提示词、视频提示词和预计时长 |
| 教学设计 + 逐字稿 | 教学环节与讲述内容对应 | 先按教学环节归组，再在环节内拆逐字稿 | 环节目标、对应原句、画面、镜头和提示词，检查有无漏讲或画面错配 |
| 已有音频 | 实际时间轴 | 以试听和波形确认的起止点拆分 | 时间码、分段试听、歌词／旁白、画面和提示词 |
| 音频 + 逐字稿／教学设计 | 实际时间轴加内容映射 | 以音频定时长，以文本和教学设计定语义与画面 | 时间码、对应原句、教学作用、试听、镜头和提示词 |

教学设计通常不能直接一段对应一个生成视频。先把每个教学环节拆成可看见的画面任务：谁在什么环境中做什么，观众需要看懂哪个知识点，适合AI生成、实拍、录屏、图表、字幕还是后期动画。逐字稿也不能机械地“一句话一镜头”；同一视觉动作可以承接相邻短句，主语、地点、时间、知识点或情绪发生变化时再切换画面。

没有音频时，先用预计时长支持画面数量和节奏规划，并明确标记为“暂定”。预计时长可以依据逐字稿试读、计划配音速度或教学设计中的环节时长产生；配音或录音完成后，必须用实际音频重新校准时间码和镜头长度。

## 二、建立单一数据源

完成素材识别和分镜拆分后，再生成页面。页面数据应来自一份结构化清单，例如 JSON、JavaScript 对象或表格导出，避免在导航、卡片和提示词区分别手工维护同一内容。制作单元可以是音频段、逐字稿句段或教学环节，但同一项目应采用稳定编号。

每个制作单元至少包含：

| 字段 | 必须表达的内容 |
|---|---|
| 单元编号与标题 | `P01`、本单元的教学、动作或叙事名称 |
| 位置与时长 | 有音频时记录实际时间码；无音频时记录教学环节顺序、原文位置和暂定时长 |
| 内容依据 | 逐字稿原句、教学设计原环节、歌词、旁白、知识点或“纯音乐转场”；保留原文，不靠概述替代 |
| 叙事作用 | 建立环境、解释知识、推进动作、表达情绪或完成转场 |
| 起始与结束状态 | 承接上一单元，并为下一单元留下明确状态 |
| 单元内镜头 | 一次生成或一个连续画面段内的镜头顺序、景别、主体动作和结束画面 |
| 制作方式 | 文生视频、关键图加图生视频、实拍、录屏、AE、Remotion或后期合成 |
| 参考资产及职责 | 每张图负责角色、风格、场景、首帧或目标状态中的哪一项 |
| 图片与视频提示词 | 根据本单元需要提供可复制文本；不需要AI生图或生视频时写明实际制作方式，不制造空提示词 |
| 验收条件 | 本单元必须看到什么、绝不能出现什么 |
| 制作状态 | 待准备、待生图、待生视频、待复核、需返工、已通过 |
| 结果与修改记录 | 当前文件、版本、失败原因和下一步修正 |

提示词正文只保存一份。页面显示、复制按钮和导出的 TXT 应从同一字段生成，防止页面中的提示词与实际上传版本不一致。

字段分为共用字段和条件字段。单元编号、内容依据、画面设计、制作方式、验收与状态属于共用字段；音频地址、实际时间码、试听按钮只在有音频时出现；教学目标、师生活动只在教学设计提供这些内容时出现。页面不能显示一排不可用的音频按钮来暗示素材缺失。

## 三、页面信息结构

### 1. 项目总览

页面顶部先让操作者确认当前项目，而不是直接落入一大段提示词。建议展示：

- 项目名称、画幅、视觉风格、目标平台与当前版本；有可靠时长时再显示总时长；
- 本次已有素材及状态，例如教学设计、逐字稿、音频、参考图和客户要求；
- 已通过、待制作、需返工的段数；
- 全片共用的角色资产、风格锚点和禁止项；
- 本轮最重要的制作说明，例如“当前按逐字稿语义拆分，时长暂定”或“已有音频是最终时间线”。

### 2. 制作单元导航

用 `P01—P09` 一类稳定编号建立目录、时间轴或标签导航。每个编号显示标题、素材位置或时间范围，以及状态文字，点击后定位到对应分镜卡。URL 锚点应可直达某一段，例如 `#P03`，方便反馈时直接指向问题位置。

状态颜色只做辅助，必须同时显示文字，避免只靠红绿判断。编号在项目中保持稳定；调整时长不随意重排编号，确需新增时可以使用明确的新编号并同步全部导出物。

### 3. 一单元一张执行卡

每张分镜卡建议按实际操作顺序排列：

1. 单元位置与内容依据：逐字稿原句、教学设计环节或实际时间码；有音频时才显示试听按钮；
2. 本段叙事作用、起始状态、结束状态和段内镜头；
3. 参考图缩略图及每张图的职责说明；
4. 场景图提示词和复制按钮；
5. 整段视频提示词和复制按钮；
6. 硬约束与验收清单；
7. 当前结果、失败原因、修改记录和制作状态。

这样操作者可以先核对当前原文或教学环节；有音频时再试听，然后判断画面并复制提示词，不需要在教学设计、逐字稿、音频文件夹、分镜文档和多个 TXT 之间来回切换。

### 4. 详情按需展开

常用信息保持可见，较长提示词、失败记录和历史版本允许折叠。默认展开当前要执行的内容，避免所有长文本同时铺开造成滚动负担。桌面端可以使用“左侧分段导航 + 右侧内容卡”；窄屏改为单列，按钮保持足够大的点击区域。

## 四、共用交互与条件交互

### 素材原文与画面的对应查看（必备）

- 每张卡保留对应的逐字稿原句、教学设计原环节、歌词或旁白，不能只显示AI概括；
- 原文、画面设计和提示词彼此邻近，能直接检查“这句话为什么配这个画面”；
- 支持从导航定位制作单元，并能看到上一单元和下一单元的内容关系；
- 只有教学设计而没有逐字稿时，明确标出需要画面表达的教学目标、教师行为、学生行为或知识点；
- 输入材料没有提供的内容标记为待补，不让AI自行编造教学事实或讲述台词。

### 分段音频播放（有音频时启用）

- 每张卡播放对应裁切音频，并显示该段时间范围和实际时长；
- 同一时间只播放一个音频，切换段落时停止上一段；
- 播放失败要显示具体提示，不能点击后毫无反应；
- 原始音频与分段音频分开标识，防止把全曲当成本段素材上传；
- 浏览器通常限制自动播放，页面应由用户点击后开始播放。

没有音频时不显示播放控件，也不把“无法试听”当作页面缺陷。页面改为显示原文定位、暂定时长和“待配音／待录音”状态；获得音频后再增加时间码与试听模块。

### 一键复制

- 图片提示词、视频提示词分别设置按钮，按钮紧邻对应文本；
- 复制内容必须与界面显示和导出 TXT 完全一致；
- 成功后显示短暂反馈，例如“已复制 P03 视频提示词”；
- `navigator.clipboard` 不可用时提供文本选择或兼容回退，不能让按钮静默失效；
- 不把标题、按钮文字或折叠说明混入复制内容。

### 参考图查看

- 显示缩略图、文件名和职责，例如“只锁定主角形象，不复制背景”；
- 点击可放大查看，缺图时显示缺失文件名；
- 每段只列剧情需要的资产，不能因为全片存在某角色就默认上传；
- 错误参考图标记为停用，不继续出现在正式视频参考列表。

### 状态与问题记录

- 状态必须表达当前制作动作，而不是模糊的“处理中”；
- 返工单元记录问题、判断依据和下一次只改什么；
- 当前采用版本与废弃版本分开，页面默认展示当前版本；
- 只有实际看图、播放视频或检查导出结果后，才能标记“已通过”。

搜索、筛选、全局进度、批量导出和版本对比属于增强功能；只有项目规模需要时再增加，不能让装饰性功能压过原文对应、提示词、看图和验收。

## 五、工作台怎样进入制作流程

1. **读取输入**：核对教学设计、逐字稿、音频、客户要求、平台、画幅和交付格式；列出实际存在与缺失的素材。
2. **选择主线**：按素材形态选择教学环节、逐字稿语义句段、实际音频时间轴或混合映射，不能默认以音频分段。
3. **建立制作单元**：保留原文，写清本单元的教学或叙事作用、对应画面、预计或实际时长，以及与前后单元的关系。
4. **设计资产**：建立可复用角色与风格资产，并按当前画面需求准备场景关键图。
5. **写入单一数据源**：把原文、位置、镜头、参考职责、图片提示词、视频提示词和验收条件放入同一条记录。
6. **生成工作台**：由数据渲染导航和分镜卡，同时生成对应 TXT 或清单；只启用当前素材支持的模块。
7. **逐单元制作**：核对原文；有音频时试听；查看参考职责并复制需要的提示词，完成生图、生视频或其他制作。
8. **回填与复核**：登记结果文件、失败原因、修正内容和状态；通过后再进入下一单元或后期。
9. **获得音频后校准**：原先只有教学设计或逐字稿时，将暂定时长改为实际时间码，必要时合并、拆分或调整镜头。
10. **最终剪辑**：以最终旁白、歌曲或成片时序对齐全部镜头；工作台状态不能代替成片验收。

需求、分镜或提示词变化时，先改数据源，再重新生成或刷新页面。不要只改页面可见文字却留下旧 TXT，也不要只改 TXT 而让工作台继续复制旧版本。

## 六、本地 HTML 的实现与交付边界

静态单页 HTML 适合本地、轻量、无需登录的制作包。建议使用相对路径组织音频、图片和提示词文件，保证整个文件夹移动后仍能运行。中文文件名和空格必须经过实际浏览器请求测试，不能只检查文件存在。

直接用 `file://` 打开时，浏览器可能限制音频、模块脚本或剪贴板权限。正式交付应提供一条简单的本地 HTTP 启动方式，例如在制作包目录运行：

```powershell
python -m http.server 8765
```

然后访问 `http://127.0.0.1:8765/页面文件名.html`。端口只是示例，占用时可以更换。页面不能写死某台电脑的绝对路径，也不能把客户隐私或本机目录暴露在对外交付版本中。

如果需要多人同步状态、云端保存结果、权限管理或在线审核，静态 HTML 不再足够，应进入应用开发流程。`localStorage` 只适合保存单机偏好或临时状态，不能当作可靠的项目数据库。

## 七、视觉与可用性要求

- 先突出单元编号、原文或教学环节、位置／时间和当前动作，再显示说明性文字；
- 提示词使用便于选择和阅读的等宽区域，但字号不能过小；
- 图片提示词与视频提示词使用稳定标签和不同按钮，不能只靠颜色区分；
- 参考图、提示词和验收条件在同一张卡中保持邻近，减少错误上传；
- 长页面保留当前位置反馈，返回导航后仍能知道正在处理哪一段；
- 交互状态包含默认、悬停、按下、成功、失败和不可用；
- 适配常见桌面宽度和手机窄屏，不能通过水平滚动才能看到复制按钮；
- 装饰、渐变和动画服务于层级，不能抢过素材原文、分镜和操作入口。

涉及实际前端开发时，同时读取[前端 UI 质量标准](../../../development/experience/frontend-ui-quality-standards.md)，检查响应式、键盘、触控、加载和错误状态。

## 八、交付前实际验收

| 检查项 | 通过标准 |
|---|---|
| 素材覆盖 | 教学设计环节、逐字稿句段或音频内容均有去向，无意外漏项和重复；页面保留可核对的原文依据 |
| 音频与时长 | 有音频时检查全部时间码、播放、暂停和切换；无音频时不显示无效控件，暂定时长明确标记，不能冒充最终时间码 |
| 提示词复制 | 图片和视频按钮逐个抽查；复制内容与当前页面及导出 TXT 一致 |
| 参考图 | 缩略图可加载、可放大、职责明确；停用图不出现在正式列表 |
| 导航 | 段号、锚点、上一段／下一段跳转正确，刷新后能定位指定段落 |
| 分镜完整 | 每个制作单元都有内容依据、教学／叙事作用、起止状态、制作方式和验收条件 |
| 状态可信 | “已通过”有实际媒体检查依据，返工项写清问题和下一步 |
| 响应式 | 桌面与窄屏内容不遮挡，按钮可操作，长提示词不撑破布局 |
| 路径与交付 | 换到交付目录后仍能通过本地 HTTP 打开；无本机绝对路径和隐私信息 |
| 最终成片 | 另行播放成片检查画面、文字、比例、时序和声音；网页检查不能替代成片检查 |

测试不能只看页面是否成功打开。有音频时，《小树叶》已经证明还要通过本地 HTTP 服务逐项测试播放和复制按钮。没有音频时，则要重点核对原文覆盖、分镜对应和提示词复制，不能为了沿用模板伪造音频模块。

## 九、让 AI 生成工作台时的任务骨架

```text
请根据本项目实际提供的教学设计、逐字稿、音频和参考资产，整理一个本地可运行的微课交互式制作工作台。不要假设所有素材都存在。

输入：列出实际收到的教学设计、逐字稿、音频、参考资产、平台要求和当前制作状态，并明确缺失项。

要求：
1. 先判断素材形态：只有教学设计、只有逐字稿、两者兼有、已有音频或混合素材；据此选择制作主线。
2. 只有逐字稿时按语义与画面变化拆分；只有教学设计时按教学环节拆成可见任务；已有音频时才使用实际时间码和分段试听。
3. 使用单一结构化数据源生成页面，不在多个区域重复维护同一字段。
4. 页面包含项目总览、制作单元导航和“一单元一张执行卡”。每张卡保留原文依据、画面设计、制作方式、参考图职责、图片／视频提示词、验收和状态。
5. 音频播放是条件模块：有音频才显示并测试；没有音频则显示原文位置、暂定时长和待配音状态，不生成无效按钮。
6. 支持查看参考图、复制实际需要的提示词、URL锚点直达，并显示待制作、需返工和已通过状态。
7. 使用相对路径，提供本地HTTP启动说明，不写死本机绝对路径；桌面和手机窄屏均可操作。
8. 交付前检查输入覆盖、原文与画面逐项对应、复制内容、图片路径、锚点和响应式；有音频时再检查全部播放与时间码，并报告未验证部分。
```

具体项目仍需把真实教学内容、制作单元、素材职责、提示词和平台限制填入任务，不能只给这段骨架让 AI 自行猜测。逐字稿中的每个句段都应有画面去向，但不等于必须为每句话单独生成一个视频；应按连续场景和模型有效时长合理合并。
