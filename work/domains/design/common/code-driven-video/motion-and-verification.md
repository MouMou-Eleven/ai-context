# 动效与验收：代码式视频怎么动、怎么查

排版定好以后，视频比平面多了时间这一维：谁先出来、停多久、跟不跟镜头走。代码实现还有几类固定的坑。本文件写这两部分，以及出片前的验收流程。

## 出场节奏（默认）

- **按信息顺序出场，不要一起出现。** 先出“空间”（坐标、网格、底图），再出“对象”（设备、部件），最后出“关系和结论”（连线、面板文字）。分镜给了时间轴就严格按时间轴。
- **同类元素依次出现**，间隔约 0.08–0.15 秒，比如 6 个定位点依次弹出。一起冒出来像闪了一下，依次出现才看得出“一个个被识别”。
- 单个元素出场 0.25–0.4 秒，用缓出（先快后慢）；弹出类可以带一点回弹。不要用线性匀速。
- 容器出场顺序：边框描出 → 底色淡入 → 标题打字 → 内容出现。文字逐字打出时，整句居中位置按**完整句子**的宽度算，不要边打字边移动。
- 进入稳定状态后保留轻微的循环动效（流光、虚线流动、呼吸光），画面不死，但幅度要小，不能抢文字。
- 不用闪白转场，切换会显得割裂（建委在创赛视频里明确否过）。

## 停留时间（默认）

- 一段文字完整出现后，至少停留到慢慢念两遍的时间，再开始下一段或进入结束。
- 片尾最后的完整画面要有一段稳定停留，不要最后一个元素刚出来就结束。
- 素材比分镜长时，不要随意砍素材；保留完整时长，多出来的时间作为稳定状态，并告诉用户可以再剪。

## 跟着画面走（默认）

- 固定机位的实拍：标注直接按画面坐标放；画面里在动的物体（车、人）要逐帧跟踪，标注跟着走。跟踪可以用模板匹配，每帧更新模板。
- 加了推镜（缩放）时，**贴在场景上的元素**（定位点、坐标轴、连线）要用同一个变换跟着缩放；**屏幕上的界面元素**（面板、字幕、Logo）不跟镜头动。
- 画中画如果从原画面裁取，要用当前帧实时裁，不要用静态截图。

## 代码实现的常见坑（默认）

| 坑 | 表现 | 做法 |
|---|---|---|
| 图层顺序乱 | 面板底色压在画中画上，画中画发灰 | 分层合成：底片 → 面板底色 → 画中画 → 线条和文字 → 发光 |
| 发光算进了图片 | 发光峰值时画中画整块泛白 | 发光只从线条和文字层计算，图片层不参与 |
| 容器尺寸写死 | 内容少时留大块空白，内容多时溢出 | 按[容器跟着内容走](layout-and-sizing.md#容器跟着内容走红线)计算尺寸 |
| 居中按字符数估 | 中英文混排时明显偏到一边 | 先测量实际渲染宽度再定位 |
| 坐标凭感觉写 | 标注偏离目标 | 先抽一帧原画面，在图上量出目标坐标再写 |
| 只在 1080p 预览 | 4K 下线条太细、字太小 | 线宽、字号都按画面高度比例写，用成片分辨率出静帧 |
| 中文字体缺字 | 部分字显示成方框 | 用确实包含中文的字体文件；英文字体只用于字母和数字 |

## 验收流程（红线）

1. **先出静帧再出全片。** 每个阶段结束时各出一张，最终稳定状态一张，用成片分辨率渲染后缩小查看。
2. **按检查表逐项看**：本目录 [README 的交付前检查表](README.md#交付前检查表) + [平面设计原则的检查表](../../graphic/design-principles/README.md#交付前检查表)里适用的几条。发现问题先改再出全片。
3. **全片渲染后，从成片文件里抽帧复查**：编码、调色、发光的问题只有在成片里才看得到。
4. 交付时说清楚：时长、分辨率、每个时间段画面上有什么，以及哪些文案或参数是自己拟的、需要用户确认。

## 返修怎么接（默认）

- 用户用红框、黄框标图时，红框通常是“这里有问题”，黄框是“改成这个大小或位置”。先把框里的问题翻译成可量化的改法（例：“文字按黄框大小” → 文字宽度占容器内宽 85% 左右），再动手。
- 一轮只改被指出的那一类，其他动画、坐标不动；改完在同一时间点出静帧对比。
- 返修中得到的新判断，回写到[排版与尺寸](layout-and-sizing.md)或本文件对应小节，不在案例里另立规则。
