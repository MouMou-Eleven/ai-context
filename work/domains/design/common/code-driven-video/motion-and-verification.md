# 动效与验收：代码式视频怎么动、怎么查

排版定好以后，视频比平面多了时间这一维：谁先出来、停多久、跟不跟镜头走。代码实现还有几类固定的坑。本文件写这两部分，以及出片前的验收流程。

## 出场节奏（默认）

- **按信息顺序出场，不要一起出现。** 先出“空间”（坐标、网格、底图），再出“对象”（设备、部件），最后出“关系和结论”（连线、面板文字）。分镜给了时间轴就严格按时间轴。
- **同类元素依次出现**，间隔约 0.08–0.15 秒，比如 6 个定位点依次弹出。一起冒出来像闪了一下，依次出现才看得出“一个个被识别”。
- 单个元素出场 0.25–0.4 秒，用缓出（先快后慢）；弹出类可以带一点回弹。不要用线性匀速。
- 容器出场顺序：边框描出 → 底色淡入 → 标题打字 → 内容出现。文字逐字打出时，整句居中位置按**完整句子**的宽度算，不要边打字边移动。
- 进入稳定状态后可以保留轻微的循环动效（流光、虚线流动），画面不死，但幅度要小，不能抢文字。动作要有内容依据：讲“数据流动”就让光点沿线跑；找不到对应动作的画面宁可静着，不为了“不静止”给物体加漂浮、呼吸。
- **节奏宁慢勿快。** 第一版几乎总是偏快：初版默认放慢一档；模拟真实操作（打字、筛选、点击）按真人速度走，看的人要能跟着做一遍。
- 速度感来自加速度，不来自匀速快：批量元素入场可以越来越快，满屏后停一下再切。

## 转场（红线）

- 版式不同的两个画面，前一个完全淡出后，后一个再淡入，不叠在一起。片头标题完全退场后正片画面才进来；片尾文字等前一画面退场后才出现。只有同一面板里内容连续变化时才用叠化。反例：片头“文有回声”大字压在已经出现的聊天面板上。
- 不用闪白转场，切换会显得割裂（建委在创赛视频里明确否过）。
- 镜头要稳：不加手持抖动；配强节奏音乐时，卡点只动主角元素，不逐拍震整个画面（整画面的冲击全片最多两三处）。

## 停留时间（默认）

- 一段文字完整出现后，至少停留到慢慢念两遍的时间，再开始下一段或进入结束。
- **每个画面的最后一个元素落定后，停 1—1.5 秒再离场**：停留期间不加新元素、不运镜。“入场就停着不动”和“刚落定就切走”都是毛病，前者显得死，后者让人看不清。
- 片尾最后的完整画面要有一段稳定停留，不要最后一个元素刚出来就结束；标题、品牌名这类要让人记住的画面停满 1 秒以上。
- 素材比分镜长时，不要随意砍素材；保留完整时长，多出来的时间作为稳定状态，并告诉用户可以再剪。

## 跟着画面走（默认）

- 固定机位的实拍：标注直接按画面坐标放；画面里在动的物体（车、人）要逐帧跟踪，标注跟着走。跟踪可以用模板匹配，每帧更新模板。
- 加了推镜（缩放）时，**贴在场景上的元素**（定位点、坐标轴、连线）要用同一个变换跟着缩放；**屏幕上的界面元素**（面板、字幕、Logo）不跟镜头动。
- 画中画如果从原画面裁取，要用当前帧实时裁，不要用静态截图。

## 特效的分寸（默认）

- **每一屏一个主角，光跟着主角走。** 发光、光晕、扫光只给这一屏最重要的那一个元素；配角、标签、说明字不发光。重点转移时，前一处的光先灭。
- **高光特效宁缺毋滥。** 扫光、泛光划过、闪烁不群发（“不需要每个卡片都闪一下”）；全片最贵的那一招只给最核心的一两个时刻。光效要被它所在的圆角框裁住，溢出圆角显得廉价。
- **一种手法全片只当一次主角。** 飞入、堆叠、翻页这类手法，某一处用它当高潮，其他地方就不要再当高潮用；同一个信息、同一段素材全片只出现一次。

## 代码实现的常见坑（默认）

| 坑 | 表现 | 做法 |
|---|---|---|
| 图层顺序乱 | 面板底色压在画中画上，画中画发灰 | 分层合成：底片 → 面板底色 → 画中画 → 线条和文字 → 发光 |
| 发光算进了图片 | 发光峰值时画中画整块泛白 | 发光只从线条和文字层计算，图片层不参与 |
| 容器尺寸写死 | 内容少时留大块空白，内容多时溢出 | 按[容器跟着内容走](layout-and-sizing.md#容器跟着内容走红线)计算尺寸 |
| 居中按字符数估 | 中英文混排时明显偏到一边 | 先测量实际渲染宽度再定位 |
| 坐标凭感觉写 | 标注偏离目标 | 先抽一帧原画面，在图上量出目标坐标再写 |
| 只在 1080p 预览 | 4K 下线条太细、字太小 | 线宽、字号都按画面高度比例写，用成片分辨率出静帧 |
| 中文字体缺字 | 部分字显示成方框 | 用确实包含中文的字体文件；英文字体只用于字母和数字 |

## 验收流程（红线）

只看几张静止帧不够：转场重叠、滚动中错位的框、某几帧压住文字，静帧里都看不到（文有回声第二版就这样被打回）。

1. **先出静帧再出全片。** 每个阶段结束时各出一张，最终稳定状态一张，用成片分辨率渲染后缩小查看。
2. **画面里有会动的元素时，跑逐帧自动检查。** 用程序每 0.1 秒记录一次所有面板、卡片、标签、框、文字块的屏幕位置，检查：卡片互压、卡片压面板、标签骑在面板边上、框交叠、框出面板、元素出画或进入安全区以外、框找不到要框的内容。结果必须是 0 处才渲染成片。
3. **按检查表逐项看**：本目录 [README 的交付前检查表](README.md#交付前检查表) + [平面设计原则的检查表](../design-principles/README.md#交付前检查表)里适用的几条。发现问题先改再出全片。
4. **挑转场、页面滚动、镜头移动这几种时刻抽帧**，人眼看一遍：是否对齐、是否撑满、层级是否清楚、文字是否完整。
5. **全片渲染后，从成片文件里抽帧复查**：编码、调色、发光的问题只有在成片里才看得到；用户提过问题的时刻和每个框出现的时刻都要截。
6. 交付时说清楚：时长、分辨率、每个时间段画面上有什么，以及哪些文案或参数是自己拟的、需要用户确认。

## 返修怎么接（默认）

- 用户用红框、黄框标图时，红框通常是“这里有问题”，黄框是“改成这个大小或位置”。先把框里的问题翻译成可量化的改法（例：“文字按黄框大小” → 文字宽度占容器内宽 85% 左右），再动手。
- 一轮只改被指出的那一类，其他动画、坐标不动；改完在同一时间点出静帧对比。
- 返修中得到的新判断，回写到[排版与尺寸](layout-and-sizing.md)或本文件对应小节，不在案例里另立规则。
