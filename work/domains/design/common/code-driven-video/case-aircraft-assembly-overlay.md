# 案例：飞机总装厂实拍的空间坐标包装

- 日期：2026-10-29
- 客户 / 受众：大学生创新创业比赛项目视频中的一个镜头（视频四），观众是评委
- 交付物：成片（4K，24fps，5 秒）
- 状态：第二版已交付，客户返修意见已落实

## 要求和限制

- 素材：一段 5 秒的飞机总装厂实拍，固定机位，画面里只有一辆小车在动。
- 分镜给了 4 秒时间轴：切入 → 坐标系出现 → 设备定位 → 构件关键点与空间关系 → 收束；三个面板“设备位置 / 空间关系 / 构件关键点”，说明句里的关键词用橙色强调。
- 之前用 AI 视频模型生成过一版，画面上的文字糊，所以改用代码逐帧绘制。

## 过程

1. 抽帧量出飞机机头、驾驶舱、翼根、翼尖、尾翼和 6 台设备的画面坐标；用模板匹配逐帧跟踪移动的小车。
2. Python（OpenCV + PIL）逐帧绘制，ffmpeg 编码。场景元素（坐标轴、地面网格、定位点、连线）跟着轻微推镜一起缩放；面板固定在屏幕上。
3. 左右面板放实时裁取的画中画（设备区域、机头区域），右侧画中画里再标关键点。
4. 先出静帧检查，再出全片，再从成片抽帧复查。

## 出过的问题和怎么改的

| 问题 | 原因 | 怎么改的 | 改后结果 |
|---|---|---|---|
| 右侧设备标签一半出画；一个标签被坐标轴挡住 | 标签统一放在目标右侧 | 靠边和拥挤的目标改放左侧 | 无出画、无遮挡 |
| 发光峰值时画中画整块泛白 | 画中画放在了参与发光计算的图层里 | 画中画单独一层，不参与发光 | 正常 |
| 拆层后画中画被面板底色压暗 | 面板底色在画中画上面一层 | 合成顺序改为底片 → 面板底色 → 画中画 → 线条文字 | 正常 |
| **客户反馈：面板里留出大块空隙，排版不好看** | 面板高度写死，内容只占一部分 | 面板高度按“标题栏 + 画中画 + 说明条 + 内边距”累加计算 | 空隙消失 |
| **客户反馈：文字太小，要按黄框大小** | 正文 46 px（4K，约 2.1% 画面高） | 正文放大到 72 px（约 3.3%），放进带底色的说明条，宽度约占面板内宽 85%，水平垂直居中 | 客户标注的大小 |
| 放大正文后标题比正文还小 | 标题沿用 64 px | 标题改为 74 px | 层级恢复 |
| 客户要求先去掉底部结论字幕 | 分镜没给结论文案，第一版是自拟的 | 移除 | — |

## 结果

第二版成片交付，客户返修的三点（空隙、字号、底部字幕）全部落实。最终用法、比赛结果未知。

## 这次能复用的做法

- 字号按画面高度换算、间距用正文字号作单位 → [排版与尺寸 · 字号](layout-and-sizing.md#字号按画面高度定默认)、[间距](layout-and-sizing.md#间距用一个单位默认)
- 容器高度由内容算出来 → [排版与尺寸 · 容器跟着内容走](layout-and-sizing.md#容器跟着内容走红线)
- 标签靠边换方向 → [排版与尺寸 · 安全区](layout-and-sizing.md#安全区默认)
- 图层顺序、发光只算线条文字、移动物体逐帧跟踪 → [动效与验收](motion-and-verification.md)
- 只适用于这一单：科技蓝配色、深色半透明面板、流光边框是这条片子的外观选择，不是通用规则。
