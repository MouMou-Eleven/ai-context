# 朋友圈文案

## 负责范围

- 朋友圈短文案、连续多条朋友圈组合和配图说明。
- 个人动态、项目进展、案例展示、观点表达和活动预告。
- 朋友圈中的自然互动与行动引导，不承担直播间实时销售流程。

## 分类边界

- 社群内部通知和群内话术进入 [`../community-copy`](../community-copy)。
- 直播销售和评论区承接进入 [`../live-sales`](../live-sales)。
- 公众号或长篇知识文章进入 [`../articles`](../articles)。
- 跨平台营销结构进入 [`../marketing-copy`](../marketing-copy)。

## 写入要求

- 一条动态只承担一个主要目的：展示结果、表达观点、记录过程或引导一个行动。
- 个人经历、项目事实和待验证判断分开写，不编造数据、客户和效果。
- 语言基础统一读取 [`../../../../system/expression/oral.md`](../../../../system/expression/oral.md)；本目录只维护朋友圈的长度、节奏和上下文呈现。

## 真实成员问题型宣发

适用于新成员加入、咨询或成交时，对方提出了一个能够解释产品定位、课程选择或服务价值的真实问题。它不是简单发布“会员 +1”，也不是借单个成员制造普遍焦虑，而是用一次真实交流说明：对方为什么来、他在意什么、产品为什么这样设计。

推荐顺序：

1. **用真实进展开头**：例如“会员社群 +1”，让读者先知道发生了什么；没有新增或成交事实时不能套用。
2. **只保留一个代表性问题**：尽量沿用对方原意，把长对话压缩成一句读者能理解的话，不拼接多个痛点。
3. **交代问题背后的实际需求**：说明对方想完成的工作或生活任务，不根据职业标签脑补动机。
4. **借问题解释一个产品选择**：例如为什么第一期从 AI 编程开始。回答必须直接对应这个问题，不能转成权益报菜名。
5. **把阶段内容翻译成可迁移能力**：写清当前主题训练的判断、协作或执行能力怎样迁移到其他场景，避免让读者误以为阶段主题就是整个产品边界。
6. **只做一次自然承接**：结尾说明适合什么人以及一个下一步，不同时要求点赞、评论、私信和购买。

可以使用下面的短结构：

```text
一个真实进展
→ 新成员的一句真实问题
→ 他真正想解决的事情
→ 这个问题为什么能解释产品设计
→ 当前阶段内容带走的通用能力
→ 一次自然邀请
```

### 事实、隐私与语言边界

- 私聊截图、头像、昵称、订单、群链接、二维码和语音时长不进入仓库；公开配图前另行脱敏。
- 未经对方明确授权，不写可识别的职业、单位、地点和个人经历；可以改成“不同行业的新成员”等必要概括。
- 单个成员只能证明这次问题真实存在，不能写成“所有人都这样”或用它推导市场效果。
- 价格、周期、权益和课程发布状态必须回具体项目 README 核对。内部设计想法不能直接写成对外承诺。
- 参考其他创作者时学习“事实—问题—判断—承接”的组织方式，不复制标志性句子、夸张预测或身份优越感。
- 表情只用于分段和语气，一条短文案通常使用一至三个即可，不能替代信息层次。

### 2026-09-15 社群新成员案例

- **场景**：一位新成员加入 AI 超级个体陪跑社群前，询问 AI 视频、办公和教育是否都要以网站为基础；他的实际需求包括把 AI 用于个人兴趣、视频制作、日常办公和 PPT 等场景。
- **本次主问题**：为什么社群第一期从 AI 编程开始，而不是直接分别讲每一种应用。
- **回答逻辑**：建委基于长期、高强度、深入使用 AI 的个人经验，认为普通人如果希望较全面地理解 AI，从 AI 编程视角切入比先学习某一个专项应用更合适。AI 编程会把目标表达、背景与资料提供、任务拆分、工具调用、执行、检查和迭代放进一个完整过程，学到的协作方法更容易迁移到办公、设计、视频、教育和日常生活。AI 视频、AI 设计等课程仍有独立价值，但更偏向各自领域的专项知识；因此第一期先建立较完整的 AI 使用视角，后续阶段再分别进入 AI 办公、AI 设计和 AI 视频。这个比较属于建委当前实践判断，不表述为对所有人的客观定律。
- **隐私处理**：仓库不保存原聊天截图、成员身份或订单信息，只记录脱敏后的问题和写法。
- **验证状态**：建委已确认采用这种方式撰写本次朋友圈；实际发布反馈、咨询与转化结果待记录，当前不能宣称这种结构必然提高转化。

后续每个新案例继续注明发布时间、场景、使用的结构、隐私处理和真实反馈；只有重复验证后，才把具体效果提升为稳定经验。
