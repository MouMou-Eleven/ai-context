# 一稿多发标题矩阵

一篇内容值几个标题，取决于它要发几个地方。同一句话铺到四个平台，至少在三个地方是错的。

目标是找出这篇内容里最值得点击、又能被正文及时兑现的那个承诺，再按发布形态分别重写。标题可以有情绪和力度，但不能扩大事实范围。

## 先认模式

| 用户给了什么 | 走哪个模式 |
|---|---|
| 内容、素材、话题，没有标题 | **生成** |
| 已经有标题，问好不好或要求优化 | **诊断**。先给能直接用的改法，再说原题病在哪一层 |
| 几个候选，问选哪个 | **评审**。先排序给理由，候选里已有能用的就直接推荐，别硬补新标题 |
| 一组标题配阅读、播放、点赞数据 | **复盘**。先恢复可比基线，再谈标题 |
| 验证过的标题，明确说存起来 | **收录**。落进本地库 |

认错模式是这类任务最常翻车的地方。用户贴了现成标题却收到一堆无关新标题，等于没干活。

**认完模式再认形态。** 平台名不足以确定产物。用户说「发 X」时先分清是短帖还是长文，这两件事交付的东西完全不同。问不到就两套都给，并标清哪套是哪个。

按需读取。需要各落点细则和字数核验流程，读 [references/platforms.md](references/platforms.md)。需要研究出处、证据分级、账号数据边界，读 [references/evidence.md](references/evidence.md)。走复盘或收录模式，读 [references/review-and-library.md](references/review-and-library.md)。

## 底层模型，内核 × 分发

标题由两件事决定，它们来源完全不同，必须分开处理。

**内核**来自内容本身，一篇内容只有一个，跟发哪儿无关。它回答的是「这里面到底有什么值得被看见的东西」。

**分发**来自平台，每个平台一套，跟内容无关。它回答的是「这个地方的人在什么状态下看到这行字」。

所以流程是**挖一次内核，铺 N 次分发**。反过来做，就会得到四条同义改写，看着是四个标题，实际只有一个。

注意，分发的最小单位是**形态**而不是平台。同一个平台上两种形态的读者状态不同，就要当两个地方处理。X 的短帖和长文是最典型的例子。

## 四条底线

**一、负面框架比正面框架能打，但负面不等于恐吓。**
公开随机实验显示标题每多一个负面词点击率小幅上升，正面词相反；同一份研究拆开情绪后，恐惧类词反而显著降低点击，真正起作用的是失落感。所以用「最差」「别再」「白花的钱」「踩过的坑」「已经失效」，不用「致命」「血崩」「恐怖」。（样本是英文新闻站，方向参考用，不作为打分依据，出处和适用边界见 evidence.md。）

**二、具体性是倒 U 形，越具体不等于越好。**
原本偏抽象的标题加数字和专名会涨，原本已经塞满参数和型号的再加反而掉。所以先判断手上这条在光谱哪一端。一堆抽象名词的标题要落地，一堆参数的标题要留白。

**三、核心信息前置，所有平台无例外。**
每个平台都在某个位置截断，手机端截得更早。最重要的那几个字放最前面，这条同时扛住截断和扫读。

**四、所有被公开的模板都会失效。**
某个短语被公布为最强句式之后，模仿标题几天内泛滥，效果随即归零。关键词也一样，某个模型名或热词在这个季度是流量锚点，下个季度可能是零。**角度库给的是机制，不是台词。** 照抄句式只会产出一股过期味儿。

## 力道纪律，事实不夸大，情绪要给足

这是最容易做反的一条。让模型写标题，最大的风险不在它瞎编，在它太守规矩。「不编造」管的是事实，管不到措辞的力道。74.2 压过 74.0 是事实，写成「把对手摁下去了」也是同一个事实，一个数字都没多，力道完全不同。把「不编造」执行成「不敢用力」，出来的全是准确但克制的说明句，一条都不会爆。

事实层逐项对素材，一个数字一个实体都不许多。措辞层反过来往饱满里写，用素材里最有劲的那个词，用作者自己说过的口语判断，用能画出来的动作。素材说「折磨人」，标题就可以说折磨人；素材说「自己革自己的命」，标题就可以说把自己的旗舰废了。

**但修辞只能加情绪，不能扩大事实。** 按普通读者对整句话的理解来检查，以下五条踩到任意一条就是越界，不是力道。

1. 扩大了比较对象或适用范围。单项跑分领先写成全面碾压，一个任务跑通写成全能。
2. 放大了领先程度、损失或确定性。「小幅领先」写成「甩开一条街」，「可能」写成「已经」。
3. 把仍需人工处理的流程写成全自动。正文里还有人工终审，标题不能说全托管。
4. 把推测、社区反馈或第三方测试写成作者亲测。素材是别人跑的，标题不能写「我实测」。
5. 省略了决定结论成立的关键条件。限定场景、限定版本、限定价格口径丢掉，结论就变了。

举个边界。「某项代码测试高 0.2 分」可以写成「在这项测试里领先」，不能写成「写代码碾压旗舰」。「官方把 API 请求切到新模型」不能自动推成「旧旗舰被废了」，除非素材里作者自己就是这么判断的。

### 把事实和态度分在逗号两边

力道纪律是一条原则，两段式是它的可执行形态，中长标题优先用这个结构。

**逗号前只放事实，逗号后只放态度，后半句不许增加新信息。**

- 「腾讯悄悄上线了 Claude Code，居然还支持微信登录。」
- 「飞书终于支持 Markdown 了，这个最弱的格式却赢下了整个 AI 时代。」
- 「今年高考我让 12 个顶级 AI 一起考了语文和数学，结果有点意外。」

好处是结构上就很难把力道误加到事实身上。写完自检两下。逗号前的部分单独拿出来，每一项都能回素材找到证据吗。逗号后的部分拿掉，前半句还是一句完整的事实陈述吗。两个都是就对了。

后半句是判断、感受、立场或者一个留白，不是第二个事实点。塞两个事实进去就变回了流水账。

### 狠动词给工具，别给作者

修辞化的动词往主位放的时候，主语优先是产品、模型或者事件本身，作者站在旁边看。「AI 杀死了破折号」「它把我整个代码库都偷走了」这类写法冲但不油。换成「我用 AI 杀爆了效率」立刻变味，因为力道落到了自吹上。

同理，第一人称出场时优先承担代价而不是成绩。被封号、浪费了多少 Token、为了省一笔钱折腾了什么，这类比「我做到了什么」更好使，也跟负面框架那条研究对得上。

### 标点，一档二档默认句号收尾

感叹号读起来是在吆喝，句号读起来是在通报一件既成事实，后者更稳也更贵气。**一档和二档默认用句号收尾，不用感叹号。** 三档可以放开，但整组交付里感叹号最多出现一次，对应「允许一处不规整」那条额度。

小红书是例外，20 字硬墙里句号要吃掉一个字，拿 5% 的空间换一点语气不划算，那边默认不收尾。X 短帖是正文不是标题，按正常句子标点走。

多打一个逗号制造停顿是一种低成本的不规整，比感叹号克制。「它的名字，叫 miclaw。」这种写法把产品名单独顶出来，用掉的也是那一处额度。

以上三条来自对一个头部中文 AI 账号三年 352 条公众号标题的结构统计，句号收尾占 87%，带逗号的两段式占 83%。**该样本没有阅读数据，所以这是写法上的结构观察，不是效果结论**，按证据等级五用，不写成规律。

## 标题党的三个档位

先把「标题党」拆开，它实际是两件事。

一种是**承诺正文里没有的东西**，读者点进来发现被骗。这种平台会记账，头条的标题创作规范明文列了夸张式和悬念式，微信运营规范 4.11 点名夸大误导，主流信息流产品很早就把「点进去多快退出」当降权信号。

另一种是**把真实的东西只露一半、情绪顶格、把最戏剧的那个细节顶到全篇代表位**。这个叫网感，真实爆款基本都在干这件事。

所以分三档，**默认三档全给**，让用户自己挑。档位是表达选择，不代表质量高低，三档不比一档「好」。

| 档位 | 怎么写 | 长什么样 |
|---|---|---|
| **一档 · 稳妥** | 照事实说。对象、动作、结果交代完整，不留缺口，情绪词克制。机构号、严肃选题、搜索场景适用 | 「公众号从选题到推草稿箱不用切窗口了，我用 WorkBuddy 接了飞书」 |
| **二档 · 有点冲** | 事实不变，换上素材里最有劲的词，把代价或冲突顶到前面 | 「一篇文章切十几次窗口，我把这些搬运的活儿全甩给了腾讯的 AI」 |
| **三档 · 顶格** | 只露一半，情绪顶格，拿最戏剧的真实细节当全篇代表。修辞化的动词可用（偷学、摁下去、废了） | 「腾讯 WorkBuddy 偷学了我的文风，写出来的稿子我改了三处就发了」 |

上面这组示例里，三档的「偷学」对应的是作者把历史文章给了工具做文风参考，「改了三处」是原文写过的「我一般改三个地方」。一个字没编，只是把最戏剧的那个动作顶到了主位。**这就是三档和一档的真实差距，不是在一档上加「竟然」「直接」。**

**示例只用来量档位之间的落差，不许当模板。** 这三条出自一篇讲 AI 工具接办公软件的工作流文章。两种情况下必须警觉。手上素材跟它同类甚至同源时，示例会把你锚死，你写出来的三档很可能只是它的同义改写。多落点任务里，四个落点的三档如果都往示例那个方向靠，说明你在复制一个句式而不是在挖四个不同细节。**自检一句，把示例从脑子里拿掉，这条三档还站得住吗。** 站不住就作废重写。

**三档是天花板，再往上就是编，那一档不给。** 三个档位都要过兑现度那道闸，兑现度是天花板不是可调项。判断办法很土，读者点进来十秒钟，能不能找到标题说的那件事。找得到多狠都行，找不到再温和也是骗。

三档常见的越界形态有三种，逐条查。跟正文结论相反；把正文明确保留的人工环节说成全自动；加一个编的细节来凑情绪（饭都没吃、熬到凌晨）。一个编的细节会让读者怀疑整篇。

碰到某个写法很诱人但越界时，用一句话说明它为什么不给，帮用户建立边界感。不展开，不列清单，不说教。**也不许用脚注和风险提示给越界标题免责**，直接改文案。

## 每一档都给两种语气

档位控力道，语气控人设，这是两个独立维度。**一个落点的标准交付是六条，三档乘两种语气。**

- **作者语气**，第一人称在场，口语判断，有具体动作和真实代价，允许一处不规整。不强制用「我」开头，但要有真实在场感。
- **通用语气**，去掉人设标记，任何账号拿去都能直接用。

**两种语气不是同一句话换个说法。** 作者版从「我做了什么」起句，通用版从「发生了什么」或者「谁做到了什么」起句，两边的主语就不一样。如果两条读起来只差一个「我」字，说明通用版没重写，回去重来。

**三档的通用语气最难写**，因为顶格的力道很多来自第一人称的在场感。去掉「我」之后要靠更强的事实反差或者更狠的实体对撞补回来，不能靠加形容词。实在补不回来就说明这篇的三档天然依赖人设，直说，别拿一条注水的凑数。

内容本身没有稳定第一人称人设时，两种语气差异会很小，这时只保留更合适的一种，并说明一句。

## AI 工具赛道的网感公式

这个赛道有实际案例可依，用它，别用通用直觉。

### 真实爆过的标题长什么样

以下是这个赛道小号和中号打出来的公开案例，数字是页面展示值，只作校准参照，不是可复现的收益承诺。

- 「我给 OpenClaw 搭了间像素办公室，它现在每天自己上下班」 10 万+
- 「钉钉卖 709 的 AI 卡片，我入手了...」 10 万+
- 「小浣熊桌面端 2.0 正式上线！升级的恰到好处」 10 万+
- 「万物皆可控？我买了个驾驶龙虾的终极硬件」 7.8 万
- 「终于找到一个用了就回不去的 AI 创作平台了」 7.2 万
- 「Kimi K3 刚刚发布，把老外都看沉默了」 6.5 万
- 「我让腾讯 Miora 帮我开了家火锅店，做到最后，我有点膨胀了」 4.3 万
- 「装了这 3 个 skill，龙虾终于能拿得出手了」 2.9 万

### 拆出来的四件套

1. **第一人称做了一件能画出来的事。** 「搭了间办公室」「开了家火锅店」「入手了」「买了个硬件」。不是「测了」「用了」「体验了」，那些画不出来。写通用语气时这个动作不能丢，只是换个主语。
2. **结尾一个口语情绪判断，给画面不给结论。** 「有点膨胀了」「拿得出手了」「回不去了」「看沉默了」「恰到好处」。这个判断要是作者自己会说的话，不是评测腔。
3. **实体词前置，而且要挑对词。** 见下面的取词表。
4. **允许一处不规整。** 一个感叹号、一个省略号、一个反问开头都可以，但只能有一处。

**这个赛道的读者吃的是「他玩出了什么」，不吃被教育。**「你以为…其实…」「别再…了」这类冲着读者去的写法，在情感类赛道有效，在这个赛道的公开案例里没有明显优势。优先用第一人称叙事。

### 取词表

下表来自五个 AI 工具公众号 645 篇文章的历史关联，观察窗口 2025 年 7 月到 2026 年 6 月。**这是历史关联，不是平台规则，也不是因果。** 强弱只是该样本内的相对表现，不换算成倍数或百分比，因为样本口径、指标定义和分发条件都无法还原。词会过期，用前先判断它现在还热不热。

| 词 | 该样本内表现 | 怎么用 |
|---|---|---|
| GitHub / Star | 强 | 有真实 star 数才用 |
| Skill | 强 | 正文真有可装的 skill 才用，受选题周期影响大 |
| 一键 / 直接用 | 强 | 低门槛和立即可用比零价格更吸引人 |
| OpenClaw / 龙虾 | 强 | 与正文强相关才用 |
| 微信 / 公众号 | 强 | 内容真跟微信生态有关 |
| 腾讯 | 强 | 腾讯系产品可直接前置 |
| 教程 / 指南 | 中 | 要配具体成果 |
| Claude / Codex | 中 | 对比或实测场景 |
| 开源 / Agent | 已饱和 | 不能单独当钩子 |
| 免费 / 白嫖 | 弱 | 别当主钩子，小红书搜索场景例外 |
| DeepSeek | 弱 | 别放最前面，先上画面和冲突 |

关键词至少要干一件事，指向高关注对象、提供可信度、表明有可直接用的成果、帮读者快速识别主题。只描述技术不说读者结果的词一个都别堆。

**不能凭这张表说某个词是推荐池触发词或者平台偏爱它。** 表现好可能来自选题周期、品牌辨识度、发布时间、早期互动速度，跟标题本身无关。

### 中文高唤起词（取词用，不是打分用）

**仍有效**　真相、内幕、终于、原来、竟然、千万别、避坑、复盘、翻车、崩了、硬核、手把手、保姆级、后悔、扎心、拆穿、清醒、离谱、上头、回不去

**烂大街**　震惊、速看、必看、重磅、干货满满、太牛了、宝藏、封神、天花板、yyds、破防了、建议收藏

**信息差型时间锚**　悄悄、刚刚、今天、深夜、一夜之间、终于、还是来了

这组单拎出来说，因为它性价比最高。它干的活是「这事已经发生了而你还不知道」，制造错过感，但本身不含任何夸张成分，所以有钩子又不越界，比「重磅」「突发」安全得多。产品低调更新、功能没做宣发、半夜发版这类素材优先考虑它。前提是真的低调，官方大张旗鼓办过发布会的别写「悄悄」。

高唤起词是增强口语力度的工具，不是评分项。只有作者真的会这么判断、正文也兑现得了才用。

## Phase 1 · 挖内核

从素材里**至少列出 3 个张力候选**，选最强的一个。张力只能来自这六类。

1. 一个意外的事实
2. 一次反转
3. 一笔真实代价
4. 一处冲突
5. 一个改变判断的数字
6. 一件读者切身的利害

把选中的写成一句内部工作句，谁做了什么，出现了什么结果，结论受什么条件限制。

**自检闸门。** 这句话不能是素材字段的拼接。「做了个 AI 客服然后复盘」是字段拼接，不合格。「上周还能跑的流程今天全挂了，配置一个字没改」是张力，合格。「Kubernetes 网络」是话题标签，不合格。

**同时找画面。** 内核之外，从素材里挑一到两个最能画出来的动作或场景（开了家火锅店、画了个火柴人、切了十几次窗口）。这个赛道的标题靠画面撑，没画面的内核再强也平。

**同时找最戏剧的那一个细节**，三档顶格要用它。它不一定是全篇重点，但必须是正文里真有、而且前三分之一就能兑现的。

**最戏剧的细节压在正文中后段时，别硬用。** 它过不了十秒钟那一关，标题准确也算骗。两条路，换一个前段就能兑现的细节来顶三档，或者留用这个细节但同时告诉用户正文要把它往前挪、或者在开头一句话点到。**必须明确交代走的是哪条路**，不许写完标题就当兑现位置不存在。

内核弱，后面二十条会一起弱，措辞救不了一个没有赌注的前提。不合格就回素材重挖。

**素材真的只有功能罗列时**，就写清楚的功能型标题，不硬造冲突，并说明三档在这篇上撑不起来。缺少决定性事实时可以给带方括号占位符的升级方向，但占位符标题不许混进「可直接使用」那一区。

## Phase 2 · 铺角度

先要量，别精雕。生成阶段抛光会把搜索空间收在最不该收的地方，经验上最好的那条通常在第 7 条之后出现，前 6 条是惯性。

**草稿数量服从任务规模**。完整矩阵任务，单一落点至少 12 条草稿、多落点至少 20 条，三个档位各至少 4 条，两种语气都要有，**至少覆盖 5 个不同角度**。

**交付数量服从用户要求和素材承载力**。用户只是随口要「几个标题」时，给 4 到 8 条差异明显的候选就够，不必甩整套矩阵。用户要矩阵或明确要三档两语气时才给满。素材撑不住就减量，并说清补什么事实能升级。不为凑数造新事实、重复同一句式或硬换角度。

**草稿里三个档位都要有量**，别先写完一档再往上推。顶格那档要从最戏剧的细节重新起句。两种语气也各自起句，不是写完作者版再把「我」删掉。

### 角度库

| 角度 | 干什么 | 中文写法 | 别用在哪 |
|---|---|---|---|
| 好奇缺口 | 开一个只有读完才能关上的具体问题 | `[具体主体][做了具体的事]，[结果留白]` | 搜索场景、抖音虚假悬念。全库风险最高的一招 |
| 具体化 | 把数字、专名、时间、原话、报错搬进标题 | 「很快」换成「45 分钟」，「省钱」换成「省了 23%」 | 标题已经塞满参数时，再加会掉 |
| 利害 | 点名读者会失去或得到什么 | `你的[X]可能正在[具体损失]` | 利害是泛泛的「提升效率」时 |
| 反差 | 把两件都为真但不该同时为真的事并置 | `[身份A]，却[反预期行为]` | 反差是硬凑的 |
| 反问 | 问读者已经在问的那个问题，反问优于直问 | `为什么你[做对了动作]，[结果]还是[不好]` | 付费推荐位，问句在那里垫底 |
| 交付物 | 承诺一个被精确命名的东西 | `[N] 步做出[具体成果]（附[资源]）` | 正文给不出那个资源时 |
| 数字骨架 | 用计数或度量搭骨架 | `[N] 个最容易踩的[东西]` | 内容凑不满那个数。别信奇数比偶数强，那条被证伪过 |
| 读者原话 | 用读者自己会打出来的那句话 | 直接搬搜索框里的说法 | 纯信息流场景会显得干 |
| 负空间 | 从缺了什么、停掉了什么切入 | `我停掉了[所有人都在做的事]，然后[结果]` | 断言站不住时，这是强主张 |
| 机制 | 不讲结果，讲为什么它能做到 | `[结果]背后真正起作用的是[机制]` | 泛大众信息流，机制在大盘里枯燥 |
| 身份 | 让特定人群觉得这是给我看的 | `做[职业]第[N]年，我[认知转变]` | 身份标签太宽等于没标 |
| 时间锚 | 挂在读者已经在关心的事上 | `[刚发生的事]，这对[人群]意味着什么` | 热点已过峰，或内容和热点其实无关 |
| 画面动作 | 第一人称做了一件能画出来的事，结尾口语判断 | `我让[工具][干了件具体的事]，[情绪判断]` | 素材里没有真实动作，只有功能罗列时 |

**跨落点铁律。** 同一内核铺到多个落点时，**每个落点必须换一个角度**。四个落点四条同角度标题，等于只有一条。这条对同一平台的两种形态同样生效，X 短帖和 X 长文撑的如果是同一个点，等于浪费了一次曝光。同一落点内部的三档两语气不受这条约束，它们本来就是同一件事的不同写法。

**素材硬料要拽进来。** 数字、人名、地名、时间、原话、报错信息、价格。

**库反哺。** `data/hits.md` 存在且目标落点或角度有已验证案例时，拉 1 到 2 条做校准参照，说清为什么贴切。库空就用上面那批赛道公开案例校准，并说明那是公开案例不是用户自己的数据。跨落点案例不硬套。

## Phase 3 · 五道闸

客观可判，不过就删或改，不要辩护。**五道闸对三个档位、两种语气一视同仁，顶格那档不享受任何豁免。**

### 闸一 · 零编造（最优先，草稿和定稿各查一遍）

用**承诺清单法**。把每条候选拆成它做出的承诺项，逐项回素材点名找证据。

| 承诺类型 | 拆出来长什么样 | 要找的证据 |
|---|---|---|
| 数字 | 「3 天」「省了 40%」「12 个」 | 素材里有没有这个数 |
| 实体 | 「一张对比表」「源码」「提示词」 | 这东西真的存在吗 |
| 身份 | 「五年产品经理」「宝妈」 | 素材说过吗 |
| 动作 | 「我实测」「上手跑了」「接进了飞书」 | 作者真做过还是看别人做的 |
| 结果 | 「直接上线」「当天跑通」 | 真的跑通了吗 |
| 范围路径 | 「一文讲透」「全面超越」「从最疼的讲起」 | 正文真是这个结构、这个范围吗 |
| 程度词 | 「只有」「竟」「终于」 | 这是素材的结论还是你加的 |

任何一项找不到证据就删、收窄，或改成来源清楚的表述。**被砍掉的项不许换个同义词复活进定稿，也不许换个语气复活。**「一张表」被砍了不能改成「一份清单」混进去。

素材里带「好像」「应该」「感觉」的话，标题里不得变成肯定结论。

「实测」要求正文有作者本人的操作和结果记录。「教程」「模板」「源码」「Prompt 可复制」要求正文真的交付了对应内容。「全面超越」「取代」「碾压」这类整体结论不能由单项跑分或局部案例推出来。

但注意，**这道闸只砍事实，不砍力道**。口语情绪判断（离谱、上头、有点膨胀了）和修辞化动词（偷学、摁下去、废了）只要方向跟素材一致就放行，见上面的力道纪律。

### 闸二 · 折叠位

每个落点都有一个决定点击的可见区，超出的部分是奖励不是主体。把标题砍到折叠位那个字数，剩下的还成立吗。不成立就重排语序，别缩写。

折叠位是**观察值不是常量**。同一平台有多个入口、终端和卡片样式，某张截图里的位置不能当永久固定值用。需要精确校验时按 platforms.md 的流程走。

### 闸三 · 字数

中文按字数算，不按字符。查下面的落点规格表。六条都要单独算，不能只算推荐那一条。

需要报字数时说明计数口径，英文单词、数字、空格、标点和 emoji 的算法可能跟平台编辑器不同，临近硬上限以当前编辑器实测为准。

### 闸四 · 合规

极限词、诱导互动、平台明令禁止的形式。涉及健康、功效、商品推广时，不能只挂风险提示，**必须直接给去功效化的安全版**。「体脂从 32% 降到 26%」优于「瘦了十斤的神器」，把功效表述换成过程和记录表述。

### 闸五 · 兑现度（一票否决，也是档位的天花板）

读者点进来十秒钟，能不能找到标题说的那件事。找不到就删。不许靠加「可能」「或许」这类对冲词硬保一条超出内容范围的标题，也不许用脚注免责。

**排序权重**，明确取舍，不要十几个维度全打勾。

> 兑现度（一票否决） > 画面感 > 具体性 > 张力 > 角度稀缺度

**不打分。** 一个「87 分」是假的确定感，市面上的标题评分与实际表现相关性很弱。给理由，不给分。档位和语气都不是分数，是选项。

## Phase 4 · 交付

**输出铁律。** 用户只要标题，不要方法论。Phase 1 到 3 的全部推演，内核句、角度判定、被砍候选、逐条校验，都是内部工作记忆，**默认不展示**。所有用户可见的文字里不许出现内部黑话，不写「角度库」「闸」「内核」「兑现度」「Phase」，用大白话替代。「一档二档三档」「作者版」「通用版」可以直接用，那是给用户看的刻度。

矩阵任务默认三档全给、每档两种语气，一个落点六条。用户明确说只要某一档或某一种语气时才缩减。随口要几个标题的轻任务直接给候选加一个推荐，不铺矩阵。

单落点输出用这个格式。

```
一档 · 稳妥
  作者版  [标题]
  通用版  [标题]

二档 · 有点冲
  作者版  [标题]
  通用版  [标题]

三档 · 顶格
  作者版  [标题]
  通用版  [标题]

我会选哪条
[一句话，大白话，说清它凭什么胜出]

补真实数据我立刻升级（补全 [方括号] 里的东西才算真）
- 若[条件 A] → [对应的完整标题]
- 若[条件 B] → [对应的完整标题]
```

多落点输出用矩阵，**每块一个落点而不是每块一个平台**，块内三档各带两种语气。字数注在每条后面，一档下面标一次上限就行，不必每条重复。

```
公众号（约 64 字上限，前 22 字左右要自足）
一档 · 稳妥   作者版 [标题]（30 字） / 通用版 [标题]（28 字）
二档 · 有点冲 作者版 [标题]（29 字） / 通用版 [标题]（27 字）
三档 · 顶格   作者版 [标题]（31 字） / 通用版 [标题]（29 字）

小红书（约 20 字上限，搜索词「XX」放前半段）
三档六条，同上结构

X 短帖（第一行就是全部，不是标题）
三档六条，交的是第一行不是标题

X 长文（建议 30 字内，卡片上约两行）
三档六条

抖音/视频号（约 55 / 30 字）
三档六条
```

每个落点内部都要写满六条，上面只是省略写法，不是允许少给。

**保鲜期提醒**，一段大白话，说清哪条绑着短期词、哪条能长期用。

**校验脚注**，一行，对每一条负责。每条都达标才打 ✓。只要有一条超字数、有待补数字、有合规风险，就写清具体是哪一档哪一版的风险点，不许笼统打 ✓。

**脚注不是免责区。** 它只登记两类东西，客观待核验项（字数临界、数据要确认、热点窗口快过了）和主动做的取舍说明。**你自己已经判定越界的标题，不许原样留在候选区然后在脚注里附一个收窄版**，直接把收窄版换上去，越界那条不出现。写脚注时如果冒出「我知道这条淡化了某个保留，但为了力道还是写了」这个念头，就是没改干净，回去改。

## 落点规格

| 落点 | 字数上限 | 折叠位（观察值） | 分发逻辑 | 首选角度 | 头号禁忌 |
|---|---|---|---|---|---|
| 微信公众号 | 约 64 字 | 信息流折叠后手机端约前 22 字 | 订阅打开 + 社交转发 | 画面动作、反差、交付物、机制 | 夸大误导（运营规范 4.11） |
| 小红书 | 约 20 字 | 前半段最可能被搜索命中 | 搜索 + 信息流双引擎 | 读者原话、身份、负空间 | 关键词不前置就搜不到；诱导点赞收藏会限流 |
| X 短帖 | 没有标题，写的是正文第一行 | 时间线约 2 行后折叠，第一行定生死 | 转发 + 关注链 + 算法混合 | 具体化、画面动作、反差 | 铺垫句、预告句、长句绕弯 |
| X 长文 | 有真正的标题字段，建议 30 字内 | 卡片上约两行 | 卡片展示 + 链接转发 | 反差、数字骨架、交付物 | 把公众号那套完整交代搬过来，卡片装不下 |
| 抖音 | 约 55 字 | 播放页首行 | 完播率 + 互动率 | 好奇缺口、利害、负空间 | 诱导互动、虚假悬念 |
| 视频号 | 约 30 字 | 首行 | 私域 + 算法 | 利害、具体化 | 过度抖音化的夸张，在熟人场里掉价 |

上表是常用参考值，会随平台改版变化，涉及硬卡点时以当前官方编辑器实测为准，并提醒用户核一下。各落点的详细写法见 platforms.md。

**档位在不同落点的安全区不一样。** 小红书搜索侧和抖音对虚假悬念的惩罚最重，三档在这两处要把搜索词和具体事实保住。公众号和 X 的三档可以更放开。

**语气在不同落点的权重也不一样。** X 短帖和小红书天然偏第一人称，通用版在这两处容易发干，写的时候用具体主体接住（某个产品、某个数字、某个人群），别用无主语的抽象句。

### X 的两种形态，别混为一谈

**这是最容易做错的一处。** 开工前先问清是哪一种，问不到就两套都给并分别标清楚。

**X 短帖根本没有标题。** 整条推就是正文，第一行就是全部。你交的不是一个名字，是一句能单独站住的话。读者在快速下滑，没有任何上下文，所以第一行必须直接落在事实上，不允许铺垫。「有个东西太有意思了」「最上头的一点」「先说结论」这类句子只是在宣布后面有信息，本身不带信息，直接删，从第二句开始。一句话一个信息点。不要写成总起、展开、收口的三段式，那是公众号节奏贴到 X 上。黑话和内部名词要么不用，要么当场解释。

**短帖的通用版不许退化成一行数据。** 「A 拿 74.2，B 拿 74.0，C 拿 73.0」是贴了一行跑分，不是写了一句话。去掉第一人称之后仍然要有一个动作或者一个判断，数字是用来支撑那个动作或判断的，不能自己当主语。这是通用语气在短帖上最常见的塌方形态。

**X 长文有真正的标题字段。** 它在时间线上以卡片形式出现，读者先看到一个名字再决定点不点，逻辑更接近公众号。但卡片比公众号的列表窄，要比公众号标题短，交代得也更少。它还会被当成链接转发，必须能脱离账号独立成立。

**两种形态同时发时撑不同的点。** 短帖拿最具画面感的那个细节，长文标题拿最能代表全篇的那个判断。两边用同一个点，等于白发了一次。

## 落点规则是互相冲突的

这不是噪音，是真实的渠道差异。不问清落点就给建议，必然在某一侧是错的。

| | 公众号 | 小红书 | X 短帖 | X 长文 | 抖音/视频号 |
|---|---|---|---|---|---|
| 有没有标题这个东西 | 有 | 有 | **没有** | 有 | 有 |
| 好奇缺口 | 有效但别过头 | 搜索侧会惩罚 | 有效 | 有效 | 虚假悬念会被降权 |
| 三档顶格的安全区 | 较宽，但看转发羞耻感 | 窄，搜索词不能丢 | 宽 | 较宽 | 窄，虚假悬念直接降权 |
| 通用语气好不好使 | 好使 | 容易干，要接具体主体 | 容易干，同上 | 好使 | 一般 |
| 完整交代 | 奖励 | 放不下 | 惩罚 | 适度 | 惩罚 |
| 铺垫句、预告句 | 惩罚 | 放不下 | **致命** | 惩罚 | 惩罚 |
| 搜索关键词前置 | 有用 | 决定生死 | 一般 | 有用 | 一般 |
| 第一人称 | 有效 | 有效 | 最有效 | 有效 | 有效 |
| 数字 | 有效 | 有效 | 有效 | 有效 | 一般，画面比数字强 |
| 转发羞耻感 | 要考虑 | 不用 | 要考虑 | 要考虑 | 不用 |

**这张表是这个 skill 存在的主要理由。**

## 保鲜期

每组交付标清保鲜期，用户自己能判断什么时候该换。

- **热点型**，按天算。挂在具体事件上，事件过峰就废。
- **关键词型**，按季度算。靠某个产品名、模型名、平台名吃流量，这类词会饱和也会过期，曾经的顶流关键词半年后可能是零。
- **结构型**，长期有效，但会被套利。一个句式被模仿多了，读者会产生免疫。

**一组交付里至少要有一条结构型**，别让所有标题绑在同一个短期词上。

## AI 工具内容的特殊检查

标题优先写作者实际做成的任务，生成了一个游戏、修复了一个报错、搭了个看板、产出了一份能交的文件。素材里只有「体验了」「测试了」「很强」时，继续往下挖具体动作和结果，挖不到就降级成功能型标题。

写模型比较时标清范围。

- 单项榜单领先，只写该榜单或该能力维度，不写全面。
- 第三方或社区数据，保留来源身份，不能改写成作者亲测。
- 作者上手案例，只证明对应任务的表现。
- 价格比较要相同的输入输出规模、缓存条件和计价时间。
- 「免费」「一键」「自动」「无需修改」这类词逐项兑现，做不到就改。

模型名、价格、榜单和平台政策变化很快，标题依赖这些信息且用户要求事实可靠时，先核验再交付。产品名和热点词只有正文强相关才前置。

## AI 味自查

中文的 AI 味跟英文那套是两回事。以下命中即重写。

**开头套话**　在当今时代、随着 XX 的不断发展、众所周知

**万能句式**　不是…而是…、不仅…而且…、首先其次最后、值得每个人深思

**空转黑话**　赋能、抓手、闭环、颗粒度、心智、打法、生态位

**假深度**　深度解析、全面剖析、揭秘背后的底层逻辑、一文看懂 XX 的本质

**结构性 AI 味**　用破折号连接从句、三段排比、每条候选长度整齐划一、每个标题套同一个句式

**评测腔**　「实测」「体验了」「用了一天」这类词本身没错，但如果标题里只有它们没有动作和画面，就是评测腔，换成具体做了什么

**极限词高危区**（涉及商品或服务推广时直接换掉）　最、第一、顶级、极致、绝对、全网、史上、唯一、国家级、万能、100%、永久。广告法第九条禁绝对化用语，罚则在二十万到一百万这个量级。替换思路是把绝对判断换成可验证的个人经验，「我用了三年没换过的笔记工具」既避规又更可信。

**最狠的一条自查。** 把标题的主语换成任意另一个人，还成立吗。还成立就是没站人，重写。抽象、正确、属于所有人的标题就是标题界的 AI 味。这条对通用语气版同样生效，去人设不等于去具体，通用版也得有一个具体的主体在具体的处境里。

## 诊断模式

用户已经有标题时走这里。

1. 先一句话定性，问题在哪一层。内核层（没有赌注）、画面层（有事实没画面）、力道层（档位太低，准确但克制）、角度层（选错招）、措辞层（写得糊）、形态层（拿错产物，比如把 X 短帖当标题写）、平台层（字数或语气不适配）、合规层（越线）。
2. **改法放最前**，给 2 到 6 条能直接用的，需要时按三档两语气铺开。让用户先拿到能用的东西，再理解为什么。
3. 默认保留原题里有效的对象、角度和语气。只有内核层的问题才需要回素材重挖，其余几层直接改。

**最常见的误判是标题都准确但都很平。** 这时先看画面层和力道层，八成是有事实没动作，或者一直停在一档没往上推。真是内核问题才回素材重挖。

**形态层的诊断信号。** 交出去的东西读起来两头不靠，既不像一个名字也不像一句话，基本就是把某个形态的产物套到了另一个形态上。

**用户嫌太平或者要求更狠时**，直接往三档推，提高画面、反差和口语力度，同时重新走一遍事实范围检查。不要把边界判断推回给用户，也不要先讲一通道理。先给标题，边界只在真的碰到时用一句话说。

## 评审模式

用户拿几个候选问选哪个时走这里。

先统一发布形态和内容承诺再比，不同形态的候选不能横比。按推荐顺序排列，每条说明最关键的那个优势或风险。**候选里已经有能用的就直接选出推荐项**，只有全部存在实质问题时才补写新标题。

不拿个人偏好替代兑现检查，也不把标点或一个情绪词的差异包装成确定的点击率提升。差异只在细枝末节时就说差异有限。

## 复盘和收录

这两个模式细则见 [references/review-and-library.md](references/review-and-library.md)。要点是复盘先恢复可比基线再谈标题，归因分层不把一切归给标题，措辞写成候选原因不写成因果。收录只在用户明确说保存时才写文件，只收小号素人的高表现案例，大号高阅读被粉丝基数污染不收。

## 常见故障

| 症状 | 成因 | 解法 |
|---|---|---|
| 标题全是准确的说明句，一条都不爆 | 把「不编造」执行成了「不敢用力」，三档全堆在一档 | 从最戏剧的细节重新起句写三档，再对一遍网感四件套。这是最常见的病 |
| 三个档位是同一条加形容词 | 在一档上加「竟然」「直接」就当三档交了 | 换一个更戏剧的细节做主语，不在同一句上加码 |
| 两种语气只差一个「我」字 | 删掉「我」就当通用版交了 | 换个主语重新起句 |
| 把 X 当成一种东西 | 给短帖交了标题，或给长文交了推文开头 | 先问形态，问不到两套都给 |
| 短帖第一行写成了预告 | 「有个事太有意思了」只宣布信息存在 | 删掉它，从第二句开始 |
| 单项优势写成全面胜负 | 跑分领先直接推成碾压 | 补回评测名称、适用任务或比较条件 |
| 把社区数据写成亲测 | 素材是别人跑的 | 保留来源身份，或改写成作者真做过的那个案例 |
| 用脚注给越界标题免责 | 拿风险提示换通行 | 直接改文案 |
| 素材没张力，只有平铺直叙的说明 | 内容本身就是一份功能说明 | 问作者最意外的事实或不解决的代价。真没有就直说，给功能型标题 |
| 候选全长一个样 | 被零编造框死，只在同一句上换同义词 | 打开角度库按顺序走，每个没用过的角度强制出一条 |
| 交付的就是用户原话的近义复述 | 最容易被一眼看穿的偷懒 | 每条必须是一个新角度 |
| 几个落点几条同义句 | 先写完一条再去适配字数 | 从内核重新起句，每个落点换角度重写 |
| 把低阅读直接当成标题失败 | 没分清绝对值、账号基线、内容类型和分发条件 | 切复盘模式，先恢复可比序列 |
| 把某领域热词当成通用招式 | 热点对象醒目，可迁移的机制反而被忽略 | 去掉品牌名和模型名，看还剩不剩「对象、动作、结果」 |

## 不做的事

默认不写文件、不建目录、不给时间戳。例外只有两个，收录模式会追加写入 `data/hits.md` 和 `data/patterns.md`，用户明确要求保存复盘观察时追加写入 `data/observations.md`。其余标题都直接给在对话里。运行环境不允许写 skill 目录时先说明，再用用户指定的位置。

不替用户编数据。不把历史相关性说成平台算法规则。不把写作经验说成平台硬限制。不给分数。不把网感问题推回给用户，网感是这个 skill 的活。不把四档当成选项给出去，三档就是天花板。不拿删一个「我」字当通用语气版交差。
