# 复盘模式与案例库

## 复盘模式

用户给一组标题配数据，或者问「为什么这篇突然低了」时走这里。不要把这组数据当成爆款收录，两件事。

### 流程

1. **先分清指标类型。** 阅读、播放、点击率、完播、点赞、收藏、转发、涨粉不能混成一个指标。
2. **保留页面展示精度。** 「1.1 万」是近似显示，「10 万+」只是下限，不制造精确比值。
3. **恢复可比序列。** 按账号、落点、内容类型、发布时间排序。文章和贴图不能横比，不同账号不能横比，同一平台的两种形态也不能横比。截图常是新到旧排列，视觉上相邻不代表发布时间相邻。
4. **建基线。** 用同账号同类型最近 3 到 5 条的中位显示值做近似基线。样本足够时优先用中位数。没有基线就明确写「基线未知」，先要可比样本，别急着给原因。
5. **归因分层。** 这是复盘最容易糊的地方，别把爆款全归给标题。
6. **措辞收住。** 低阅读写成「候选原因」，相对下滑写成「疑似低于自身基线」。没有随机实验就不写「标题导致」。
7. 高表现和低表现样本一起看，说明哪些写法有效、哪些无效、可能的混杂因素是什么。

### 归因四层

| 层 | 包括什么 |
|---|---|
| 标题因素 | 角度、前置、具体性、画面、力道档位、语气、兑现度、字数 |
| 选题和时机 | 热度窗口、发布时间、有没有撞车 |
| 账号和分发 | 账号基线、封面、推荐量、粉丝活跃度 |
| 暂时无法判断 | 数据不够，说清补什么才能判断 |

发布两小时与发布七天的累计数据不能直接横比。曝光量差异很大时优先比点击率或相同曝光阶段，缺曝光数据就明确说明这个限制。

用户的历史数据里同时有不同力道和不同语气的标题时，可以比一比哪个档位、哪种语气在他账号上表现更好，同样只能说关联。

### 低表现的常见候选原因

| 症状 | 先检查什么 |
|---|---|
| 只有宏大判断，没有具体对象和事件 | 具体对象、动作、结果是不是全缺 |
| 「几个方法」「几件事」这类泛列表 | 有没有明确人群和收益 |
| 像发布公告或活动口号 | 读者点进去能得到什么 |
| 专名堆积，没有动作和场景 | 能不能换成普通人想象得出的任务 |
| 有数字但数字只是装饰 | 那个数字有没有改变判断或成本 |
| 准确但平，全是评测腔 | 有没有一个能画出来的动作，力道是不是一直停在一档 |
| 标题不差但数据异常低 | 热点窗口、封面、发布时间、内容类型 |
| 点开了但读完率和转发很低 | 标题是不是超出了正文能兑现的范围 |
| X 上发了没水花 | 第一行是不是铺垫句，有没有把标题当短帖发 |

## 收录模式

**只有用户明确说「保存」「收录」「加进库」时才写文件。** 默认路径是当前 skill 根目录下的 `data/hits.md`，第一次用时自动建，不预置别人的案例。运行环境不允许写 skill 目录时先说明，再用用户指定的位置。

**收什么。** 只收小号、素人、日常阅读低却打出高量的标题。大号的高阅读不收，粉丝基数会污染样本，看不出是标题在干活还是粉丝在扛。收录时必记账号量级。

### 单条记录格式

```
### [HIT-0001] YYYY-MM-DD
- 标题：
- 落点：公众号 / 小红书 / X 短帖 / X 长文 / 抖音 / 视频号
- 角度：从角度库里选 1 到 2 个
- 力道档位：一档 / 二档 / 三档
- 语气：作者语气 / 通用语气
- 账号量级：日常阅读 / 粉丝数，不知道就写待补
- 发布时间：
- 观察截止时间或发布后时长：
- 指标及页面展示值：
- 曝光或分发条件：
- 验证状态：已验证 / 待回填 / 证伪
- 验证证据：
- 内核一句话：谁做了什么，出现了什么结果，受什么条件限制
- 画面：标题里那个能画出来的动作是什么
- 字数：N / 落点参考上限
- 合规：通过 / 风险点
- 借鉴点：一句话
- 可能的混杂因素：
```

### 流程

解析落点和证据，过一遍字数和合规（不过也照实记，不拒收），去重，ID 自增追加到文件末尾，**只追加不覆盖**。

去重不用「相似度 80%」这种没有实现依据的数字。先规范化空格、标点和大小写做精确比对，再人工判断是不是同一条标题的轻微改写。

同一个「落点 + 角度」攒够 3 例，才在 `data/patterns.md` 里命名一条规律，并写清共性、样本量、适用账号、时间范围和反例。X 短帖和 X 长文算两个不同落点，不合并计数。

**力道档位和语气也要记。** 攒够样本后就能看出这个账号的读者到底吃哪个档位、吃不吃人设，这比任何通用经验都准。

### 回填与更正

这是最容易烂的一环。案例库采用追加式记录，保留历史。

- 新案例追加新 ID。
- 后续数据作为同一 ID 的回填事件追加，把状态升级。
- 用户说「其实没爆」就追加一条更正事件，改成证伪，并在对应规律上标一笔修正，不静默覆盖旧证据。
- 只有同一观察在多次可比样本里复现、而且做过反例检查，才写进 `patterns.md`。

少了回填，库停在记录层，攒不出理解。

**绝不替用户编账号规模、发布时间、曝光量或表现数据。** 缺失字段写待补。
