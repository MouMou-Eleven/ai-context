# Title Matrix · 标题矩阵 Skill

第三方 Skill，作者／维护者为 [zhouwei713](https://github.com/zhouwei713/title-matrix)，**非建委自研**。按建委2026-09-24要求，实体放在“自媒体与个人IP经营 → 自媒体标题与选题”；[通用Skill目录](../../../other/skills/README.md)仅提供索引，不复制第二份。

建委已反馈个人测试效果可以，要求明确调用和按任务自主使用。该反馈是采用依据，不代表已验证所有平台点击率或不同模型的效果。

## 能做什么

- 从已有文章、素材中生成标题；同稿面向不同发布形态分别拟题。
- 诊断已有标题、比较候选，给出可用改法与推荐。
- 对有可比账号数据的标题做复盘；区分标题、选题、封面、分发和观察窗口。
- 主体是文字规则和参考资料；读取完整Skill后由AI执行，不需要运行第三方程序或调用收费API。

## 何时自主使用

| 当前任务 | 调用方式 |
|---|---|
| 明确说“调用标题Skill／title-matrix”、起标题、改标题、选标题 | 进入对应生成、诊断、评审模式；实际读下方Skill及所需参考 |
| 写／实质改写公众号、自媒体图文、小红书笔记，需要成品标题，即使未点名Skill | 先确定读者、平台和正文事实，再自主用于标题环节；正文按原领域方法完成 |
| 短视频／口播稿需要发布标题，或X短帖需要开头 | 按发布形态使用；不将完整正文替换为一套标题矩阵 |
| 标题与真实阅读、播放等数据复盘 | 读取复盘参考；缺曝光、窗口或账号基线时只给有限观察 |
| 只查Skill位置／来源、只收录素材、只改错字、保留原标题或逐字保护 | 只查必要入口，不生成新标题、不改已确认内容 |
| 合同、项目方案、出版章节、学员课件、内部文档的标题 | 默认不激活自媒体标题打法；若另做宣传稿，宣传稿按自媒体流程单独处理 |

用户只指定自媒体板块时，AI自行判断本次是否要拟题；不要求用户补一句“调用Skill”。平台已知不重复询问；平台未知但不影响推进时，先给不依赖平台限制的标题，并说明假设。缺正文时仅依据已知主题给暂定题，不编造实测、资源或结果。

## 执行顺序与交付

1. 读本页和[版本来源](./upstream.json)，再读[完整SKILL.md](./source/skills/title-matrix/SKILL.md)，按[平台参考](./source/skills/title-matrix/references/platforms.md)确定产物形态。不能读完本页就宣称使用了Skill。
2. 依据正文提取真实对象、动作、结果、比较范围、前提与可交付资源；按原Skill挖掘不同角度，逐项检查标题承诺。需要引用研究、流量或平台判断时读[证据参考](./source/skills/title-matrix/references/evidence.md)。
3. 写文章的任务默认交付一条推荐标题加正文；用户要备选时给少量差异明显的候选。明确要求跨平台／三档矩阵时再完整展开，不强制每篇文章附一整套分析、矩阵和脚注。
4. 交付前逐项回正文核对数字、第一人称经历、自动化程度、资源承诺、比较范围与兑现位置。定稿后正文变了，标题再次复核。只查路径或文件完整性不算效果测试。
5. 复盘／收录读[复盘规则](./source/skills/title-matrix/references/review-and-library.md)。日常生成不自动写库；用户要求沉淀时按本仓[写入流程](../../../../../system/repository/ingestion-workflow.md)保存适合公开的经验及证据，放在titles下的主记录并更新索引，不写进只读上游source/data。少量样本只形成候选，不按固定例数宣布普遍规律。

## 与现有经验怎样配合

[文章与图文](../../articles/README.md)负责正文结构；[读者问题宣传](../../marketing-copy/reader-question-led-promotion.md)负责真实购买问题及回答顺序；[技术解释](../../../training/experience/technical-explanation/problem-driven-technical-explanation.md)负责概念理解。本Skill只接标题／开头工作，不能倒过来为了标题编正文事实或把所有小标题改成营销钩子。项目价格、权益、课程归属仍回项目核对。

本仓事实、专业用途、用户保留边界与[表达规则](../../../../../system/expression/README.md)优先。上游快照原样保留，但以下表述不直接升级为本仓硬规则：

- “所有模板都会失效”“一条都不会爆”“某平台奖励／惩罚某种结构”是上游经验判断，未在本次独立验证；不据此保证流量或断言推荐机制。
- 上游“标题通常不直接进推荐”与其“无官方依据不断言”有冲突，采用后者；平台字数、展示截断和政策需要时核对当前编辑器／官方资料。
- 上游案例、统计、研究解释不是建委经历和账号数据；不把645篇、352条或第三方阅读量当作本人证据。
- 小幅领先不能改成全面碾压；作者说“旧旗舰废了”也不自动使其成为客观事实。可保留真实态度，但整句不能误导比较范围和确定性。
- 标点、三档、两种语气、跨平台不同角度均按实际任务选择；不为强行满足形式而编事实或改变用户确认标题。
