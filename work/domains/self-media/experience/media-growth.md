# 自媒体增长、承接与复盘

自媒体这个渠道怎么定内容任务、怎么把人接到下一步、怎么复盘。跨行业的\"内容 → 需求 → 成交 → 交付\"整套商业方法见[内容驱动的需求识别与商业承接](../../other/commercial/experience/content-demand-and-conversion.md)，本页不重复；成果展示、用户动机和知识怎么配合见[成果展示与用户动机](./outcome-and-motivation.md)。

> 来源：原 media-growth.md 与 live-sales/conversion-path.md，2026-09-28 合并。

## 自媒体在业务里的作用（默认）

自媒体负责触达、解释、建立信任、把人接到下一步。它不是完整的商业闭环：真实的产品或服务、合适的渠道、清楚的下一步、真实交付，缺一样都不成立。

## 一条内容先定一个主要任务（默认）

| 类型 | 主要作用 |
|---|---|
| 痛点型 | 让目标用户意识到问题和自己有关 |
| 过程型 | 展示真实的解决过程和判断方法 |
| 教程型 | 给出能照做的步骤或检查方法 |
| 案例型 | 用能核实的结果证明方法落地了 |
| 观点型 | 建立长期认知和专业判断 |
| 转化型 | 说明资料、直播、咨询或产品这一步 |

一条内容不要同时承担所有任务。抽象的工具和技术词要翻译成具体的人、动作和结果：不要只说\"AI 编程\"，要说它帮哪类人做出了什么看得见的小工具。

## 把人接到下一步（红线＋默认）

```text
公开内容 → 有价值的资料或明确下一步 → 评论、预约、私信或直播
→ 深度交流、确认需求 → 对应的产品、服务或社群 → 真实交付与复盘
```

- **红线**：不承诺还没准备好的资料，不做标题党引流；价格、权益、边界只按具体项目的事实写，通用方法里不写死。
- **默认**：先给价值再提行动；一条内容只设一个主行动；资料、直播、社群要和内容承诺一致；用户行动后要有人接、有回复、有后续。
- 适合用文档承接的：短视频讲不完的步骤、检查清单和模板；用户需要保存、跟做、复查的内容；已经真实存在、能交付的资料。
- 只讨论自媒体承接时，不自动读取付费社群项目。任务明确提到某个项目时，才组合它的价格、权益和话术。平台私信、评论、导流规则会变，执行前要核实。

发布前检查：这条内容给了什么即时价值？承接物真的存在吗？用户要做的唯一动作是什么？谁来回复和交付？评论、领取、预约、到场、成交这些真实数据有没有记下来？

## 测试与复盘（可灵活）

- 前期可以试观点、案例、避坑、教程、轻松聊天、直播切片等不同形式。每轮尽量只改一个主要变量，比如标题、开头、结构或行动。
- 记录平台真实给出的数据，不只看播放量。样本不够时只写阶段性判断，不写成普遍规律。

复盘顺序：人群和场景找对了吗 → 开头的承诺和正文一致吗 → 中间有没有持续给新信息 → 案例和数据能不能核实 → 唯一行动清楚吗 → 用户行动后有没有被接住 → 下一轮保留、修改、停止哪些变量。

需要结合建委的商业判断时，读[商业增长闭环](../../other/commercial/experience/business-growth-loop.md)，不是每个自媒体任务都要读。
