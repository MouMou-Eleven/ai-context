# 内容到行动的承接路径

## 基本路径

```text
公开内容
→ 有价值的资料或明确下一步
→ 评论、预约、私信或直播
→ 深度交流与需求确认
→ 对应产品、服务或社群
→ 真实交付与复盘
```

这条路径的重点不是“把所有人导进群”，而是让用户在得到公开价值后，有一个清楚、低门槛且与内容一致的下一步。

## 文档承接适用场景

- 短视频无法完整讲清的步骤、检查清单和模板。
- 用户需要保存、跟做或复查的内容。
- 已经真实存在、能够交付的资料。

## 行动设计原则

1. 先给价值，再提出行动。
2. 一条内容只设置一个主行动。
3. 资料、直播和社群必须与内容承诺一致。
4. 不承诺尚未准备的资料，不做标题党式引流。
5. 用户行动后必须有明确的接收、回复和后续路径。
6. 需要成交时，价格、权益和边界服从具体项目，不在通用方法中硬编码。

## 发布前检查

- 这条内容给用户什么即时价值。
- 对应的承接物是否真实存在。
- 用户要完成的唯一动作是什么。
- 谁负责回复、交付或继续沟通。
- 内容与下一步是否一致。
- 是否记录了评论、领取、预约、到场和成交等真实数据。

## 严格边界

- 只讨论自媒体承接时不自动读取付费社群项目。
- 只有任务明确涉及某个项目时，才组合该项目的价格、权益、话术和目标。
- 平台私信、评论、广告和导流规则可能变化，执行前需重新核验。
