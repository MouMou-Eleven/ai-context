## 容易混淆的四种"上传"

| 名称 | 是什么 | 当前值 | 来源 |
|---|---|---|---|
| 项目内单文件上传 | 生成的应用里，最终用户上传文件的大小上限 | 见上表：免费版 50MB，付费版 500MB | 官方计费页，2026-09-28 核对 |
| 对话附件 | 你在秒哒对话框里给秒哒发的附件（比如 Codex 打好的源码包） | 一次最多 5 个，每个 20MB | 建委实测：2026-08-09、2026-09-25、2026-09-26 三次；非官方文档 |
| 素材库 | 跨项目复用的素材仓库 | 见上表 | 官方计费页 |
| 应用对象存储 | 应用运行时保存的文件总量 | 免费版 200MB；付费版可切换套餐 | 官方计费页 |

- 付费版的 500MB 不会自动生效。要在项目对话里说"上传大小改为 500MB，同步修改前后端限制"，然后实际上传测一遍。（来源：V3.7 官方文章，2026-08-27）
- 500MB 单文件上限不等于还有 500MB 剩余存储，也不等于弱网下一定传得上去。
- 打包给秒哒的源码包，建议单包小于 19,000,000 字节，给 20MB 上限留余量。

## 后端数据库

做法（单环境和多环境的区别、哪些改动不能撤回、迁移怎么写）在[数据库与后端存储](./topics/backend-storage.md)。这里只放会变的数字和档位。2026-10-16 核对官方文档。

| 项目 | 免费版 | 标准版 | 高级版 | 团队版 | 企业版 | 来源 |
|---|---|---|---|---|---|---|
| 创建项目时开多环境、共享后端、自定义存储与并发 | — | — | ✔ | ✔ | ✔ | [计费页](https://cloud.baidu.com/doc/MIAODA/s/ymmbrojwl) |
| 开启后端保活 | — | ✔ | ✔ | ✔ | ✔ | 计费页、[后端保活](https://cloud.baidu.com/doc/MIAODA/s/smuzcqmd2) |
| 每日自动备份保留 | 7 天 | 7 天 | 14 天 | 14 天 | 60 天 | [数据库备份能力](https://cloud.baidu.com/doc/MIAODA/s/dmv8vk79d)（页面更新于 2026-10-15） |
| 手动备份、自助恢复 | 不支持 | 不支持 | 支持 | 支持 | 支持 | 同上 |

- **数据库底座**：Supabase（PostgreSQL），2025-09-17 V1.5 起新建应用使用；此前创建的旧应用不能切换到新库。
- **手动备份**每次扣 100 秒点；备份内容是表结构、数据和 Auth 用户数据；恢复是原地覆盖线上库，不可撤销。会员降级后已有备份按原到期时间清理。
- **自动暂停**：没开后端保活时，应用连续 7 天不活跃，数据库服务自动暂停，重新访问或手动启用后恢复，需要一段时间。保活只作用于线上环境，不影响后端套餐的每日扣费。（V3.7 更新日志写的是"连续 5 天未活跃"，与保活文档不一致，按 5 天预防。）
- **单环境 ↔ 多环境**：已生成的应用可以双向切换。单 → 多会新建开发库，并把线上库同步过去；多 → 单会关闭开发库。（[后端服务多环境](https://cloud.baidu.com/doc/MIAODA/s/emrm8ossc)，页面更新于 2026-09-09）
- **免费基础套餐**：数据库 1GB、并发 10；对象存储计费页写 200MB，[后端资源套餐](https://cloud.baidu.com/doc/MIAODA/s/5mrmxjwkw)页（2026-09-24）写 300MB，规划容量按 200MB。资源套餐页把基础版列为每天 20 秒点，另有小容量到超大容量四档（每天 30～100 秒点）；后端处于激活态就按套餐每天扣秒点。超出容量后只能读不能写。

## 应用运行时与工具安装边界

2026-09-28 核对言剪 AI 的 B8/v46、v47 执行截图及秒哒对 FFmpeg 安装问题的回复。以下区分项目回执与平台自述，不把一段 AI 回复当作全部套餐的永久限制。项目版本和待回收文件只维护在[言剪当前进度](../../../../projects/yancut-ai/README.md#当前进度)。

| 对象 | 当前认识与证据范围 |
|---|---|
| 已生成应用 | 言剪源码与部署回执显示前端为 React/Vite，后端为 Supabase 风格 Deno Edge，数据库为 Postgres。不能据此推定所有历史应用的配置完全相同。 |
| 发布构建命令 | 2026-10-22 本命音律两个应用的发布修复回执均按 `pnpm install && npx vite build --logLevel error` 验收；发布时平台以模板维护 `vite.config.ts`、`postcss.config.js`、`pnpm-workspace.yaml`。`package.json` 声明 `packageManager: npm@…` 会让发布失败，见[踩坑 #27](./pitfalls.md#27-云端发布流水线按平台模板重建配置--上传源码本地能构建发布时装依赖或构建失败)。下载的源码里带平台检查脚本 `.rules/lint.sh`：依次跑 `tsgo -p tsconfig.check.json`、`biome lint`、`.rules/check.sh`（ast-grep 规则：`<Button>` 必须有点击处理、Edge 的 GET 请求不能带 body、`index.html` 不能放 CSP meta、用 useAuth 必须包 AuthProvider 等）、tailwind 编译 `src/index.css`、`.rules/testBuild.sh`（`npx vite build --minify false --logLevel error`）。2026-10-22 本命音律下载包核对：其 `vite.config.ts` 引用 `vite-plugin-svgr`，但 `package.json` 和 `pnpm-lock.yaml` 都没有它，同一下载包的 `pnpm-lock.yaml` 也和 `package.json` 不同步（vite、vitest、supabase-js 版本对不上，少 12 个依赖），`pnpm install --frozen-lockfile` 会失败；本地复建用 `pnpm install`（不冻结）加补装 `vite-plugin-svgr`，和平台发布命令一致。说明下载的源码不等于完整构建环境。 |
| 应用后端的主机权限 | 秒哒本轮自述：应用后端是受限的 Serverless 环境，不提供可自行管理的 root Linux VPS，不能直接安装原生 FFmpeg、运行 Docker 或常驻渲染进程。未取得独立的系统权限探测结果，后续能力变化须按项目复核。 |
| 安装依赖 | JS/TS 包要分别验证浏览器或 Deno 兼容性；npm 包可下载不等于运行时可用。秒哒回复把 `canvas` 列为示例，但其中可能存在原生依赖，不能照单认定兼容；涉及 node-gyp、原生 addon、子进程、线程或系统二进制的项目须逐项核验。 |
| 浏览器处理 | 回复提出 `@ffmpeg/ffmpeg` / WebAssembly 作为候选，不代表言剪已接入，也不代表性能优于现有导出链。ffmpeg.wasm 官方[性能说明](https://ffmpegwasm.netlify.app/docs/performance/)表明其示例测试慢于原生 FFmpeg；此为上游特定环境结果，不能转换成本项目耗时承诺。 |
| 外部渲染 | 回复提出独立服务通过 HTTP API/Webhook 接入。它是待实施路线，不是秒哒已提供 FFmpeg/Chromium 主机或已有可用 Worker 的证明。 |

[Supabase 官方限制页](https://supabase.com/docs/guides/functions/limits)（2026-09-28 核对）可帮助理解 Edge 的资源与部分原生依赖限制，但其套餐数字不能直接当作百度秒哒限额。开发/构建工具、自定义 Skill、已发布应用的 Edge 是不同执行环境；某次构建能运行命令或浏览器，不证明生产 API 能长期运行同一进程。具体选型方法见[平台基础](./basics/platform-basics.md#三应用底座是-supabase-风格)。
