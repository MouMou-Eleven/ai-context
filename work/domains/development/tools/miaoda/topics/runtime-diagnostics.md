# 运行诊断与证据回传

> 来源：2026-09-12 从原提示词合集按主题拆出，原始版本在 Git 历史里；拆分时没有重新实测秒哒产品能力。
> 模板中的页面名、接口、路径和配置是对应案例条件；执行前替换为当前项目已核验事实。查看模板不代表已授权收费、部署或外部发送。

## 源码改了但页面没变，先核对构建和入口

**默认**：秒哒已有应用接收源码增量、或云端直接热修后，若回执成功而页面没变，按“应用与环境 → 包接收与落盘 → 构建输入 → 产物 → HTML 引用 → 浏览器加载”逐层取证。先记录当前应用/环境/版本和真实访问地址，再核对相关文件哈希、构建脚本及配置、输出目录、根入口引用和实际加载的 JS/CSS。只有落盘位置与实际构建输入不一致的证据，才判断为应用或源码路径用错；不能从页面没变化推导附件上传错入口。

例如，一个迁移项目以子目录源码构建静态前端，再交给根 Vite 服务托管，改源码不自动等于根页面更新。构建必须针对实际 Vite 入口；根 build 若只输出提示或嵌套 package.json/build 仍为 Next，则不能作为生产构建证据。类型检查同样查看 include/exclude、别名和实际覆盖文件：只检查根 src 不能证明工作台子目录通过。CRLF/LF 导致补丁锚点不匹配时先检查行尾；若转换字节，显式记录并重算哈希，不豁免完整性检查。

**默认：交接说明要与实现逐项核对。** 插件是否参与生产要看 transform、apply 等真实钩子与限制，不能因名称含 bridge 就认定仅用于本地调试；`publicDir` 复制出的子目录须按源码素材树和实际 URL 判断，不能凭“正常不存在”的描述删除。补充截图用于补齐版本和时间线，不能替代代码。只读整理若实际安装依赖，则记录越出任务范围及可能的环境差异，不直接推断业务源码已变。测试结果保存完整日志和真实退出码；`tsc | head` 或 `install | tail` 后的 `$?` 在通常 shell 设置下属于末尾过滤器，未确认 pipefail/PIPESTATUS 时不能宣称原命令成功。

**红线**：源码、检查、产物生成、部署和浏览器验收分别报告。不能把 lint 通过、根检查成功、静态目录已有文件或强刷后一次成功写成增量全部生效。

## 发布后动态导入失败，核对新旧资源兼容

**默认**：出现 Failed to fetch dynamically imported module 时，记录实际失败 chunk URL、状态码、MIME 和当前 HTML 引用，区分旧 hash 404、权限 401/403、HTML 回退及网络错误。若发布移走旧资源，已打开页面仍持有旧入口，后续懒加载会请求旧 chunk；这类问题由发布兼容处理，不能靠让用户每轮清缓存兜底。

新资源先完整上传并验证，再切换 HTML/入口；旧 hash 资源至少保留到兼容窗口结束，制定容量、保留时间与清理条件，避免无上限累积素材与备份。合并拷贝只能解决保留旧资源的部分问题，不能自动证明发布原子性。HTML 缓存须与切换策略相符，Vite 官方建议 no-cache；核对实际响应头，不能只改本地文件后宣称已生效。

`vite:preloadError` 可作为恢复入口，限会话内刷新次数、防循环，考虑未保存工程和表单数据；持久失败显示可理解的恢复提示，不吞掉诊断证据。所谓“每会话一次”须检验标记的清除时机：若每次页面 load 就清除，仍在同一 sessionStorage 会话内，下次失败会再次刷新；按失败→重载→load→再次失败模拟或复测，不凭注释宣称防循环已验收。验收必须包含“发布前已打开页面 → 发布后进入懒加载路由”和“新会话首次打开”，再核对新旧 chunk 均按策略可达。只验证首页或只做 HTTP 200 探针不够。

## 开发任务整体失败，和应用页面故障分开取证

**默认**：连轻量只读任务都返回同一不可重试的平台错误时，保全已有版本、源码及必要日志，停止没有新证据的重复任务；记录真实终态、命令返回与退出码是否存在。应用在线、后端健康标记、开发执行和结果回传分别判断，不把前端 chunk 404 当作沙箱故障原因。

大体积备份、并行构建和不匹配的 Next 构建是排查线索；缺平台资源/OOM/磁盘日志及官方说明时，只能记为待验证。恢复后先轻量取证，再串行校验真正入口。备份默认只包含本次变更前文件、清单与哈希；先保全再制定上限，排除打包/扫描不等于既存体积已减少，禁止因推测直接删除恢复点或业务数据。

以上方法来源：[言剪官方恢复后的复盘案例](../../../../../projects/yancut-ai/case-miaoda-source-migration.md#官方恢复后的静态发布复盘)；技术机制核验于 2026-09-30，[Vite 官方说明](https://vite.dev/guide/build.html#load-error-handling)。项目目录、命令和版本是案例条件，不推广为秒哒所有应用的固定结构。

## 预览域名请求被拒绝时，先分清来源校验和业务权限

**默认**：游客打开公开页面报 403 时，先记录实际页面 Origin、请求方法/路径、返回错误码及拒绝层。若为 `ORIGIN_DENIED`，先检查 Edge 的来源白名单，不能直接去放宽数据库权限或强制游客登录。

检查已核实的本应用主域名、预览别名和正式域名；以解析后的协议、hostname、端口和应用身份匹配。不能只放行一个主域名，也不能用“包含应用 ID”或“以 miaoda.online 结尾”的宽松字符串判断。明确列出的本机来源只用于开发配置，正式环境默认关闭。

正例：本应用预览来源请求公开列表返回 200；匿名用户仍不能创建作品、改配置或扣积分。反例：为修复广场而放行所有 Origin、其他应用预览域名或关闭认证。至少测试主站、实际预览来源、带恶意后缀的仿冒域名、其他应用来源及 `null` Origin；浏览器还要检查 OPTIONS 和实际响应的 CORS 头，单独 HTTP 探针不等于页面已验收。

来源：2026-09-28 用户回传[言剪 B8 后 v47 热修](../../../../../projects/yancut-ai/README.md#当前进度)，秒哒报告预览来源 200、第三方来源 403；本轮未取得该云端函数全文和独立浏览器复测。此证据支持上述分层排查，不证明截图中的白名单实现已覆盖所有仿冒来源。

### 片段 7：云端应用的临时诊断日志面板

**背景**：此模板用于云端测试无法复现用户环境的情况，不表示秒哒永久没有浏览器测试能力。当前能力按[运行时边界](../basics/platform-basics.md#运行时诊断的正确边界)核对。手机端通常不便查看 Console，可把诊断证据呈现在应用内，由用户复现后复制回传。

**适用场景**：支付、登录、游戏 AI、触控、横竖屏、权限等只能在预览版、发布版或真机中复现的问题。

**提示词模板**：

```text
本轮只增加临时诊断能力，不修复、不重构、不调整现有业务行为，也不要改数据库、素材和部署配置。

请在当前秒哒云端项目中增加一个应用内“诊断日志”按钮和可展开面板。本诊断版本直接显示入口，不要求用户修改 URL 或添加查询参数；如果项目已有可靠的管理员身份体系，只对管理员显示，否则把它明确标记为临时诊断按钮，不要为了隐藏按钮新建登录或数据库。

要求：
1. 页面/场景进入后自动开始记录，使用有容量上限的内存环形缓冲，刷新后允许清空，不写 localStorage，不上传敏感信息。
2. 每条日志包含时间戳、会话 ID、对象 ID、事件名和结构化字段。记录状态转换、异常事件以及限频快照；禁止逐帧输出，快照频率按问题控制在 5-10Hz。
3. 面板提供“复制全部”“下载 JSON”“清空”三个操作；复制失败时提供可选中文本区域。
4. 可以同步镜像到 console，但应用内面板是手机端回传证据的主入口。
5. 不要声称已经在浏览器或真机中复现、验收或修好问题。你只需回报修改文件、日志字段、静态检查/测试/构建结果，以及用户应如何在页面内打开面板。

完成后停止，不继续修改业务逻辑。用户会手动复现问题，并把复制或下载的日志交给 Codex 分析。
```

**实现约束**：

- 仅已有可靠管理员身份时才使用 `is_admin` 或白名单；不能为了诊断擅自增加认证和数据库。
- 环形缓冲必须限制条数和单条长度，敏感字段、Token、手机号、订单隐私必须脱敏。
- 诊断完成后隐藏或删除按钮、高频采样和临时日志字段；如需长期远程支持，再单独设计 `client_logs` 表与权限，不能在临时诊断中顺手扩张范围。

### 片段 10：故障证据阶梯与训练台验收

**适用场景**：课程演示或真实项目需要把“现象—证据—修复—复测”连成一条可回放的排错流程。

```text
请把本次问题按最小证据路径处理，不要一开始重构或扩大范围。

先确认当前现象能否稳定复现；如果口述不足，再按需采集 Console、录屏、Elements、Network 或应用内诊断日志。每种证据只记录与本问题直接相关的内容。

本轮只增加/修改能够定位该问题的窄范围代码。严禁顺手重构无关页面、数据库、登录、支付、订单、权限和上传链路。

完成后必须分别回报：
1. 秒哒实际修改的文件、函数和静态检查/构建结果；
2. 用户需要在预览或发布页面执行的复现步骤；
3. 复测时应看到的成功结果和失败结果；
4. 尚未由真实浏览器或手机确认的项目。

不要把构建通过或“已修复”摘要写成真实运行验收通过。问题确认后移除或隐藏临时诊断入口和高频日志。
```
