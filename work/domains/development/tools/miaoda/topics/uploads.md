# 大文件与小程序上传

> 查看模板不代表已授权收费、部署或外部发送。

> 当前限额只看[事实表](../facts.md)，这里不重复。

## 大文件、大视频上传：按会员改上限，再实测

**适用**：应用里让最终用户上传视频、大文件。上限是"项目内单文件上传"（免费版 50MB，付费版 500MB，见[事实表](../facts.md)），和你给秒哒发源码包用的对话附件额度（一次 5 个、每个 20MB）是两回事，不要混用。

**做法（默认）**：

1. 确认会员档位和对象存储剩余容量。500MB 是单个文件的上限，不代表还剩 500MB 存储，存储满了照样传不上。
2. 付费版的 500MB 不会自动生效，要在对话里让秒哒同步改前端校验和后端限制，只改页面提示文字不算。
3. 用一个无敏感内容、接近真实大小的视频，在正式域名上实测：能不能传完、刷新后还在不在、能不能播放和拖动进度条。
4. 直接用平台原生上传能力，不要自己设计分片合并、代理播放这类架构。弱网要断点续传时，用存储服务原生的 multipart，最终保存为一个完整对象。
5. 私密、付费或按用户隔离的视频，单独验证访问权限；不能拿文件名里的 UUID 当鉴权。

秒哒控制不了你的浏览器和手机，第 3 步由建委实际操作并回传截图或报错。

**提示词**：

```text
本批只配置和验证项目内大文件上传，不改其他功能。

当前空间为付费会员，项目内单文件上限 500MB，对象存储剩余容量足够。
请把项目内上传大小改为 500MB，同步修改前端校验和后端限制，不要只改页面提示文案。
使用平台原生上传能力，不要自行实现分片上传、分片合并或视频代理播放。

完成后回报：
1. 前端校验和后端限制分别改在哪里，值是多少。
2. 上传后文件保存在哪个存储桶、对象路径规则是什么、视频 URL 是否支持 Range（能拖动进度条）。
3. 我在正式域名上应该怎么测：上传哪种文件、看哪些结果算通过。
完成后停止。
```

建委实测失败时，把浏览器网络请求里的状态码（如 413、CORS 报错、超时）和秒哒「调试」里的后端日志截图发给 Codex，再判断是限额、存储容量还是代码问题。

## 微信小程序上传：禁止复用 H5 文件选择

**适用场景**：目标是微信小程序，涉及图片、视频、附件上传；或已经出现 `invalid filepath`。

```text
当前项目是微信小程序，不是 H5/Web 页面。请修复图片/视频上传逻辑。

红线：
- 不要复用 H5 的 input file / File API / 浏览器文件路径逻辑。
- 不要把 Web 预览能上传当作小程序真机可用。
- 不要切换应用类型或重构无关页面。

任务：
1. 图片选择必须使用微信小程序方式（如 wx.chooseImage 或 Taro 对应 API）。
2. 视频选择必须使用微信小程序方式（如 wx.chooseVideo 或 Taro 对应 API）。
3. 上传前请处理小程序返回的临时文件路径，不要使用浏览器 File 对象。
4. 保持现有上传后的展示、保存和权限逻辑不变。

完成后请说明：
1. 修改了哪些文件。
2. 图片和视频分别使用了哪个小程序 API。
3. 真机小程序里应该如何验证。
```
