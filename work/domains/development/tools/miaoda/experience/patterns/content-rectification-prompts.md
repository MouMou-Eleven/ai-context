# 秒哒内容整改提示词拆分处方

> 来源：2026-06-11 德锦周锦网站备案主体一致性整改。场景是：网站已上线，用户只能通过秒哒 AI 修改云端项目，目标是调整公开文案、SEO、栏目名称和页面口径，不改数据库结构、接口、支付、登录、订单等后端能力。

> 本文是 [Codex 辅助秒哒开发工作流](./codex-assisted-workflow.md) 在“内容整改/主体口径/公开文案”场景下的具体处方；更通用的“Codex 先拆方案、用户再粘贴给秒哒执行”的流程请先读该工作流。

## 适用场景

| 场景 | 是否适用 |
|---|---|
| 备案主体一致性整改 | 适用 |
| 网站公开内容与主体/品牌关系不一致 | 适用 |
| 需要批量调整 SEO、分享文案、栏目名、页面标题 | 适用 |
| 只改前端展示，不改后端业务能力 | 适用 |
| 新增支付、上传、登录、订单等功能开发 | 不适用，走对应功能处方 |

## 核心结论

内容整改类任务不要写成“给人看的方案”，要写成“给秒哒直接执行的任务”。

秒哒 AI 是指令式执行，提示词里越多背景解释、角色设定、链接和寒暄，越容易稀释真正要执行的动作。最终有效的提示词应该做到：

1. **直接进入任务**：说清楚本批改什么、怎么改、哪些不能动。
2. **每批都是可执行修改**：不要用“第 0 批：先检查”开头，除非用户当前只想诊断。若目标是整改，第一批应直接改最高风险项。
3. **不要写无意义角色设定**：不要开头写“你是百度秒哒 MIAODA 项目内置开发助手”。秒哒已经知道自己在哪个项目里。
4. **不要贴网站链接当任务背景**：用户已经在当前秒哒项目里操作，链接通常没帮助，还可能诱导它去理解外部网站而不是改当前项目。
5. **不要写“不要依赖上一轮对话记忆”**：这句话对秒哒执行没有实际帮助。要通过每一批重复关键口径和红线来实现自包含。
6. **事实类整改要防止编造**：涉及公司主体、设计师身份、合作关系、备案、出版、售后主体时，要明确“不要编造、不要夸大、不要把未确认关系写成确定事实”。
7. **先改最容易被抓取的隐藏信息**：备案/主体一致性整改中，`index.html`、SEO、OG/Twitter、JSON-LD、秒哒分享配置通常比可见页面更容易被遗漏。

## 推荐拆批

内容整改不要一次发完。按“风险最高 + 改动边界最清楚”的顺序拆：

| 批次 | 修改范围 | 为什么这样排 |
|---|---|---|
| 第 1 批 | 全站 SEO、分享文案、隐藏文案、JSON-LD | 审核和搜索抓取最容易看到，且常有平台生成残留 |
| 第 2 批 | 顶部导航、移动端菜单、页脚栏目名称 | 全站公共组件，先统一口径 |
| 第 3 批 | 首页首屏、首页模块、首页高风险区块 | 首页是人工审核第一眼看到的地方 |
| 第 4 批 | 最严重的独立主体页面或合作方页面 | 如协会、机构、合作方、第三方品牌页面 |
| 第 5 批 | 关于页、品牌故事、人物介绍 | 容易被写成个人 IP 或另一主体 |
| 第 6 批 | 商品列表、商品详情、文创产品 | 补运营主体、售后主体，避免误改价格库存 |
| 第 7 批 | 书籍、资讯、文章详情 | 补展示/销售主体，清理“权威发布/官方发布” |
| 第 8 批 | 残留风险词清理和最终验收 | 只做小范围文案清理，不再重构 |

不建议默认加入“第 0 批检查”。检查批适合审计和写方案，不适合用户已经明确要整改、且秒哒需要分批执行的场景。此类任务可以把检查动作放进每批末尾：“完成后输出修改文件、残留风险词、是否未动后端能力”。

## 每批提示词结构

推荐固定结构：

```text
请严格、严谨、认真、负责地完成本批 <整改类型>。不要编造，不要夸大，不要把未确认关系写成确定事实，不要自行扩展任务。

本批只修改 <允许修改的范围>。

严禁修改：
- 数据库结构
- 数据库记录
- API / 接口
- Edge Function
- 支付、登录、订单、购物车、退款、地址管理
- 商品数据、价格、库存、图片

整改目标：
<一句话说清楚本批要达成的状态>

请按以下方式修改：
<逐条给出新标题、新描述、新说明、要隐藏的入口、允许保留但要加归属说明的词>

完成后请只输出：
1. 修改了哪些页面和配置。
2. 哪些风险词仍有残留及其位置。
3. 是否未修改数据库、接口、支付、登录、订单等后端能力。
完成后停止。
```

## 关键写法

### 1. 不要让秒哒猜法律关系

错误：

```text
把周锦改成公司创始人，把协会写成战略合作单位。
```

更稳：

```text
如无法确认“首席设计师”“创始人”“战略合作”等关系，不要编造。统一使用更稳妥表述：
- 人物：合作设计师
- 品牌：授权合作品牌或产品系列
- 协会/机构：行业合作单位
```

### 2. 不要删除数据库记录

内容整改经常遇到“协会章程、会员单位、组织架构、会员权益”等高风险内容。秒哒底层虽像 Supabase，但用户没有原生控制台，贸然让它删数据风险很高。

推荐写法：

```text
如果这些内容来自数据库，不要删除数据库记录，只在公开页面不渲染或过滤掉。
如果只存在于管理后台或数据库原始记录中，但不在公开页面展示，请在报告里注明，不要删除。
```

### 3. SEO 批必须包含隐藏渠道

不要只写“改 SEO”。要点名：

```text
请重点检查并修改：
- index.html 中的 title、description、keywords
- Open Graph：og:title、og:description、og:site_name
- Twitter Card：twitter:title、twitter:description、twitter:site
- JSON-LD 结构化数据
- 秒哒外部分享配置中的 share.title、share.desc、share.image
- 项目中任何站点名称、站点描述、分享标题、分享描述字段
```

如果是 React/Vite 单页应用，再补一句：

```text
如果项目里已有 SEOHead、useSEO、Helmet 或类似统一 SEO 组件，请优先复用现有结构，不要重写整套 SEO 体系。
如果是 React 单页应用，请不要只改 index.html。核心页面切换后 title、description、keywords 也必须保持统一口径。
```

### 4. 提示词不要写成报告

不推荐：

```text
本次整改背景为云服务商反馈网站开站内容与备案主体不一致。请先完整检查当前项目，并输出诊断报告。
```

推荐：

```text
本批只修改首页公开展示文案、标题、模块说明、按钮文字和必要的前端展示判断。

首页 Hero 主标题改为：
太阳鸟·华服文化

首页协会模块副标题改为：
合作单位：山东省服装设计协会 · 共促华服文化交流
```

### 5. 结束语要阻止继续扩展

每批末尾加：

```text
完成后请只输出：
1. 修改了哪些页面和配置。
2. 是否仍有风险词残留。
3. 是否未修改后端能力。
完成后停止。
```

“完成后停止”比“等待下一条指令”更直接。

## 高风险词清理清单模板

备案主体一致性、品牌主体整改、协会/机构页面整改时，可以把下列清单按项目替换：

```text
请搜索以下高风险表述是否仍存在：
- AI编程全栈独立打造
- 个人IP综合平台
- 个人IP品牌展示
- 个人品牌展示
- 行业协会权威发布
- 协会权威发布
- 通过协会官方背景提升个人IP
- 商业变现
- 电商板块实现流量商业变现
- 行业权威组织
- 专业背书
- 官方发布
- 权威发布
- 协会风采
- 协会章程
- 会员单位
- 组织架构
- 会员权益
- 协会联系方式
- 平台默认账号或平台生成痕迹（如 @MiaodaAI）
```

## 验收标准

每批完成后，不只看秒哒 Summary。至少人工预览：

- 首页
- 关于/品牌故事页
- 高风险合作方/协会/机构页
- 商品列表页
- 任意商品详情页
- 书籍或内容列表页
- 任意详情页
- 移动端菜单
- 页脚
- 分享卡片与页面源码中的 meta

最终验收时要求秒哒回报：

```text
1. 已修改的页面和配置。
2. 仍存在的风险词及其位置。
3. 是否涉及数据库、接口、支付、登录、订单逻辑改动。
4. 公开页面是否均能正常访问。
5. 仍需人工确认的事项。
```
