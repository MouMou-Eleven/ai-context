## 大文件上传：先按会员配置 500MB，旧分片代理只兜底

**背景**：2026-08-27 官方计费页明确免费版项目内单文件 50MB，专业版、旗舰版和企业标准版 500MB，并提示通过对话同步修改前后端限制。旧环境曾同时撞 CORS、Edge Function 资源和 Storage 413 三层墙，但这一旧结论不能再直接套到新项目。完整判断流程见 [patterns/large-video-upload.md](../patterns/large-video-upload.md)，历史复盘见 [pitfalls.md #14](../pitfalls.md)。

**当前核心：先确认会员和存储容量，再配置、测试当前环境。** 500MB 权益不等于既有项目自动改好，也不等于弱网下无需 multipart。当前原生上传能通过，就使用原生能力；只有旧项目仍复现旧限制时，才使用永久分片 + Range 代理。

**第一步：新环境能力测试提示词**：

```text
本批只配置和验证当前后端的大文件上传能力，不要直接部署旧的永久分片方案。

前提：当前空间为专业版或以上会员，且对象存储剩余容量足够。
请把项目内上传大小改为 500MB，同步修改前端校验和后端限制；不要只改页面提示文案。

然后使用一个无敏感内容、接近真实业务大小的 MP4 测试文件，验证当前正式访问域名和当前后端套餐：
1. 前后端显示和实际执行的单文件上限是否一致。
2. 是否能通过平台当前原生上传能力上传成功。
3. 浏览器网络请求是否出现 CORS、413、超时或连接中断。
4. 后端日志是否出现 WorkerRequestCancelled、内存/时长超限或对象大小不一致。
5. 上传完成后对象的实际字节数是否等于本地文件。
6. 页面重新加载后视频是否仍存在，能否播放和拖动进度条，Range 请求是否正常。

完成后只输出测试结果表：测试项、实际结果、HTTP 状态/报错、是否通过。
不要在本批改上传架构。完成后停止。
```

测试全部通过：使用当前平台原生上传；如需弱网重试，优先使用平台或云存储原生 multipart / 断点续传，最终保存为一个正常对象。

旧项目仍复现旧环境限制时，按 [旧兼容合同](../reference-materials/video-chunked-upload/legacy-contract.md) 读取专用模板。

## 微信小程序上传：禁止复用 H5 文件选择

**适用场景**：目标是微信小程序，涉及图片、视频、附件上传；或已经出现 `invalid filepath`。

```text
当前项目是微信小程序，不是 H5/Web 页面。请修复图片/视频上传逻辑。

红线：
- 不要复用 H5 的 input file / File API / 浏览器文件路径逻辑。
- 不要把 Web 预览能上传当作小程序真机可用。
- 不要切换应用类型或重构无关页面。

任务：
1. 图片选择必须使用微信小程序方式（如 wx.chooseImage 或 Taro 对应 API）。
2. 视频选择必须使用微信小程序方式（如 wx.chooseVideo 或 Taro 对应 API）。
3. 上传前请处理小程序返回的临时文件路径，不要使用浏览器 File 对象。
4. 保持现有上传后的展示、保存和权限逻辑不变。

完成后请说明：
1. 修改了哪些文件。
2. 图片和视频分别使用了哪个小程序 API。
3. 真机小程序里应该如何验证。
```
