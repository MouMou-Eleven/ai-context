> 来源：从原 [prompt-patterns.md](../prompt-patterns.md) 的实战模板按主题整理，原始版本由Git历史保留；2026-09-12仅拆分与明确适用边界，未重新实测秒哒产品能力。
> 模板中的页面名、接口、路径和配置是对应案例条件；执行前替换为当前项目已核验事实。查看模板不代表已授权收费、部署或外部发送。

## 首轮生成：应用形态 + 真实后端存储

**背景**：秒哒首轮生成时，如果没有明确应用形态，Web / 小程序 / APP 后期强转会非常不稳定；如果没有明确后端存储，模型可能用浏览器缓存做临时数据，当前浏览器看似可用，换设备就丢。

**适用场景**：新建一个需要长期使用、多人访问、跨设备保存数据的应用；尤其是导航站、课程平台、微课展示、订单/报名/反馈/后台管理类应用。

**提示词模板**：

```text
我现在要做一个 <Web 应用 / 微信小程序 / APP>，请从首轮就按这个应用形态生成，不要生成成其他类型。

红线（必须遵守）：
- 本项目是 <Web 应用 / 微信小程序 / APP>，不要在后续实现中切换应用类型。
- 需要真实后端数据库存储，不允许只用浏览器缓存、localStorage 或前端状态保存业务数据。
- 需要生成必要的数据表、增删改查能力，以及管理员可用的数据查看维护页面。

核心功能：
1. <功能一>
2. <功能二>
3. <功能三>

验收要求：
1. 请说明生成了哪些数据表，每张表有哪些字段。
2. 请说明哪些页面或操作会写入后端数据库。
3. 请说明我如何用无痕窗口或另一台设备验证数据是否真的持久化。
```

**为什么要这么写**：秒哒会尽量快速把原型做出来，如果不强调“真实后端数据库”，它可能用本地缓存模拟；如果不强调形态，小程序发布、上传、登录、支付这些能力会在后期出现技术栈错位。

## 已生成应用补数据库：从本地缓存迁移到后端

**适用场景**：已经做好的应用里，当前浏览器能看到数据，但换浏览器、无痕模式或换设备后数据丢失。

```text
当前应用的数据疑似只保存在浏览器缓存或 localStorage 中，换浏览器/无痕模式后会丢失。
请基于当前应用补充真实后端数据库存储功能。

红线：
- 不允许继续把业务数据只保存在浏览器缓存、localStorage 或前端状态里。
- 不要删除现有页面和功能。
- 不要重构无关模块。

任务：
1. 识别当前应用中所有需要持久化的数据。
2. 为这些数据创建后端数据表。
3. 把新增、编辑、删除、查询逻辑改为读写后端数据库。
4. 基于现有表结构生成管理员可用的数据查看维护页面。
5. 如果当前本地已有示例数据，请提供迁移或重新录入建议。

完成后请只输出：
1. 新增/修改了哪些表和字段。
2. 哪些页面已改为读写后端数据库。
3. 如何用无痕窗口验证数据持久化。
4. 是否仍有 localStorage / 浏览器缓存用于业务数据；如果有，列出位置和原因。
```
