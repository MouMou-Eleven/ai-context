# 秒哒提示词模板

三条协作路径各自的可粘贴模板。流程说明见 [workflow.md](./workflow.md)，这里只放模板。尖括号里的内容用当前项目已经核实过的事实替换，不要照抄案例里的页面名、接口和路径。

## 所有提示词共用的写法

**默认用工单式写法**，红线放最前面：

1. 涉及技能调用时，`@技能名` 放在最前面。
2. 本批只改什么。
3. 严禁改什么（红线写在前面，秒哒可能边读边改，放在末尾就晚了）。
4. 具体改成什么。已经验证过的关键代码直接贴出来让它照用，不要让它自己另写。
5. 必须用的文件、URL、环境变量。
6. 完成后回报什么，然后停止。

不要这样写：

| 写法 | 问题 |
|---|---|
| "你先完整分析一下这个网站，然后告诉我怎么改" | 秒哒会产出分析文字或乱扫项目，而不是执行 |
| "你是百度秒哒项目内置开发助手，不要依赖上一轮记忆" | 这类角色句对秒哒没有约束作用 |
| "帮我把这个功能修好，不要影响其他功能" | 范围太大，没说哪些不能动，秒哒会顺手重构 |
| "把我这份方案一次性改完" | 任务太大，容易漏改、误改、总结过度乐观 |
| "看情况""建议""考虑" | 含糊措辞会让它自由发挥 |

## 首次全量交付

### 第一条：只接收校验

```text
本次先不要生成页面，也不要改写任何源码。

请按编号解压上传的 <N> 个压缩包，逐个核对文件数、字节数和 SHA-256（清单见各包内的 manifest）。
缺文件、哈希不一致、对象存储额度不足时，立即停止并报告，不要用占位图、重绘或自由发挥补齐缺失内容。

核对通过后，把图片、音频、视频、模型等静态素材解压到云端对象存储，回报"原相对路径 → 对象键 → HTTPS 地址 → SHA-256"的映射表。

完成后只回报接收结果和映射表，然后停止。
```

### 第二条：确认齐全后开始创作

```text
请先确认全部编号压缩包、逐文件 SHA-256 和对象存储 URL 映射均已通过；如有缺失，停止并报告，不得用占位内容补齐。

本项目是 Web 应用，技术栈固定为 React + Vite。禁止 Next.js、SSR、Next API Routes、next 依赖和必须依赖常驻 Node 服务的方案。保留上传源码中的现有功能、交互、素材和测试，不要从零重写，不要替换素材，不要通过删功能或降质量解决性能问题。

生产环境必须通过统一资源解析器读取秒哒云端对象存储中的稳定 HTTPS URL；禁止 Base64 大资源、临时 Blob URL、本地绝对路径和浏览器缓存伪存储。业务数据需要跨设备保存时使用真实后端数据库，并回报表结构、权限和无痕窗口验收结果。

按源码中 package.json 的 packageManager 和锁文件安装依赖，执行自动测试和生产构建；产物必须为 dist/。完成后回报 PRD 路径、修改文件、对象存储映射、数据库表、静态检查与构建结果、需要我人工完成的桌面与移动端验收清单、剩余风险和人工确认项。不得把构建通过描述成真实设备已经验收通过。

严格依照上传的源码，然后给我生成网页应用，给我生成产品需求文档，并立即开始创作。
```

最后一句不能省。

## 增量包执行

```text
请严格执行本次百度秒哒增量包交付，不要编造、不要自行扩展、不要用占位内容补缺失文件。

版本：<当前版本>
基线版本：<基线版本>
增量包：<zip 文件名>（同批多包时按 <顺序> 应用）

本批只允许修改 manifest 中列出的相对路径文件，以及明确列出的数据库迁移。
严禁删除或重建未列出的表、数据、接口、登录、权限、支付、订单和上传链路；严禁改变未列出的对象存储路径、环境变量和公开 URL；严禁在校验前开始修改或部署。
这是已有应用的迭代：不要重新生成应用，不要重写产品需求文档。

请按顺序执行：
1. 确认当前版本与基线版本一致，并定位可还原的全量源码基线；缺失或不一致立即停止并回报，不从增量包猜补全量工程。
2. 校验增量文件相对路径、字节数和 SHA-256；失败停止。建立可回滚版本，在完整基线上叠加增量。
3. 对叠加后的目标文件再次校验，核对新文件、删除清单、依赖锁文件、资源和迁移。
4. 先回报实际源码目录、构建脚本/配置、输出和托管目录、HTML入口；确认类型检查覆盖本次目标，按锁安装依赖并串行执行相关检查、测试和本项目实际的构建链。根目录 build 只打印提示、或真正的构建在嵌套子项目里时，根 build 成功不能当作构建成功的证据。按本包约定执行迁移并验证。新资源就绪后再切入口，按约定窗口保留旧hash资源，记录备份容量与保留条件。
5. 核对实际HTML引用、JS/CSS及懒加载chunk、HTML缓存响应头；分别检查发布前已打开页面进入懒加载路由、发布后新会话打开页面；不能用强刷后一次成功代替。按随包的「问题对照与验收清单」逐项回报实际结果；区分本地、云端和待我手动验收，不要把构建成功当成所有问题已通过。
<如随包带取证要求：6. 按 EVIDENCE-REQUEST-<版本>.md 采集指定证据；需要完整文件的，按清单打一个无密钥审查包，列出路径、字节数与 SHA-256。不要输出未要求的全库数据。>

完成后不要只回复"已完成"。回报基线来源、实际改动、校验/测试/构建/迁移结果、当前部署版本与未解决风险，然后停止，不要自行启动下一批。
```

## 纯提示词协作

### 每批骨架

```text
请严格、严谨、认真、负责地完成本批任务。不要编造，不要夸大，不要自行扩展任务。

本批只修改：
<允许修改的范围>

严禁修改：
- <不能动的功能/数据/配置>
- <不能动的功能/数据/配置>

目标：
<本批完成后应该达到什么状态>

请按以下方式修改：
1. <具体动作>
2. <具体动作>

完成后请只输出：
1. 修改了哪些文件、页面或配置。
2. 哪些风险点仍未处理。
3. 是否未修改严禁修改的范围。
4. 需要人工确认的事项。
完成后停止。
```

### 保护现有功能

新增功能时秒哒容易"顺手重构"，把稳定的部分点名锁住：

```text
当前 PC 端用的是 <X 接口>，已经稳定运行，本次任务保持不变，
不要动 PC 端任何代码、配置或环境变量。
<新路径> 与 <旧路径> 必须能并存、互不影响。
```

### 按问题类型怎么拆批

| 问题类型 | 拆批顺序 | 专题 |
|---|---|---|
| 内容、SEO、主体口径整改 | SEO 与分享信息 → 导航页脚等公共组件 → 首页首屏 → 高风险主体页 → 关于页 → 商品详情 → 文章 → 残留词清理 | [SEO 与内容](./topics/seo-and-content.md) |
| 前端 UI、移动端 | 只改样式和当前组件、不动数据加载 → 保持桌面端效果 → 单独检查移动端菜单、按钮、弹窗、滚动 → 难复现时加临时日志面板 | [运行诊断](./topics/runtime-diagnostics.md) |
| 支付、订单、退款 | 原有稳定支付链路一行不动；新通道按 `pay_channel` 分流；密钥不进前端和日志；新 Edge Function 先验证环境变量名 | [支付](./topics/payment.md) |
| 上传、存储、大文件 | 先按会员配置原生上限并实测；旧分片方案只在旧项目仍报错时用 | [上传](./topics/uploads.md) |

建议顺序：先改最孤立、风险最高、最容易验证的部分，再改公共组件，再改单页，最后做残留清理和验收。
