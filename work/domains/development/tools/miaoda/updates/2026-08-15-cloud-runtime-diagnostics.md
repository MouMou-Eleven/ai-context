# 秒哒云端运行时诊断协作边界修订

> 日期：2026-08-15
>
> 状态：当前有效
>
> 来源：「混世魔牛」野怪卡死诊断提示词复盘

## 修订原因

此前把 Codex 的本地浏览器调试流程直接写进秒哒提示词，要求通过 URL 查询参数启用诊断，并要求秒哒自行完成浏览器或真机验证。该口径错误：百度秒哒 MIAODA 的源码修改、构建和发布在云端进行，但秒哒 AI 不能像 Codex 一样控制真实浏览器、手机或 Playwright 完成动态复现。

## 旧口径（废止）

- 让秒哒自行打开浏览器、点击页面并宣称动态问题已验证。
- 把 `?debug=1`、`?enemyTrace=1` 等 URL 参数作为用户必须掌握的唯一诊断入口。
- 只输出 Console 日志，或要求用户在手机端读取控制台。
- 把 lint、单元测试或构建通过等同于真实运行问题已解决。

## 当前口径

角色必须分开：

1. **秒哒**：在当前云端源码中加入窄范围诊断埋点和应用内可复制日志面板；完成它实际可执行的静态检查、测试、构建和发布。
2. **用户**：在秒哒预览版或发布版中手动复现问题，复制或下载诊断日志。
3. **Codex**：读取用户回传的真实日志，定位根因并生成下一轮修复提示词。

诊断版本应直接显示临时入口，不强迫用户修改 URL。日志使用有容量上限的内存环形缓冲，记录状态转换、异常事件和限频快照，支持“复制全部”和“下载 JSON”；Console 仅作为可选镜像。诊断轮不得顺手修改业务逻辑，问题解决后应隐藏或删除诊断 UI。

- `patterns/codex-assisted-workflow.md`：明确秒哒、用户、Codex 三方诊断闭环。

## 后续检查

以后为秒哒编写动态问题诊断提示词时，必须回答以下问题：

- 这项动作是秒哒能完成的云端源码/构建动作，还是必须由用户在真实页面完成的复现？
- 手机端是否能直接看到并复制诊断证据，而不依赖 URL 参数或开发者控制台？
- 秒哒的回复是否只陈述它实际完成的静态检查与构建，没有虚构浏览器或真机验收？
- 日志是否限频、限容量、脱敏，并能在诊断完成后移除？
