## 文档已确认的能力

| 能力 | 文档口径与开发含义 |
|---|---|
| 工作流调用 | 可视化组合模型、代码、插件等；智能体中的工作流配置类似插件，可设置调用方式，且可直接输出结果，避免外层模型再次总结 |
| 开始与结束 | 开始节点接收输入并定义变量，结束节点返回变量或文本；开始参数可受外部模型提取影响，重要字段还需确认和校验 |
| 大模型节点 | 接收前置变量，输出文本、Markdown或JSON；结构化格式不代替业务校验 |
| 条件与循环 | 条件支持等于、大小、包含、正则、空值等判断；循环支持数组、次数及无限模式，课堂活动优先有限退出 |
| 知识库 | 支持本地文档、自定义文本与QA；检索有混合、语义、全文及召回限制。工作流结果包括rawText与output，关键引文优先核对原文 |
| 变量 | 可新增输入控件或变量；工作流变量节点可获取或设置值。具体跨会话、跨用户作用域须实测，不能仅因文档称全局就当成安全隔离 |
| 数据表 | 支持字段定义、唯一值、必填、数据导入和增删改查，也可引用至智能体；文档未充分证明课堂所需行级权限 |
| 问答与过程输出 | 问答节点可补充输入，过程输出可反馈阶段结果；不因此保证可恢复任意中断任务 |
| 异常 | 节点可设置超时、重试、特定返回和异常流程；流式输出开始后不能再按同样方式重试或跳异常分支 |
| 调试 | 可查看调用组件的输入输出；这为逐节点验证提供入口，不等同于流程已通过 |
| 工作空间 | 个人与团队空间的数据资源相互隔离；团队空间支持所有者、开发者、观察者协作，文档描述支持转让空间所有权 |
| 导出 | 大赛教程称智能体为.agent、工作流为.workflow；能否携带知识库、插件和数据表等依赖需重导入核验。教程中的数据表导出后缀可能有表述问题，以实物为准 |

## 正式账号建议

正式作品由每位客户的参赛负责人或其学校可控制的团队空间持有，建委通过适当的开发角色协作。两位客户各用独立空间，调研账号保留无客户数据的原型。该建议基于可维护与隔离需求，不宣称赛事强制账号注册人必须等同负责人。

客户先完成注册登录和团队创建，再邀请协作者。转让、迁移、公开发布和正式提交分别核实权限、资源点、依赖和链接变化；不先假定个人空间的一切资产可无损转交。当前没有用两个客户的真实账号完成这些步骤。

平台“输入老师模式”只属于业务选项，不是身份认证。需要学生自助使用与教师汇总时，先验证跨账号访问与数据隔离；验证前采用教师控制账号、投屏组织和匿名小组记录的方式。

## 导入与更新的实测约束

原生导出提示知识库文档和数据表数据不随配置导出。导入含依赖的流程会另建空库、表和插件副本，恢复时需重新绑定实际全文库、核对表，再上传资料。不能只看到节点连线完整就判断恢复成功。

### Agent 与 Workflow 配置的可复用迁移流程（默认）

**场景：** 为天津平台升级、迁移或离线生成配置时，优先以带完整 Workflow 快照的 Agent 作为整体导入入口；独立 Workflow 用于单独开发与排错。

**做法：**

1. 从目标平台下载同版本原生 `.agent` 和 `.workflow` 作模板，保留原件。先比较最外层键、节点对象形状、参数类型和引用关系，再修改业务内容。独立 Workflow 使用 `{name, templateConfig, type}` 外壳；Agent 的 Workflow 组件使用完整 `targetConfig`，不要把两种层级互换。
2. `nodes` 保留整张执行图，包括 Start 和 End；专用 `startNode`、`endNode` 与列表内对应节点保持一致。检查节点 ID 唯一、所有连线目标存在、输入输出引用能解析。缩减旧流程时同时更新四处：节点列表、开始结束快照、工作流外层参数、Agent 组件快照与映射。
3. 检查脚本分别加载生成的 Agent 与独立 Workflow，对比两者真实节点、代码和参数。不要用同一 Workflow 对象与自己比较，或只检查 JSON 可以解析；这会漏掉交付 Agent 仍带旧配置的问题。
4. 在“智能体开发”只导入 Agent 一次。平台会为内嵌 Workflow 创建资源、重映射 ID，并可能给同名资源加后缀；不要同时单独导入相同 Workflow，也不要因 Agent 报错就连续重试。先核对已经新增的资源，失败导入也可能留下流程副本。
5. 打开新 Agent 的工作流组件实际链接，检查画布、代码、开始参数类型与文本输出；试运行正确答案、缺字段和边界错误。输入契约按业务选择：结构化工具可用 Object；每轮都需要边界审查的陪伴学习，用 String 接收学生原话和会话上下文，绑定系统变量并设为自动调用、直接输出。通过后发布工作流，核对实际调用方式与输出映射。每个配置页签分别保存，再关闭重开确认；切页前未保存可能丢失绑定。
6. 若 Agent 不携带完整 Workflow，才单独导入工作流并手动绑定。独立导入成功后仍须打开画布与实际运行；资源卡片存在不等于节点已恢复。旧副本按 ID 和引用核对后处理，不按同名批量删除。
7. 开场、快捷问题和界面开关一起检查。核对 `openingChatMsg`、`openingGuidQuestions`、界面保存字段与 `openSuggest`，并在新会话验证实际显示。测试模型抽取后的真实工具输入，不只测手工 JSON。编辑器输入优先整体粘贴，检查平台回显原始输入，以排除自动补括号造成的测试污染。

**验收：** 先完成工作流试运行，再从 Agent 自然语言入口调用同一输入；知识库或数据表另查实际资源和内容。区分文件结构、导入成功、画布打开、工作流运行、Agent 调用和正式发布六个状态。

**反例：** 把裸流程对象当独立模板；仅保留 Code、把 Start/End 从 `nodes` 删除；先导 Workflow 又多次导 Agent；绑定缺失时把模型写出的“调用参数”当成真实工具调用。前两项会导致格式错误或空白画布，后两项会制造重复资源或虚假执行表述。

原因：平台按完整节点图恢复资源，并为 Agent 的依赖另建对象；快照、独立资源和实际绑定必须一起核对。

HTTP插件支持默认固定Header与Body参数、自动解析出参。原生导出可能携带真实认证，不能假定平台自动清除。公开 Agent、Workflow、Plugin 及其嵌套快照先递归扫描和脱敏，私密原件分开保存；换空间导入后重新填认证并核对节点绑定。固定认证配置不能当作加密凭据库。

插件认证或预设更新后，按上述迁移流程重新核对实际绑定版本，并从学生入口与后台输入输出检查变更是否生效。

多条件TableDataQuery需显式配置conditionType为AND；只增加条件数组仍可能校验失败。普通字符串字段容量为255字符，本轮课堂卡片实际超限；fieldType7提供长文本（界面标注0—16M），还要同步代码出参、写表引用、查询children/subArgs，最后用超过255字符的实际记录验证。平台将课文和教师QA一起召回时，需同时读取rawText、question和output。

智能体配置更新时，开场正文使用openingChatMsg，快捷问题实际由guidQuestionDtos序列化到openingGuidQuestions；只更新后者可能保留旧按钮。保存发布后以真实新会话页面确认。

当前会话上下文可供代码解析本任务学习记录，完整业务指令避免依赖历史窗口永久保留；明确换课文后可以清空旧回答；作用域、防篡改和跨账号隔离并未因这个机制自动成立。正式发布在教师个人空间的智能体，可由其空间广场“开始使用”进入，评审访问仍单独测试。侧栏默认个人空间路由可能与作品所属空间不同，使用作品实际spaceId核对。

## 原话校验、产物分流与正式入口验收（默认）

陪伴学习同时提供网页与图片时，先提取意图，再由代码校验范围、条件、单位和产物类型，分别进入学习、数学核对、网页、图片分支。普通概念提问直接解释；缺尺寸只在实际需要尺寸时追问；同时索要网页和图片可先问要哪一种。不要用一段系统提示词代替这些执行边界。

保留学生原话供代码核对显式条件和错误单位。模型可能漏提图形、沿用旧场景，或先把“体积45π平方厘米”改成正确单位再交给校验器。代码应从明确表述恢复当前图形与尺寸，换题清冲突值，再独立核对数值和单位；不能只信模型抽取后的对象。

对外回复由代码过滤内部思考、JSON与后台信息。验收依次看工作流、Agent调试、正式学生入口；从新会话检查开场与快捷问题，从连续会话检查改条件和换图形。平台自身工具卡与模型正文分别检查，正文过滤不能隐藏平台框架控件。

## MCP排障与三维网页替代交付（默认）

外部部署MCP按传输、鉴权、会话、工具发现、部署五层排查。SSE连接成功后，保持连接并立即向服务返回的消息端点发送初始化，再调用工具；记录状态码和错误阶段，日志不记认证与正文。会话阶段返回“Unknown or expired session ID”时，先查客户端是否保持SSE、会话路由和服务端会话存储，不能直接推论接入平台不支持MCP。未完成工具发现前，不能宣称查过配额或部署规则。

逐题部署暂时不可用时，可统一托管一套交互程序，再为每题生成规范化数学参数链接。页面保持一致的风格和控件，按当前题目显示图形；参数只能包含白名单数学条件，不含学生原话、姓名或认证。对外说明这是统一程序加每题配置链接，与每次重新部署HTML区别开。发布后核验公网版本、实际题目链接、改参和展开，再单独测试学校网络与评审身份。

面向多人课堂，统一程序只在发布版本时部署；每道题只生成参数链接。相同入口在不同浏览器实例中各自持有参数与交互状态，避免覆盖一份共享配置，也避免每个学生提问都进入部署队列。测试时分别打开不同题目，轮流改参并检查另一页面是否变化；页面隔离检查与平台并发容量测试分开执行。

常见概念图优先使用已核对的轻量静态图片，特殊情境再调用生图服务。静态图片说明概念关系，不因本题尺寸变化就重新生图；精确尺寸、数值和单位由数学代码与三维页面负责，避免学生把示意图比例当成测量结果。

### 国内 HTTP 管理部署接口记录

2026-10-27收到并实测的新接口为 `POST https://backend.appmiaoda.com/projects/supabase240127511164403712/functions/v1/admin-deploy/deployments`。上传已构建的静态文件，服务端不执行 npm 构建或解压 ZIP；JSON 请求最多 5 MiB、50 个文件，根目录有 HTML 入口，二进制使用 base64。每次业务运行使用唯一 `Idempotency-Key`，同次重试保持不变；同键改内容返回409。

任务使用 JSON 响应或 SSE 事件；只有 `state === "completed"` 或 `completed` 事件且返回 `result.url` 才算部署成功。断线后用同一认证 GET 原端点加任务 ID；收到 `reconnect` 继续查询，失败后重新部署换业务运行键。文档限制为每个管理员同时1个任务、每分钟3次、每日100次，沿用项目数量配额。认证留在服务端或私密部署环境，不放学生页面和公开配置。

## 官方答疑信息的使用（默认）

知识库导入前先核对支持格式；遇到不支持的表格格式，可转为支持的文本格式或按用途放数据表。视频可考虑在线视频链接和播放器呈现，仍需检查学生入口是否允许相应标签及媒体访问。不要把群内答疑直接当成所有账号、版本都已验证的能力。

来源与状态：2026-10-27在数学账号实测自动调用、三路分流、生图、国内 HTTP 部署完成与两会话参数隔离，见数学升级案例；接口容量来自建委提供的服务文档，未做高并发压测。xlsx与视频建议来自建委提供的平台技术支持群截图，未独立执行对应导入与播放器验证；截图含私人联系方式，不入库。
