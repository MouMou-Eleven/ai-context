## 课堂任务与技术分工

用12块棱长2厘米正方体搭桌面作品展示台，最多6列、2行、2层，每格从桌面连续向上搭，按整面相接成为整体。与桌面接触的面不贴纸，其余暴露在空气中的面均贴纸，包括凹处。忽略厚度与剪裁损耗，不推断实际承重或建筑安全。

学生先实物拼搭、手算并解释，再以每格高度录入方案。数值判断由代码按相邻积木逐面核验；模型理解理由，只给待确认线索；知识库维护任务边界、微型检验和教师观察量规；数据表保存方案、学生原话、数值结果、支持程度和修订轮次。教师用匿名样例组织方案比较、补讲与同伴讨论。

两种原创示例：两排均为`1,1,1,1,1,1`时，体积96立方厘米，全部表面积160平方厘米，贴纸112平方厘米；两排均为`2,2,2,0,0,0`时，体积仍96立方厘米，全部表面积128平方厘米，贴纸104平方厘米。这是规则计算结果，不是学生样本或教学提升指标。只比较给定方案，不宣称求得全局最优。

## 真实发现与处理

### 向量检索依赖

混合检索节点返回403与“积分已用完”。这是本次实际接口错误，不能推断整个竞赛账号都没有资源，也不代购积分。改用平台原有全文检索后，检索、模型、入表与回执完整路径运行成功。仅有空库节点成功还不算资料被使用，所以补做文档存在与命中验证。

### 导出导入依赖

原生工作流导入会创建带后缀的新知识库和新表；知识库文档未随结构一同复制。搭建后必须核对实际引用ID和文档数量，并在实际调用库补齐源文档。表结构与数据也分开处理，不能用空结构导出宣称过程记录已备份。

### 输入和输出契约

最初单字段JSON字符串接口出现模型传原生对象的调用；真实返回拒绝该次修订，未入表。修改开始节点为原生Object输入，预设同步为对象契约；结束节点切换返回文本，并将`report`作为输出内容。不得用“节点执行成功”掩盖输入转换失败，也不把失败修订写成已保存。

模型原有JSON契约还要求“解释完整”时必须选一个问题方向，造成不必要的不确定性和格式失败。修订为READY、CONTACT、BOTTOM、UNIT、REASON五个代号，READY不强行制造问题；代码核验代号后组织反馈，异常返回仍转教师。修改过的代码通过原生编辑器粘贴并读回比对，最终原生导出中的校验器与本地文件逐字一致。

## 空间与图形升级草稿（2026-10-27）

### 目标和文件形态

在未覆盖旧 `数学搭一搭.agent` 的前提下，另做“小学数学空间与图形探究助手”导入草稿，目标是用四类任务包扩展：当前正方体积木展示台、长方体/正方体组合、圆柱体积和表面积、长方形/正方形/圆周长与面积。学生自然语言提问，不绑定特定年级；网页或提示词不把任务号、教师诊断、后台记录和保存回执展示给学生。

新版 Workflow 的执行链缩为开始Object输入→确定性JavaScript计算→结束TEXT。输入中的`action`区分visual/check/help，`scene`保存本题图形和尺寸，`quantity`、`guess`用于数值与单位复核。流程不依赖数据库或知识库，便于先单独迁移和调试；只有平台导入验证后再决定是否接回课堂资源。

Agent 快照包含一个Workflow组件和完整`targetConfig`；独立工作流则必须采用平台 `.workflow` 导出的 `{name, templateConfig, type}`包裹结构。把内部工作流对象直接作为文件顶层曾触发平台“请上传正确的模板文件”。后续改为基于平台下载的原工作流封装，保留同类 Start/Code/End 节点字段形状，并增加本地结构校验。该错误处理和迁移步骤已写入[平台能力记录](./platform-tianjin-agent.md)；本案例保留数学项目细节，不重复通用操作方法。

### 提示词与交互约定

系统提示词为学生设置自然对话边界：四类主题之外简短引导回当前范围；缺条件时一次追问一个关键项；操作帮助可直接回答；要可视化时才调用当前题目配置；同一套页面风格承载不同问题，不一次铺出四类任务和全部答案；链接未部署时不编造链接并继续讨论数学。Agent开场包含完整使用方法，预设三个问题并打开显示开关，长期记忆关闭。文本作为安全文本展示，不插入可执行HTML。

网页由Canvas按世界坐标和深度顺序生成模型，支持拖动旋转、缩放、键盘和固定方向观察。改变尺寸时模型顶点和计算一起改变；积木柱高与拆分、组合体尺寸、圆柱连续展开、平面图形比例均有对应控件。探究页面按“先想一想→动手试试→验证解释”逐步显示结果，允许跳过书写直接操作。其交互设计的本地复建脚本和测试在交付包，不是平台已部署的证据。

### 数学约束与本地检查

- 积木按占用位置逐面计数，体积随棱长三次方变化；贴纸面再扣除桌面接触底面。
- 组合体沿整面拼合时必须核对相接面的两条边分别相同，不能只看面积相等；表面积减去两份接触面。
- 圆柱保留π系数表示体积、侧面积和总表面积；平面任务区分周长/面积及对应单位。
- 缺条件只追问；单位不符不判正确；题目配置的文字不执行。
- 边长2厘米的12块方案：铺成一层时体积96、贴纸面积112；叠成两层时体积96、贴纸面积104。
- 组合体示例3×2×2与2×2×2：体积20、表面积48。早期草稿误写体积40，已按12+8更正。
- 半径3、高5圆柱：体积45π、侧面积30π、表面积48π；长方形8×5周长26、面积40；半径4圆周长8π、面积16π。
- 本地工作流用例11项通过；浏览器页面15组场景通过，包括五个屏宽、四类图形、三阶段、相机旋转缩放、模型像素随参数变化、非法组合面、缺少条件和未部署链接分支。干净目录重建和平台模板结构核对通过。后续检查修正了原校验脚本只对独立 Workflow 自比较的缺陷，改为真正读取 Agent 内嵌图并比对。

### 导入故障、修复与实测

用户反馈独立 Workflow 可以导入但打开空白并报 missing start node，Agent 导入则报错；多次失败导入仍增加同名工作流。对照本轮平台原生 Agent 与 Workflow，发现生成器缩减流程时只保留 Code，遗漏 `nodes` 中的 Start/End，虽然专用开始、结束字段仍在，画布无法恢复完整图。先补 Start 的中间版本仍缺 End，进一步比对后同时补齐三节点。

2026-10-27，最终修复包在数学账号只导入 Agent 一次，成功创建 [Agent 1485](https://aiagent.tjtc.edu.cn/space/932/agent/1485)，平台自动创建并绑定 [Workflow 1608](https://aiagent.tjtc.edu.cn/space/932/workflow/1608)，名称后缀 `_7`；未另行导入独立 Workflow。画布显示开始→确定计算→结束，未出现原报错。实际试运行：圆柱45π立方厘米核对通过；只有半径时追问高度；将体积单位写成cm时提示立方厘米。此工作流已在个人空间发布。

调试过程中曾误解除新 Agent 的工作流组件，已重新选择1608并继续验证。缺少绑定时模型曾把调用参数当文字输出；恢复绑定后，三维请求实际触发工具调用，回答交互图暂时打不开并自然继续圆柱探究，没有虚假链接。旧Agent未修改，重复流程未删除。通用恢复做法只维护在[平台迁移方法](./platform-tianjin-agent.md#agent-与-workflow-配置的可复用迁移流程默认)。
