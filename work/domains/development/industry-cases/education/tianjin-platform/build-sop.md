# 天津平台搭建流程：从登录到可评审

给客户在天津平台上做新智能体、改已有智能体时按本页顺序走。平台有什么、节点怎么组合见[能力体系](./capabilities.md)；智能体本身怎么跟学科结合，先看[学科融合](../subject-integration/README.md)。

整体路线：

```text
确认客户账号与空间 → AI 接管已登录浏览器 → 用导出包导入骨架 → 在画布里改节点与提示词
→ 工作流试运行 → Agent 调试 → 发布 → 新会话回归 → 生成评审链接 → 清理旧资源 → 导出交付
```

## 一、账号与浏览器（默认）

1. 客户自己注册、登录、建团队空间，建委以开发者身份协作；每位客户一个空间，不混用。记下作品实际 spaceId。
2. 让 AI 操控浏览器：用 Playwright 或 Chrome DevTools 协议（CDP）连一个**专门的浏览器配置目录**，客户在这个窗口里亲自登录一次，之后 AI 复用登录态。账号密码不发给 AI、不写进仓库；登录态文件只放本机项目目录。
3. 开工前在浏览器里确认当前空间是不是作品所在空间（侧栏默认个人空间经常不是）。

## 二、用导出导入快速起步（默认）

已有相近作品时，不从空白画布搭：拿它的原生 `.agent` 改成新作品再导入。

1. 从平台下载同版本的原生 `.agent` 和 `.workflow` 做模板，保留原件。先比较最外层键、节点对象形状、参数类型和引用关系，再改业务内容。独立 Workflow 用 `{name, templateConfig, type}` 外壳；Agent 里的 Workflow 组件用完整 `targetConfig`，两种层级不能互换。
2. `nodes` 保留整张执行图，包括 Start 和 End；专用 `startNode`、`endNode` 与列表里的对应节点一致。检查节点 ID 唯一、连线目标存在、输入输出引用能解析。删减节点时同时改四处：节点列表、开始结束快照、工作流外层参数、Agent 组件快照与映射。
3. 检查脚本分别加载生成的 Agent 和独立 Workflow，对比两边真实的节点、代码和参数。不要拿同一个对象跟自己比，也不要只看 JSON 能解析。
4. 在"智能体开发"里**只导入 Agent 一次**。平台会为内嵌 Workflow 建资源、重映射 ID，同名资源可能加后缀；不要再单独导入同一个 Workflow，Agent 报错也不要连续重试。先看已经新增了哪些资源，失败的导入也可能留下副本。
5. Agent 不带完整 Workflow 时，才单独导入工作流再手动绑定。

反例：把裸流程对象当模板（报"请上传正确的模板文件"）；把 Start/End 从 `nodes` 删掉（空白画布）；先导 Workflow 又多次导 Agent（一堆重复资源）。

## 三、在画布里修改（默认）

- 代码节点整体粘贴，再回读原文和本地源码逐字比对，排除编辑器自动补括号。
- 每个配置页签单独保存，关掉重开确认绑定还在。
- 开场白、快捷问题、界面开关一起改，核对 `openingChatMsg`、`openingGuidQuestions`、`openSuggest`。
- 插件认证、知识库、数据表导入后都要重新绑定到真实资源：打开主流程实际引用的库看文档数量和一次命中，从后台读回表记录。
- 点击画布节点会触发自动保存，显示"已更新但未发布"；内容没变不用重发。

## 四、验收：六个状态分开记（红线）

文件结构对、导入成功、画布能打开、工作流试运行通过、Agent 自然语言能调用、正式发布——这是六件事，交付记录里分开写，不能用前一个代替后一个。

1. 工作流试运行：正确输入、缺字段、边界错误、偏题、注入各一条。
2. Agent 调试：用自然语言触发同一输入，确认真的调用了工作流，而不是模型自己编了"调用参数"。
3. 发布后在**新会话**看开场白和快捷问题；在**连续会话**里改条件、换题。
4. 本地测试通过、平台配置已保存、在线流程跑通、正式入口发布，也要分开说；旧版本跑通不能代替新版回归。

## 五、清理旧资源（默认）

1. 从正式 Agent 出发，沿绑定组件、主流程、嵌套子流程、节点配置递归列出实际依赖（依赖闭包），列成保留清单。
2. 其余资源列删除清单给建委确认。按 ID 和真实引用判断，不按同名、"已发布"或创建时间判断；同名插件要从正式节点反查实际 ID。
3. 删除前原生导出配置，另存知识库文档与 QA、表内记录；导不出的损坏资源记录故障。
4. 逐项删除，核对弹窗名称并确认从列表消失；最后在"全部/所有人"列表复核只剩保留清单。

## 六、生成评审链接

作品卡片右下角"…"→"临时会话"→"临时会话链接管理"→"新增链接"。不勾选"登录可用"，有效期留空，复制该行生成的完整链接（形如 `https://aiagent.tjtc.edu.cn/chat-temp/<平台生成标识>`）。

不能用浏览器地址栏、作品 ID 拼的地址代替：`/agent/<ID>`、`/home/chat/...` 和后台编辑地址都需要登录。生成后核对作品名、登录选项、日期为空，再用无登录的浏览器打开确认。临时会话的数据标识是新的匿名身份，依赖历史记录的功能（如教师报告）要另测。完整临时链接只写进参赛材料，不进仓库。

## 七、导出交付

比赛和备份都按资源类别逐个导出，不能只下载 Agent 就算交齐：

| 资源 | 导出入口 | 产物 |
|---|---|---|
| 智能体 | "智能体开发"→目标卡片"…"→"导出配置" | `.agent` |
| 工作流 | "组件资源→工作流"→主流程和**每个**嵌套子流程分别"…"→"导出配置" | 各自的 `.workflow` |
| 插件 | "组件资源→插件"→"…"→"导出配置" | `.plugin` |
| 数据表 | "组件资源→数据表"→"…"→"导出配置"，确认"仅导出数据表结构" | `.table`（表数据页的"导出"是另一种用途） |
| MCP | "MCP管理"→"…"→"服务导出"，复制完整配置 | 保存为 JSON，不虚构 `.mcp` 格式 |

- 先从正式 Agent 递归列依赖，再逐项导出；实际没用的类别写"未使用"，不为凑齐建空资源。教程把数据表后缀写成 `.workflow`，实物是 `.table`，按实物记录，不改后缀。
- 原生导出不带知识库文档和表数据：知识库另附全文、QA、模板和检索设置；表数据需要时另导。
- 每个文件记录类别、名称、ID、被谁引用、原生文件名和 SHA-256。递归扫描所有包和嵌套快照里的认证（MCP 配置可能带可直接调用的 URL），对外包脱敏并写明重新授权方法，私密原件另存。
- 不同次导出会重新生成部分参数的编辑器 key；比较时先确认差异只在这类标识，代码、连线、参数名、类型、业务值逐项对照。独立插件保存服务定义，流程内的插件快照还带 prompt 与 Authorization 绑定，两者不要求逐字相同。
- 是否能导入恢复、是否真实运行分开记录；不在原账号重复导入来充当恢复验收。

比赛提交包怎么组织见[天津大赛 · 提交材料](../tianjin-ai-contest/submission-package.md)。
