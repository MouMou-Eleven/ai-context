# 天津指定智能体平台：能力体系

在天津平台上设计或改造智能体前先读本页：平台有哪些资源、工作流有哪些节点、怎样组合成一个教育智能体、哪些地方已经踩过坑。具体怎么一步步搭、导入导出、发布和清理见[搭建流程](./build-sop.md)。

## 平台识别

- 平台地址 `aiagent.tjtc.edu.cn`，从天津市 AI 教育大赛官网入口跳转；比赛要求赛道二作品必须在这里搭建，开发测试消耗的资源点由平台提供。
- 界面和资源结构与开源 Coze Studio（扣子开源版）高度相近：智能体、工作流、插件、知识库、数据表、变量、MCP 的概念和用法基本一致。扣子的经验可以拿来参考，但**以本平台实测为准**（默认）：本平台没有公开源码或官方声明，不对外写"基于 Coze 改造"。
- 官方帮助：[用户手册](https://aiagent.tjtc.edu.cn/site-help/user-manual.html)、[智能体编排](https://aiagent.tjtc.edu.cn/site-help/agent-design.html)、[工作流](https://aiagent.tjtc.edu.cn/site-help/workflow.html)、[知识库](https://aiagent.tjtc.edu.cn/site-help/kb.html)、[数据表](https://aiagent.tjtc.edu.cn/site-help/table.html)、[工作空间](https://aiagent.tjtc.edu.cn/site-help/workspace.html)、[大赛作品创建与提交教程](https://www.kdocs.cn/l/cgpNFEkMdyXN)。

## 一、资源模块总览

| 模块 | 能做什么 | 实测要注意 |
|---|---|---|
| 智能体 Agent | 外层模型、系统提示词、开场白、快捷问题、绑定工作流/插件/知识库/变量；发布后有使用入口 `/agent/<ID>` | 开场正文存 `openingChatMsg`；快捷项须在 `guidQuestionDtos` 中使用 `{type:"Question",info:"自然语言问题"}`，平台据此写入 `openingGuidQuestions`。仅有info能显示但type为空时点击无动作，必须发布后开新会话实际点击 |
| 工作流 Workflow | 可视化编排节点；在智能体里像插件一样调用，可设"自动调用"和"直接输出" | 直接输出能避免外层模型再总结一遍、改写结论；教育学伴类默认开 |
| 插件 Plugin | HTTP 接口封装，可设固定 Header/Body、自动解析出参 | 原生导出可能带真实认证，平台不会自动清除 |
| 知识库 | 本地文档、自定义文本、QA；混合/语义/全文检索 | 结果同时有 `rawText`、`question`、`output`，课文和教师 QA 一起召回时三者都要读；向量检索可能因积分报 403，可改全文检索。文档分析状态、向量状态、存储原文与实际全文命中分别核对，不能用其中一项替代其他项 |
| 数据表 | 字段定义、唯一值、必填、导入、增删改查；可引用到智能体 | 普通字符串 255 字符，长内容用长文本 fieldType7（0—16M）；多条件查询要显式 `conditionType=AND` |
| 变量 | 输入控件、会话变量；工作流变量节点读写 | "全局"不等于跨用户隔离，作用域要实测 |
| MCP | 自定义 MCP 服务，"MCP管理"里配置 | 失败的服务卡片可能只有"日志、删除"，没有"服务导出" |
| 工作空间 | 个人/团队空间，数据隔离；团队有所有者、开发者、观察者 | 侧栏默认个人空间可能和作品所在空间不同，按作品实际 spaceId 核对 |
| 临时会话链接 | 作品卡片"…"→"临时会话"→"新增链接"，复制结果包含临时标识及appid等查询参数 | 这是评审链接的唯一来源，完整性、登录状态与未登录运行核对见[搭建流程](./build-sop.md#六生成评审链接红线) |

## 二、工作流节点

| 节点 | 用途 | 教育场景里怎么用 |
|---|---|---|
| 开始 / 结束 | 接收输入、定义变量；返回变量或文本 | 学伴类用 String 接收学生原话 + history；结构化工具才用 Object。结束节点返回 TEXT 并配直接输出 |
| 大模型 | 接收前置变量，输出文本、Markdown 或 JSON | 拆成"提取当前意图/条件"和"组织回复"两个节点；JSON 输出后仍要代码校验 |
| 代码 | JavaScript 精确处理 | 数学计算、单位核对、引文是否在原文里、意图路由、过滤内部 JSON 和后台信息 |
| 条件 | 等于、大小、包含、正则、空值 | 按意图分支：学习、核对、网页、图片、教师报告、引回主题 |
| 循环 | 数组、次数、无限 | 课堂活动用有限次数，不用无限循环 |
| 知识检索 | 从知识库召回 | 先篇名定位，再读完整原文；找不到就请教师补资料，不让模型凭记忆编课文 |
| 问答 / 过程输出 | 补充输入、阶段反馈 | 不保证能恢复任意中断的任务 |
| 变量 | 读写会话变量 | 当前任务状态；不代替过程记录表 |
| 数据表增删改查 | 写入过程、查询汇总 | 教师报告查询同时限定 uid 和 agent_id；读取有上限，未做自动分页时要提示范围 |
| 插件 | 调外部接口 | 生图、部署；超时、重试、异常分支要配 |
| 子流程 | 嵌套工作流 | 教师报告这类独立功能拆成子流程，便于维护 |

节点可设超时、重试、特定返回和异常流程；流式输出开始后不能再按同样方式重试或走异常分支。调试面板能看每个组件的输入输出，这是逐节点验证的入口，不等于整条流程已通过。

## 三、常用组合配方（默认）

先按课堂需要选配方，再增减节点。组件数量不代表难度，没被主流程调用的组件要删掉。

| 配方 | 节点链 | 适合 | 实例 |
|---|---|---|---|
| 学伴追问型 | 开始(原话+history) → 模型提取 → 代码校验 → 条件分支 → 模型回复 → 代码过滤 → 结束(直接输出) | 学生自然提问、教师要求 AI 先引导再讲 | 两个案例都以它为骨架 |
| 依据核验型 | 篇名检索 → 读全文 → 代码核验引文/数值 → 模型解释 | 答案必须有出处或必须算准 | 语文引文核验；数学单位与数值核对 |
| 过程记录 + 教师报告型 | 主流程每轮写表（长文本存完整载荷）→ 教师口令进子流程 → 按 uid+agent_id 查表 → 归并 → 报告 | 教师要看学生卡点和前后变化 | [文有回声](../case-wenyouhuisheng-chinese.md) |
| 产物生成型 | 代码生成描述/参数 → 生图插件或网页链接 → 代码校验网址 → 结束 | 学生要看图、要动手操作 | [几何助手](../case-geometry-helper-math.md)的三维网页与示意图 |

几条跨配方的做法：

- **保留学生原话给代码看。** 模型提取会漏图形、沿用旧场景，甚至先把学生写错的单位"改对"再交给校验器。代码要从原话恢复明确表述，换题时清掉冲突的旧值，再独立核对。
- **对外回复由代码过滤。** 内部思考、JSON、任务号、后台回执都不进学生正文。平台自己的工具卡（"运行完毕"、AI 声明）属于界面框架，正文过滤管不到，要分开检查。
- **模型文本先清理思考段再解析结构。** 大模型节点返回文本可能在JSON之前含多段`<think>…</think>`。解析前移除这些段落并检查JSON结构，再核对原话和事实来源；不要因“节点成功”便跳过实际出参检查，也不要把解析失败当成用户没有提交观察。
- **知识库验收分开看构建状态与实际召回。** 自定义文本可能有原文、全文能命中，但异步分析或向量构建仍失败；反过来，“构建成功”也不证明发布流程读取了正确文档。逐份记录文档状态、失败原因、向量状态、正文及分段，再用工作流实际搜索策略核对返回的文档和原文。“0KB”先查计量口径，不直接当空库；模型回复出现资料编号不作为命中证据。失败任务通过原生重建处理，核对任务错误及终态，不直接改状态字段或跳过失败页充当修复。
- **图片上传必须检查模型实际收到的内容。** 上传成功或模型列表标注Image，不等于该对话链已经传入视觉内容。如果真实用户消息只有附件JSON中的`fileUrl`，从系统本轮消息取得平台文件地址，由受信服务端节点调用视觉接口，成功后将“图片可见事实”与用户原话分开交给分析节点。无图不调用，失败明确返回；不凭静态图推断身份、情绪、行为时序或诊断。凭据只在受控服务端配置，对外导出必须替换认证。
- **原生视觉先识别，再按需调用核验流程。** 平台能向自定义图文模型传递图片时，可由外层模型转录，再以明确的结构化参数交给工作流。需要模型填转录结果的流程用按需调用；自动调用可能先于模型观察执行，拿到原话却没有识图参数。工作流先检查页数、文本、疑字和本轮附件的对应关系，识别回显使用已检查的逐字转录，不让第二个模型重新润色。照片首次识别和用户核对分开，确认后才进入评价；无图问题不复用旧图片。
- **文件访问错误不能当作照片模糊。** 外部视觉接口读图失败时检查HTTP状态、Content-Type和真实响应。返回鉴权JSON时先核实平台文件授权接口与账号已有权限，不能把200状态当图片有效，或让学生反复拍清楚。平台API Key存在也不保证有该接口权限；不扩大权限时可采用已实测的原生视觉通道。自定义模型的认证独立于聊天提示词和代码，迁移后在目标空间重新配置。
- **原文精确核验容许恢复换行，不改词句。** 图片转录或学生文本可能带换行，模型引用则连成一句。引用去空白后能连续定位时，按原文字符位置取回原样片段；不能定位的引用要求重新核对，不把相似意思自动当成真实引文。每篇单独核验，防止多篇作品串证据。
- **教师的附件操作和历史消息渲染分别检查。** 教师通过聊天框“＋”上传图片并说自然语言，无需提供URL或附件JSON。发送时的图片卡、刷新后的历史气泡和服务端保存的消息分别核对；服务端把附件包装文本写进USER正文时，工作流清洗只能保护分析与回复，不能修复平台历史气泡。不要用临时隐藏DOM作为产品修复。
- **常规操作绕过分析模型，故障返回必须可见。** 帮助、工作台、边界提醒和序号选用可由条件与代码直接处理；观察分析才进入模型。分析节点异常返回结构化失败状态，后续节点明确告知本次未新增观察，不把空返回当成缺少用户资料。备用服务也要查真实错误；DNS失败、模型失败与上传失败分别留证。
- **常见概念图用静态图片，特殊情境才实时生图。** 静态图说明关系，精确尺寸和数值交给代码与交互网页，避免学生拿示意图比例当测量结果。
- **交互网页用"统一程序 + 每题参数链接"。** 程序只在发版时部署一次，每道题只生成带白名单数学参数的链接（不含学生原话和个人信息）；每个学生在自己的浏览器里持有状态，互不覆盖，也不会每次提问都排队部署。
- **教师记录工作台使用固定页面与受控数据同步。** 主记录仍放平台表，通过已验证的教师身份范围查询，再将必要字段交给固定页面展示。没有后端实时接口时，可采用对话生成压缩快照链接，但必须说明新记录需重新同步，不能称旧链接会自动读取数据库。快照涉及教学信息时不沿用数学公开参数的传播范围；先核对数据权限、分享对象和记录上限。静态托管若通过沙箱iframe显示页面，应验证查询参数、hash、缓存和地址清理的真实行为，不只看初次空页面加载。

## 四、外部扩展

- **HTTP 插件**：固定认证配置不是加密凭据库。公开分享的 Agent、Workflow、Plugin 及其嵌套快照先递归扫描脱敏；换空间导入后重新填认证并核对节点绑定。插件更新后从学生入口和后台输入输出确认生效。
- **MCP**：外部 MCP 按传输、鉴权、会话、工具发现、部署五层排查。SSE 连上后要保持连接并马上向返回的消息端点初始化；报 "Unknown or expired session ID" 时先查客户端是否保持 SSE、会话路由和服务端会话存储，不能直接下结论说平台不支持 MCP。
- **国内静态部署接口**：`POST https://backend.appmiaoda.com/projects/supabase240127511164403712/functions/v1/admin-deploy/deployments`。上传已构建的静态文件（服务端不构建、不解压 ZIP），JSON 最多 5 MiB、50 个文件，根目录要有 HTML，二进制用 base64。每次业务运行一个唯一 `Idempotency-Key`，同次重试不变；只有 `state === "completed"` 且返回 `result.url` 才算成功，断线用同一认证 GET 原端点加任务 ID 续查。限额：每个管理员同时 1 个任务、每分钟 3 次、每日 100 次。认证只放服务端。
- **官方答疑里的建议**（来自技术支持群，未逐项实测）：不支持的表格格式可转文本或改用数据表；视频可用在线链接和播放器呈现，要先确认学生入口允许相应标签和媒体访问。

## 五、账号与空间（默认）

正式作品放在客户（参赛负责人或其学校）能控制的空间，建委用开发角色协作；不同客户各用独立空间，调研账号只留无客户数据的原型。客户先注册登录、建团队，再邀请协作者；转让、迁移、公开和正式提交分别核实权限、资源点、依赖和链接。

平台里"输入老师模式"之类的口令只是业务分支，不是身份认证。需要学生自助加教师汇总时，先验证跨账号访问与数据隔离；验证前用教师控制账号、投屏和匿名小组的方式组织课堂。

## 六、已知坑速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 导入提示"请上传正确的模板文件" | 把内部流程对象当成独立 Workflow 顶层 | 用原生外壳 `{name, templateConfig, type}`，见[迁移流程](./build-sop.md#二用导出导入快速起步默认) |
| missing start node、空白画布 | `nodes` 里漏了 Start/End | 节点列表保留整张图，四处快照同步 |
| 导入后多出同名带后缀的流程、库、表 | Agent 导入会自动为依赖建副本；失败重试也会留副本 | 只导一次 Agent，按 ID 和真实引用核对后再清理 |
| 导入后知识库是空的 | 原生导出不带知识库文档和表数据 | 打开实际引用的库补文档，做一次真实命中 |
| 混合检索403或向量构建失败 | 配额、模型配置或上游服务异常需分开查 | 检查真实报错，全文命中与向量终态分别验收；模型价格未配置由平台管理员处理，已有授权且可配置时可验证自定义向量接口后重建 |
| 写表失败 | 普通字段 255 字符上限 | 加长文本字段，同步代码出参、写表引用、查询子字段，用超长记录实测 |
| 多条件查询发布失败 | 缺 `conditionType=AND` | 显式配置 |
| 开场快捷问题空白或点击无动作 | `guidQuestionDtos`中使用了错误字段，或漏`type` | 使用Question类型和info正文，保存发布后点击验证，不只看按钮显示 |
| 改完绑定丢了 | 切页签前没保存 | 每个页签单独保存，关掉重开核对 |
| 点画布节点后显示"已更新但未发布" | 点击触发自动保存 | 内容没变就不用重新发布；录屏时注意 |
| 模型传对象给字符串参数失败 | 输入契约和模型实际调用不一致 | 按业务选 String 或 Object，测试模型实际抽取后的调用，不只测手工 JSON |
| 编辑器里粘贴的代码多了括号 | 编辑器自动补全 | 整体粘贴，回读原文比对 |
