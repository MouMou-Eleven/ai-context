# 天津大赛赛道二：提交材料与文件夹

给客户准备 2026 年天津市 AI 教育应用场景、智能体设计应用和课程案例大赛**赛道二（教育智能体设计应用）**的参赛材料时按本页做。Word 怎么排版、字怎么写见[文档规范](./document-format.md)；视频和逐字稿见[演示视频](./demo-video.md)；平台导出的具体按钮见[搭建流程 · 导出交付](../tianjin-platform/build-sop.md#七导出交付)。

## 一、比赛要求（2026 年通知原文要点）

依据：市级通知 8 页（第 3—5 页赛道二）、附件 1 申报书、附件 3 推荐汇总表、相关工作提示。新一年的比赛先拿新通知逐条对照本节，变了就改本节。

| 要求 | 内容 |
|---|---|
| 参赛对象 | 各级各类学校教职工和在校学生，各区教育局及直属单位工作人员 |
| 作品形式 | 围绕"教、学、研、管、评、育"等场景自主设计教育智能体；必须在指定平台搭建，资源点由平台提供 |
| 提交材料 | 申报书、智能体访问链接、作品导出包或替代复现材料、演示视频、技术说明和验证报告 |
| 访问链接 | 平台生成的可访问链接，评审全程可用；需要登录的作品另交评审专家专用测试账号 |
| 导出包 | 平台支持导出的问答型智能体或工作流必须交导出包；不支持的说明原因，交配置说明、工作流图、关键提示词 |
| 演示视频 | ≤5 分钟，MP4，≤500MB，直观呈现实际运行过程、交互界面和核心功能 |
| 技术说明 | 模型与工具、提示词、工作流、知识库、插件或接口、运行条件 |
| 验证报告 | 模拟或真实场景的测试用例、预期结果、实际输出、工具调用过程、问题分析；准确性、异常输入、权限控制、不当内容防护的测试情况 |
| 申报书字数 | 基本概况 300、主要做法 1800（要求图文结合）、应用成效 600、创新点 300、存在不足 200 字以内；封面表"简介"200 字以内 |
| 团队 | 负责人 1 人，含负责人不超过 5 人；通知第 7 页要求说明团队贡献和人工智能工具使用情况 |
| 时间 | 2026-10-18 至 11-18 报名提交，由各单位管理员统一登录大赛官网提交；初赛 11-20 至 12-10；决赛 12 月中下旬现场展示答辩。学校内部截止时间以学校通知为准 |

赛道一"满一个学期"、赛道三"完整课时实录"不适用赛道二，不要套用。

## 二、交付文件夹（默认）

每个作品一个总文件夹，下面固定三个子文件夹。评审包只打包"参赛提交"；完整交接包三个都含。

```text
<作品名>/
├── 参赛提交/                       ← 交给评委的，里面每个字都是给评委看的
│   ├── 附件1_赛道二申报书_<作品名>.docx
│   ├── 技术说明与验证报告_<作品名>.docx
│   ├── 演示视频_<作品名>.mp4
│   ├── 作品访问说明.txt            ← 临时会话链接 + 三五步体验路径
│   └── 作品复现材料/
│       ├── 原生配置/               ← .agent / .workflow（主流程和每个子流程）/ .plugin / .table / MCP配置.json
│       ├── 提示词与节点代码/       ← 系统提示词、各模型节点提示词、代码节点源码
│       ├── 知识库资料/             ← 全文、QA（csv/json）、新增模板（用到知识库时）
│       ├── 验证附件/               ← 测试用例与实际输出、关键截图
│       ├── 组件依赖与导出覆盖清单.json
│       ├── 恢复与授权说明.txt
│       └── SHA256.json
├── 学校推荐材料/
│   └── 附件3_作品推荐汇总表.docx   ← 学校盖章扫描后由学校管理员提交
└── 录制与报送工作资料/             ← 只给建委和客户自己看，不进评审包
    ├── 演示视频逐字稿与分镜.docx
    ├── 纯旁白逐字稿.txt
    ├── 录屏可复制输入.txt
    └── 报送前检查与材料状态.txt
```

- **工作提示只放第三个文件夹**（红线）：填报提醒、"姓名待客户填"、录屏预设问题、彩排步骤、报送待办，一律不进"参赛提交"。
- 文件名用作品名，不带"最终版""v3""修改"字样。

## 三、复现材料怎么准备（默认）

1. 从正式 Agent 递归列出实际依赖，按 Agent、Workflow、Plugin、Table、MCP 五类逐项导出（按钮见[导出交付](../tianjin-platform/build-sop.md#七导出交付)）。没用到的类别在覆盖清单里写"未使用"，不建空资源。
2. 导出配置不带知识库文档和表数据：用到知识库就另附全文与 QA；表只交结构，说明数据范围。
3. 递归扫描所有包和嵌套快照里的认证，对外包脱敏，在"恢复与授权说明"里写清导入顺序、要重新绑定的资源和要重新填的认证。
4. 覆盖清单每项写类别、名称、ID、被谁引用、文件名、SHA-256；打包后再核对压缩包 CRC 和逐文件哈希，防止 F 盘最新材料和旧副本不一致。

## 四、评审链接和账号

用平台"临时会话"生成的链接，不勾选"登录可用"，有效期留空（操作见[评审链接](../tianjin-platform/build-sop.md#六生成评审链接)）。用免登录浏览器验证能打开、能连续对话后，就不再另交开发账号密码。链接写进申报书"应用成效"末尾或作品访问说明，以及技术报告第一节的作品信息表。

## 五、交付前检查

- [ ] "参赛提交"里没有任何工作提示、填写提醒、代做字样（运行下方脚本，并逐页看渲染图）。
- [ ] 申报书各部分字数在限额内；项目名称和“××项目详细介绍”已填作品名，只有人员身份字段留空。
- [ ] 技术报告覆盖第一节"技术说明""验证报告"两行的每一项。
- [ ] 视频 ≤5 分钟、MP4、≤500MB，完整播放一遍。
- [ ] 申报书、技术报告、视频、访问说明里的作品名、节点数、模型名、链接一致。
- [ ] 复现材料五类覆盖清单齐全，认证已脱敏，哈希已核对。

```text
python system/repository/maintenance/check-deliverable.py <docx> --profile competition --layout tianjin-contest-word
python system/repository/maintenance/check-deliverable.py <纯旁白逐字稿.txt> --profile competition
```

脚本能抓到填写提示、代做、过度澄清、书面腔开头、标题主题字体、主副标题未居中、一级标题无编号、编号后用空格、汉字间空格分隔、正文无首行缩进、空段落撑间距、图注未居中、申报书项目名空未填、团队表职责留空几类问题；没报不等于没问题，仍要逐页看。引用智能体真实输出时出现"请老师补充"之类，属于正常引用，可以保留。
