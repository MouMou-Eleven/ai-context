# 教育智能体与学科融合方法

## 适用范围

适用于教师或学校使用的学科智能体、课堂交互应用与教学自动化，不限平台。目标是解决教师或学生的真实工作与学习需求，让备课、教学、作业评价、辅导或教研中的任务能够完成，产物能用于实际教学。面向学生的作品保留学生思考与学习证据；面向教师的作品也可以交付教学设计、批改意见、讲评方案和教研分析，不强制设计学生与AI对话。普通课件排版、微课视频和培训大纲按其原领域执行。

本页顺序：先选场景（第一节），再选融合手段（第二节），遇到新学科按第三节推导，然后按后面各节把课堂任务落成执行流程。

## 一、先选场景：教、学、研、管、评、育（默认）

智能体不只用来"陪学生学"。教育行业现在围绕"教、学、研、管、评、育"六类场景谈 AI 赋能，天津大赛赛道二的作品形式也是这样要求的。动手前先问教师：这个智能体主要服务哪一类场景、谁在用。

| 场景 | 谁用 | 智能体能做什么 | 例子 |
|---|---|---|---|
| 教 | 教师备课、上课 | 生成情境素材、分层任务、课堂提问链；投屏演示交互 | 根据课文生成三个难度的追问；投屏三维图形边改尺寸边讲 |
| 学 | 学生 | 陪伴提问、按困难追问、核对答案、生成学习产物 | 文有回声的阅读追问；几何助手的单位核对与三维网页 |
| 研 | 教研组 | 整理课例、比较学生错误类型、生成研讨材料 | 汇总一个单元学生的高频误解，供教研讨论 |
| 管 | 班主任、教务 | 通知、作业收集、日程、资源管理 | 作业提交提醒与统计（用确定规则，不必上多轮对话） |
| 评 | 教师 | 过程记录、作业反馈、学情报告、量规打分辅助 | 文有回声的教师报告：卡点、前后修正、下一步追问 |
| 育 | 德育、心理、家校 | 主题活动、品格养成、家长沟通 | 基于受控史料的人物视角访谈（A08） |

一个作品可以覆盖两三类（常见是"学 + 评"）。选定后，后面的任务链、组件和验收都围绕选定场景来定。

**选题先看需求价值，再找创新点（默认）。** 先确认教师或学生经常做什么、哪一步耗时或影响教学、现有做法有什么困难，优先选择能持续使用的完整任务，再确定智能体怎样减少重复劳动或改善反馈。问清使用频次、典型输入、当前处理过程和可直接使用的输出；没有实测时只写待验证的收益，不编省时比例。把一个低频、零碎的课堂片段包装成独立作品，并不会因为角度少见就有参赛价值。

例如小学语文可从拍照作文批改与讲评、结合教材与学情的备课、作业诊断与后续辅导切入，再把创新落实为任务评价标准、原文证据、教师复核和后续教学的连接。转述、换词比较、细节追问可在确有需求时作为这些任务中的活动，不因它们小众就优先立项。检查“去掉新奇名称后，教师是否仍愿意反复使用、拿到结果能否推进教学”；两项都说不清时，回到需求选题。

## 二、选融合手段（可灵活）

融合手段是"用什么形式帮学生或教师"。由课堂缺口决定，不为了显得丰富而堆。

| 手段 | 适合解决 | 学科例子 | 注意 |
|---|---|---|---|
| 对话追问 | 学生说不清理由、需要一步步引导 | 语文找原句说理由；数学说清为什么这样算 | 只追问缺的那一项；操作方法直接讲 |
| 知识库依据 | 答案必须有出处 | 课文全文、教材定义、史料 | 读完整原文再核验，找不到就请教师补 |
| 代码精确核验 | 数值、单位、引文、规则对不对 | 数学计算与单位；语文引文是否在本篇 | 模型理解意思，代码负责判断对错 |
| 交互网页 | 需要动手操作、观察变化 | 几何图形旋转、展开、改尺寸；物理实验模拟；地理地图 | 统一程序加参数链接，见[天津平台组合配方](../tianjin-platform/capabilities.md#三常用组合配方默认) |
| AI 生图 | 需要情境、示意、作品展示 | 古诗意境卡；几何示意；历史场景 | 常见概念用静态图；图中文字要核对；不能当测量依据 |
| AI 视频 | 需要动态过程或情境导入 | 科学现象过程、历史情境短片 | 生成慢、成本高，多用于教师备课素材 |
| 学习卡片 / 图文排版 | 把学生表达变成可交流的作品 | 阅读理解卡、解题思路卡、错题卡 | 保留学生原话，AI 整理不改意思 |
| 过程记录表 | 教师要看全班卡点和变化 | 阅读误解与修正、方案与修订轮次 | 先定教师要做什么决定，再定字段 |
| 角色扮演 | 需要换视角理解人物或情境 | 课文人物访谈、历史人物对话 | 告知是模拟，引用与想象分开 |
| 语音 / 朗读 | 低年级、口语表达、朗读训练 | 语文朗读、英语口语 | 先确认平台和课堂设备支持 |

## 三、新学科怎么推导（默认）

遇到没做过的学科（英语、科学、道法、美术、音乐、体育、信息科技……），不要从头想，按这四步从已有案例迁移：

1. **找学科的核心难点。** 这门学科学生最常卡在哪里？是"说不清依据"（像语文）、"算不准、想象不出"（像数学），还是"记不住、用不出"（如英语词汇）、"看不到过程"（如科学实验）？
2. **对上融合案例的机制。** 在[融合案例对照](./README.md#融合案例对照)里找难点相似的机制：说不清依据 → 文有回声的"表达—依据—追问"；想象不出 → 几何助手的交互网页；需要换视角 → A08 的人物访谈。
3. **换掉学科内容，保留机制骨架。** 知识库换成本学科材料，核验规则换成本学科的"对错标准"（英语的语法规则、科学的实验变量），产物换成本学科的作品形式（英语对话卡、实验记录单）。
4. **写成一页设计稿交给建委。** 包括：场景（第一节）、任务链六件事（第五节）、融合手段（第二节）、节点草图、学生产物、教师怎么用。建委确认后再搭建。

例：初中英语"写不出完整句子"→ 对上"表达—依据—追问"机制 → 知识库放课文例句和语法点，代码检查句子成分是否完整，追问只问缺的成分 → 产物是"我的句子修改卡"，教师报告看全班最常缺的成分。

做完的新学科作品，在[融合案例对照](./README.md#融合案例对照)加一行。

## 四、学科适配要点（默认）

| 学科 | 对错标准由谁定 | 常见做法 |
|---|---|---|
| 语文 | 原文和版本 | 一篇一文件，带篇名、版本、全文边界；引文代码核验；理解是否合理由模型引导、教师复核 |
| 数学 | 计算和单位 | 代码算数值、核单位；交互网页看形状变化；示意图只表关系不表尺寸 |
| 科学 | 实验条件与现象 | 模拟实验控制变量；结论要回到证据 |
| 英语 | 语法与语用 | 例句库；代码或规则检查结构；口语看平台语音能力 |
| 历史 / 道法 | 史料与价值导向 | 受控史料；角色扮演标明是模拟；价值表述由教师审核 |

不在表里的学科，按第三节推导后补一行。

## 五、把课堂需求写成任务链（默认）

开发前先写清六件事：谁在什么教学或工作环节遇到什么困难，教师或学生必须保留哪些专业判断与思考，原先怎样处理，AI具体补哪一项缺口，最终交付什么可用产物，使用者拿到结果后怎样继续工作或教学。每一项都能落到一次实际任务，先不以功能名代替需求。教师备课类要说明学情与教材如何进入教学设计、设计怎样被教师修改和使用；作业评价类要说明原作如何进入批改、教师怎样复核、批改怎样用于讲评或辅导，不能只画一个“输入—生成”框。

例如，学生能给人物贴标签却找不到文中依据，活动应让学生选原句、解释联系并修订理解；最终产物是带证据的阅读表达，教师根据缺少解释或遗漏上下文继续追问。若只是需要查询一个词义，短问答即可完成，不必为它搭建多阶段课堂系统。

## 六、按缺口选择技术组件（默认）

| 课堂责任 | 可选择的实现 | 何时值得使用 |
|---|---|---|
| 专业依据与材料边界 | 审核文本、题库、知识库与来源标识 | 教材或史料不能由通用模型随意补写，且需按任务定位时 |
| 固定步骤与明确分支 | 工作流、条件判断、有限循环与问答节点 | 必须先确认材料再核验、不同回答需要不同处理时 |
| 本次活动状态 | 输入控件、会话变量、带任务版本的状态对象 | 要记住当前任务、提示层级、已提交答案和修订阶段时 |
| 结构化过程与教师复盘 | 数据表、事件记录和确定规则汇总 | 教师需要比较多组回答或前后变化，且存在合法的数据访问路径时 |
| 不可猜测的判断 | 代码、审核规则、确定计算工具 | 精确分数比较、引文是否存在、字段合法性等要求可复核时 |
| 外部能力 | 插件、接口或MCP | 平台内能力确实不足，且依赖、授权、成本及失败处理可接受时 |
| 学生作品呈现 | 文字卡、图表、固定素材、图文排版 | 产物能帮助解释数量关系、文本关系或支持同伴交流时 |

组件数量不作难度或价值指标。先给每个组件安排真实输入、处理责任和输出；删去没有被主流程调用的组件。长期记忆也不是过程记录的替代物，活动版本和逐次回答优先由可查询、可更正的结构化记录管理。

## 七、把教学路径变成执行契约（默认）

对每条主工作流写出输入字段、前置条件、节点顺序、分支条件、输出结构、异常去向和完成标准。把流程中必须发生的核验放在确定节点；模型承担表述理解与反馈组织，代码承担精确判断，教师承担教学解释和使用决策。字段属于结构化对象时优先使用平台原生对象类型，分别测试调试面板输入和智能体实际调用；手工JSON能跑通，仍可能在模型把对象传给字符串参数时失败。输出记录单需要保留原话与确定反馈时，配置明确的文本返回和直接输出，再核对外层模型有没有追加问题或改写结论。

以阅读任务为例，文章与版本确认后，先核验引文位置，再讨论引文是否支持解释；句子存在只能说明引用真实，不能自动证明人物判断正确。以数学任务为例，先把学生所说的规则转换为教师审核范围内的条件，要求确认后再精确计算；没有找到反例只能说明在当前测试范围内未发现，不代替一般性证明。

需要多轮时，把阶段切换写成允许的动作和状态变化。材料不完整就补充，证据不够就保留待确认，两次无进展或超过活动约定时长就转教师；不用无限循环制造“智能”。模型结构化输出也需做字段和取值校验。

## 八、让教师持续维护材料（默认）

教师需要以后继续加课文、题目或案例时，把篇名、版本、完整材料、教学任务与引导问题设成稳定的资料契约。工作流读取检索回来的真实原文，再核对当前篇目和版本；精确核验代码不维护另一份容易不同步的硬编码正文。材料缺少边界或同名多版本时先请教师补全，不把不同文章片段拼成一篇。

例如，一篇新课文按模板上传后，应能从学生入口开始新课、读出首尾并核验引文，不修改核验程序。上传成功后仍要检查分段和真实召回，完整文件被拆碎也可能无法取得完整依据。多版本用不同的明确名称区分；公版原作与教材改写不能相互替代。

旧库与空依赖副本明确标未使用，教师只面对一个维护入口；用途写在资源说明里。这样材料可以由教师接手，避免技术人员每加一篇文章就改程序，也减少多库之间传错材料。

## 九、学生完成关键思考，AI提供适量支持（默认）

区分哪些问题适合直接说明，哪些任务需要保留学生思考。解释操作方法、说明术语和纠正明显事实错误，可以直接清楚回答；当目标是训练推理、解读或表达时，优先让学生先尝试，再按当前困难提供最小支架。

学生首次使用时，把完整任务拆成眼前的一步：先说理解，再找原句，再解释联系。每次回复明确已经完成什么、接下来只需答什么；操作方法直接说明，不让学生先学会填写复杂字段。完整输入仍可一次提交。

小学阶段应把自然语言当作默认输入。学生可能一口气说出人物判断、动作和理由，也可能只说“我不知道”或只复述一处词语。工作流应从当前原话中抽取已说内容，再只追问缺少的一项；不要要求学生输入任务号、组号或“我的理解／原文依据／我的解释”等内部字段。学生界面只呈现下一步学习问题，任务标识、阶段、修订次数和教师线索留在后台记录。

不把“永远不告诉答案”固定成所有场景规则。学生不知道操作步骤时继续反问会增加负担；同样，学生只复述了系统给的句子，也不能据此认定已独立理解。记录提示前、提示后和新任务中的不同表现。

## 十、让教师拿到可以行动的反馈（默认）

从教师下一步要作的决定倒推记录字段：哪些学生或小组需要补材料，哪些需要解释关系，哪些已经可以进入新任务。保留学生原始回答、工具检查、提示层级和修订内容，模型的诊断建议另外标注，并给教师确认或更正入口。

教师报告先给本次需要补讲或巩固的重点，再用学生原话说明卡点或前后变化，最后给与该知识点对应的课堂追问和观察要点。词义可要求换成日常说法并读通句子，修辞可改写后比较效果，篇目混淆可先核对出处再找本篇依据；不要给每个知识点重复“同伴互讲、换句迁移”等万能建议。同一表达同时支持多个相关知识点时合并呈现。统计口径、内部判断规则和测试边界留在维护说明，教师成品只保留影响本次教学决策的信息。

教师日常识别儿童需要姓名时，保留教师明确提供的姓名、原话与行为对应关系，不强制改成A、B。姓名来自教师说明，照片不承担身份识别；多张照片也不自动认定同一儿童。回访同时关联活动与参与者，同名多活动、换班级或新旧孩子不一致时用自然语言确认。公开展示使用专门的演示人物与数据，内部台账的姓名展示按学校授权范围处理。

交付时画清学生对话、教师材料维护、过程记录的关系，附实际入口和一次从开始到作品的操作示例。只有后台表就称后台查看，不写成已拥有独立教师端；教师需要知道看哪个字段后做何种教学动作。

在线平台出现配额、积分或外部服务错误时，要把“本地逻辑检查通过”“平台配置已保存”“在线流程运行通过”“正式入口发布”分开记录。任何一次旧版本成功运行都不能代替新版的在线回归；资源恢复前不得把新版草稿写成已交付成果。

汇总计算使用确定规则。空白、未完成、工具失败与错误回答分别计数；统计写明分母、活动版本和时间。能由一张表计算的完成率，不依赖大模型自由生成。数据只有被教师用于追问、分组、补讲或调整任务，才形成教学反馈。

## 十一、学习产物服务后续活动（可灵活）

选择能承载本学科思考的产物：原文与解释对照卡、规则修订卡、数学表示图、访谈证据单、比较表等。先保护学生的观点与原话，再检查AI整理是否改变意思。生成图片或展厅适合表达空间、历史环境或作品关系时再采用；输出漂亮卡片本身不证明理解提升。

课堂先完成学生与AI的局部交互，再让学生与学生比较、讨论、修订，教师负责收束到本课目标。根据年龄、设备与任务复杂度决定个人、小组或教师投屏形式，不固定使用一人一平板、双智能体或某个AI课时比例。

## 十二、知识依据与角色边界（红线）

使用教材、历史人物或专门学科资料时，建立来源、版本、允许用途和更新责任。把原文、权威资料、学生解释和模型生成内容分别标识；检索无结果或材料矛盾时补充信息或转教师，不能通过拟人化语气掩盖依据缺失。

角色扮演只在确实支持课程目标时使用。历史人物互动应让学生知道这是基于资料的教学模拟，引用与想象分开；不能把生成的第一人称回答当作史料或真实证词。具体史料与学科正确性由教师审核。

## 十三、账号与教学数据（默认）

正式应用由教师或学校可控制的空间持有，技术协作者按实际需要获得开发权限。两个互不相关的使用方分开组织资源；迁移或导入后重新检查依赖、链接、配额和访问权限。知识库结构与文档分别核对：打开主流程实际引用的库，确认文档数量、分段和一次真实命中；不要只检查导入成功或检索节点变绿。过程表也要从后台读回记录，区分结构备份与数据备份。

采集前确定用途、字段、保存期限、访问角色和清理方式。先用原创模拟数据开发；课堂试用采用学校允许的告知、授权和去标识方案。匿名小组标签也可能与现场身份关联，不能因此跳过访问控制。用户输入“老师模式”不作为教师身份凭据；权限不能验证时采用教师控制的活动和人工收集反馈。

## 十四、参考案例与原创设计（默认）

参考时拆成“当时的难题、学习动作、AI分工、技术依赖、课堂产物、教师反馈”，再问当前学科与班级是否有同样缺口。借鉴机制，重新选择题材、资源、交互和验证方法；不固定沿用同一角色、插件、闯关层数或图文模板。

检索相近作品后，按教学任务、学生操作、执行机制、产物和反馈用途比较，记录已知重合及自己解决的不同问题。来源、词语和作品名换了不等于形成原创实现；有限检索也不能保证全网没有相同方案。正式表述以可展示的实际贡献为准。

## 十五、分层验证与回写（默认）

依次检查学科真值、节点输入输出、整条工作流、实际发布身份、学生操作路径与教师反馈用途。正常输入、材料缺失、歧义、重复提交、工具失败和越权请求都要有实际返回记录。通用证据等级和交付要求引用[交付与测试](../../../experience/delivery-and-testing.md)，不另建一套口径。

教学试用按可组织条件选择同任务前后修订、新任务独立完成、同课不同支持方式或经学校允许的对照设计。写清任务与支持程度，保留失败、未完成和教师复核；不把一次成功对话解释成长期能力提升，也不强制每个原型做实验班与对照班。

## 完成检查

- 学生知道要完成什么，教师知道何时介入；AI每次调用都有教学用途。
- 至少一条主流程实际连线执行，关键分支有正常与失败用例；组件调用记录可核对。
- 依据、状态、精确判断、记录和呈现各有责任边界；工具失败不会生成虚假成功。
- 有可比较的学生产物和教师下一步动作；提示完成与独立完成分开呈现。
- 账号、依赖、访问和数据处理已经按部署方式检查。
