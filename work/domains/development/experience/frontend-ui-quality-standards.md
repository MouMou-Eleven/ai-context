# 前端 UI 质量标准：层级、节奏与多端交互

状态：当前采用。确认人：杨建委；确认日期：2026-09-15。适用于 React/Vue 网站、管理后台、发布编辑器和移动端页面；不是某个组件库的主题模板。

## 触发与排除

遇到页面改版、组件选择、响应式适配、加载/错误状态、编辑器交互或“更有设计感”的要求时，先读本文件，再读目标项目 README、现有页面和真实参考站点。若只是后端迁移、数据库修复或无界面脚本，不加载本方法。

## 建委确认的判断标准

“不好看”的典型不是颜色少，而是层级、对齐和节奏失控：默认组件堆叠、胶囊标签泛滥、所有内容居中、按钮和标题比例单一、空白忽多忽少、移动端把桌面两行硬挤在一起。此类页面即使加背景图，也没有形成视觉中心。

认可的 Cirrus 参考（建委提供截图）：大而统一的标题建立视觉中心，正文宽度受控；导航以紧凑浮动容器组织；黑色主按钮与白色次按钮形成清楚优先级；产品预览在首屏下方承接叙事；间距、圆角、字重和对齐形成整体系统。云朵、蓝色或黑色不是固定配方，不能复制为所有项目的模板。

## 实施方法

1. 先定义内容优先级和一条主路径，再决定网格、字号和按钮数量。标题、说明、操作、内容卡片必须有可解释的层级。
2. 使用统一的容器宽度和基线对齐；留出可读的呼吸空间，但每段空白都要服务于分组或视觉停顿。避免空白孤岛与贴边拥挤。
3. 为 1920、1024、768、390/360 CSS 像素分别检查：桌面布局重排为移动布局，不能只缩小字体；触控目标至少 44px；同一组标签、分享和筛选操作在移动端应有明确的一行或有意的底部面板。
4. Hover 只补充桌面信息，键盘焦点和触控必须有同等入口。编辑器的行首添加、元素工具和浮动菜单应按元素状态显示，空白状态不得常驻噪点。
5. 图片、视频、嵌入和网络请求都要有加载、成功、失败、重试和离线边界；失败不能留下看似空白的卡片。预览外链必须校验协议并隔离权限。
6. 参考 Anime.js 文档和 21st 社区组件时只借鉴可解释的动效节奏与组件结构；先核对现有技术栈、可访问性和性能，再实现最小必要效果，不为装饰引入依赖。

## 验收清单

- 首屏只有一个清晰视觉中心，标题/说明/操作/内容的权重可读。
- 文字与控件在同一网格基线，间距既不挤满也没有无意义大片空白。
- 390/360 宽度无横向溢出，导航、分享、搜索和主要操作可触达；深浅色没有矩形断层。
- 空、加载、失败、重试、无权限和断网状态可理解；真实错误保留可诊断信息但不泄漏秘密。
- 通过真实浏览器截图和键盘/触控路径复核，静态 lint 或组件快照不能代替成品验收。
