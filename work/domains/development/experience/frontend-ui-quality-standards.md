# 前端 UI 质量标准：层级、节奏与多端交互

状态：当前采用。确认人：杨建委；确认日期：2026-09-15。适用于 React/Vue 网站、管理后台、发布编辑器和移动端页面；不是某个组件库的主题模板。

## 触发与排除

遇到页面改版、组件选择、响应式适配、加载/错误状态、编辑器交互或“更有设计感”的要求时，先读本文件，再读目标项目 README、现有页面和真实参考站点。若只是后端迁移、数据库修复或无界面脚本，不加载本方法。

## 建委确认的判断标准

“不好看”的典型不是颜色少，而是层级、对齐和节奏失控：默认组件堆叠、胶囊标签泛滥、所有内容居中、按钮和标题比例单一、空白忽多忽少、移动端把桌面两行硬挤在一起。此类页面即使加背景图，也没有形成视觉中心。

认可的 Cirrus 参考（建委提供截图）：大而统一的标题建立视觉中心，正文宽度受控；导航以紧凑浮动容器组织；黑色主按钮与白色次按钮形成清楚优先级；产品预览在首屏下方承接叙事；间距、圆角、字重和对齐形成整体系统。云朵、蓝色或黑色不是固定配方，不能复制为所有项目的模板。

## 实施方法

1. 先定义内容优先级和一条主路径，再决定网格、字号和按钮数量。标题、说明、操作、内容卡片必须有可解释的层级。
2. 使用统一的容器宽度和基线对齐；留出可读的呼吸空间，但每段空白都要服务于分组或视觉停顿。避免空白孤岛与贴边拥挤。
3. 为 1920、1024、768、390/360 CSS 像素分别检查：桌面布局重排为移动布局，不能只缩小字体；主要触控操作以 44px 为起点，密集文字导航结合误触风险与行距单独判断；同一组标签、分享和筛选操作在移动端应有明确的一行或有意的底部面板。
4. Hover 只补充桌面信息，键盘焦点和触控必须有同等入口。编辑器的行首添加、元素工具和浮动菜单应按元素状态显示，空白状态不得常驻噪点。
5. 图片、视频、嵌入和网络请求都要有加载、成功、失败、重试和离线边界；失败不能留下看似空白的卡片。预览外链必须校验协议并隔离权限。
6. 参考 Anime.js 文档和 21st 社区组件时只借鉴可解释的动效节奏与组件结构；先核对现有技术栈、可访问性和性能，再实现最小必要效果，不为装饰引入依赖。

## 验收清单

- 首屏只有一个清晰视觉中心，标题/说明/操作/内容的权重可读。
- 文字与控件在同一网格基线，间距既不挤满也没有无意义大片空白。
- 390/360 宽度无横向溢出，导航、分享、搜索和主要操作可触达；深浅色没有矩形断层。
- 空、加载、失败、重试、无权限和断网状态可理解；真实错误保留可诊断信息但不泄漏秘密。
- 通过真实浏览器截图和键盘/触控路径复核，静态 lint 或组件快照不能代替成品验收。

## 移动端：从真实失误提炼的检查方法

来源：建委 2026-09-15 第二轮纠错的 9 张截图及逐项说明。以下是用户明确要求长期执行的规则；本轮实现尚未获得用户审美验收，不把浏览器检查通过写成用户认可。

| 重复问题 | 修正动作与原因 | 可观察验收 | 不应照用的情形 |
|---|---|---|---|
| 标题右侧空着，查看全部却另占一行 | 先核算文字和操作宽度；短标题与单个次要操作同一行，对齐中线 | 360px 下标题与按钮中心线一致，不以缩字或裁字换取同排 | 很长标题、多操作、200% 字体确实放不下时允许有意重排 |
| 标签与分享塞在大卡片中上下错位 | 导航与动作分离；导航强调当前位置，分享用独立的 44px 图标按钮，保留可访问名称 | 3 个入口完整可点；分享无空白孤岛；搜索后分享保留关键词、分类、排序和页码 | 图标含义不明确、操作很重要时仍保留文字 |
| 搜索/排序挤出屏幕，首个标签被截断 | 检查真实 DOM、flex 子项最小宽度、绝对定位和滚动容器坐标；搜索独立分配宽度，排序按可用宽度组织 | 检查整个文档与每个关键控件边界；切换标签、刷新和往返路由后再次检查 | 必要的横向分类列表可局部滚动，但首项和当前项须完整可达 |
| Logo 贴边、手机菜单缺入口 | 页眉内容留 16px 左右起始间距并兼容 safe-area；逐项对照桌面信息架构 | 访客/登录两态，360/390/430/768 都可进入主栏目；抽屉可滚动、关闭、键盘访问 | 16px 是本次网站起点，不是所有设备强制常数 |
| 底部单列导航旁边空出大片区域 | 短链接按两列网格排布；与标题、联系方式形成稳定对齐 | 两列无文字挤压或溢出；点击目标足够大 | 链接长、字号放大时允许回退单列 |
| 竖图分享卡被横向拉伸 | 读取原图宽高比，决定卡片画布；限制极端长图高度时用 contain 留底色 | 16:9、3:4 和超宽图的圆形仍为圆形；预览与下载用同一画布；手机弹窗可滚动 | 展示完整封面时不使用 cover 裁掉内容；确需裁切必须明确用途 |

规则再次失效时先分类：没触发、没读取、没执行、样式覆盖、交付包失效，还是规则本身不适用。此次“文件改了但界面没变”的风险要同时检查懒加载 CSS 的优先级，以及增量 ZIP 是否保留 `src/...` 目录。不能只重复添加“严禁遗漏”。

2026-09-15 第三轮反馈补充：R27 的受控短名称测试未覆盖真实长分类，不能继续用“多尺寸通过”概括已修复所有手机问题。R28 在 390px 视口用长分类复现了 639px 文档宽度。对于内容长度变化明显的界面，验收必须带入真实长度、数量与层级，而不只切换设备尺寸。

| 适用情形 | 具体动作与可观察验收 | 反例与限制 |
|---|---|---|
| 长分类、长标题或很多标签 | 用最长名称及实际数量填充，检查 grid 的最小内容宽度、flex 子项、跨列跨度；分类局部滚动时整页 scrollX 应保持 0，聚焦末项后再检查 | 正文大表格允许局部横滚；不能统一隐藏页面溢出来掩盖被裁掉的内容 |
| 后台需要管理父子目录 | 左侧显示父级、右侧只显示所选父级的子项；创建时绑定当前父级，排序仅作用同级；保存后刷新，并验证前台实际读取同一份配置 | 无父子关系的标签库不要硬套两级；导航入口、内容类型和筛选分类不能因名字相似而混为一套数据 |
| 两列短链接仍显松散 | 同时核算行高、内边距和额外 gap；不能把大按钮的44px高度再叠加行距套到所有文字链接；检查三行整体高度与标题距离 | 主要按钮或误触风险高的操作仍需要较大触控区域；本次36px手机链接行高不是跨项目强制值 |
| 图标按钮变成文字按钮 | 按内容重新分配宽度，检查原32px/36px方形规则是否仍生效；长标签保持可读，工具条不遮挡正文 | 有完整可访问名称的纯图标按钮仍可用方形；外部 iframe 正文的换行不能靠宿主CSS承诺控制 |

可迁移小样：把“素材专区→Skill入口”替换为“资料中心→模板入口”，父子选择与同级排序的验收不变；单层标签列表不适用。这是结构迁移示例，不代表第二个项目已经上线。上述规则来源为建委明确要求及本轮复现，视觉成品仍等待建委实际使用反馈。

## 后续反馈的准入与自动整理

用户在开发迭代中指出 UI 问题时，AI 主动判断是否属于本方法，按[仓库提炼流程](../../../../system/repository/ingestion-workflow.md)处理，无需用户每次列索引。先查已有条目，同义反馈合并证据。

进入正文至少具备：可定位的具体观察、适用场景、可执行动作、为何有用、能观察的验收，以及一个不适用例子。单个页面的临时参数留项目；“更高级、更好看”但没有具体结构依据的反馈，不扩成通用规则。AI 新推论标为候选；用户明确确认的长期要求可在限定范围采用，不能夸大成跨所有网站验证。

例如这次“最新作品与查看全部同排”可迁移到资料库的“最新文档／查看全部”，验收同样比较控件边界；长标题加多个操作就是反例。此例只验证方法动作可迁移，不冒充另一个已上线项目。

调用顺序：目标项目 README → 本文适用条目 → 真实参考或组件源码 → 实施 → 浏览器逐项验收。其他 AI 工具须实际读取仓库入口才能采用，GitHub 存储不会自动训练模型，也不能保证未接入仓库的工具触发。
