# 商单与实践案例

保存单次任务的真实输入、选择、人工与AI分工、失败修正、结果及证据。长期项目中的案例留在该项目，这里只登记链接。

## 案例准入门槛

只有同时具备以下内容，才能新建案例文件并登记到导航：

- 可以定位的真实任务、项目、落地场景或商业场景；
- 具体输入、限制和实际交付物；
- 至少一项真实过程信息，例如关键选择、实施步骤、人工与AI分工、失败修正或客户反馈；
- 可以观察的结果、产物入口、验收证据，或者边界清楚且有事实依据的当前状态。

只有标题、展示文案、设想或大部分核心字段均为“待补”的内容不构成案例，也不为预留名称建立占位文件。材料不足时保留在可追溯的原始来源或待归属资料中，取得实际过程和结果后再入库。案例通过准入后，局部未知字段可以标记为“待补”，但不能用“待补”代替主体内容。

已收录记录也不自动等于完整工程或客户验收。复用前读案例的证据与限制，不能把拟定功能、宣传表述或一次成功当作普遍有效的方法。

新增记录用[唯一案例模板](../../../system/repository/templates/case.md)，按照[更新流程](../../../system/repository/ingestion-workflow.md)补主领域、交付物和关联领域。下方列表与领域页相关案例区块由同一登记生成，方法正文留在最适用的领域。
