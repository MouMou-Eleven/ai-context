# 2026-09-15：首期 AI 编程论证改为具体工具与连接方式

## 触发背景

建委在继续审阅朋友圈和飞书介绍页时指出，上一版虽然写出了“全面视角”和“跨领域迁移”，但用于支撑判断的“目标表达、资料提供、任务拆分、工具调用、结果检查、持续修改”仍然过大、过泛，没有触达他选择 AI 编程作为第一期主题的核心依据。

本次不是改变课程顺序，而是校正论证方式：不再用抽象能力清单证明 AI 编程更适合作为第一视角，改用实际会接触的工具、接口、连接方式和使用场景来说明。

## 当前确认

1. **观点来源使用第一人称表达。** 对外可以写：“我告诉了他一个我长期、高强度使用 AI 之后形成的判断。”避免把个人实践判断写成没有主体的客观结论。
2. **AI 编程提供的是全方位视角。** 这个切口会让学员接触 Codex、WorkBuddy 等主流 AI 工具，理解 API 怎样调用，学会在 GitHub 上查找并判断可用的项目和 Skill，并了解 MCP 怎样把 AI 接入办公等外部任务。
3. **具体用途必须写出来。** Skill 不只服务编程，也可用于文章提炼、AI 视频制作等工作；学习过程中还会持续练习怎样与 AI 更高效地对话、怎样指挥它使用工具完成任务。
4. **迁移依据来自工具与场景的连接。** 当学员理解 AI 工具、模型、接口和工作场景怎样连接起来，这套认识可以继续迁移到办公、设计、视频、教育和日常生活，而不是因为文案笼统声称它“可迁移”。
5. **专项课程仍然保留。** AI 办公、AI 设计和 AI 视频不是不重要，而是更聚焦各自领域；第一期先建立整体视角，第二期、第三期和第四期再陆续进入这些专项方向。

## 表达边界

- 不再使用“目标表达、资料提供、任务拆分、工具调用、结果检查、持续修改”作为首期排序的主要论据；这些动作可以出现在具体教学说明中，但不能代替工具与场景证据。
- “从 AI 编程切入更合适”属于建委长期实践后的个人判断，不写成适用于所有人的客观定律。
- 提到 GitHub 项目与 Skill 时使用“查找并判断可用”或“根据需求选择”，不暗示所有社区项目都安全、可靠或适合直接安装。
- 当前资料发布状态仍按项目 README 与资料索引核对；本修订确认的是课程定位和表达方式，不据此宣称每一项专题都已发布。
