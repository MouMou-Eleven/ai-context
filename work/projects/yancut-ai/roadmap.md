# 言剪 AI 路线图

> 当前阶段：比赛原型；更新时间 2026-09-03。

## 第一阶段：可讲清、可操作的比赛闭环

目标是让评委看到真实操作，而不是一组静态界面。

1. 用户上传一段常见口播或知识分享视频。
2. 用户用中文说“删除停顿、生成字幕、改成 9:16”。
3. AI 返回结构化计划和影响范围，缺信息时先追问。
4. 用户确认后，把可执行命令落到真实时间线。
5. 用户选择个人声音完成一段配音。
6. 用户直接对 AI 说出包装目标，AI 把 Remotion 动效方案写入当前可编辑时间线，再从同一工作台导出结果。

截至 2026-08-31，第 2、3、4、6 项已具备本地真实执行路径，并通过模型计划与浏览器时间线写入回归；专业剪辑命令已扩展到真实转场、ducking、响度/波形分析、代理预览、速度曲线和证据驱动高光切片。第 1 项素材导入仍需真实长视频压力测试，第 5 项仍依赖正式声音供应商和授权回写验证。

比赛前必须准备一个本地兜底素材和本地规划器路径，避免现场网络故障导致核心演示中断。

## 第二阶段：在本地把接口闭环变成产品闭环

- 声音克隆：补齐录音质量检查、授权确认、试听、重命名、删除和配音回写时间线。
- AI 剪辑：当前已有计划确认、版本保护、执行回执、撤销与本轮失败回滚；下一步增加执行前后差异预览、分段批准、轨道锁定保护和长任务取消。
- 包装渲染：本地异步 Remotion 队列、远端 provider 合同、数据库任务状态、用户归属和失败退款已完成；下一步部署独立服务，验证时长、分辨率、并发、成本、对象存储回写和失败重试。
- 参考剪辑：提取参考视频的镜头边界、节拍、BPM、响度和高潮点，用用户自己的素材生成可确认方案。
- 价格与权益：统一产品目录、免费/付费边界、积分扣减/退款、月季年套餐、积分包和价格中心已完成；当前按已确认的微信二维码和联系方式 `15020414318` 人工确认购买，不自动扣款，也不显示客服名称。下一步在秒嗒验证二维码识别，并固化付款核验、人工开通与对账流程。
- 数据与接口：Postgres 兼容 Schema、迁移、类型、索引、积分/订单/订阅/声音/渲染数据模型和 API 参数已完成；管理后台新增真实业务概览、用户管理员授权、服务配置和审计 API。下一步在秒哒执行迁移、配置权限策略并做跨账号隔离测试。
- 运营管理：本地 `/admin`、管理员权限、加密服务配置、审计记录及运行时动态读取已完成；下一步接入秒哒 Auth 与共享 Postgres，验证首位管理员初始化、密钥轮换和生产审计留存。
- 云适配：把 Auth、数据库、对象存储、模型、声音和渲染服务收口到适配器，不让核心业务依赖单一平台。
- 质量门禁：完成单元测试、集成测试、生产构建和桌面/移动浏览器验收。
- 模板创作包：真实必填素材槽位和连续时间线实例化已完成；下一步补可选槽位、镜头替换预览、字幕样式和配乐规则。

## 第三阶段：生成百度秒哒兼容交付包

- 重新核验秒哒当期 Web 技术栈、附件数量和大小限制、Auth 插件、短信、存储与后端能力。
- 解决当前 Next.js 基线与秒哒 React + Vite 稳定导入形态的冲突；必要时提供独立 Vite 兼容应用。
- 按 `01`、`02`、`03`、`04` 连续编号拆分源码、PRD、云合同、运行时素材和视频模板。
- 为每个文件和压缩包生成 SHA-256，并在空目录重建、测试和生产构建。
- 生成“接收校验 → 对象存储入库 → 云能力接线 → 构建部署 → 验收 → 改动回收”的分批提示词。

## 第四阶段：由百度秒哒接管云端能力

- 使用平台内置 Auth 完成真实手机号注册、登录、会话和账号恢复；短信插件能力以当期实测为准。
- 创建真实 Postgres 数据库、对象存储和 Edge Function，按本地 Schema 与接口合同接线。
- 验证跨账号和跨设备持久化、权限隔离、音视频 Range、任务重试、配额扣减与云端日志。
- 把秒哒产生的必要兼容改动同步回本地权威源码，后续修复使用增量补丁包。

## 第五阶段：验证商业价值

先验证大众高频任务，不同时追求所有专业剪辑能力：

- 口播去停顿 + 字幕。
- 个人声音复用配音。
- 横竖屏改版。
- 知识分享、产品介绍和生活记录的统一包装。
- 一条长素材生成多个短版本；在语义切片服务完成前，AI 必须追问平台、单条时长和内容主题，不能伪装已完成高光理解。

## 专业剪辑能力吸收顺序

参考 Shotcut/MLT 的成熟工作流，按网页端价值和实现风险排序：

1. 近期：轨道锁定、响度标准化/真峰值、波形标记、批量属性、素材标签和转场参数化。
2. 中期：代理持久化与音画代理、速度曲线编辑器、关键帧曲线、画面稳定、基础调色与滤镜预设管理。
3. 后期：MLT XML / OpenTimelineIO 交换、可选独立 MLT 渲染工作进程、多机位、运动跟踪、复杂调色和语义高光模型。
4. 任何 MLT/Shotcut 代码级接入前，先完成部署形态、进程隔离和 GPL 分发义务评审；默认只吸收公开产品与架构经验。

建议先观察四项指标：第一次成片成功率、从上传到导出耗时、AI 计划确认率、每次有效导出的模型与渲染成本。

## 上线前条件

- 确认独立源码仓库与开源/商业分发策略。
- 补齐隐私政策、服务条款、声音授权和数据删除机制。
- Key 全部服务端保存，增加配额、限流、日志脱敏和滥用防护。
- 执行管理表迁移，设置独立的 `YANCUT_ADMIN_ENCRYPTION_KEY`，用管理员与普通用户双账号完成越权和密钥掩码测试。
- 验证主流 Chrome/Edge 环境、常见视频格式和长视频内存占用。
- 价格中心显示当前产品验证价格；正式成本测算和支付通道验收前不得自动收费，调整价格时必须同步统一产品目录与支付商品映射。
- 云端上线前完成手机号规范化、账号唯一性、数据库权限、对象存储映射和数据删除回归。
- 秒哒交付前必须完成 React + Vite 兼容构建或重新确认平台已支持当前 Next.js 基线。
