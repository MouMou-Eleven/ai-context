# Expression — 表达、写作与知识讲解

> 状态：当前有效
> 口径确认：2026-08-02
> 作用：统一管理建委的沟通偏好、写作方法、知识讲解方法和外部优秀案例。这里学习的是可复用的方法，不是机械模仿某个人。

## 目录结构

| 入口 | 内容 | 何时读取 |
|---|---|---|
| [`communication-preferences.md`](./communication-preferences.md) | 沟通语气、自然表达、去 AI 味和文字选项偏好 | 任何需要生成对外文字或长期协作时 |
| [`tutorial-writing/README.md`](./tutorial-writing/README.md) | 面向普通人的教程、经验帖、学员资料和操作说明 | 写保姆级教程或学员正文时 |
| [`methods/README.md`](./methods/README.md) | 已从多个优秀案例中提炼、可直接调用的表达与讲解方法 | 用户要求参考仓库里的表达习惯、讲解经验或写作逻辑时 |
| [`source-materials/README.md`](./source-materials/README.md) | 外部作者逐字稿、原始文章和来源说明 | 需要核对方法来源、语句节奏或补充新案例时 |

## 默认触发语义

用户出现以下表达时，不需要再追问某位作者姓名，默认读取本目录：

- “参考仓库里的语言表达习惯。”
- “按我沉淀的表达和讲解经验来写。”
- “减少 AI 味，讲得像人一点。”
- “把这个知识讲得更清楚、更容易吸收。”
- “参考我收集的优秀表达案例，但不要照抄。”

默认读取顺序：

```text
communication-preferences.md
→ methods/README.md
→ 选择与任务匹配的一种方法
→ 只有需要核对来源时才进入 source-materials/
```

## 按交付物选择

| 当前任务 | 默认读取 | 额外规则 |
|---|---|---|
| 技术科普、AI 概念解释 | 沟通偏好 + 表达方法 | 优先使用问题推导、日常比喻、事实和限制 |
| 课程学员正文 | 表达方法 + 教程写法 + 所属项目或培训规则 | 教学目标、练习和验收优先于语言节奏 |
| 自媒体口播 | 当前项目脚本规则 + 表达方法 | 人群、场景、真实案例和承接动作优先 |
| 普通文章、报告、说明 | 沟通偏好 + 对应方法 | 不强制套用短视频或课程结构 |
| 飞书书稿 | 飞书书籍项目的专属规则 | 不自动叠加本目录全部方法 |
| 招生海报、私聊成交 | 对应项目运营规则 | 不用长篇科普节奏拖慢转化 |

## 融会贯通规则

- 新增优秀作者或案例时，原始材料进入 `source-materials/<source>/`，并写清来源、时间、适用范围和事实风险。
- 真正值得长期调用的方法提炼进 `methods/`，方法名按作用命名，不用作者姓名命名。
- 同一个方法经过多个来源验证后，更新方法文件的“来源与证据”，不复制成多个近义规则。
- 外部材料中的技术参数、平台版本、数据和个人经历不能变成建委的事实。
- 学习叙事、拆解、逻辑和知识传达方式，不逐句仿写，不复制标志性措辞。
