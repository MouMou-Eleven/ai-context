# 已退役的说法

被建委推翻、或者被更好的做法取代的规则和说法，登记在这里。**平时做任务不用读这一页**：正文里只有现在的说法，这里只是留痕和防止旧说法“复活”。

## 什么时候读、什么时候写

- **建委又要回旧做法时**：不删这一行，在“退役日期”一格写上“YYYY-MM-DD 建委要回”（检查就不再拦这一行的检测词），再把被推翻的那条新说法登记成新的一行。来回改过几次都看得到。
- **写入或晋升规则时读一遍**（[进化机制第三节](./evolution.md#三什么时候把观察升成通用规则ai-自己判断默认)查重查冲突那一步）：要写进去的东西如果和这里某一行意思一样，就是把退役的说法又捡回来了，不写。
- **规则被推翻、被取代时写一行**：正文直接改成新的说法（[写入规范](./ingestion-workflow.md#第三步改原文不要追加)），旧说法不在正文里并列，登记到下表。
- 只是措辞调整、补充细节的，不登记；Git 历史够用。

## 为什么这样不会增加冗余

正文只有一份当前说法，AI 干活时读到的就只有新的。这一页不在任何任务的必读里，只在写入和体检时读。**真正防止旧说法回来的是提交检查**：[content-guards.py](./maintenance/content-guards.py) 拿“检测词”去扫规则文件（AGENTS、brain、work/domains、system），出现了就拦下，不靠 AI 记得。

检查不扫这些地方，它们本来就该提旧说法：本页、观察记录、使用日志、进化机制、修订记录、`navigation/` 和 `maintenance/` 目录、项目和场次记录（那是当时的事实）；规则文件里“来源”“来历”“来源与状态”这类二级标题下面的内容（到下一个二级标题为止）。另外，检测词紧挨着的前后几个字在说它已被取代时也放过，例如“而不是同一排一样大”“以前的五问法已经拆进对照表”；只是同一行别处有“不是”“以前”，照样会拦。
