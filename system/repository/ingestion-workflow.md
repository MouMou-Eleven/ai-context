# 新内容写入与更新流程

状态：当前有效。确认：2026-09-12。适用于新增、修改、迁移、删除、复盘、纠错、收录Skill和“沉淀到某板块”。建委无需列出要改哪些索引；本流程由执行AI完成。

## 1. 写之前：查已有内容和真实归属

读取AGENTS、llms、STRUCTURE及目标README；搜索同义方法、主题别名和旧状态。查当前远端与工作区，保护无关改动。

先确定项目/客户/活动/课程系列，不凭课号、标题、平台、文件所在旧目录推定归属。建委明确纠正优先；缺证据时保留待归属资料，不塞进最近的现有项目。一次课程可在多个活动复用，但教材资产一份、授课记录各自关联。

## 2. 分清本次新增的价值

| 信息 | 写入位置与动作 |
|---|---|
| 人物稳定事实 | personal的指定事实文件，项目过程不混入 |
| 项目状态、计划、约定 | 当前权威记录，补来源/日期；旧摘要同步 |
| 商单/实践案例 | work/projects/cases或既有项目内，记录输入、过程、选择、失败、结果和证据；不在每个领域再建一份 |
| 可复用技巧 | work/domains对应方法位置，带适用/排除条件、步骤、验收与案例链接 |
| 个人认知 | brain对应主题，必须有建委明确表达或认可；AI不能从个案自动宣布其个人信念 |
| 通用表达/个人口吻 | 通用标准进system/expression；明确认可的个人偏好进personal，不复制领域体裁规范 |
| 自研Skill | 能力条目、origin=internal、维护者、版本/修订和实际执行入口 |
| 第三方Skill | 原作者/上游URL、固定commit、许可、同步日期、依赖与完整快照 |
| 原始参考 | 就近raw/reference-materials，来源和用途登记，默认不读 |
| 失效内容 | 当前入口改指替代项；有必要才留历史；用户要求彻底清除时不另建归档 |

## 3. 案例变成方法

案例与方法互相链接。先区分新增证据、新候选方法、修订已有方法、强化重复错误或信息不足。单次经验可以留候选，不以一次成功证明普适；重复验证或建委明确确认后提升为当前采用，并注明验证范围。

一个方法只保留一处完整正文。视频制作已合并于设计：AE、MG与AI生成按制作环节调用；通用镜头方法放视频共用，平台参数放工具，特定片型方法就近维护。不要把特定客户的业务数量、风格、金额或模板数据提升为默认规则。

已有规则再次失效，判断是没找到、没执行、太模糊、规则冲突还是方法无效，分别改路由、步骤、验收或适用范围。不能只增加“必须/严禁”。记录真实复用结果，未记录使用不等于从未使用。

## 4. 影响范围检查：每次都做

| 变化 | AI必须检查更新 |
|---|---|
| 新增/移动/删除文件 | 最近README；引用旧路径的全部文件；STRUCTURE.md与HTML |
| 新项目、案例或归属变化 | 项目/案例主记录、navigation/projects.json中的类型与domainEntries、上级项目/案例索引及相关领域（派生区块）、personal业务概要 |
| 新能力或调用范围变化 | 能力README、来源metadata、navigation/routes.json、相关领域双向引用与路由用例 |
| 当前事实变化 | 权威事实表、项目摘要、执行说明、被替代段落与来源日期 |
| 课程/章节变化 | 稳定ID、所属系列、计划/资料发布/实际授课状态或新旧章映射；不串项目 |
| 新方法/重要反馈 | 方法正文、案例来源、最近索引、任务触发与可观察验收 |
| 重大方向/运行规则变化 | revisions/YYYY-MM-DD-slug.md，写原因、新旧差异与受影响入口；history如存在只留摘要/链接 |

对于“只是内容变动”的提交也要检查这些项目，适用项必须完成；不适用则无需创造空文件。模板见[templates](./templates/README.md)。

## 5. 让AI知道怎样调用

主领域README写清“何时用、先读什么、按需展开什么、相关能力、写入方式”。新经验必须至少有一个自然任务入口和一个不适用场景；相邻领域按真实依赖链接。能力来源登记≠安装，发现≠执行；真正执行Skill才加载其正文。

根llms保留兼容短指针，完整task-guide由navigation/routes.json生成；项目、案例及领域关联区块由projects.json生成，只含名称、路径与适用范围，不复制项目当前状态。完整结构与日常导航由维护工具同步。生成文件过期时校验失败，不能以“已经写了正文”结束。

## 6. 验收与发布

执行[维护步骤](./maintenance/README.md)：检查链接/入口覆盖、结构一致、路由与项目归属、Skill来源、生成文件和相关内容约束。新方法的效果需要真实任务复测，静态通过不能冒充成品质量通过。

只暂存本次改动；从同一暂存版本生成派生文件并校验；遵守直接main政策提交推送，回读远端commit与关键路径，核对删除目标确实不存在。桌面结构同步单独记录。交付说明本次纠正、可调用入口、已验证事项与仍待确认事实。

## 模型与工具升级、后续复盘

继续使用同一组业务场景检查：能否找对课程/项目、能否跨域调用、是否误用旧事实、是否重复犯错、读取是否过量。只在实际查找瓶颈出现时再加全文/向量检索；增加工具不能替代事实与来源治理。
