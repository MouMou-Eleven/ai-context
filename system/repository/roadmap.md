# 长期维护与演进

确认：2026-09-12。目标是让新增资料提高后续任务的准确性与复用效率；文件数量、规则长度和Skill数量不是价值指标。

## 已建立的运行方式

当前采用personal、brain、work、system四个主入口。work分领域知识与具体项目，Skill库在领域知识的其他领域；表达、治理和设备在system。个人信息按身份、经历、背书、业务概要排序，能力摘要按[证据规则](./capability-evidence.md)维护。按以下顺序渐进读取，不把它理解成保证准确率的特殊算法：

```text
目标与已知项目身份
  -> AGENTS + 系统任务导航（llms为兼容短指针）
  -> 主项目事实 / 领域短规则 / 适用表达体裁
  -> 必要的跨领域方法与能力卡
  -> 需要核验才读原始材料、历史或源码
  -> 完成任务、验证并回写实际经验
```

项目、课程、案例、方法、Skill分别承担事实、场次、证据、操作和工具能力。一个正文只存一处，其他板块提供索引；关键词路由辅助找候选，不能替代AI对目标、对象和证据的判断。

## 每次新增就维护

建委只需表达“把这次MG商单的经验沉淀到设计”或“以后做这种培训用这套方法”。AI按[写入流程](./ingestion-workflow.md)完成归属、去重、案例与方法连接、所有受影响的索引和状态，以及校验和远端回读。

- 一次实践：先留下输入、做法、失败与结果，候选方法可立即入库，效果边界写清。
- 再次复用：给既有方法增加证据或适用条件；无新差异不另建同义方法。
- 出现反例：修正适用条件或标明替代，不让旧方法继续作为默认入口。
- 外部工具更新：核对版本、接口与许可后再提升快照；文字收录不算本机验证。
- 新课程系列：先登记稳定身份和归属，局部课号不跨系列复用。

不规定每次都更新所有文件，只更新影响范围内的入口和状态；检查责任始终由AI承担。

## 以真实任务检查价值

每次重大规则变化、模型更换或出现实际调用失败时，用维护目录中的路由用例做静态回归，并选近期真实任务做一次完整人工/AI执行复盘。两种结果分开记录。

| 检查项 | 可观察证据 | 失败后处理 |
|---|---|---|
| 找对项目 | 引用的课程/项目身份与明确来源一致 | 补归属、别名或排除条件 |
| 找到旧经验 | 生成方案中实际用了适用方法，并说明条件 | 补自然任务入口或跨域引用 |
| 少读而不漏读 | 入口足以选路径，必要约束均进入任务，中文成品与写库复合任务两者均覆盖 | 拆短入口、调整条件依赖 |
| 表达适合成品 | 同一已确认事实在课堂、书稿或朋友圈符合各自目的，不机械套一种腔调 | 核对体裁、样例与实际修改依据 |
| 经验可以复现 | 同类任务按步骤得到有验收证据的结果 | 补前提、修方法或降为候选 |
| 更新没有遗漏 | 链接、README覆盖、生成文件与路由校验通过 | 修受影响索引及生成源 |
| 事实没有老化 | 状态、功能和价格注明适用日期及来源 | 重新核验并同步所有摘要 |

不预设真实成功率。本轮自动用例验证的是路径与规则，不证明后续每个模型都会遵守，也不证明外部平台功能仍有效。

## 后续工作顺序

1. **补足现有缺证据项**：培训待归属区7个主题逐项补系列/主办方/场次；现有设计案例补原稿、工程、验收与可公开范围。获得资料时处理，不猜测补齐。
   认可样稿在取得明确依据后留所属领域／项目，共享表达只提炼可复用纠错；方法示例不能冒充本人作品。
2. **用真实商单检验闭环**：下一次AE、MG或AI视频任务优先检索已有案例，交付后把实际有效和无效环节写回；需要时再创建独立客户项目。
3. **按实际规模升级检索**：当前入口+全文搜索仍能定位时继续保持。只有多次出现检索漏项、超长上下文或跨库查找成本时，再增加全文索引、混合检索或工具接口；每项仍要保留稳定路径、来源、更新策略和回归用例。

本页是实施与评估顺序，不会自动创建定时任务。日常维护随实际写入与复用发生。

分类依据、导航职责与扩展取舍见[信息架构](./information-architecture.md)。默认日常视图逐层找知识，完整文件视图核查实现；不为每个新话题预建一套空目录。
