# 方法模板（能用到别处的做法）

**什么时候写方法**：一个做法在一次真实任务里有效，并且下次同类任务还能用。先搜仓库：已有讲同一件事的方法，就改那一处，不新建。

**放哪**：对应领域的目录，例如 `work/domains/training/experience/`、`work/domains/design/video/promo/`。只在某个工具上成立的放 `tools/<工具>/`；在两个以上领域都成立的才放 `common/`。

## 怎么做

每一条写清楚：场景、动作、一个正例或反例、为什么。标上级别：

- **红线**：不能违反（例：给学员的课件不写讲师安排）。
- **默认**：没有特别理由就照做。
- **可灵活**：看场景判断，写出判断依据（例：抽象概念用生图，操作步骤用现场演示）。

## 怎么检查做到了

交付前能对照检查的几条，最好是看得见的：比如"每页至少一个具体例子"，而不是"内容要生动"。
