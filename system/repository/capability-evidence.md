# 从实践归纳个人能力

状态：2026-09-12当前规则。由AI在每次新增、修改或删除领域经验、案例、成果时执行，纳入[沉淀流程](./ingestion-workflow.md)。这里的自动是执行AI承担检查和更新，不是GitHub后台自行理解文章，也不要求建委另填能力清单。

## 判断等级

| 等级 | 所需证据 | 放在哪里 |
|---|---|---|
| 了解／探索 | 收藏资料、收录Skill、教程摘录、计划、未完成尝试或单纯AI演示 | 原领域材料；不新增个人能力 |
| 实践中 | 至少一个实际完成任务，能定位结果、检查记录与建委本人参与；试做和正式交付分清 | 原案例优先；确实改变个人工作方向时，概要可简记“实践中”，不称熟练 |
| 可重复完成某类任务 | 至少两个独立需求的已完成实践，每个都有结果证据、核验依据与本人贡献；至少一次把已有方法复用于新任务，并记录适用条件、失败处理和验收 | 个人业务概要可新增限定范围的能力摘要，链接原证据与方法 |

“两个独立任务”是保守入库门槛，不是客观能力认证；涉及高风险或专业资质的工作，仍按其专业标准判断，不自动写“精通”。建委明确确认的能力可登记为本人确认，标注日期与范围，不能伪造满足上述实践门槛。

## 哪些不能重复计数

- 同一客户任务的草稿、修订、截图、发布记录与复盘算一个实践。
- 换标题、换目录、转载同一教程、收录别人Skill及其中示例都不增加实践证据。
- 独立实践有不同需求或使用约束和各自结果；同一长期项目内只有独立目标、验收与真实复用证据的子任务才能分开计数。
- AI独立生成样例不等于建委亲自掌握。必须区分本人需求拆解、制作、判断、调试、验收、AI辅助和他人代做的部分。
- 证据链接可访问不等于内容证明能力；AI需要读结果与检查记录。只写“完成”而没有可定位结果或反馈，不自动晋级。

## 每次沉淀的执行顺序

1. 从本次实际资料提取技能／交付物、任务身份、日期、本人贡献、结果和核验状态；没有依据不补造字段。
2. 搜索已有同类案例与方法，读取相关证据，排除同源资料和同一任务修订。
3. 对照上表判断：未新增证据、探索、实践中或满足可重复完成。只有相关领域有积累才检查，不全库盲读。
4. 先把证据写回原项目／案例，复用方法维护于领域；达到门槛或出现新的边界时，更新[个人业务概要](../../personal/business-overview.md#能力摘要)。摘要只写范围、等级、证据链接、方法、核对日期和限制，不复制复盘全文。
5. 新增、撤回或修正证据后复核所有受影响摘要。删除来源导致门槛不足时降为实践中或移除该推导；历史本人确认记录单独判断，不靠文件数量降级。
6. 本轮交付说明一句能力处理结论及依据即可，例如“本次为首次试做，已留在案例，未升级个人能力”；不生成每次重复的空审核文件。

旧个人资料的已有能力摘要于本次合并保留，属于既有个人记录，不能称为通过新门槛自动认证。以后有相反证据或建委校准时修订，并保留真实原因。

## 例子

- 第一次存Blender学习笔记：了解；不能据此写“掌握三维建模”。
- 完成一次Blender商单，有作品与验收：实践中；明确本人建模、AI辅助与他人部分。
- 在第二个独立需求复用建模流程，结果通过检查，记录能解决的模型类型与限制：可归纳该范围能力；不能扩张为全部三维动画或专业渲染能力。

以上仅为判断示例，不是建委已经完成的事实。
