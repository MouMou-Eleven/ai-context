# 自然任务检索与遵循链修复

来源：建委2026-09-21反馈。保留已认可的四主入口和领域结构，改进不报文件名时的调用。

## 实际复现

基线a53d726。对同一仓库运行原context-route.py：

| 自然任务 | 原结果 | 修复后的读取 |
|---|---|---|
| 参考GitHub仓库，做客户预约小程序 | 仓库维护 | 应用开发及开发经验，不推定为言剪或秒哒项目 |
| 参考仓库，做自动整理表格的脚本 | 仓库维护 | 应用开发及通用经验，不加载页面/课程规则 |
| 写公众号文章 | 只到自媒体总入口及表达层 | 继续到文章与图文子目录，材料涉及解释或营销时再组合方法 |
| 秒哒大视频上传页面 | 秒哒llms和辨析，未列上传方法 | 平台README、上传提示词、大视频上传处方与相关候选；旧兼容源码不默认加载 |
| 只说看GitHub仓库，无其他上下文 | 仓库维护 | 不捏造工作目标；执行AI先查当前对话，仍无目标才询问要做什么 |

这证实入口词匹配、子目录继续读取和实际采用之间有缺口；不能据此宣称所有文章都失败或测出全模型遵循率。

## 改动

- 根AGENTS、llms与任务指南统一自然任务流程；不能运行脚本的网页宿主沿README、方法短表和文件搜索走同样步骤。
- 路由加入常见开发说法、板块范围、自动意图判断和条件依赖；明确项目事实继续读对应资料，但工具名不决定项目身份。
- 标准库实时正文检索给路径、标题、行号和片段，不建立需用户维护的数据库。新增正文即时参与；默认排除历史、原材料、Skill源码及已登记停用方法。候选仍需适用性判断，不是自动生效规则。
- 可选正文包实际读取计划文件，记录SHA256；缺失和超预算明确列为待续读，不以摘要冒充全文。默认计划不声称AI已理解。
- 成品计划提供检查模式；执行卡将来源、采用动作、实际检查位置与结果关联。学员资料默认learner，内部备课和对外方案另分；最终交付仍须检查实际成品。
- 写入流程增加自然任务正例与不适用反例，由AI维护入口和回归，用户只提供经验及归属。

## 同时发现的当前口径错误

协作心法第3课曾错误列在“配套文章”表，已移回课程表；技术词典与协作心法的待确认残留按2026-09-17本人确认统一。保留原正文核验日期，不声称本次重新读取飞书，也不推定授课日期。

GitHub readme API在修复前返回.github/README.md，说明根首页确被该文件优先级遮住；此前仅改其标题未解决根内容展示。移除重复README，将工作流说明留在维护入口、配置保留原位，并加入废弃路径校验防止重现。

## 验证与边界

新增自然任务、目录范围、新增方法检索、停用/历史排除、正文完整性、预算和受众检查回归，结合既有项目、课程、方法及成品检测正反例运行。测试只证明这些输入与读取/检查行为，不证明所有模型都执行流程，也不冒充真实发布、教学或运营效果。

本地92项回归通过，仓库校验0错误；保留EditaPlot上游快照34组重复内容警告。实际CLI正文包回放：秒哒大视频上传13份／39196字符，公众号文章8份／13543字符，培训分享7份／17337字符，三次计划正文均完整装入；培训包确实包含学员视角和讲师安排排除要求。正文数量只用于核对本次读取覆盖，不作为质量指标。新增正文可发现的测试使用临时新方法，未给它新增路由关键词配置。

调用者仍须能实际访问仓库并执行入口规则。后续若再出错，保留任务描述、仓库版本、实际读取正文、执行卡与最终错误片段，区分没检索到、没读完、选错规则、执行遗漏或验收遗漏，修复对应环节。
