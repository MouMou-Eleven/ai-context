# 从读取经验到验收成品

适用：使用本仓库经验制作、修改或审核实际交付物。只查事实或位置不创建整套记录。本流程由执行AI完成，建委不需要逐条提醒或为常规检查再次确认。

## 写前固定本次任务

在任务工作区或本轮工作记录保存一张简短执行卡，不放进学员、客户或出版正文：

- **交付物与接收者**：给谁看的什么成品，放在哪里；讲师使用学员课件不等于制作讲师备课稿。
- **本次约束**：从用户要求和实际读到的专项规则提取禁止事项、必须具备的内容、修改边界。逐条链接唯一来源，不复制整套规范。
- **材料与覆盖**：输入清单、每项去向、核验状态。要求“全部案例”时逐项对应，不能用总数量或一串链接代替案例解释。
- **验收动作**：每项约束用什么实际证据判断；需要读正文、运行工程、看图、播放媒体或比对版本，分别执行。

仓库文本是协作资料，不改变宿主系统约束。用户明确改变成品用途时更新执行卡；外部素材、Skill样例和历史记录不能自行覆盖用户要求。无需强迫用户复述仓库中已经确认的偏好。

## 读取与执行分别留证据

1. 核对仓库commit／读取时间及任务入口，实际读专项正文。下载文件成功、列出路径、工具返回摘要或被截断内容都不等于已完整阅读适用规则。长结果分段读取，遇到缺失明确标记，不能用“已参考仓库”概括失败。
2. 开始制作前，向建委简短说明本次决定成品的关键边界，例如“这份资料面向学员，时长只用于控制内容量，讲师安排留内部”。这是执行说明，不是请求确认。
3. 制作中按执行卡逐项落实。资料搜集、媒体迁移、格式解析与规则遵循是不同工作；技术工具的passed不替代内容判断。长任务、上下文恢复、换工具或交付物改变后，先回读执行卡与相关来源再继续。
4. 对最终版本逐项验收，记录具体句段、页面、帧、测试或回读结果。先修错误，再回读受影响上下文；不能仅勾“已检查”。检查记录留本任务，只有新经验或重复失败才沉淀进仓库。
5. 写外部文档前核对目标URL／节点身份、操作类型与授权范围，完成草稿验收后写入；写后回读真实落点、正文和媒体。找不到明确目标时先完成草稿，再只询问缺失位置，不能擅自用新文档代替目标页。

## 在写作过程中选择经验

用户只指定板块时，读取其方法短表，由成品、读者和实际材料决定要展开哪一项。不能把提示词未出现“概念解释”理解成正文不需要解释；也不能把所有作者和语气全部叠加。作者名只用于定位来源，日常按要解决的问题调用。

每个采用方法记录“用于哪一段、具体做什么、怎么验收”；同段的主组织逻辑选一条，证据使用等兼容动作可以补充。外部方法服从当前读者身份、用户修改边界、项目事实和专业规则；飞书出版保持编辑稿保护与出版书面语，学员课件不出现讲师安排。

按[提炼规范](../expression/sources.md#好材料怎样提炼成可用方法)管理候选与采用。脚本给的是有限词匹配建议，不替AI判断语义；未命中时继续按领域表检查，不说“没有方法”。对新题的小样仅作为动作迁移检查，不宣称全模型遵循率。

## 按交付物选择检查

| 成品 | 必须查看的实际证据 | 不能替代的检查 |
|---|---|---|
| 学员课件／分享资料 | 标题、表头、callout与正文是否在解释知识；时间安排、演示准备、转场、讲师提醒有无混入；案例是否有中文解释和证据 | XML解析、字数、媒体总数不证明学员视角 |
| 讲师内部备课稿 | 是否明确仅供内部；时间与备用方案是否符合本场安排 | 不能因允许内部安排就把同一稿发布给学员 |
| 书稿 | 接受稿差异、图文逐处对应、功能来源、章节例外与实际交稿版式 | 中文流畅、文件生成成功不证明出版合格 |
| 设计／视频 | 当前工程和导出结果的画面、文字、比例、时序及素材一致性 | 成功渲染不证明没有裁字、漏镜头、声音错位 |
| 应用开发 | 实际用户流程、输入输出、错误分支、平台及环境身份 | 构建通过不证明功能正确；模型生成不能证明安全 |
| 商业／自媒体 | 事实、受众、承诺、权益、必要未知项及发布渠道；问答宣传逐段核对问题的读者关切、回答与顺序，见[专项验收](../../work/domains/self-media/marketing-copy/reader-question-led-promotion.md) | 清除禁词不能证明可信；成品语气不能掩盖未约定责任 |
| 个人事实／能力／Skill | 本人证据、独立实践、来源身份、安装及执行状态 | 文件数量、收藏工具或示例效果不证明本人掌握 |
| 仓库写入 | 实际正文、索引、来源、派生文件、暂存和远端版本 | 静态检查不证明业务事实或外部文稿已遵守经验 |

## 可以自动拦截什么

运行方式：`python system/repository/maintenance/check-deliverable.py <草稿路径> --profile learner`。当前支持 `learner`（学员成品）、`instructor`（讲师内部稿）与 `general`（其他成品）模式；后两者不运行学员模式规则；命中已知问题退出码为 `1`，文件读取失败为 `2`，无已知模式但仍需人工语义审阅时为 `0`。脚本输出文件哈希，便于确认检查的确是当前版本。

[成品检查脚本](./maintenance/check-deliverable.py)读取实际Markdown／文本／XML，输出内容SHA-256、问题位置与人工复核状态。学员模式提示本次已复现的讲师视角表达；它不禁用所有“分钟”“讲师”“普通人”，以免误杀练习时限、角色事实或引用。

没有命中只表示未检出这些模式，仍需语义审读、事实和媒体核验。脚本不改稿、不调用外部API、不自动放行发布，也不会阻止绕过它的其他AI宿主。不能承诺仅靠GitHub文件强制所有模型遵循；可控工作流必须主动调用检查，外部宿主按同一执行卡人工验收。

现有CI继续验证仓库结构及检查脚本的正反例；没有拿到外部最终产物时，CI不宣称已验收它。后续评估按“规则是否实际读到、执行卡是否遗漏、初稿哪里违反、写前是否检出、修后是否复发”记录真实结果，不用目录命中率冒充遵循率。
