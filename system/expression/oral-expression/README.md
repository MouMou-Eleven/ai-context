# 口语化表达

> 面向朗读、口播、直播、授课讲解和真实交流。口语化只改变表达形式，不降低事实与逻辑要求。

## 唯一位置与使用边界

所有跨领域通用的口语表达规则、口语推进和口语化论证方法统一放在本目录。`README.md` 是通用规则入口，[`spoken-argument-and-transition.md`](./spoken-argument-and-transition.md) 是论证、举例和前后承接方法；不得把同一套口语规则复制到 AI 培训、AI 自媒体或其他领域目录。

本目录只控制“怎样说得自然、清楚、能听懂”。

- AI 培训目录补充课堂主文档的学员视角、课程承接、讲解顺序和讲师/学员边界。
- AI 自媒体目录补充平台目标、选题、脚本节奏、销售承接和行动设计。
- 书稿、教程和正式文档是否使用书面表达，由 [`../written-expression/README.md`](../written-expression/README.md) 和对应领域规则决定。

同一段内容同时属于培训或自媒体时，先调用本目录的通用口语规则，再调用对应领域的专项规则；不要把两个领域的表达方法混写成一套。

## 适用特征

- 句子短一些，先说人能听懂的动作和结果，再补概念。
- 可以有自然停顿和转折，但每次转折都要服务于理解。
- 使用“先说结论”“真正卡住的地方是”“你可以先这样判断”等自然连接。
- 允许保留真实的判断、失败过程和限制，不把内容写成完美宣传稿。
- 术语出现时先用场景解释，再给出术语名称。

## 不要这样写

- 不用连续语气词、感叹号、网络黑话制造“像真人”的假象。
- 不用“大家都知道”“一定可以”“轻松解决”替代证据。
- 不把书面长句直接切碎，也不把口语稿写成客服或广告腔。
- 不用“接住”“赋能”“闭环”等万能词掩盖具体动作。

## 口播检查

1. 第一段是否说明真实场景或判断，而不是空泛问候。
2. 每句话是否能自然朗读，主语和动作是否清楚。
3. 观众听完这一段后，是否知道下一步理解什么或做什么。
4. 画面文字是否只保留精华，旁白是否补充原因、场景和边界。
5. 结尾是否完成本段目的：观点与记录可自然收束；确有练习、报名、领取或购买目标时，再保留一个清楚且可执行的主行动，不为所有口播强加 CTA。

## 调用方法

- 需要检查自然口语、句子节奏、主语和动作时，读取本 README。
- 需要设计观点推进、举例、反问、段落承接或结论落点时，读取 [`spoken-argument-and-transition.md`](./spoken-argument-and-transition.md)。
- 需要写 AI 培训或 AI 自媒体时，再分别读取对应目录；本目录不保存课程事实、平台规则、销售话术或个人经历。
