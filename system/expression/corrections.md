# 中文纠错与真实反馈提炼

本表提炼仓库已有培训、书籍编辑和商业交付反馈，同时保留基础语法检查。来源编号见本文件末尾的[来源表](#来源表)；建议改法是方法示例，不冒充客户认可稿或原始逐字改稿。写前先用[短卡](./README.md)，不必每次加载本表。

## 高频问题与修正

| 问题与识别线索 | 修正动作与示例 | 范围与来源 |
|---|---|---|
| 报告腔代替现场解释；“课堂要看什么”、讲师转场混进学员正文 | 改成学员要理解的动作、变化、原因。把“课堂要看什么”移为内部提醒，正文直接解释对应对象与判断 | 培训反馈T1；专业书面文章仍可用正式语言，不把“拒绝书面化”升为所有文体规则 |
| 抽象动词搭配空泛：“赋能业务”“构建能力闭环”“提升体验”却没有内容 | 问清主体、动作与结果，再依事实改为“核对缺失字段后再提交”等具体说明。若上下文已定义闭环、赋能等概念且有必要，可保留 | T2与共享纠偏G1；不是全局禁词表，示例不构成实际项目事实 |
| 不自然的比喻，或用空间动作含糊代替实际操作：“把问题接住”“先把话说稳一点”；栏目表头写“适合什么时候来” | 先明确对象和动作。文档、栏目、资料的说明应写清查看、阅读、下载或提问；表头按列内容写“适合什么时候查看”或“能够帮助你什么”。“来／走”等词不能为追求口语化替代具体动作。逐个表头连同行内容读一遍，确认搭配自然、用途明确，再检查正文同类表述 | G1、G3；G3为建委明确要求长期采用的真实反馈。适用于说明性标题、导航、表格和操作指引；真实到访、方向移动、自然邀请及必要文学修辞不机械禁用“来／去” |
| 表面专业，实际上省略关键判断与执行步骤 | 书稿补对象、入口、动作、预期结果、权限或失败分支；方案补真实责任与验收。菜单和参数必须查证，不用“按需配置”遮住未知 | 出版B1、B2；通用原则是信息足够，步骤详度由体裁和读者决定 |
| 同义反复、每段都总结、图表复读正文 | 比较相邻段落新增了什么：保留原因、关系、异常或下一步；只换说法的删合。图表有比较或定位作用再用 | T1、B1、B2；不规定每段必须有例子或每页几张图 |
| 导语许诺很多，正文没解释；术语、案例突然换对象 | 检查承诺能否在正文找到依据，保持案例对象连续；跨节用真实问题关系衔接 | B1；“不是X而是Y”只在确需纠正误解时用，不作为固定段落句式 |
| 为显得像正式稿，删除重要“待确认” | 区分内部制作提醒与影响履约、范围、权利的未定项。前者移出正文，后者准确写明“交付日期尚未约定”等实际状态 | 商业C1；示例非真实合同约定。不得把“请客户确认”机械替换成确定承诺 |
| 为显得像人，堆“然后、其实、就是说”，或编造第一人称经历 | 依听觉节奏整理主干，必要承接保留；个人体验必须有来源，无材料就用中性解释 | T1、O1、G2；正式文件不强加口头禅，创意口播也不抄外部作者个人故事 |
| 一律使用成果开头、痛点、反问、金句或销售结尾 | 先看这份内容是在解释、叙事、记录还是转化。需要行动时写真实承接；无需行动可在观点说完时结束 | 自媒体M1与2026-09-12确认G2；短视频经验不能约束合同、书稿或纯教学 |
| 问句和选项不对应，“其他／不适用”含义不明 | 逐项读成回答，例如问“是否自备电脑”，选项“会自备／不自备”；确需其他项时说明覆盖什么 | G1；不能为了简化删掉真实必要的分支 |

## 基础中文检查

| 检查 | 如何修正 |
|---|---|
| 错字、漏字、多字、专名、数字与单位 | 对照原资料和适用版本；不因自动纠错改产品名或代码标识 |
| 主谓、动宾与修饰关系 | 找句子主干，确认谁对谁做什么；如“通过修改，使文档……”可依上下文补主语，但不能猜执行者 |
| 成分残缺、重复、词序与句式杂糅 | 补有依据的对象或条件，删同义成分；“原因是……造成的”选择一种结构，不改变因果 |
| 指代、否定、范围、比较与逻辑 | 明确“它／这／后者”所指，检查双重否定、前后条件是否一致、相关性是否被写成因果 |
| 翻译腔与名词堆叠 | 将无必要的“进行……的实现”改为明确动作；真正的技术术语保留并按读者需要解释 |
| 标点、括号、层次、中英文与术语一致 | 遵守适用出版／渠道格式，检查不闭合括号、并列层级和数字单位；不凭一般排版建议破坏已接受编辑稿 |
| 过度修订 | 对比改前改后：是否改变原意、丢失限制、增加承诺、损失有意节奏；只改可指出问题的句段 |

基础分类参考F1—F8。它们擅长提醒可检查的错误，不能证明文章有经验、有判断或像真人；后者要读完整成品与真实反馈。

## 使用和更新

发现对应失误，先核源事实与体裁，再执行表内动作并回读上下文。候选改法不全盘叠加；正式稿先对照[底线卡](./README.md)，口播对照[口语样稿](./voice-samples.md)。新反馈补到同一问题行与[来源表](#来源表)，保留适用和排除条件；领域专属细节仍由领域维护。

## 好材料怎样提炼成可用方法

建委只需提供材料、指出喜欢的地方或指定沉淀板块；下面的整理、归属、入口与校验由执行AI完成。目标是学会一种解释、组织或表达方法，不默认建立某位作者的人格或全套文风。

先分清要学什么：解释逻辑、信息结构、证据使用、语言节奏、图文配合可以分别提炼；作者个人立场、商业结论、时代事实与本人经历不能直接成为建委的观点或新任务事实。只喜欢某一段解释，不扩大成喜欢整位作者的所有风格。

### 最小记录写在原领域的方法正文中

每条新增方法保留下列信息，可用一张短表或一段结构化文字，不要求每项拆文件。支持已有方法的材料补证据，不另建作者目录或同义文件。

| 项目 | AI需要写清 |
|---|---|
| 来源与样本范围 | 作者或材料身份、可定位链接／版本／片段、日期；读了几篇、是否完整、图是否实际查看，未知信息明确保留 |
| 喜欢或要修正的点 | 建委确认的是哪种用途、哪段写法；区分原文观察、AI推断和用户认可 |
| 要解决的读者问题 | 谁遇到什么理解或表达困难，不以作者姓名代替适用场景 |
| 方法动作 | 从材料的具体做法提炼步骤，说明为什么可能有用；统计特征不自动成为写作配额 |
| 适用与排除 | 体裁、读者、目的、适用环节；哪些场景会过长、跑题或冲突 |
| 最小示例与反例 | 原片段或忠实概述、方法变换、一个不能照用的场景；新写演示标明是示例，不能冒充用户实战结果 |
| 状态与证据 | 候选／当前采用／停用，谁在何时确认、验证到哪里；单次认可不等于跨场景有效 |
| 成品验收 | 看哪句、哪段、哪张图能判断动作发生，失败时修改哪个环节 |

### 按学习目标选择材料量

- 学一项局部方法：一篇完整材料或上下文足够的片段也能提出候选。先保留原用途与边界；建委明确认可可在限定范围采用，不宣称已还原作者完整风格。
- 判断作者的稳定习惯：需要覆盖不同题材、时间与成品类型，并排除同文转载和不同修订的重复计数。样本不足就缩小结论，不用固定“20篇”当充分性证明。
- 句长、标点或词频仅在确需比较语言风格时统计。记录切分、分母与缺失项；不能把某主题高频词写成任何主题都要使用的词表。
- 图片承担论证或演示时必须实际看对应图；纯文本不能推断字体、颜色、截图细节。缺图先标缺失，不凑视觉风格文件。
- 作者材料只用于提炼动作与必要来源定位；公开仓库不默认复制整批原文。需要校准才按相关性展开少量片段，不为每次写作固定读五篇原文。

### 候选到采用，再到纠错

新材料先对照已有方法。AI新推导、未被确认的做法留候选，只有用户明确认可其适用范围，或取得独立任务复用及实际验收证据后才标为当前采用。当前采用表示仓库可在该范围建议调用，不表示效果已有统计保证。

新方法至少做一次不同题目的小样与一个不适用场景检查；样例只检查动作能否迁移，不能称盲测。后续有真实成品时记录输入、采用段落、用户反馈和失败处。信息正确、受众正确先于文风相似；违反事实或读者身份时直接修订，不拿“更像某作者”抵消。

成熟方法的触发条件登记到[现有路由](../repository/navigation/routes.json)的methodRules，生成相关README短表和任务指南。正文、来源、状态只在对应位置维护；变更后检查索引、停用状态和正反例，不给建委增加一份维护表。常规新增方法沿用登记与生成，不为每位作者改脚本。

## 后续反馈怎样进入规则

1. AI在原项目／领域记录实际问题句、修改后文本（如果已有）、用途、用户反馈日期与依据；未知认可状态不得补为认可。正文只存一份。
2. 找到纠错表已有同类问题就补该行证据，优先修正读取入口、执行或验收漏洞；不为每次失败另建同义文件。
3. 单次特例留项目；多任务反复出现或建委明确要求长期执行时，提炼“错误类型—修正动作—适用／排除范围—来源—验收”。缺反复验证但值得试用的标为候选，不默认激活。
4. 若新规则涉及结构与语气，检查培训、出版、自媒体、正式交付四种边界。能兼容的合并，互为选项的限定条件，不能平均拼接多位作者文风。
5. 更新本文件的问题行和来源表；只有高频通用底线变化才改[底线卡](./README.md)。以真实成品和反馈评估是否有效，方法示例不作实战效果证据。
