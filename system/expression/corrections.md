# 中文纠错与真实反馈提炼

本表提炼仓库已有培训、书籍编辑和商业交付反馈，同时保留基础语法检查。来源编号见[来源表](./sources.md)；建议改法是方法示例，不冒充客户认可稿或原始逐字改稿。写前先用[短卡](./README.md)，不必每次加载本表。

## 高频问题与修正

| 问题与识别线索 | 修正动作与示例 | 范围与来源 |
|---|---|---|
| 报告腔代替现场解释；“课堂要看什么”、讲师转场混进学员正文 | 改成学员要理解的动作、变化、原因。把“课堂要看什么”移为内部提醒，正文直接解释对应对象与判断 | 培训反馈T1；专业书面文章仍可用正式语言，不把“拒绝书面化”升为所有文体规则 |
| 抽象动词搭配空泛：“赋能业务”“构建能力闭环”“提升体验”却没有内容 | 问清主体、动作与结果，再依事实改为“核对缺失字段后再提交”等具体说明。若上下文已定义闭环、赋能等概念且有必要，可保留 | T2与共享纠偏G1；不是全局禁词表，示例不构成实际项目事实 |
| 不自然的比喻：“把问题接住”“先把话说稳一点” | 按原意写“判断下一步”“解决报错”“先说清已确认的结论”。只有语境确实需要且读者能理解的修辞才保留 | G1，来源是已有纠偏记录；没有原始逐句确认凭据，不标为本人原话 |
| 表面专业，实际上省略关键判断与执行步骤 | 书稿补对象、入口、动作、预期结果、权限或失败分支；方案补真实责任与验收。菜单和参数必须查证，不用“按需配置”遮住未知 | 出版B1、B2；通用原则是信息足够，步骤详度由体裁和读者决定 |
| 同义反复、每段都总结、图表复读正文 | 比较相邻段落新增了什么：保留原因、关系、异常或下一步；只换说法的删合。图表有比较或定位作用再用 | T1、B1、B2；不规定每段必须有例子或每页几张图 |
| 导语许诺很多，正文没解释；术语、案例突然换对象 | 检查承诺能否在正文找到依据，保持案例对象连续；跨节用真实问题关系衔接 | B1；“不是X而是Y”只在确需纠正误解时用，不作为固定段落句式 |
| 为显得像正式稿，删除重要“待确认” | 区分内部制作提醒与影响履约、范围、权利的未定项。前者移出正文，后者准确写明“交付日期尚未约定”等实际状态 | 商业C1；示例非真实合同约定。不得把“请客户确认”机械替换成确定承诺 |
| 为显得像人，堆“然后、其实、就是说”，或编造第一人称经历 | 依听觉节奏整理主干，必要承接保留；个人体验必须有来源，无材料就用中性解释 | T1、O1、G2；正式文件不强加口头禅，创意口播也不抄外部作者个人故事 |
| 一律使用成果开头、痛点、反问、金句或销售结尾 | 先看这份内容是在解释、叙事、记录还是转化。需要行动时写真实承接；无需行动可在观点说完时结束 | 自媒体M1与2026-09-12确认G2；短视频经验不能约束合同、书稿或纯教学 |
| 问句和选项不对应，“其他／不适用”含义不明 | 逐项读成回答，例如问“是否自备电脑”，选项“会自备／不自备”；确需其他项时说明覆盖什么 | G1；不能为了简化删掉真实必要的分支 |

## 基础中文检查

| 检查 | 如何修正 |
|---|---|
| 错字、漏字、多字、专名、数字与单位 | 对照原资料和适用版本；不因自动纠错改产品名或代码标识 |
| 主谓、动宾与修饰关系 | 找句子主干，确认谁对谁做什么；如“通过修改，使文档……”可依上下文补主语，但不能猜执行者 |
| 成分残缺、重复、词序与句式杂糅 | 补有依据的对象或条件，删同义成分；“原因是……造成的”选择一种结构，不改变因果 |
| 指代、否定、范围、比较与逻辑 | 明确“它／这／后者”所指，检查双重否定、前后条件是否一致、相关性是否被写成因果 |
| 翻译腔与名词堆叠 | 将无必要的“进行……的实现”改为明确动作；真正的技术术语保留并按读者需要解释 |
| 标点、括号、层次、中英文与术语一致 | 遵守适用出版／渠道格式，检查不闭合括号、并列层级和数字单位；不凭一般排版建议破坏已接受编辑稿 |
| 过度修订 | 对比改前改后：是否改变原意、丢失限制、增加承诺、损失有意节奏；只改可指出问题的句段 |

基础分类参考F1—F8。它们擅长提醒可检查的错误，不能证明文章有经验、有判断或像真人；后者要读完整成品与真实反馈。

## 使用和更新

发现对应失误，先核源事实与体裁，再执行表内动作并回读上下文。候选改法不全盘叠加；正式稿与口播分别读[书面](./written.md)或[口语](./oral.md)。新反馈补到同一问题行与来源表，保留适用和排除条件；领域专属细节仍由领域维护。
