# 表达与成品验收

本流程用于成品审核、复杂改稿、重复失误排查和模型变化后的对照。简单回复按[短卡](./README.md)检查即可。AI负责完成复核和修订，不要求建委逐项提醒，也不在每份最终正文后附一张冗长自评表。

## 两项验收分别进行

1. **读取是否完整**：实际记录所读入口、主要体裁、必要专业规则与项目事实版本。路由返回路径只是读取建议，不能当作已阅读的证据。
2. **成品是否合格**：直接检查最终文字与资料，给出具体句段或缺漏位置；不能用“已读取规范”“测试通过”代替作品检查。

## 成品怎么检查

| 检查项 | 可执行动作 | 不通过时怎样处理 |
|---|---|---|
| 事实与原意 | 将姓名、数字、角色、条件、结论和效果逐项对照来源；改稿比较是否扩大承诺或删掉限制 | 修正已知错误；关键未知项保留为工作稿问题，不通过润色变成已确认 |
| 读者与体裁 | 对照[体裁入口](./genres.md)，检查接收者是否拿到所需信息；区分学员正文、出版段落、个人动态与内部说明 | 修正视角和结构；必要信息没有依据时标缺口 |
| 专业完整性 | 按该领域验收项核对前提、判断、步骤、例外、证据与结果，不以术语多少评价专业性 | 补有依据的内容，删除无用铺垫；不能发明流程、界面或行业事实 |
| 自然与连贯 | 口语逐段朗读；书面逐段检查主语、指代、承接和逻辑。指出具体难读句或跳步 | 重写有问题句段，保持原意；不把所有句子机械改短 |
| 信息与呈现 | 检查相邻段落、标题、表格、画面和旁白各增加了什么 | 合并同义重复；媒体只补必要理解，不追求固定数量 |
| 语气与身份 | 个人署名稿对照已认可样稿；专业文书对照体裁要求。检查是否编造第一人称经历或借用外部作者口头禅 | 无个人样稿时只遵守已确认偏好，不宣称已经模仿本人 |

检查结论只用`通过`、`需要修改`、`资料不足`或`不适用`，并说明关键依据。不以AI味检测分数、字数、标题数量或禁词命中数代替判断。自动规则只能提示可检测问题，不能证明专业性和自然度。

## 复核步骤

1. 锁定同一份任务材料和事实清单，确认主要成品与必须保留的原意。
2. 生成或修改内容；将内部推敲与接收者正文分开。
3. 先核事实，再核体裁和专业完整性，最后检查语句、重复和呈现。
4. 修正后回读受影响部分及前后关系；有新事实、新歧义或跨段改动时再扩大检查范围。
5. 交付最终稿；仅报告影响使用的缺口和需建委决定的事项。不得把尚未核验内容称为正式定稿。

## 用对照改进规则

可用同一真实材料分别写成目标体裁进行对照，检查具体句段；[纠错表](./corrections.md)的建议改法只演示方法，不能证明真实项目效果。实际评估时保存输入、输出、日期、规则版本、执行模型（可获得时）、检查问题和依据，项目结果留项目；通用规则只记录提炼结论与来源链接。

| 样本类型 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 合成示范 | 解释规则、演练条件和输出差异 | 建委认可、真实授课效果、法律/行业有效性 |
| AI按标准审读 | 本轮发现的具体问题与修订依据 | 建委本人认可或独立专业审定 |
| 建委明确认可稿 | 该成品与确认范围内的偏好依据 | 所有体裁的统一个人口吻 |
| 真实交付反馈 | 该项目、受众与版本下的结果 | 无条件通用于其他客户、账号或课程 |

同一错误再次出现，先定位是没找到规则、没实际读、理解错误、执行不到位、验收漏项还是规则条件不合适。修正唯一规则或入口，并更新对应检查；不要再加一份同义“严禁”。新规则经重复任务验证或建委确认后才提升为通用默认，单次经验可先作为候选保留。
