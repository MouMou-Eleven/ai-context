# 表达与成品标准

所有中文成品都要守住的底线。**这里不是写作方法的主来源**：写课件、方案、文章、脚本时，先按 [AGENTS.md](../../AGENTS.md) 的任务表读对应领域的方法，领域里的规则优先。本目录只补两样东西：建委的说话方式（口语样稿），和所有体裁都不能犯的错。

> 为什么这样分：以前的做法是"通用表达规则＋领域规则"叠加，实际效果反而不如只用领域经验。原因是两套规则都很长、有重叠、偶尔还说法不一，AI 不知道听哪个。所以现在领域规则说了算，这里只留底线。

## 底线短卡（所有中文成品）

1. **先弄清读者和用途**：给谁看、看完要做什么。给学员的、给讲师的、给主办方的、给潜在客户的，是四种东西。
2. **说具体的**：谁做什么、对什么起作用、得到什么结果。删掉没有新信息的客套、套话、重复总结、机械排比。"赋能业务""构建闭环""提升体验"这类词，后面没有具体内容就删掉或改具体。
3. **不编**：不编经历、数字、荣誉、客户、效果。荣誉和数字只按[背书表](../../personal/credentials.md)写。不确定的写"待确认"，不要为了显得正式把它删掉。
4. **语法过一遍**：主谓搭配、指代清楚、因果对得上、问句和选项对应。
5. **读一遍再交**：口语稿出声读，书面稿看上下文是否连贯。

## 要"像建委说话"时

讲课、口播、社群、朋友圈、招生宣传，先读**[建委口语样稿](./voice-samples.md)**。那里有建委本人认可的原文和共同特点，比任何规则描述都准。

## 冲突时

## 写入

建委给了新的满意样稿，加进 [voice-samples.md](./voice-samples.md)。某个错误在不同领域反复出现，才写进 [corrections.md](./corrections.md)；只在一个领域出现的，写进那个领域。
