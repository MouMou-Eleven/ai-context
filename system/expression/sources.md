## 好材料怎样提炼成可用方法

建委只需提供材料、指出喜欢的地方或指定沉淀板块；下面的整理、归属、入口与校验由执行AI完成。目标是学会一种解释、组织或表达方法，不默认建立某位作者的人格或全套文风。

先分清要学什么：解释逻辑、信息结构、证据使用、语言节奏、图文配合可以分别提炼；作者个人立场、商业结论、时代事实与本人经历不能直接成为建委的观点或新任务事实。只喜欢某一段解释，不扩大成喜欢整位作者的所有风格。

### 最小记录写在原领域的方法正文中

每条新增方法保留下列信息，可用一张短表或一段结构化文字，不要求每项拆文件。支持已有方法的材料补证据，不另建作者目录或同义文件。

| 项目 | AI需要写清 |
|---|---|
| 来源与样本范围 | 作者或材料身份、可定位链接／版本／片段、日期；读了几篇、是否完整、图是否实际查看，未知信息明确保留 |
| 喜欢或要修正的点 | 建委确认的是哪种用途、哪段写法；区分原文观察、AI推断和用户认可 |
| 要解决的读者问题 | 谁遇到什么理解或表达困难，不以作者姓名代替适用场景 |
| 方法动作 | 从材料的具体做法提炼步骤，说明为什么可能有用；统计特征不自动成为写作配额 |
| 适用与排除 | 体裁、读者、目的、适用环节；哪些场景会过长、跑题或冲突 |
| 最小示例与反例 | 原片段或忠实概述、方法变换、一个不能照用的场景；新写演示标明是示例，不能冒充用户实战结果 |
| 状态与证据 | 候选／当前采用／停用，谁在何时确认、验证到哪里；单次认可不等于跨场景有效 |
| 成品验收 | 看哪句、哪段、哪张图能判断动作发生，失败时修改哪个环节 |

### 按学习目标选择材料量

- 学一项局部方法：一篇完整材料或上下文足够的片段也能提出候选。先保留原用途与边界；建委明确认可可在限定范围采用，不宣称已还原作者完整风格。
- 判断作者的稳定习惯：需要覆盖不同题材、时间与成品类型，并排除同文转载和不同修订的重复计数。样本不足就缩小结论，不用固定“20篇”当充分性证明。
- 句长、标点或词频仅在确需比较语言风格时统计。记录切分、分母与缺失项；不能把某主题高频词写成任何主题都要使用的词表。
- 图片承担论证或演示时必须实际看对应图；纯文本不能推断字体、颜色、截图细节。缺图先标缺失，不凑视觉风格文件。
- 作者材料只用于提炼动作与必要来源定位；公开仓库不默认复制整批原文。需要校准才按相关性展开少量片段，不为每次写作固定读五篇原文。

### 候选到采用，再到纠错

新材料先对照已有方法。AI新推导、未被确认的做法留候选，只有用户明确认可其适用范围，或取得独立任务复用及实际验收证据后才标为当前采用。当前采用表示仓库可在该范围建议调用，不表示效果已有统计保证。

新方法至少做一次不同题目的小样与一个不适用场景检查；样例只检查动作能否迁移，不能称盲测。后续有真实成品时记录输入、采用段落、用户反馈和失败处。信息正确、受众正确先于文风相似；违反事实或读者身份时直接修订，不拿“更像某作者”抵消。

成熟方法的触发条件登记到[现有路由](../repository/navigation/routes.json)的methodRules，生成相关README短表和任务指南。正文、来源、状态只在对应位置维护；变更后检查索引、停用状态和正反例，不给建委增加一份维护表。常规新增方法沿用登记与生成，不为每位作者改脚本。

## 后续反馈怎样进入规则

1. AI在原项目／领域记录实际问题句、修改后文本（如果已有）、用途、用户反馈日期与依据；未知认可状态不得补为认可。正文只存一份。
2. 找到纠错表已有同类问题就补该行证据，优先修正读取入口、执行或验收漏洞；不为每次失败另建同义文件。
3. 单次特例留项目；多任务反复出现或建委明确要求长期执行时，提炼“错误类型—修正动作—适用／排除范围—来源—验收”。缺反复验证但值得试用的标为候选，不默认激活。
4. 若新规则涉及结构与语气，检查培训、出版、自媒体、正式交付四种边界。能兼容的合并，互为选项的限定条件，不能平均拼接多位作者文风。
5. 更新纠错表、来源表和必要体裁入口；只有高频通用底线变化才改短卡。以真实成品和反馈评估是否有效，方法示例不作实战效果证据。
