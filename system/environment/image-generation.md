# 本机生图调用规则

> 来源：建委在2026-09-12本轮提供的AGENTS.md环境指令。
> 状态：用户确认的环境配置，本轮未检查凭据、未执行生图、未验证运行结果。
> 适用设备：本轮所称“本机”；尚未确认它对应设备档案中的哪台电脑，不自动归入“台式电脑1”。新设备先核对配置，不能直接继承为已验证事实。

## 调用

- 建委要求生图、画图、生成图片或视觉概念时，通过启动器 `~/.codex/skills/imagegen/scripts/imagegen.cmd` 调用imagegen CLI。
- 启动器默认模型已配置为 `gpt-image-2`，不需要另外传 `--model`。
- 禁止直接执行 `python image_gen.py`：用户说明全局 `OPENAI_API_KEY` 和 `OPENAI_BASE_URL` 已移除，直接调用会鉴权失败。
- 禁止使用Codex内置ImageGen：用户说明该通道经过cc-switch官方通道，本机曾返回上游400/401。
- 生图使用aiwanwu直连；凭据由启动器内部配置，不经过cc-switch。按用户配置说明，cc-switch切换官方或中转登录不会改变这条生图通道。

本卡只记录调用入口与环境边界。实际制作时再读取对应imagegen Skill的使用方法和本轮任务要求；查询配置或整理仓库不自动执行生图。

## 失败排查与维护

1. 新设备或路径失效时，先确认当前设备、启动器是否存在和相应CLI依赖，不读取其他电脑的凭据或照搬其配置。
2. 遇到“模型不存在”或鉴权失败，核对是否实际通过本卡启动器调用；再在本机安全核验启动器配置的凭据是否有效，以及密钥轮换、账户余额等情况。没有证据不推断原因，也不靠切换cc-switch或恢复全局密钥变量试错。
3. 不把启动器完整内容、API Key、Token或其他凭据打印到终端、对话、日志和Git；仓库只记录是否通过、脱敏错误类别、核验日期与处理结论。
4. 用户确认配置变化或完成实际核验后，同步本卡的来源日期、适用设备、调用入口和验证状态，再更新 [环境索引](./README.md)；设备映射确认后才关联对应 [设备档案](./computers/README.md)。
