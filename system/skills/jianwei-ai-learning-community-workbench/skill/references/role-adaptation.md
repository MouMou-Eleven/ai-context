# 身份适配与工作台骨架

本文件是通用推理方法，不是用户画像库。示例角色只用于说明如何提问；任何新身份都必须从真实工作任务推导，不得强行套用最近似的例子。

## Role Profile Schema

```yaml
role: 用户自称或可验证的角色
context: 工作或使用场景
primary_outcome: 近期最重要的可观察结果
deliverables: [主要交付物]
inputs: [资料、请求、数据或素材]
jobs:
  - job: 高频任务
    frequency: daily|weekly|occasionally
    friction: 当前阻力
decisions: [关键判断]
skill_level: beginner|intermediate|advanced|mixed
time_budget: 每次和每周可投入时间
collaborators: [协作者、客户、管理者、AI]
devices: [desktop, tablet, mobile]
constraints: [隐私, 网络, 无障碍, 合规, 预算]
success_metrics: [完成率, 交付数, 反馈闭环率, 周期]
```

## 角色到模块的推导示例

| 工作倾向 | 首要模块 | AI 辅助 | 关键指标 |
| --- | --- | --- | --- |
| 设计与创意 | 灵感、方案、版本、交付 | 研究、探索、检查、归档 | 交付周期、修改轮次 |
| 教学与辅导 | 备课、授课、反馈、资料 | 生成练习、批改初稿、总结 | 反馈时效、达标率 |
| 销售与客户 | 线索、跟进、方案、成交 | 摘要、提醒、方案草拟 | 响应时效、转化率 |
| 研究与分析 | 资料、证据、分析、引用 | 检索、归纳、对比、校验 | 证据完整度、分析周期 |
| 内容与运营 | 选题、生产、发布、复盘 | 研究、改写、分发、复盘 | 产出数、复盘闭环率 |
| 管理与决策 | 目标、进度、异常、资源 | 趋势摘要、预警、决策记录 | 周期、目标达成率 |
| 自定义角色 | 以 `primary_outcome` 为中心 | 只启用与结果相关的能力 | 用户确认 |

## 模块选择规则

1. 首屏只放一个主任务和最多两个辅助任务；其余内容进入二级导航或稍后处理。
2. 每个模块必须定义对象、状态（未开始/进行中/待审阅/已完成/已归档）和空状态。
3. 用“下一步行动”替代只展示统计数字；统计必须能回到任务。
4. 协作、评论、分享和权限只在用户的真实工作需要时启用，不为“完整”而添加。
5. AI 功能按“建议 → 用户确认 → 执行 → 可追溯结果”设计，默认可关闭。
