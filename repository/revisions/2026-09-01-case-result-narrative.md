# 案例结果叙事方法入库修订

> 日期：2026-09-01
>
> 范围：跨行业商业经验、产品演示、直播销售、课程/社群招生、AI 自媒体和 AI 编程产品展示

## 一、修订原因

建委确认：案例演示不能只展示设计效果或功能，而应面向准确人群呈现真实痛点、可验证结果和未来可能的工作状态；案例还要承载建委的观点和叙事，并把结果与产品、课程或社群的真实机制连接起来。

## 二、当前结论

新增 `work/other/commercial/experience/case-result-narrative.md`，沉淀以下跨行业方法：

- 案例同时承担证明、映射、预览、论证和产品承接五个作用。
- 叙事顺序为：人群与场景 → 痛点与代价 → 观点 → 关键干预 → 前后结果 → 因果机制 → 产品连接 → 条件边界 → 下一步。
- “卖结果”指展示结果路径、进步和产品支持，不承诺所有人获得同样的收入、客户、播放量或效率。
- 结果必须说明证据类型、输入条件、人工参与、授权和样本限制。

## 三、路由变化

- 商业经验索引、商业总入口、`llms.txt` 和 `AGENTS.md` 增加案例演示触发词。
- AI 自媒体和直播销售仅在案例用于产品价值或商业承接时组合该文件，不自动激活 AI 培训。
- 付费社群项目在课程招生、直播案例和学员结果任务中引用该文件；价格、权益和项目事实仍以项目 README 为准。
- AI 编程总入口在产品答辩或 AI 应用商业演示时引用该文件；开发事实仍以编程工具和项目 README 为准。

## 四、清洗边界

- 不把用户的个人表达原样写入方法文件，不保存截图和未经授权的客户资料。
- 不把 PPT、AI 网站、会员社群等单一案例误写成行业普遍规律。
- 与 `content-demand-and-conversion.md` 的关系是互补：后者解决需求识别和内容承接，本文件解决案例如何证明、叙事和连接结果。
