# Remotion 内部导演加工、动作自然度与背景保真

## 背景

2026-09-05 对同一 `live-demo-title-remotion` 工程的两份 5 秒成片进行复核：自有 Skill 版本的布局已经基本还原，但动作偏单调；`motion-director` 版本通过徽章落位、图标冲击、局部响应和多关键姿态相机获得了更自然的动感。两版仍共同把参考图的深海军蓝背景提亮成灰蓝。

源码查证确认，两版共用的 `Stage.tsx` 使用 `shade(bgColor, 0.52)` 作为大面积径向渐变中心，导致背景向白色混合。针对三块无前景安全区进行实际像素检查，两版相对参考图的亮度差分别约为 `0.105 / 0.290 / 0.114`，全部超过新增的默认门槛 `0.05`。

## 新口径

- 用户简短提示仍先形成公开制作规划并等待确认；确认后、写代码前，在内部进行两遍二次加工，生成 `production-brief.json`。内部稿默认不展示给用户，但必须通过校验，且不得修改已批准文案、布局、背景和时长。
- 第一遍提取语义、视觉事实和不可变约束；第二遍形成驱动/预备、主变化、冲击或转折、支撑响应、回收归位的动作能量链，并检查死板单调、装饰替代动作、背景漂色和阅读冲突。
- 动作丰富度优先来自事件因果和速度状态变化，不来自新增无关粒子、星点、标签或全屏发光。
- 相机至少包含起点、强调点和目标帧归零点；相机响应主体事件，不能用一条从偏角到零的单调插值代替主体动作。
- 参考图背景与文字、排版、主体占比同为受保护事实。至少采样三个无前景区域的平均 RGB 和相对亮度，禁止以“科技蓝”“深色”文字猜色。
- 深色背景不得使用大范围正向 `shade()`、白色径向渐变、全屏雾化或曝光提升；局部事件光效必须在稳定区前衰减归零。

## 可执行变更

1. 新增 `prompt-expansion-contract.md`、`internal-production-brief.schema.json` 和 `validate_production_brief.py`，稳定不同模型对简单输入的二次导演加工。
2. 新增 `background-fidelity-contract.md` 和 `compare_background_regions.py`，把背景 RGB MAE 与亮度差变成预览交付前硬门槛。
3. `motion-blueprint.schema.json` 与 `validate_blueprint.py` 新增强制 `backgroundProfile`；公开 Blueprint 必须登记采样区、重建方式和动态限制。
4. 动作与质量契约新增主动作四阶段、多关键姿态相机、事件响应、单一冲击峰值和稳定区归零规则。
5. 低清预览仍优先于最终渲染；背景和动作门槛未通过时不得请求全量渲染确认。

## 影响

这次升级不改变既有的参考图几何锁定、参数化 Studio 编辑和两次确认流程。它补足了此前只检查前景构图、没有量化背景，也只要求“有动作”却没有判断动作自然度的缺口。
