# 2026-09-01 Remotion Skill 导演层与参数化默认输出修订

## 触发原因

建委实测 `motion-director` 后确认，其动画比现有 `jianwei-ai-community-remotion-video` 更自然、更有动效和观赏性。对比发现，现有 Skill 虽然具备确认门、逐元素动作契约、确定性和完整质量检查，但容易让模型先填写结构和技术字段，再补创意；同时 JSON 校验器要求时间轴严格首尾相接，实际禁止了自然动效常用的因果重叠。

## 对比结论

- `motion-director` 的优势不是更多技术规则，而是把一个记忆点、一处状态反差、一个干净收尾和目标最终帧放在最前面。
- 它要求建立、主动作、核心内容和细节在保持因果的前提下重叠，因此短片头更紧凑。
- 现有 Skill 的确认门、图片输入安全、逐帧确定性、Schema 和质量门槛仍然更适合作为长期稳定外壳，不应被替换或削弱。

## 新口径

- 先过导演门槛，再拆逐元素动作表。导演稿必须说明目标最终帧、状态反差、最值得记住的一秒和收尾回扣。
- 方案平淡时先升级动作逻辑、视觉隐喻或节奏，不得用更多装饰伪装完成度。
- 参考图默认是目标最终帧；任何改版差异必须在确认前列出。
- 静态标题、海报和图片头默认使用 4–5 秒；复杂信息确有需要时再扩展到 6–8 秒。
- 时间轴允许因果重叠。校验器改为要求从 0 秒起无空档覆盖总时长，不再要求后一段必须等于前一段结束时间。
- 默认输出改为参数化 Remotion 工程，并可渲染当前默认参数的 MP4。参数化至少覆盖主文字、画面中存在的编号和关键颜色。
- 参数化使用 Zod `z.object()`，颜色使用 `zColor()`；必须测试至少一组非默认参数。
- 明确区分：MP4 是参数快照，Remotion 工程才是可编辑载体。
- 只有用户明确选择固定值、硬编码或不可编辑成片时，才使用固定成片模式。

## 保留能力

- 规划确认后实施，不把详细需求视为直接授权。
- 逐元素触发、起始状态、路径、速度、因果、结束状态和确定性规则继续生效。
- 官方 Remotion Skills 与当前项目版本继续作为技术权威。
- 类型检查、代表帧、Studio 预览、渲染规格和完成报告继续作为交付门槛。

## 同步范围

- 更新 Skill 主入口、导演策略、图片分析、动效规则、输出契约、质量门槛和 Remotion 保守契约。
- 更新 Motion Blueprint JSON Schema 与验证脚本，增加导演字段、参数化契约和重叠时间轴语义。
- 更新 UI 默认提示词、条目 README 与 `upstream.json`。
- `workflowRevision` 提升为 3，默认输出模式固定为 `parameterized-remotion-project`。
- 同步 ai-context 权威快照、本机 Codex 安装目录与本地交付压缩包。
