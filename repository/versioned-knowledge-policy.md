# Versioned Knowledge Policy — 动态产品知识治理规则

> 状态：当前有效
> 确认日期：2026-08-02
> 适用对象：秒哒、飞书、Codex、AI 模型、平台 API、价格套餐、界面路径和其他会持续变化的产品知识。

## 核心原则

动态产品只能有一个“当前口径入口”。旧功能和新功能不能在同一个当前说明里并列成同等有效，也不能依靠 AI 自己判断哪一条更新。

历史不能无痕删除，但必须退出当前入口，只保存在明确标记的版本时间线、修订记录或历史目录中。

## 四种状态

| 状态 | 含义 | 能否作为当前答案 |
|---|---|---|
| 当前有效 | 已通过官方资料或实际环境核验，且未被更新取代 | 可以 |
| 待确认 | 有线索但缺少官方来源或实际验证 | 不可以写成确定事实 |
| 已被取代 | 曾经有效，已经有明确新口径 | 不可以；必须指向替代记录 |
| 历史材料 | 仅用于追溯过去方案、价格、界面或故障 | 不可以 |

## 产品知识目录标准

```text
<product>/
├── README.md                 当前入口、最新核验日期、读取顺序
├── <current-topic>.md        当前有效能力和操作方法
├── patterns/                 重复验证过的执行处方
├── reference-materials/      可直接使用的源码或原始资料
├── version-features.md       版本时间线，不作为当前能力入口
└── revisions/                重要变化的新旧差异和取代关系
```

并非每个目录必须立即创建所有子目录，但一旦出现第二次重要版本变化，就必须建立 `revisions/README.md`。

## 每次记录新功能时必须完成

1. 先核验官方文档、更新公告或当前实际环境，记录来源与核验日期。
2. 搜索仓库内同一功能、按钮、限制、价格或版本的旧说法。
3. 判断新信息是补充、局部替代还是完整替代。
4. 更新当前入口，只保留今天有效的结论。
5. 被取代内容移入版本时间线或日期化修订，标明“已被什么取代”。
6. 更新最近一层 README 的文件索引和读取条件。
7. 全仓扫描旧关键词，确认没有另一个文件仍把旧口径写成当前事实。
8. 运行仓库校验脚本。

## 动态事实的最低记录字段

每条容易过期的事实至少回答：

- 产品或平台是什么。
- 具体能力、限制、价格或界面路径是什么。
- 适用版本、套餐、地区、账号类型或运行环境。
- 来源链接或实际测试依据。
- 最后核验日期。
- 它取代了哪条旧口径，或者被哪条新口径取代。

## AI 读取规则

- 先读产品 README 和当前专题，不默认读取 `version-features.md`、全部修订或历史材料。
- 用户询问“以前为什么这样”“某版本什么时候改”时，才进入版本时间线和修订。
- 当前入口与历史记录冲突时，以当前入口为准；当前入口缺少核验日期时，必须重新查证。
- 平台更新频繁时，不因仓库有记录就跳过官方核验。

## 安全规则

- 不写入 API Key、Token、Cookie、密码、内部地址、完整认证文件或可用凭证。
- 原始配置只记录变量名、结构和安全位置，不保存真实值。
- 删除或覆盖重要历史前，确认 Git 已追踪且有可恢复提交。
- 推送前检查差异范围，避免把无关本地文件、导出物和隐私资料带入仓库。
